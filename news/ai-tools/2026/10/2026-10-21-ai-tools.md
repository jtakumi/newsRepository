### 1. Claude Code / `v2.1.305`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-10-20（GitHub Releases、20:46 / CHANGELOG）
- 概要: 直前の `v2.1.304` で入った回帰を修正する安定版。ゲートウェイがツール検索（tool search）を拒否した際に Vertex / Bedrock などで全リクエストが失敗していた問題を直し、ツール検索を外して自動リトライするようになった。`sandbox.allowNestedUserNamespaces` の追加、無人リトライ時に利用上限の解除を検知する `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS` の追加なども含む。
- 何が便利か: `v2.1.304` 更新後にゲートウェイ経由（Vertex / Bedrock / 社内プロキシ）で動かなくなっていた環境が、アップデートだけで復旧する。`/effort` や `/autocompact` が `modelOverrides` の値と大文字小文字や `[1m]` タグ違いで効かなかった問題も解消。
- 使いどころ: エンタープライズで LLM ゲートウェイ経由に Claude Code を使っている場合は最優先で更新したい。Linux サンドボックス内で Chromium や rootless podman を動かしたいときは `sandbox.allowNestedUserNamespaces` を明示的に有効化する（サンドボックスのファイル保護を回避しうる点に注意）。
- 開発者にとっての価値: Code Review 系の修正（複数プッシュが連続した際に最新コミットをレビュー対象から取りこぼす不具合、ブロッキング指摘が未解決のまま再レビューが LGTM で始まる挙動）も入り、PR 自動レビューの取りこぼしが減る。ベア（bare）リポジトリで新規 worktree が default ブランチでなくローカル HEAD から始まる不具合も修正。
- 注意点: `/artifacts` の削除確認が `1`/Enter で保持・`2` で削除・Esc でキャンセルに変更され、`y`/`n` は使えなくなった。`allowedMcpServers` が `env` 内でのみ `${VAR}` を使う `managed-mcp.json` の stdio サーバーをフィルタしなくなったため、止めたい場合は `deniedMcpServers` を使う。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.305
- メモ: 10-20 記事で扱ったのは `v2.1.304`（`/auto-mode-setup` 追加）。本記事の `v2.1.305` はその回帰修正が主眼で別リリース。

#### 使用例

# バージョン確認

### 2. GitHub Copilot CLI / `v1.0.101`（安定版）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-10-20（GitHub Releases）
- 概要: 前日の安定版 `v1.0.100` に続く安定版。対応モデルでの動的ワークフローサブエージェント向けネイティブ構造化出力と、Assisted Permissions 用の `assistedApprovalInstructions` 設定が安定版に昇格。権限プロンプトが昇格の理由を説明し、診断用コマンドを提示するようになった。`/config`・`/settings` から `showReasoning` を設定でき、セッション再開の高速化やサンドボックス MCP サーバーの再起動削減も入った。
- 何が便利か: 権限プロンプトが「なぜその昇格が必要か」を示すので、許可判断がしやすくなる。推論表示（`showReasoning`）を設定で切り替えられ、長い作業の再開が速くなる。
- 使いどころ: 権限まわりで迷ったときは提示される診断コマンドで原因を確認できる。サンドボックス内で MCP サーバーを多用する構成では、再起動が減って安定しやすい。
- 開発者にとっての価値: ネイティブ構造化出力が安定版に入ったことで、ワークフローサブエージェントの出力を型として安全に扱える。シェルコマンド・MCP サインイン・macOS のサンドボックス localhost アクセス・Google モデルの画像上限・Windows シェルの信頼性など多数の修正も同梱。
- 注意点: 10-20 時点の最新安定版は `v1.0.101`、同日の `v1.0.101-1` はプレリリース。構造化出力と `assistedApprovalInstructions` 自体は前日のプレリリース `v1.0.101-0` で先行導入されていたもので、本リリースはそれらを安定版に取り込みつつ権限プロンプト改善などを追加した位置づけ。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.101
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: 10-20 記事で扱ったのは安定版 `v1.0.100` とプレリリース `v1.0.101-0`。今回は安定版 `v1.0.101` で別リリース。

#### 使用例

```bash

npm install -g @github/copilot

# 設定から推論表示を切り替え
copilot
# 対話内で

```

### 3. Gemini CLI / `v0.65.0`（安定版）

- 種別: CLI
- 関連: Gemini / Google AI
- 公開・更新日: 2026-10-20（GitHub Releases、21:17 / 「Latest」）
- 概要: 安定版 `v0.64.0`（10-13）以来の新しい安定版。信頼されていない（untrusted）フォルダでは、ワークスペース設定を読み取り専用として強制するようになった。対話モードでの Enter によるハング修正、素早い Ctrl-C でのセッション破損（session poisoning）防止、ignore フィルタリングの最適化、許可リスト審査で 1 つの拡張機能が落ちても他の読み込みを続ける改善が入った。
- 何が便利か: 信頼できないディレクトリを開いたときに設定が勝手に書き換わらないため、他人のリポジトリやクローンしたばかりのコードを安全に触りやすい。Enter でのハングや Ctrl-C 連打でのセッション不整合が減り、日常の操作が安定する。
- 使いどころ: 外部から持ち込んだリポジトリをまず Gemini CLI で調べるとき、untrusted 扱いのままでも設定面の安全性が高い。複数の拡張機能を入れている環境でも、1 つの不備で全体が立ち上がらない事態を避けられる。
- 開発者にとっての価値: セキュリティ（untrusted フォルダでの読み取り専用強制）と堅牢性（ハング・セッション破損の修正）を中心にした地道な安定版で、業務利用の土台が固くなる。プレビュー `v0.66.0-preview.0` では Gemini 4 向け最適化が未了である旨のバナーや、ターミナルのスクロールバック保持などが先行。
- 注意点: 10-20 時点の「Latest」は安定版 `v0.65.0`。より新しい機能はプレビュー `v0.66.0-preview.0` や nightly（プレリリース）側にあり、業務利用は安定版 `v0.65.0` を基本に。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.65.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 過去記事で本文採用した安定版は `v0.64.0`（10-14 版）。`v0.65.0` は本記事が初出。

#### 使用例

```bash
# インストール / 更新
npm install -g @google/gemini-cli

# バージョン確認
gemini --version   # 0.65.0 を確認
```

### 4. Vercel AI SDK / `ai@7.0.147`（＋ `ai@7.0.146`）

- 種別: OSS / ライブラリ（TypeScript）
- 関連: Vercel AI SDK
- 公開・更新日: 2026-10-20（GitHub Releases / npm）
- 概要: `ai@7.0.146` が実験的な decision 呼び出しに `maxOutputTokens` と `reasoning` オプションを追加し、言語モデルを使う decision に引き渡せるようになった（ネイティブ decision プロバイダは未対応の場合に警告）。ツール呼び出しを整理する際に孤立した reasoning パートを正しく除去する修正や、オプショナルツールが型へ誤って `undefined` メンバーを足す不具合の修正も入った。`ai@7.0.147` はストリーミングされる UI メッセージパートで修復済みのツール名が保持されるよう修正し、`@ai-sdk/gateway` を `4.0.120` に更新。
- 何が便利か: decision（モデルに分岐・判断をさせる実験的機能）で出力トークン上限と reasoning を制御できるようになり、判断系ワークフローのコスト・挙動を調整しやすい。ツール整理まわりの型・ストリーミングの不整合が減る。
- 使いどころ: エージェント的な分岐処理を `experimental` の decision で組んでいる場合に、`maxOutputTokens` / `reasoning` を明示して挙動を制御する。ストリーミング UI でツール名が化けるケースの回避にも有効。
- 開発者にとっての価値: 実験的 API ながら decision 系の制御性が上がり、エージェント構築時のチューニング余地が広がる。`@ai-sdk/workflow` や `@ai-sdk/vue` など周辺パッケージも追従更新されている。
- 注意点: decision 関連は `experimental_` 接頭辞付きの実験的機能で、今後の変更可能性がある。ネイティブ decision プロバイダは `maxOutputTokens` / `reasoning` 未対応時に警告を出す。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.147
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 10-20 記事で扱ったのは `ai@7.0.144`（低メモリストリーミングの API 変更）。今回はより新しい `7.0.146` / `7.0.147` で、decision オプション追加が主眼。

#### 使用例

```bash
# インストール / 更新
npm install ai@latest
```
