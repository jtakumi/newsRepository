### 1. Claude Code / `v2.1.294`・`v2.1.295`

- 種別: CLI / 拡張機能
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-10-07〜10-08 頃（JST。公式 CHANGELOG 最新。`v2.1.293` までは 10-08 版記事で既報）
- 概要: `v2.1.293` に続く更新。`v2.1.295` の目玉はフックの `onFailure: "block"`。コマンド／HTTP フックが起動できない・タイムアウトする・想定外の終了コードで終わった場合に、その操作を素通しさせず「ブロック」できるようになった。あわせて Program Status Protocol（OSC 7501）対応が入り、対応ターミナルで Claude Code が「作業中／入力待ち／完了」のどれかを表示できる。`/copy` の引用テキスト対応（下書きを `>` マーカーなしでコピー）、`claude plugin install`／`enable`／`disable`／`marketplace add` が書き込み先の設定ファイルを読み込めないときの警告、`claude -p` が最終ターン後も開いたままのときに何を待っているかを stderr に出す行の追加なども入り、MCP・Bash・プラグイン・VS Code 拡張にまたがる多数の不具合修正を含む。`v2.1.294` は、指示文として書かれた `prompt`／`agent` フック（例:「〜なコマンドをブロックして」）がブロックすべきものを素通ししていた問題を修正し、Stop／SubagentStop の `prompt` フック（例:「ビルドが壊れていても続けて」）の判定を改善して、早すぎる停止を起きにくくした。
- 何が便利か: `onFailure: "block"` により、「このフックが通らない限り操作を進めない」という安全側の既定を宣言的に書ける。フック自体の失敗（起動不可・タイムアウト・異常終了）を見逃さないため、ガードが意図せず無効化される事故を防げる。指示文で書いたフックが意図通りに効くようになり、自然言語ベースのガードレールの信頼性が上がる。
- 使いどころ: lint／型チェック／秘密情報スキャンなどをフックで強制し、失敗したら操作をブロックしたいチーム。自然言語の指示でコマンドの可否や停止条件を書いている場合。`claude -p` を CI やスクリプトで非対話実行していて、ハングの原因を切り分けたい場合。
- 開発者にとっての価値: フックが「失敗したら素通し」から「失敗したらブロック」を選べるようになり、ガードレールを本番運用で信頼できる強度にできる。`claude update` だけで既存ワークフローに乗る。
- 注意点: `onFailure: "block"` を付けたフックが不安定だと正当な操作まで止まり得るため、フック自体の安定性（起動・タイムアウト設定）を先に確認する。CHANGELOG はバージョンごとに日付が付かないため、公開日は直近のリリース間隔からの概算。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://code.claude.com/docs/en/overview
- メモ: 更新は `claude update`（または再インストール）後に `claude --version` で `2.1.295` 以上を確認。

#### 使用例

```bash
# 更新してバージョン確認
claude update
claude --version   # 2.1.295 以上を確認
```

```json
// settings.json の例: フックが失敗したら操作をブロックする（v2.1.295）
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "./scripts/guard.sh", "onFailure": "block" }
        ]
      }
    ]
  }
}
```

### 2. OpenAI Codex CLI / `rust-v0.162.0`

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 安定版 `rust-v0.162.0`（2026-10-08、GitHub Releases で「Latest」）。`0.161.0` は 10-08 版記事で既報。
- 概要: worktrees 機能を有効にしている場合に、管理対象の Git worktree を作成・一覧するツールが追加された。エージェントの Command Center でタスクをピン留めでき、共有の Pinned グループにまとめられる。トランスクリプトは `/copy` でブロック単位のコピー、選択範囲は `Ctrl+Insert` でコピーでき、マウスホイールのスクロール速度も設定可能になった。多くのプロンプトやバナーで URL がクリック可能になり（折り返されたリンク含む）、カスタムの Responses 互換プロバイダ向けにライブ Web アクセスとリモート compaction の設定が入った。Code Mode ではオプトインのランク付きツール検索も追加。修正面では、新しい TUI スレッドにサーバー側のモデル／推論サマリー既定が適用される（明示指定は引き続き優先）、`apply_patch` で CRLF 改行が保持される、Linux サンドボックスの複数修正、Responses／WebSocket のリトライで `Retry-After` を尊重、PowerShell インストールのアーカイブ整合性検証の修正などが入った。
- 何が便利か: worktree の作成・一覧をエージェント操作の中から扱えるため、ブランチ並行作業をセッションを離れずに回せる。`/copy` と `Ctrl+Insert` でトランスクリプトや選択範囲をそのまま持ち出せ、ログ共有や引用が楽になる。タスクのピン留めで注目中の作業を見失いにくい。
- 使いどころ: Codex CLI で複数ブランチ（worktree）を並行して回す開発者。会話ログを課題管理やレビューに貼る運用。カスタムの Responses 互換プロバイダを使っている場合はライブ Web アクセス／リモート compaction 設定が効く。
- 開発者にとっての価値: 並行作業（worktree）・履歴の持ち出し（copy）・注目タスク管理（pin）という日常操作が一式強化され、安定版なので業務運用に乗せやすい。
- 注意点: worktree ツールは worktrees 機能を有効にしている場合のみ。`0.163.0-alpha` 系や `0.162.0-alpha` 系はプレリリースのため、業務利用は安定版（`0.162.0`）を基本に。既定モデル／推論サマリーがサーバー側既定で動くようになったため、特定設定を前提にしている場合は明示指定を確認する。
- 公式リンク: https://github.com/openai/codex/releases
- 参考リンク: https://github.com/openai/codex
- メモ: 更新は `npm install -g @openai/codex`（または `brew upgrade codex`）後に `codex --version` で確認。

#### 使用例

```bash
# 更新してバージョン確認
npm install -g @openai/codex
codex --version   # 0.162.0 以上を確認

# TUI 内でトランスクリプトをブロック単位でコピー（v0.162.0）
# codex 起動後にスラッシュコマンドを入力
/copy
```

### 3. GitHub Copilot CLI / `v1.0.94`

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.94`（2026-10-08、GitHub Releases で「Latest」）。`v1.0.93` は 10-08 版記事で既報。
- 概要: モデル選択と `--model` の補完に Claude Haiku 5.5 が追加された。Assisted Permissions（アシスト承認）が、実行予定のシェルコードを承認判定側に見える形で渡すようになり、不要な手動承認が減る。MCP まわりでは、`copilot mcp add` が MCP 設定の初期化を途中で中断した後でも復旧できるよう修正され、MCP サーバーを起動せずにサーバー探索前の有効化／無効化ができるようになった。管理設定が起動時の権限バイパスフラグを抑止している場合にポリシー警告を表示、管理設定が新しい CLI バージョンを要求する場合はプロンプトをブロックせずに更新案内を表示。管理ポリシーで Assisted Permissions を無効化し、セッションを手動承認モードに固定できるようになった。Sessions サイドバーの行切り替えの不具合も修正。
- 何が便利か: Assisted Permissions が実行予定コードを判定に渡すことで、安全性を保ったまま手動承認の回数を減らせる。MCP の有効化／無効化がサーバー起動なしでできるため、構成を軽く試せる。中断した MCP 追加からの復旧で設定作業のやり直しが減る。
- 使いどころ: Copilot CLI をエージェントとして常用し、MCP を複数つないで運用する開発者。組織で権限ポリシーを管理したいエンタープライズ利用（承認モードの固定、バージョン要求の案内）。軽量モデルとして Claude Haiku 5.5 を使いたい場合。
- 開発者にとっての価値: 承認体験の改善（手動承認の削減）と MCP 運用の取り回し向上がまとまって入る。エンタープライズ向けの管理ポリシー制御も強化され、業務運用に乗せやすい。
- 注意点: Assisted Permissions の挙動は承認判定にコードを渡す設計のため、組織のポリシー（Manual Approval 固定など）との整合を確認する。さらに先の機能はプレリリース（`v1.0.94-x` 系）側にある。
- 公式リンク: https://github.com/github/copilot-cli/releases
- 参考リンク: https://github.com/github/copilot-cli
- メモ: 変更内容は Releases の各タグのノートで確認できる。インストール手順は公式 README に従う。

#### 使用例

```bash
# バージョン確認（安定版 v1.0.94 を確認）
copilot --version

# モデル選択に Claude Haiku 5.5 が追加（--model 補完でも選べる）
copilot --model <tab補完で Claude Haiku 5.5 を選択>
```
