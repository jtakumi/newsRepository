### 1. Claude Code / `v2.1.296`

- 種別: CLI / 拡張機能
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-10-08〜10-09 頃（JST。公式 CHANGELOG 最新。`v2.1.295` までは 10-09 版記事で既報）
- 概要: `v2.1.295` に続く更新。Read ツールに `allow_large` オプションが追加され、通常の上限を超える大きめのファイル（または行範囲）を明示的に読み込めるようになった。サブエージェントごとに自動コンパクションの発火しきい値を変える `autoCompactWindow` 設定、ワークフローから呼ぶサブエージェントのモデルを固定する `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` 環境変数が入った。運用面では、過負荷（HTTP 529）で返ってきたときのリトライ待機に上限を設けられるようになり、MCP の再接続バックオフも改善。MCP ツール説明（tool description）の既定上限が 4,096 文字に引き上げられた。あわせて、管理対象フック（managed hooks）、MCP サーバー、ゲートウェイのサインイン、VS Code 拡張にまたがる多数の不具合修正を含む。
- 何が便利か: `allow_large` により「大きいファイルだからと途中で切られる」ケースを、必要なときだけ明示的に解除できる。`autoCompactWindow` をサブエージェント単位で持てるので、長時間動くサブエージェントと短命なサブエージェントでコンパクションの挙動を変えられる。MCP ツール説明の上限引き上げで、説明文が長い MCP ツールが途中で切れずに渡せる。
- 使いどころ: 大きめのログ・データファイルをエージェントに読ませたい場面（`allow_large`）。マルチエージェント/ワークフローでサブエージェントごとにモデルやコンパクション挙動を作り分けたいチーム。説明文の長い MCP ツール群をつないでいて、説明が切り詰められていた場合。
- 開発者にとっての価値: 大きいファイルの読み込み、サブエージェントの細かな制御、MCP 運用の取り回しがまとめて改善。`claude update` だけで既存ワークフローに乗る。
- 注意点: `allow_large` はコンテキストを大きく消費しうるため、本当に全体が必要なときに限定するのが前提。CHANGELOG はバージョンごとに日付が付かないため、公開日は直近のリリース間隔からの概算。`CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` はワークフロー機能を使っている場合に効く設定。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://code.claude.com/docs/en/overview
- メモ: 更新は `claude update`（または再インストール）後に `claude --version` で `2.1.296` 以上を確認。

#### 使用例

```bash
# 更新してバージョン確認
claude update
claude --version   # 2.1.296 以上を確認

# ワークフロー用サブエージェントのモデルを環境変数で固定
export CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL=claude-haiku-5-5
```

### 3. GitHub Copilot CLI / `v1.0.95`

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.95`（2026-10-09、GitHub Releases で「Latest」）。`v1.0.94` は 10-09 版記事で既報。
- 概要: macOS でネイティブの Microsoft Entra ブローカー認証を使えるようになり、利用できない環境ではブラウザ認証にフォールバックする。`--context` オプションが、新規セッションだけでなく再開した ACP セッションにも効くよう変更され、「既定や保存済みのコンテキストティアが暗黙に使われる」挙動がなくなった。`copilot config` がサンドボックスの認証情報を注入する `injectHosts` キーに対応し、Bash/Zsh/Fish でキー補完が効く。管理対象プラグインのセットアップは、メッセージ失敗のたびではなく 1 時間ごと（またはポリシー変更時）にリトライするようになった。
- 何が便利か: macOS で Entra ブローカー認証に乗れるため、組織の SSO/条件付きアクセス環境でのサインインが素直になる。`--context` が再開セッションにも効くので、コンテキストティアを指定した運用が再開後も崩れない。`injectHosts` でサンドボックス実行時にホスト単位の認証情報注入を設定できる。
- 使いどころ: 企業の Microsoft Entra（旧 Azure AD）配下で Copilot CLI を使う開発者。ACP セッションを再開しながらコンテキスト量を制御したい場合。サンドボックス実行で特定ホストへの認証を通したい場合。
- 開発者にとっての価値: エンタープライズ認証（Entra ブローカー）とセッション/サンドボックス運用の実用改善がまとまって入る。安定版なので業務運用に乗せやすい。
- 注意点: Entra ブローカー認証は macOS 向けの対応。さらに先の機能はプレリリース（`v1.0.95-x`／`v1.0.96-x` 系）側にある。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.95
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: 変更内容は Releases の各タグのノートで確認できる。インストール手順は公式 README に従う。

#### 使用例

```bash
# バージョン確認（安定版 v1.0.95 を確認）
copilot --version

# 再開セッションにもコンテキストティアを明示指定（v1.0.95）
copilot --context <tier>
```

### 4. Ollama / `v0.40.2`

- 種別: ローカルLLM / CLI / OSS
- 関連: Ollama / ローカルLLM関連ツール
- 公開・更新日: 安定版 `v0.40.2`（2026-10-08、GitHub Releases で「Latest」）。10-09 版記事の時点ではプレリリース扱いだったものが安定版に昇格。
- 概要: 旧バージョンの Ollama でダウンロードしたモデルを、初回実行時にバックグラウンドで自動アップグレードするようになった。性能と llama.cpp 互換性の改善が目的。アップグレード中は元のモデルのコピーをバックアップとして残すため一時的にディスク使用量が増えるが、`jq` を使う削除スクリプトが案内されており、将来のリリースで自動削除される予定。`ollama list` がアップグレード済みモデルを重複表示しなくなり、`ollama launch claude` がモデルのフルコンテキスト長を使うようになった。
- 何が便利か: 既存のローカルモデルを再ダウンロードせずに、新しいランタイムの性能・互換性を受けられる。`ollama list` の重複が消えて管理しやすい。`ollama launch claude` でフルコンテキストを使えるため、長い入力の扱いが素直になる。
- 使いどころ: 手元で複数のローカルモデルを運用していて、Ollama を上げたらそのまま性能・互換性を改善したい個人開発者・検証環境。オフラインや機密データでクラウドに出せない処理をローカルで回す場面。
- 開発者にとっての価値: 再 pull なしでローカル推論の土台が更新され、日常のローカルLLM運用がそのまま速く・安定する。OSS でセルフホストでき、個人でもすぐ試せる。
- 注意点: 自動アップグレードはバックアップを残すため一時的にディスクを多く使う。`v0.40` より古いバージョンへダウングレードする可能性がある場合、バックアップを削除すると該当モデルの再 pull が必要になる。削除スクリプトの実行には `jq` が要る。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.2
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 更新後、普段使うモデルを一度 `ollama run` すると初回にアップグレードが走る。

#### 使用例

```bash
# 更新後、普段のモデルを実行すると初回にバックグラウンドで自動アップグレード
ollama run llama3

# 重複表示が解消された一覧を確認
ollama list
```
