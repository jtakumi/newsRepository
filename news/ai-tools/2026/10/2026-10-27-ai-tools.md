## 今日の注目

### 1. Claude Code / `v2.1.311`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-10-26（前回カバーの `v2.1.310`（10/23）に続く最新リリース）
- 概要: 新機能・多数のバグ修正・挙動変更をまとめた大型リリース。安定運用上の細かい詰まりどころをまとめて解消している。
- 何が便利か: `self-hosted-runner` に `--hold-idle-file` と `--max-hold-min` を追加し、ホスト側が「まだ動いているプロセスがある」と報告する間アイドルセッションを保持できる。標準コンテキストのセッションがリクエストで 200K トークンを超えたとき「Usage credits required for 1M context」で止まっていた問題を修正し、会話をコンパクトして継続するようになった。接続完了が遅れた MCP サーバーのツールをサブエージェントが使えない問題、数千行の編集後に Write / Edit が最大 5 秒固まり「0 行変更」と報告する問題、自動コンパクト直後に古い MEMORY.md / CLAUDE.md を参照する問題、`claude -p` / SDK でトランスクリプトの順序が狂う問題なども修正。`ultrathink` は対話ターミナルで Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1 を xhigh effort で実行するよう変更された。
- 使いどころ: セルフホストランナーでの長時間ジョブ運用、長い会話を標準コンテキストで回す日常作業、MCP サーバー＋サブエージェント構成、Bedrock / Vertex / Foundry でのエージェント運用。
- 開発者にとっての価値: 「特定条件でだけ止まる・固まる」系の摩擦が広くつぶされており、長時間・大規模な作業でも落ちにくくなる。モデル名からの `[1m]` 除去や起動時間短縮など日常の細かな体験改善も多い。
- 注意点: `DISABLE_COMPACT` は設定ファイルやモッドの `$.env.set` ではコンパクトを「無効化」する方向にしか効かなくなった。Bedrock / Mantle / Vertex / Foundry ではモデル設定を downloads.claude.ai 上の署名済みファイルから読むようになり、無効化するには `CLAUDE_CODE_MODEL_CATALOG=off` を設定する。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.311
- メモ: npm の `@anthropic-ai/claude-code` から更新可能。前回カバーは `v2.1.309` / `v2.1.310`（10/25 付記事）。

#### 使用例

```bash
# 更新して最新版を確認
npm install -g @anthropic-ai/claude-code
claude --version
```

### 2. Cline / Desktop `v0.0.49`・VS Code `v4.1.26`・SDK `v0.2.0`・CLI `v3.0.74`

- 種別: 拡張機能 / デスクトップアプリ / SDK / CLI
- 関連: Cline / ローカルLLM（Ollama / LM Studio）
- 公開・更新日: 2026-10-26（前回系列は 10/16〜17）
- 概要: デスクトップ・VS Code 拡張・SDK・CLI を同日に更新したまとまったリリース。デスクトップ版の機能拡充とタスクアタッチ周りの改善が中心。
- 何が便利か: Desktop `v0.0.49` でターン単位・セッション単位の差分を見る「Changes」ボタン、プロジェクトファイルパネル、統合ターミナル（Ctrl + ` ）、Ollama / LM Studio 向けのローカルモデル設定ページを追加。キーバインドも設定可能になり、Hub 起動失敗時には Retry 付きの起動画面を表示する。CLI `v3.0.74` は別の Cline アプリで既に動いているタスクへアタッチでき、`cline hub status` / `cline doctor` は 3 秒でタイムアウトしてハングしなくなった。SDK `v0.2.0` は実行中セッションのランタイムを置き換えず再アタッチし、推論だけが流れて落ちたターンを再試行する。VS Code 拡張 `v4.1.26` は設定に Local / Cloud トグルを追加し、モデルカタログを刷新した。
- 使いどころ: ローカルLLM（Ollama / LM Studio）中心のコーディング、デスクトップアプリで差分を確認しながらの作業、CLI とデスクトップを併用して同一タスクを引き継ぐ運用。
- 開発者にとっての価値: ローカルモデル設定ページとローカル実行の再アタッチにより、外部 API に出さずローカル完結で試せる範囲が広がる。デスクトップの統合ターミナル・差分ビューで作業が 1 アプリ内に収まる。
- 注意点: Local / Cloud トグルの「Cloud」はクラウドタスク向けの設定。VS Code 拡張ではモデルのリトライ回数が 5 回から 3 回に減り、CrofAI / iFlow / Llama がカタログから削除された。
- 公式リンク: https://github.com/cline/cline/releases
- 参考リンク: https://github.com/cline/cline
- メモ: 前回 AI Tools News で Cline を扱ったのは 10/16〜17 系（SDK v0.0.95 / Desktop v0.0.48 / CLI v3.0.73）。今回はメジャーに近い SDK v0.2.0 とデスクトップ機能追加があるため採用。

### 3. Vercel AI SDK / `ai@7.0.154`

- 種別: OSS / TypeScript SDK
- 関連: Vercel AI SDK
- 公開・更新日: 2026-10-26
- 概要: エラーハンドラとテレメトリ、実験的 steering を追加した機能リリース。
- 何が便利か: `generateText` / `streamText` / `ToolLoopAgent` にステップ単位で失敗を拾う `onStepError` コールバックを追加。`ToolLoopAgent` には `onError` / `onAbort` も追加され、途中のエラーや中断をフックできる。テレメトリイベントに `aiVersion` が付与され、どの SDK バージョンの実行かを計測側で判別できる。さらに `generateText` / `streamText` / `ToolLoopAgent` に実験的な steering（生成途中で方向づけする仕組み）が入った。
- 使いどころ: ツール呼び出しを含むエージェント実装でのステップ単位のエラー処理・リトライ、生成の中断ハンドリング、OpenTelemetry などでのバージョン別計測。
- 開発者にとっての価値: マルチステップのエージェント処理で失敗箇所を特定・回復しやすくなり、本番運用時の可観測性が上がる。steering は生成制御の新しい実験的手段。
- 注意点: steering は experimental 扱いで今後 API が変わる可能性がある。同時刻に出た `ai@6.0.316` / `ai@5.0.282` は `@ai-sdk/gateway` の依存更新のみ。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.154
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 前回カバーは `ai@7.0.153`（10/25 付記事、非ストリーミング構造化出力の修正）。

#### 使用例

```bash
# 最新版へ更新
npm install ai@latest
```

### 4. LiteLLM / `v1.106.4`（＋ 1.103〜1.105 系バックポート）

- 種別: OSS / Python SDK / プロキシ
- 関連: LiteLLM / 各種モデルプロバイダ
- 公開・更新日: 2026-10-25
- 概要: 起動時クラッシュの回帰修正を複数の系列にバックポートしたパッチリリース。
- 何が便利か: リモートのモデルコストマップに到達できないとき、プロキシが起動時に ImportError で終了することがある不具合（`v1.104.0` 以降存在した回帰）を修正。あわせてイメージスキャンが brotli 1.2.0・あるルート CA・未使用のロックファイルパッケージを誤検知する問題も修正。`v1.106.4` / `v1.105.5` / `v1.104.7` / `v1.103.9` に同趣旨の修正が入っている。公式リリースノートは「アップグレードに追加作業は不要（No action needed to upgrade）」としている。
- 使いどころ: ネットワーク制限下やコストマップ取得が不安定な環境での LiteLLM プロキシ運用、CI でのイメージスキャン。
- 開発者にとっての価値: 外部到達性に依存して起動が落ちるリスクが減り、ゲートウェイ運用の安定性が上がる。
- 注意点: これは `v1.106.3`（10/24）の cosign 署名鍵変更の後続パッチ。署名検証をしている場合は `v1.106.3` 時点のコミット `e82a3c6` の新しい `cosign.pub` への差し替えが引き続き前提（旧鍵では検証が通らない）。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.106.4
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 前回カバーの安定版は `v1.106.3`（10/25 付記事）。今回は起動時 ImportError の回帰修正のみの後続ホットフィックス。

#### 使用例

```bash
# 最新版へ更新
pip install -U litellm
```
