### 1. Claude Code / `2.1.302`（安定版）

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 安定版 `2.1.302`（2026-10-16、`anthropics/claude-code` の公式 CHANGELOG で最新）。前回（10-16 版）記事では `2.1.299`〜`2.1.301`（10-14〜10-15）までを本文採用していたため、`2.1.302` の内容は本記事が初出。
- 概要: fork サブエージェント（`subagent_type: "fork"`）が `claude -p`、Agent SDK、デスクトップアプリ、VS Code でデフォルト有効になった（`CLAUDE_CODE_FORK_SUBAGENT=0` で無効化）。クライアント側 auto mode 分類器が使うモデルを選べる `CLAUDE_CODE_AUTO_MODE_MODEL` を追加。サードパーティプロバイダ利用時、権限モード未指定の `claude -p`／Agent SDK セッションは `default` モードで開始するよう変更（`--permission-mode auto` を付ければ auto を維持）。修正面では、コンパクション中にターンを止めた際の「Prompt is too long」エラー、Read ツールが画像ファイル（やパイプ・デバイス）をサイズ問わずメモリに丸ごと読み込む問題（128MB 超は拒否）などが入った。
- 何が便利か: fork サブエージェントのデフォルト有効化で、`claude -p` や SDK からの並列的なサブタスク委譲が追加設定なしで効くようになり、調査と実装を分けて走らせやすくなる。`CLAUDE_CODE_AUTO_MODE_MODEL` は auto mode の分類器に軽量モデルを割り当てるなどコスト・レイテンシの調整余地を与える。Read の 128MB 超拒否は、誤って巨大画像を読み込んでメモリを圧迫する事故を防ぐ。
- 使いどころ: 非対話の `claude -p` やエージェント SDK を使った自動化パイプライン、auto mode を使う構成でのモデル指定、画像を含むリポジトリでの安全な読み取り。
- 開発者にとっての価値: `npm i -g @anthropic-ai/claude-code`（または各配布経路）で安定版をそのまま更新でき、CI やスクリプトからの利用（`-p`／SDK）で fork サブエージェントが標準化される。既存の自動化がデフォルト挙動変更の影響を受け得るため、更新時に権限モードと fork の挙動を確認したい。
- 注意点: サードパーティプロバイダでの権限モード既定変更と fork デフォルト有効化は、既存の非対話スクリプトの挙動を変える可能性がある。想定と違う場合は `--permission-mode` と `CLAUDE_CODE_FORK_SUBAGENT=0` で明示的に戻せる。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: 前回扱った `2.1.301`（vim の `%` モーション、Grep/Glob の検索失敗エラー化など）からの積み増し。更新後は `claude --version` で `2.1.302` を確認。

#### 使用例

```bash
# インストール / 更新
npm i -g @anthropic-ai/claude-code

# バージョン確認（2.1.302 を確認）
claude --version

# 非対話実行で fork サブエージェントを無効化したい場合
CLAUDE_CODE_FORK_SUBAGENT=0 claude -p "リポジトリの概要をまとめて"

# auto mode 分類器のモデルを指定（例）
export CLAUDE_CODE_AUTO_MODE_MODEL=claude-haiku-5-5
```

### 2. GitHub Copilot CLI / `v1.0.99-2 / -3`・`v1.0.100-0 / -1`（プレリリース）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: プレリリース `v1.0.99-2`（2026-10-16 00:49）、`v1.0.99-3`（2026-10-16 15:08）、`v1.0.100-0`（2026-10-16 20:10）、`v1.0.100-1`（2026-10-16 22:41）。いずれも `github/copilot-cli` の Releases で Pre-release。安定版（Latest）は依然 `v1.0.98`（10-14）。前回（10-16 版）記事では `v1.0.98` と `v1.0.99-0/-1` までを扱ったため、`v1.0.99-2` 以降は本記事が初出。
- 概要: オンラインセッションでセマンティックコード検索をデフォルト有効化（`v1.0.99-2`）。`/sessions`・`/session`・`/resume` が統合 Sessions ブラウザをデフォルトで使うようになり、アカウントのセッション探索は最大 500 件に制限し `Retry-After` ヒントを尊重（`v1.0.100-1`）。クライアントテレメトリ送信を止める `--disable-client-telemetry` を追加（`v1.0.99-3`）。サンドボックス設定が無い場合に host ルールの通信で `HTTPS_PROXY`／`HTTP_PROXY` を使うよう修正（`v1.0.100-1`）。管理者設定が選択モデルを上書きした際の通知表示、MCP サーバがハングした際のセッション停止修正、Gemini のツール呼び出し失敗修正（`v1.0.99-2`〜`v1.0.100-0`）なども入った。
- 何が便利か: セマンティックコード検索のデフォルト化で、キーワード一致だけでなく意味ベースでリポジトリ内の該当箇所を探しやすくなり、大きめのコードベースでの調査が速くなる。統合 Sessions ブラウザは過去セッションの再開（`/resume`）導線を一本化する。`--disable-client-telemetry` は社内規定でテレメトリを止めたい環境向けの明示スイッチ。サンドボックスの `HTTPS_PROXY`/`HTTP_PROXY` 対応は、プロキシ必須のネットワーク下での利用を安定させる。
- 使いどころ: 大規模リポジトリでの意味ベースのコード探索、過去セッションの再開運用、テレメトリを抑止したい企業環境、プロキシ経由でしか外部に出られないネットワークでの利用。
- 開発者にとっての価値: Copilot CLI を日常のコード調査・編集に使う場合、検索精度とセッション管理の改善が効く。ただし本記事分はプレリリースのため、業務の基盤に据えるなら安定版 `v1.0.98` を基本に、新機能を試すときにプレリリースを使い分けたい。
- 注意点: `v1.0.99-2`〜`v1.0.100-1` はすべて Pre-release で、Latest は `v1.0.98`。セマンティックコード検索の「デフォルト有効」はオンラインセッションが対象。プレリリースは挙動が変わり得る。

- メモ: 前回扱った `v1.0.99-0/-1`（`--trust-folder`、browser-use への改名など）の続き。インストールは `npm i -g @github/copilot`、プレリリースを試す場合はタグ指定でのインストールを検討。

### 3. Ollama / `v0.40.6`（安定版）

- 種別: OSS / ローカル LLM ランタイム
- 関連: ローカルLLM / Ollama Cloud
- 公開・更新日: 安定版 `v0.40.6`（2026-10-16 22:00 UTC、`ollama/ollama` の Releases で「Latest」。バイナリのタイムスタンプは 2026-10-17）。前回（10-16 版）記事では安定版 `v0.40.5`（10-14）を扱っていたため、`v0.40.6` の差分は本記事が初出。
- 概要: decision model 「clef」を Ollama のクラウドで提供開始。GGUF の `q2_0` テンソルおよびファイル形式に対応。`--ask` モードを、質問キーに識別子を使う方式へ変更。Windows でランナープロセスが孤児化するのを防ぐ修正を追加。
- 何が便利か: `q2_0` 対応で、より低ビットに量子化した GGUF モデルを読み込めるようになり、VRAM/メモリが限られた環境でも大きめのモデルを動かす選択肢が広がる。「clef」のクラウド提供は、ローカルに pull せずに decision model の挙動を試せる。`--ask` の識別子化は、スクリプトから質問への回答を安定して紐付けやすくする。Windows のランナー孤児化修正は、長時間運用での余分なプロセス残留を防ぐ。
- 使いどころ: メモリ制約下での低ビット量子化モデルの検証、クラウド経由での decision model の試用、`--ask` を使った対話の自動化、Windows でのローカル運用。
- 開発者にとっての価値: `ollama pull` ／ `ollama run` で使うローカルランタイムに量子化形式とクラウド経由モデルの選択肢が増え、ローカル/クラウドを使い分けた検証がしやすくなる。安定版なので既存環境にそのまま更新できる。
- 注意点: `q2_0` のような低ビット量子化は品質低下とのトレードオフがあるため、用途に応じて精度を確認したい。「clef」はクラウド経由のため、サインインや利用規約・コストの確認を伴う。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.6
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 前回扱った `v0.40.5`（NVIDIA Nemotron 3.5 Super・`clef:cloud` 系対応）からの積み増し。更新後は `ollama --version` で確認。
