## 今日の注目

### 1. GitHub Copilot CLI / `v1.0.96`（安定版）・`v1.0.97-0`（プレリリース）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.96`（2026-10-12 18:52 UTC、GitHub Releases で「Latest」）。プレリリース `v1.0.97-0`（2026-10-12 20:45 UTC）。前回記事（10-12 版）では `v1.0.95` が Latest、`v1.0.96-x` 系はプレリリースとして言及していた段階だったため、安定版昇格と `v1.0.97-0` の内容は本記事が初出。
- 概要: `v1.0.96` で、対話型サンドボックス設定が環境シークレットを提案し保存前にマスキング対象ホストを追加できるようになった。`/model`・`/config` のモデル ID は大文字小文字を区別せず正規化された ID で保存される。`/add-dir` で追加したディレクトリはそのセッション中サンドボックスからアクセス可能になり、`/user list` はサインイン中の各アカウントの認証ソースを表示する。権限タイムラインには、各許可判断を「自分 / Assisted Permissions / ポリシー / 無人フォールバック」のどれが下したかが出る。プレリリース `v1.0.97-0` では、カスタムエージェントごとにスコープを限定したフック（agent-scoped hooks）が追加され、画像がデフォルトでインライン表示される。
- 何が便利か: `/add-dir` のサンドボックスアクセスで、作業中に追加したディレクトリを一度許可すればセッション内で繰り返し尋ねられずに済む。権限タイムラインの判断主体表示は、無人実行やポリシー適用時に「なぜ通った／止まったか」を後から追える。`v1.0.97-0` の agent-scoped hooks は、特定のカスタムエージェントだけにフック（例: 実行前チェックや後処理）を限定でき、エージェントごとの挙動を分離できる。
- 使いどころ: 複数ディレクトリにまたがる修正、チーム/企業ポリシー下での無人・半自動実行、カスタムエージェントを複数定義して役割ごとに前後処理を変えたい運用。
- 開発者にとっての価値: サンドボックス・権限まわりが実運用で詰まりにくくなり、監査性（誰が許可したか）も上がる。agent-scoped hooks はエージェント設計の自由度を広げる。
- 注意点: agent-scoped hooks とインライン画像表示はプレリリース `v1.0.97-0` 側。業務利用は安定版 `v1.0.96` を基本に。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.96
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: `v1.0.95`（Entra ブローカー認証・`injectHosts`）は 10-12 版記事で既報。本記事は `v1.0.96` 安定版昇格以降の差分を扱う。

#### 使用例

```bash
# インストール / 更新（npm 経由）
npm install -g @github/copilot

# 作業ディレクトリを追加してサンドボックスアクセスを付与
/add-dir ./packages/api

# サインイン中アカウントの認証ソースを確認
/user list
```

### 2. LiteLLM / `v1.105.0`

- 種別: OSS / API ゲートウェイ（プロキシ）
- 関連: OpenAI 互換 / Anthropic / xAI / Databricks / MCP
- 公開・更新日: 安定版 `v1.105.0`（2026-10-11 09:53 UTC、GitHub Releases で「Latest」）。前回の AI ツール記事での LiteLLM 言及は 9 月（`v1.101`〜`v1.102` 系）で、`v1.105.0` は初出。
- 概要: MCP 周りが強化され、プロトコルバージョンの設定とケイパビリティ検出、上流ツール説明のスキャン/ピン留め、ツール面をまたいだ互換性考慮の結果変換、Microsoft 365（Graph）サーバのカタログ追加に対応。新プロバイダとして Sail・Prism・Cortecs（OpenAI 互換）を追加し、Databricks Zerobus のトレースログコールバック、Fireworks AI ルータ（auto / auto-instant / firerouter）のルーティングと一覧表示が入った。xAI はネイティブ batches/files に対応し、Grok 4.7 の価格が各プロバイダに追加された。`litellm.agent()` から Claude Code・Codex・opencode・deep agents をゲートウェイ経由で実行でき、CLI は保存済みのエージェント設定を再利用しつつ再設定オプションを追加。`fail_closed_rate_limit_enforcement` は Redis のレートリミットカウンタに到達できないとき 503 を返す。
- 何が便利か: 複数プロバイダ・複数モデルを 1 つの OpenAI 互換エンドポイントに集約する運用で、MCP ツールの取り扱いと監査（説明のピン留め・スキャン）が標準化される。`litellm.agent()` でエージェント系 CLI をゲートウェイ越しに統一的に呼べる。
- 使いどころ: 社内 LLM ゲートウェイ、コスト・レート制御、複数プロバイダのフェイルオーバー、MCP サーバをチームで共有する構成。
- 開発者にとっての価値: プロバイダ追加・価格更新・MCP 運用が頻繁に反映されるため、ゲートウェイを自前運用する場合の追従コストが下がる。`fail_closed_rate_limit_enforcement` は Redis 障害時に「開きっぱなし」を避けたい本番運用で有効。
- 注意点: 新プロバイダや `litellm.agent()` は環境・認証情報の設定が前提。レートリミットの fail-closed 挙動を有効にすると Redis 到達不可時にリクエストが 503 になるため、可用性要件と合わせて検討する。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.105.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 同日に `v1.104.3`（1.104.x へのバックポート）、翌日にかけて `v1.106.0-rc.1` などのプレリリースも進行中。本番は安定版「Latest」の `v1.105.0` を基準に。

#### 使用例

```bash
# インストール
pip install 'litellm[proxy]'

# プロキシ起動（設定ファイルで複数プロバイダ/MCP を集約）
litellm --config config.yaml
```

### 3. Ollama / `v0.40.4-rc0`（プレリリース）

- 種別: OSS / ローカル LLM ランタイム
- 関連: Google（EmbeddingGemma）/ ローカルLLM
- 公開・更新日: プレリリース `v0.40.4-rc0`（2026-10-12 19:00 UTC）。安定版は `v0.40.3`（10-11、10-12 版記事で既報）。本記事は `v0.40.4-rc0` の新規差分を扱う。
- 概要: llama.cpp を build b11521 に更新し、「decision models」と EmbeddingGemma 2 への対応が入った。サーバの推論ルートが検証済みマニフェストとロード済みモデルを再利用するようになり、MLX は投機的ロールバック後に復元した recurrent state をコンパクトにする。`ollama launch codex` の `/model` ピッカーにインストール済みモデルが表示されるようになった。
- 何が便利か: EmbeddingGemma 2 に対応したことで、ローカルでの埋め込み生成（RAG のインデックス作成など）の選択肢が増える。推論ルートのマニフェスト/モデル再利用は、連続リクエスト時の効率に効く。
- 使いどころ: ローカル RAG の埋め込み生成、オフライン環境での検証、Codex 連携時のモデル選択。
- 開発者にとっての価値: ローカルで完結する埋め込み・推論の構成を試しやすくなる。クラウドに出せないデータでの RAG 検証に向く。
- 注意点: `v0.40.4-rc0` はリリース候補（rc）であり本番向けではない。EmbeddingGemma 2 や decision models の詳細は公式リリースノートに追加説明がなく、モデルの入手可否・仕様は別途確認が必要。安定運用は `v0.40.3` を基準に。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.4-rc0
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 安定版 `v0.40.3`（コーディングツール連携の警告削除・バックグラウンド更新の一時停止）は 10-12 版記事で既報。

#### 使用例

```bash
# rc は通常の自動更新には乗らないため、入手可否はリリースページで確認
# 安定運用は v0.40.3 を使用
ollama --version
```
