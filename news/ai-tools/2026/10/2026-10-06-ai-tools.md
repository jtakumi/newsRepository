### 1. GitHub Copilot CLI / `v1.0.92`（安定版昇格 + トークン非伝播のセキュリティ既定）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.92`（2026-10-05）。プレリリース `v1.0.92-5`（2026-10-05）で Entra サインイン後のアカウント選択と `/logout` を追加。
- 概要: 10-05 版記事でプレリリース（`v1.0.92` 系）として既報だった `copilot config`（list/read/set/remove）と、会話開始前に Ctrl+E でローカル/クラウドの実行環境を切り替えるピッカーが、安定版 `v1.0.92` に昇格した。あわせてセキュリティ既定が変わり、サンドボックス内の shell は明示設定がない限り ambient な `GITHUB_TOKEN` を渡さなくなった。コンテキスト超過時に最新プロンプトを保持する compaction、Entra 保護の MCP サーバー向けのサイレントなトークン更新と Entra サインインのブラウザ認証フォールバック、レガシー HTTP+SSE 接続が無限にハングする不具合の解消、大きなファイル書き込み後のセッション低下の改善なども入った。
- 何が便利か: プレリリースで試せた設定管理と実行環境の切替が、安定版でそのまま使える。サンドボックス shell が GitHub トークンを自動では渡さなくなり、意図しないトークン露出のリスクが下がる。コンテキストが溢れても直近の指示が残る。
- 使いどころ: Copilot CLI をエージェントとして常用し、ローカルとクラウドを行き来する開発者。サンドボックスや CI で回すチーム、Entra（Azure AD）認証環境を使う組織。
- 開発者にとっての価値: 先行機能が安定版に落ちて業務に乗せやすくなり、トークン非伝播という安全側の既定変更が加わった。既存の Copilot CLI ワークフローにそのまま追加できる。
- 注意点: `GITHUB_TOKEN` 非伝播は既定の挙動変更。サンドボックス内で `gh` などがトークンを前提にしている場合は明示的に渡す設定が必要になる。アカウント選択や `/logout` の OAuth サインアウトは現状プレリリース（`v1.0.92-5`）の機能。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.92
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: 更新後に `copilot --version` で `1.0.92` 以上を確認。安定運用は安定版 `v1.0.92`、Entra アカウント選択など先行機能はプレリリースで試す。

#### 使用例

```bash
# バージョン確認（安定版 v1.0.92 以上）
copilot --version

# 設定管理（安定版に昇格）
copilot config list
copilot config set <key> <value>

# 会話を始める前に Ctrl+E でローカル⇄クラウドの実行環境を切り替え
# サンドボックス shell で gh 等にトークンが必要な場合は明示設定する
```

### 2. LiteLLM / `v1.104.0`（+ `v1.105.0-rc.1`）セキュリティ強化

- 種別: OSS / API ゲートウェイ（LLM プロキシ）
- 関連: その他（マルチプロバイダ / OpenAI / Anthropic / Azure / MCP）
- 公開・更新日: 安定版 `v1.104.0`（2026-10-03）、プレリリース `v1.105.0-rc.1`（2026-10-04）
- 概要: 多数の LLM を 1 つの OpenAI 互換エンドポイントに束ねる LiteLLM Proxy のセキュリティが大きく強化された。`v1.104.0` は「master key が未設定・空・公知の値の場合は起動を拒否する」破壊的変更を導入。あわせて漏洩パスワード検知をパスワードポリシーに追加、セルフサービスでのパスワード変更、漏洩/管理者設定パスワードの強制リセット、無効化済み JWT ユーザーの拒否、ログアウト/パスワード変更時の UI セッショントークン失効を実装。マイグレーションは v2 リゾルバを既定化し、リリース間アップグレード経路のテストを追加した。MCP 周りはサーバー一覧を更新をまたいで安定化、プロンプト/リソース探索のページネーション、重複するサーバー名/エイリアスの拒否などを追加。プレリリース `v1.105.0-rc.1` では cosign による Docker イメージ署名検証に対応した。
- 何が便利か: 弱い（または公知の）master key のまま本番起動してしまう事故を既定で防げる。認証・セッション周りが堅くなり、Docker イメージの署名検証で配布イメージの真正性を確認できる。
- 使いどころ: 複数プロバイダのモデルを社内に集約提供するゲートウェイ運用。鍵・認証・監査を重視する本番環境、コンテナ配布の真正性を担保したいチーム。
- 開発者にとっての価値: ゲートウェイの運用安全性が「設定しなくても安全側」に底上げされる。MCP 接続の安定化も日常のエージェント連携に効く。
- 注意点: master key の起動拒否は破壊的変更。既存デプロイは強い master key を明示設定しないと起動しなくなる点に注意。`v1.105.0-rc.1` はプレリリースのため、署名検証の本採用はリリースノートで安定版化を確認してから。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.104.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: `v1.104.0` へ上げる前に、本番の環境変数で強い `LITELLM_MASTER_KEY` が設定されているかを確認する（未設定だと起動しなくなる）。

#### 使用例

```bash
# master key を明示設定して起動（未設定・空・公知の値だと v1.104.0 は起動拒否）
export LITELLM_MASTER_KEY="sk-<十分に長いランダム値>"
litellm --config config.yaml
```

### 3. OpenAI Codex CLI / `0.160.1`（リモート stdio MCP の Windows 環境変数保持）

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 安定版 `0.160.1`（2026-10-05）。プレリリース `0.162.0-alpha.14`〜`alpha.16`（2026-10-05）。
- 概要: `0.160.1` は保守リリース。リモート stdio MCP サーバーを起動する際、明示的に設定されたリモート環境変数に対して Windows の `SYSTEMROOT`/`TEMP`/`TMP` を保持するよう修正した。Unix ホストから Windows 実行環境を起動する場面での環境変数取りこぼしを防ぐピンポイント対応。10-04 版記事で既報の安定版 `0.160.0` の後続パッチにあたる。`0.162.0-alpha` 系は引き続きプレリリースとして進行中。
- 何が便利か: Windows 実行環境を絡めたリモート MCP サーバーの起動が安定し、環境変数起因の起動失敗を避けられる。
- 使いどころ: Codex から Windows 実行環境 + リモート stdio MCP を使うクロスプラットフォーム構成。
- 開発者にとっての価値: MCP 連携の信頼性向上（単一の環境依存修正だが、該当環境では効く）。安定版を追いつつ、先行機能を見たい場合は alpha 系も選べる。
- 注意点: 環境依存の修正が中心で、該当しない環境では影響がない。`0.162.0-alpha` 系はプレリリースのため業務利用は安定版 `0.160.1` を基本に。
- 公式リンク: https://github.com/openai/codex/releases
- 参考リンク: https://github.com/openai/codex
- メモ: 更新は `npm install -g @openai/codex`（または `brew upgrade codex`）後に `codex --version` で `0.160.1` 以上を確認。

#### 使用例

```bash
# 更新してバージョン確認
npm install -g @openai/codex
codex --version   # 0.160.1 以上を確認
```
