### 1. OpenAI Codex CLI / `0.163.0`（安定版）

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 安定版 `0.163.0`（2026-10-15 21:30 UTC、GitHub Releases で「Latest」。npm `@openai/codex` の `latest` も同 21:37 UTC に `0.163.0` へ更新）。前回（10-14 版）記事までは安定版 `0.162.1`（10-09）が据え置きで、期間中は `0.163.0-alpha.8`〜`.11` 系プレリリース（リリースノートはバージョン名のみ）だったため、安定版 `0.163.0` の内容は本記事が初出。
- 概要: 検索できる `/config` 画面を追加し、設定項目を名前で探せるようになった。応答の途中で指示を差し込んで方向を変えられる mid-response steering、`/keymap` でのリーダーキー（leader key）設定、`/daemon` からのデーモン再起動、read-only ツールの並列実行に対応。対象アカウントでは Daybreak がデフォルトで有効になった。修正面では、再開したスレッドでの権限復元、ネットワークプロキシのチェック、`/side` のナビゲーション、Windows/WSL での貼り付け、コマンド出力の扱いなどが入っている。
- 何が便利か: read-only ツールの並列実行で、ファイル読み取りや検索など副作用のない操作をまとめて走らせられ、調査フェーズの待ち時間が縮む。mid-response steering は、長い生成の途中で「やっぱりこの方針で」と割り込めるため、最初の指示が不完全でもやり直しコストが減る。`/config` の検索は設定項目が増えた CLI で目的のオプションに素早く到達できる。
- 使いどころ: コードベースの調査・把握（複数ファイルを並列に読む）、要件が固まりきらないまま進める対話的な実装、デーモン運用での再起動オペレーション、キーバインドを自分好みに詰めたい日常利用。
- 開発者にとっての価値: 久々の安定版で、`npm i -g @openai/codex`（または Homebrew）で `0.163.0` をそのまま業務に乗せられる。並列 read-only と mid-response steering は「調査を速く・修正を柔軟に」という対話型コーディングの実利に直結する。
- 注意点: Daybreak の「デフォルト有効」は対象アカウント（eligible accounts）に限られ、全環境で同じ挙動になるとは限らない。より新しい変更は `0.163.0-alpha` 系プレリリース側にあるが、業務利用は安定版 `0.163.0` を基本に。

### 3. Claude Code / `2.1.299`〜`2.1.301`

- 種別: CLI
- 関連: Claude / Anthropic
- 公開・更新日: `2.1.299`（2026-10-14 00:23 UTC）、`2.1.300`（2026-10-14 14:27 UTC）、`2.1.301`（2026-10-15 14:34 UTC）。いずれも npm `@anthropic-ai/claude-code` の公開時刻で確認。前回（10-14 版）記事では CHANGELOG 最新が `2.1.296`（10-09）据え置きで新規エントリなしとしていたため、本 3 バージョンは本記事が初出。
- 概要: `2.1.299` でターミナルのアイドルコンパクションを追加（20 万トークン超の会話を約 54 分放置すると 1 時間のプロンプトキャッシュ失効前にコンパクト化。`CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` で調整、`"idleCompaction": false` で無効化）。`CLAUDE_CODE_DISABLE_FILE_MENTIONS` で `@` メンションをファイル内容ではなくパス渡しにできる。WSL2 のサンドボックス `bwrap` エラーや、macOS のサンドボックスが symlink 経由で拒否パスに到達する問題を修正。`2.1.300` では大きいリクエストの gzip 圧縮（`CLAUDE_CODE_GZIP_REQUEST_BODIES=0` で無効化）、MCP ツールの入力スキーマを API が拒否して毎ターン 400 で失敗する問題の修正、エージェントフックの `model` 設定の尊重などが入った。`2.1.301` では、Grep/Glob が検索失敗時に「ヒットなし」ではなくエラーを返すよう修正、Read ツールが `.xlsm`・`.parquet`・`.epub`・`.heic` などバイナリをテキストとして読まないよう修正、小さいコンテキストのモデルへ切替時に前モデルで会話を要約してから渡すように改善。
- 何が便利か: アイドルコンパクションは、長時間放置した大きな会話がキャッシュ失効でコストを膨らませる前に自動で圧縮し、再開時の無駄を抑える。`@` メンションのパス渡し（`CLAUDE_CODE_DISABLE_FILE_MENTIONS`）は、巨大ファイルを丸ごとコンテキストに載せず、必要箇所だけツールで読ませたい場合にトークンを節約できる。Grep/Glob のエラー報告は「本当に 0 件か、検索自体が失敗したか」を取り違えずに済む。
- 使いどころ: 長時間の対話セッションを跨いで作業する運用、巨大ファイルを含むリポジトリでのコンテキスト節約、MCP ツールを多用する構成、サンドボックス（WSL2 / macOS）下での実行。
- 開発者にとっての価値: `npm install -g @anthropic-ai/claude-code` で更新でき、コスト（キャッシュ・トークン）と安定性（サンドボックス・MCP・ツールのエラー挙動）の両面で地道な底上げが入る。環境変数で挙動を細かく制御できる点も実務向き。
- 注意点: アイドルコンパクションや gzip 圧縮はデフォルト挙動の変更を含むため、意図しない場合は該当の環境変数/設定で無効化する。`@` メンションのパス渡しはオプトイン（環境変数で有効化）。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://www.npmjs.com/package/@anthropic-ai/claude-code
- メモ: バージョン番号は飛んでいる（`2.1.297 / 2.1.298` は npm 公開記録になし）。更新後は `claude --version` で確認。

#### 使用例

```bash
# インストール / 更新（npm 経由）
npm install -g @anthropic-ai/claude-code

# アイドルコンパクションを無効化したい場合（settings.json）
#   "idleCompaction": false

# @ メンションを「パス渡し」にする（内容を載せない）
export CLAUDE_CODE_DISABLE_FILE_MENTIONS=1
```

### 5. Vercel AI SDK / `ai@7.0.142`・`ai@6.0.308`

- 種別: OSS / SDK
- 関連: Vercel AI SDK / OpenAI（Responses API 互換）
- 公開・更新日: `ai@7.0.142`（2026-10-15 18:11）、`ai@6.0.308`（2026-10-15 18:15）。同日の他パッケージ（`@ai-sdk/zai`・`@ai-sdk/xai` など）は依存更新中心で、実挙動の変更はこの 2 つ。
- 概要: カスタムツールの入力ストリーミングの扱いが変わった。Responses API クライアントへ転送する利用者向けに、生の OpenAI カスタムツール入力デルタを復元するようにした。ストリーミングされる入力には `inputEncoding: 'text'` が付き、UI クライアントが JSON をパースせずに入力を逐次表示できる。部分的な UI メッセージを保存・再開してもこのエンコーディングは保持される。最終的なプロバイダのツール呼び出し入力は従来どおり JSON エンコードのまま。なお `ai@7.0.141`（10-15 02:23）は `telemetry.includeRuntimeContext` が許可する場合にランタイムコンテキストを渡すよう修正している。
- 何が便利か: カスタムツールの入力を「テキストとして逐次表示」できるため、ツール呼び出しの引数が組み上がっていく様子を UI にそのまま流せる。JSON を待って一括パースする必要がなく、ストリーミング UI の表示が滑らかになる。
- 使いどころ: Vercel AI SDK でカスタムツール（function/tool calling）を使い、入力を UI にストリーム表示するチャット/エージェント実装。OpenAI Responses API 互換クライアントへデルタを転送する構成。
- 開発者にとっての価値: ツール入力のストリーミング表示という UX の細部が整い、`inputEncoding` を手掛かりに UI 側の分岐を書きやすくなる。再開時もエンコーディングが保たれるため、永続化した会話の復元でも表示が一貫する。
- 注意点: 影響範囲はカスタムツールの入力ストリーミングを扱う実装に限られる。最終的なツール入力は引き続き JSON のため、デルタ（text）と最終値（JSON）の両方を正しく扱う必要がある。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://github.com/vercel/ai
- メモ: 10-14 版記事で扱った `@ai-sdk/workflow@2.0.71`（URL 入力のダウンロード位置の変更）とは別の変更。
