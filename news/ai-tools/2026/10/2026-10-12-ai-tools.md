### 1. Claude Code / `v2.1.296`

- 種別: CLI / 拡張機能
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-10-09〜10-10 頃（JST。公式 CHANGELOG の最新エントリ。`v2.1.295` までは 10-09 版記事で既報。CHANGELOG はバージョンごとに日付が付かないため、公開日は直近のリリース間隔からの概算）
- 概要: `v2.1.295` に続く更新。目玉はサブエージェント向けの `autoCompactWindow`。サブエージェントの frontmatter と `--agents` 定義に書けるようになり、サブエージェントだけメイン会話のウィンドウより早くオートコンパクト（履歴の自動圧縮）を始められる。ワークフロー実行では `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` で全ワークフローエージェントを 1 つのモデルに固定しつつ、他のサブエージェントは各自のモデルのままにできる。`CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS` で、過負荷（529）レスポンス時のバックオフ最大待機を長めに設定できる。Read ツールには `allow_large` オプションが追加され、全体が必要でコンテキストに余裕があるとき通常のサイズ上限を超えたテキストファイルを 1 回で読める。修正面では、managed 設定の `PreToolUse` フックが `"continue": false` でツール呼び出しを拒否したときや managed `prompt` フックがブロックしたときに、呼び出しは拒否するもののターンを終わらせていなかった問題、headless セッションでそのフォルダ向けに切っていた `.mcp.json`／プラグイン MCP サーバーがディレクトリ変更やプラグイン再読み込み後に起動していた問題、`Edit`／`NotebookEdit` が有効な UTF-8 でないファイル（Windows-1252・Shift-JIS・GBK）の非 ASCII 文字をすべて置き換えていた問題（そうした編集は拒否されるように変更）、Windows で約 1KB を超える PowerShell コマンドが常に権限確認を求めていた問題（許可ルールと読み取り専用判定が 32KB まで効くように）などを修正。
- 何が便利か: `autoCompactWindow` で、長時間動かすサブエージェントの履歴肥大をメインより早く抑えられ、調査系サブエージェントの安定度が上がる。`CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS` は API 過負荷時に待機を延ばして自動リトライで粘れる。`allow_large` で大きめのログや設定ファイルを分割せず一括で読める。Shift-JIS など非 UTF-8 ファイルを壊す編集が拒否されるため、日本語環境のレガシーファイルを巻き込む事故が減る。
- 使いどころ: サブエージェントやワークフローを多用し、長い調査・生成を回すユーザー。API が混み合う時間帯に非対話実行で止まりがちなユーザー（過負荷リトライの延長）。Windows / Git Bash や Shift-JIS のファイルを含むリポジトリで作業するユーザー。
- 開発者にとっての価値: サブエージェント運用の安定化（早めのオートコンパクト、ワークフローのモデル固定）とファイル取り回しの安全性（非 UTF-8 の誤置換防止、大きいファイルの一括読み）がまとまって入る。`claude update` だけで既存ワークフローに乗る。
- 注意点: CHANGELOG はバージョンごとに日付が付かないため公開日は概算。`autoCompactWindow` を短くしすぎると必要な文脈まで圧縮され得るため、まずは控えめな値から試す。managed 設定（組織ポリシー）利用時は該当フック修正の挙動変化を確認する。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://code.claude.com/docs/en/overview
- メモ: 更新は `claude update`（または再インストール）後に `claude --version` で `2.1.296` 以上を確認。

#### 使用例

```bash
# 更新してバージョン確認
claude update
claude --version   # 2.1.296 以上を確認

# 過負荷(529)時のリトライ最大待機を延ばして非対話実行
CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS=60000 claude -p "..."
```

```markdown
---
# サブエージェント定義の frontmatter 例: メインより早くオートコンパクトさせる
name: researcher
autoCompactWindow: 120000
---
```

### 2. GitHub Copilot CLI / `v1.0.95`

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.95`（2026-10-09、GitHub Releases で「Latest」）。`v1.0.94` は 10-09 版記事で既報。
- 概要: macOS でネイティブの Microsoft Entra ブローカー認証に対応し、ブローカーが使えない場合はブラウザ認証にフォールバックする。`copilot config` にサンドボックスの `injectHosts` 系キーが追加され、サンドボックス実行時に到達を許すホストを設定ファイルで管理できる。`--context` が、新規セッションに加えて再開した ACP（Agent Client Protocol）セッションにも適用されるようになった。管理対象（managed）プラグインのセットアップは、1 時間ごと、またはポリシー変更後に自動で再試行される。プレリリース側の `v1.0.96-x` 系では、`/model`・`/config` のモデル ID が大文字小文字を区別せず正規化された ID で保存される、サンドボックス設定が環境シークレットを提案しマスキング対象ホストを追加できる、起動時にエンタープライズポリシー解決中でも `/allow-all` が使える、git リポジトリでの対話セッションが高速化、などの変更が進行中。
- 何が便利か: macOS で Entra ブローカー認証が使えるため、組織アカウントのサインインがネイティブ連携で滑らかになる（失敗時はブラウザに自動フォールバック）。`--context` が再開セッションにも効くことで、途中から再開しても付与したコンテキストが維持される。`injectHosts` をファイルで管理でき、サンドボックス運用の構成を再現しやすい。
- 使いどころ: Microsoft Entra（Azure AD）で管理された組織で Copilot CLI を使う macOS ユーザー。ACP 連携のエディタ／クライアントからセッションを再開して使う運用。サンドボックス実行で許可ホストを明示管理したいチーム。
- 開発者にとっての価値: エンタープライズ認証（Entra ブローカー）とサンドボックス構成管理、ACP 再開時のコンテキスト維持がまとまり、組織運用に乗せやすい安定版更新。
- 注意点: Entra ブローカー認証は macOS 向け。より新しい機能はプレリリース（`v1.0.96-x` 系）側にあり、業務利用は安定版（`v1.0.95`）を基本に。
- 公式リンク: https://github.com/github/copilot-cli/releases
- 参考リンク: https://github.com/github/copilot-cli
- メモ: 変更内容は Releases の各タグのノートで確認できる。インストール手順は公式 README に従う。

#### 使用例

```bash
# バージョン確認（安定版 v1.0.95 を確認）
copilot --version

# サンドボックスの到達許可ホストなどを設定で確認
copilot config list
```

### 3. OpenAI Codex CLI / `rust-v0.162.1`

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 安定版 `rust-v0.162.1`（2026-10-09、GitHub Releases で「Latest」）。`0.162.0` は 10-09 版記事で既報。
- 概要: 2 点のバグ修正が中心のパッチ。複数行にわたる非同期の質問（async question）で TUI がクラッシュしていた不具合を修正し、改行とハイパーリンクの完全なリンク先が保持されるようになった。もう 1 点は、バックグラウンドで動いているサーバーと CLI の既定とで機能設定（feature settings）がズレているときに起動が失敗する不具合の修正で、互換性チェックはコマンドラインで明示的に上書きした機能フラグにのみ適用されるよう変更された。

- 使いどころ: Codex CLI を常用し、TUI でエージェントとやり取りするユーザー。バックグラウンドサーバーを立てて CLI から接続する構成を使っている場合。

- 注意点: `0.163.0-alpha` 系はプレリリースのため、業務利用は安定版（`0.162.1`）を基本に。新機能追加ではなく修正中心のリリースである点に留意。

### 4. Ollama / `v0.40.3`

- 種別: OSS / CLI
- 関連: Ollama / ローカルLLM関連ツール / Claude Code / Codex
- 公開・更新日: 安定版 `v0.40.3`（2026-10-11、GitHub Releases で「Latest」）。`v0.40.1` は 10-09 版記事で言及（内容が薄く本文では見送り）。
- 概要: コーディングツール連携の `ollama launch` 周りの地味だが実用的な改善。`ollama launch claude` が Claude コネクタに関する不要な警告を出さなくなり、`ollama launch codex` がサービスティアに関する不要な警告を出さなくなった。あわせて、埋め込み（embedding）などのリクエスト性能を優先するため、バックグラウンドでのモデル更新を一時停止するようになった。`ollama launch` 自体は以前からある機能で、Claude Code・Codex・OpenCode・Droid などのコーディングツールを、ローカルまたはクラウドのモデルに接続して起動するためのコマンド（`ANTHROPIC_BASE_URL` などの環境変数を自動設定してローカル Ollama を指すよう構成する）。今回はその連携時の警告ノイズを減らす調整が入った。
- 何が便利か: `ollama launch claude` / `ollama launch codex` 実行時の無関係な警告が消え、ローカルモデルでコーディングツールを試すときの体験がすっきりする。埋め込みなどを多用するワークロードで、バックグラウンド更新に性能を食われにくくなる。
- 使いどころ: 手元のローカルモデルで Claude Code や Codex を試したいユーザー（コスト・プライバシー重視の検証）。Ollama を埋め込みサーバーとして使っていて、裏側のモデル更新で遅延が出るのを避けたい場合。
- 開発者にとっての価値: ローカル／クラウドのモデルを主要コーディング CLI に接続する `ollama launch` の連携体験が磨かれ、ローカル LLM でのエージェント検証に乗せやすくなる。
- 注意点: 本リリース自体は新機能追加ではなく警告削除と性能調整が中心。`ollama launch` でのコーディングツール利用には十分なコンテキスト長（目安 64,000 トークン以上）と、モデルによっては相応の VRAM が必要。ローカルモデルの品質はモデル依存で、クラウドモデル前提の運用とは差が出る。
- 公式リンク: https://github.com/ollama/ollama/releases
- 参考リンク: https://docs.ollama.com/
- メモ: 更新後は `ollama --version` で `0.40.3` を確認。`ollama launch` の対応ツールや設定は公式ブログ/ドキュメントを参照。

#### 使用例

```bash
# バージョン確認
ollama --version   # 0.40.3 を確認

# ローカル/クラウドのモデルで Claude Code を起動（対話メニューは `ollama launch` のみ）
ollama launch claude

# 起動せず連携設定だけ行う
ollama launch claude --config
```
