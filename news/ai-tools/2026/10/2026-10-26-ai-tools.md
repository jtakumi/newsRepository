## 今日の注目

### 1. LiteLLM / `v1.106.4`（＋ `v1.105.5` / `v1.104.7` / `v1.103.9`）

- 種別: OSS / Python SDK / プロキシ
- 関連: LiteLLM / 各種モデルプロバイダ
- 公開・更新日: 2026-10-25
- 概要: プロキシの起動時クラッシュ修正を中心にした安定版パッチ（現在の「Latest」）。複数の系列に同じ修正をバックポート。
- 何が便利か: リモートのモデルコストマップ（価格表）に到達できないとき、プロキシが起動時に `ImportError` で落ちる不具合（`v1.104.0` 以来のリグレッション、#46711）を修正。これにより、コストマップ取得が失敗する／遅延するネットワーク環境でもプロキシが正常に起動するようになった。あわせてコンテナのイメージスキャンが brotli 1.2.0・emSign ECC Root CA - G3・未使用のロックファイルパッケージを脆弱性として誤検知する問題（#48283 / #48300）も修正。同じ修正が `v1.105.5` / `v1.104.7` にもバックポートされ、`v1.103.9` はイメージスキャン修正のみを含む。
- 使いどころ: 制限されたネットワークやプロキシ経由でコストマップ取得が不安定な環境での LiteLLM プロキシ運用、コンテナイメージの脆弱性スキャンを CI に組み込んでいる構成。
- 開発者にとっての価値: 「特定のネットワーク環境でだけプロキシが起動しない」という気づきにくく致命的な不具合が解消。リリースノートに「No action needed to upgrade」と明記されており、追加作業なしで上げられる。
- 注意点: このリリース自体のアップグレードに追加作業は不要。ただし前回（10/25 付記事）で案内した `v1.106.3` 系での cosign 署名鍵の変更は引き続き有効なので、Docker イメージ・Helm チャートの署名検証をしている場合は新しい `cosign.pub` への差し替えが必要。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.106.4
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 前回カバーの安定版は `v1.106.3`（10/24 公開、cosign 鍵変更）。

#### 使用例

```bash
# 最新版へ更新（追加作業は不要）
pip install -U litellm
```

### 2. LangGraph / `langgraph 1.2.17`（＋ `langgraph-sdk 0.4.9` / `langgraph-cli 0.4.38`）

- 種別: OSS / Python SDK / Agent Framework
- 関連: LangChain / LangGraph
- 公開・更新日: `langgraph 1.2.17` 2026-10-24 / `langgraph-sdk 0.4.9`・`langgraph-cli 0.4.38` 2026-10-23
- 概要: スレッド優先度（Priority）設定の追加と、再帰制限・RemoteGraph まわりの小修正を含むリリース群。
- 何が便利か: `langgraph-sdk 0.4.9` と `langgraph-cli 0.4.38` でスレッド優先度（Priority）設定が追加され、`langgraph.json` に priority セクションを記述してスレッドの処理優先度を指定できるようになった。本体の `langgraph 1.2.17` では、デフォルトと同値の明示的な再帰制限（recursion limit）を設定するようにし、`RemoteGraph.stream(subgraphs=True)` が呼び出し側の名前空間を保持するよう修正、さらに依存ライブラリに付けていた過剰な上限（precautionary upper bounds）を撤廃した。`langgraph-cli 0.4.38` は `uv` を 0.13.4 に更新。
- 使いどころ: LangGraph Platform / サーバー構成で、キューに積まれたスレッドの処理順を制御したいマルチテナント運用、`RemoteGraph` でサブグラフをストリーミングするエージェント、他ライブラリと依存バージョンが競合しやすいプロジェクト。
- 開発者にとっての価値: スレッド優先度で「重要な処理を先に流す」制御が入れやすくなり、依存上限の撤廃で既存プロジェクトへの導入時のバージョン衝突が減る。
- 注意点: スレッド優先度は主に LangGraph Platform / サーバー側の機能で、ローカル実行だけでは恩恵が限定的。`langgraph 1.2.17` 本体のパッチは小規模な修正が中心。
- 公式リンク: https://github.com/langchain-ai/langgraph/releases
- 参考リンク: https://github.com/langchain-ai/langgraph
- メモ: 直近の AI Tools News では LangGraph 単独の項目は扱っていなかった（7〜8 月以来）。前後のリリースでは Oct 16 に resume / checkpoint の正確性修正が入っている。

#### 使用例

```bash
# 本体と CLI を更新
pip install -U langgraph langgraph-cli
# langgraph.json にスレッド優先度（priority）セクションを追加して利用
```

### 3. Anthropic Python SDK / `v2.3.0`（＋ `v2.2.0`）

- 種別: OSS / Python SDK
- 関連: Claude / Anthropic / Claude Developer Platform
- 公開・更新日: `v2.3.0` 2026-10-23 / `v2.2.0` 2026-10-23
- 概要: メッセージスレッドとディメンション別の使用量・コストレポートを追加したマイナーリリース群（`v2.3.0` が現在の「Latest」）。
- 何が便利か: `v2.2.0` でメッセージスレッド（message threads）と、ディメンション別の使用量・コストレポート（usage / cost reports by dimension）が追加された（従来のレポートは legacy 扱いに）。これにより、Claude API の利用量とコストをワークスペースやプロジェクトなどの軸ごとに集計・取得できる。tool runner の複数の修正も含む。`v2.3.0` では Claude Enterprise 組織向けの Claude Tag エンドポイントを追加し、google-cloud クライアントのユーザープロファイル取得を組織エンドポイントに修正、エンドポイントパスにハードコードされていたクエリパラメータを送らないよう整理した。
- 使いどころ: Claude API の利用コストをディメンション別に集計・モニタリングする社内ダッシュボード、スレッド単位でメッセージ履歴を管理するアプリ、Claude Enterprise 環境での運用。
- 開発者にとっての価値: コストを軸ごとに追跡できるようになり、チーム・プロジェクト別の利用状況の可視化や按分がしやすくなる。公式 SDK に標準で入るため追加実装の手間が減る。
- 注意点: `v2.0.0`（10/21 公開）は API version `2026-10-21` 対応の破壊的変更を含むメジャー更新なので、1.x から上げる場合は先に `v2.0.0` の変更点を確認すること。`v2.2.0` は tool runner の挙動が変わり、`append_messages()` の後はメッセージ履歴の管理を呼び出し側に委ねるようになった。
- 公式リンク: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.3.0
- 参考リンク: https://github.com/anthropics/anthropic-sdk-python/releases
- メモ: 直近の AI Tools News では Anthropic 公式 Python SDK 単独の項目は扱っていなかった。関連して Claude 開発者プラットフォームの API version `2026-10-21` が前週に公開されている。

#### 使用例

```bash
# 最新版へ更新
pip install -U anthropic
```
