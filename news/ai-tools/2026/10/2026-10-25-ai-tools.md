### 1. Claude Code / `v2.1.310`（＋ `v2.1.309`）

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: `v2.1.310` 2026-10-23 / `v2.1.309` 2026-10-22（前回カバーの `v2.1.308` に続く最新 2 リリース）
- 概要: `v2.1.310` は新機能とゲートウェイ互換性・コンパクション周りの修正をまとめたリリース。`v2.1.309` はサンドボックス・worktree 分離・権限チェックのセキュリティ修正を中心にした大型メンテナンス版。
- 何が便利か: `v2.1.310` で Monitor ツールとプラグインモニターが、Bedrock / Vertex / Foundry 上やテレメトリ・非必須通信を無効にした環境でも使えるようになった（それらの環境では長時間のフォアグラウンド sleep もブロックされる）。`effort-2025-11-24` ベータ値や会話途中のシステムメッセージを拒否するゲートウェイ／互換サーバー向けに、それらを外して自動リトライするようになり、プロキシ経由で詰まっていたリクエストが通る。「Prompt is too long」後のコンパクションが base64 や SVG のような高密度テキストを残しすぎて次のリクエストも失敗する問題や、`cleanupPeriodDays` を極端に大きく設定したときに貼り付け画像など最近のファイルが削除される問題も修正。`v2.1.309` ではサンドボックス化した Bash がサンドボックス外でシェルの起動ファイルを実行していた問題、worktree 分離が一部コマンドを取り逃がす問題、`--mcp-config` で渡した MCP 設定ファイルがサンドボックス実行や自動承認編集で書き換えられる問題などを修正。ロール名やプレースホルダをメンション化して無関係な GitHub ユーザーに通知してしまう問題も解消。
- 使いどころ: TLS 検査プロキシや独自ゲートウェイ越しの利用、Bedrock / Vertex / Foundry でのエージェント運用、worktree を複数使うサンドボックス実行、PR へのコメント自動化。
- 開発者にとっての価値: ゲートウェイ互換性の自動リトライで「特定環境だけ失敗する」摩擦が減り、サンドボックス・権限まわりの抜け穴がまとめて塞がれる。壊れると気づきにくい分離・認証の信頼性改善が中心。
- 注意点: `sed -i` は従来のファイル編集プレビューではなく通常の Bash コマンドとして実行されるようになり、他の Bash 編集と同様 `/rewind` で復元されなくなった。`claude ultrareview` はワークスペースの信頼確認を要求するようになり、スクリプトでは `--trust-workspace` を渡すか環境変数で無効化が必要。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: npm の `@anthropic-ai/claude-code` から更新可能。前回カバーは `v2.1.307` / `v2.1.308`（10/23 付記事）。

#### 使用例

```bash

npm install -g @anthropic-ai/claude-code
claude --version
```

### 2. Ollama / `v0.40.11`（＋ `v0.40.10`）

- 種別: OSS / ローカルLLMランタイム / モデル
- 関連: Ollama / ローカルLLM / OpenAI 互換 API
- 公開・更新日: `v0.40.11` 2026-10-24 / `v0.40.10` 2026-10-23
- 概要: 音声出力と新しい決定モデル・視覚言語モデルを追加した安定版。`v0.40.11` が現在の「Latest」。
- 何が便利か: `v0.40.11` で macOS 向けに音声出力が追加され、`ollama run` がテキストやチャット応答を読み上げるほか、アプリ側は OpenAI 互換の `/v1/audio/speech` エンドポイント経由で音声をストリーミング受信できる。あわせて分類・Yes/No 回答・選択肢のスコアリングに向けた決定モデル「d3」（2B / 4B / 9B / 27B）を追加し、軽量なローカル判定器として使える。前日の `v0.40.10` では 128K トークンのコンテキストを持つ視覚言語モデル NVIDIA Nemotron 3.5 Bolt E4B（投機的デコード用のドラフトモデル付き）を追加。
- 使いどころ: ローカルで完結する音声応答アプリの試作、ログやテキストの分類・ルーティングをローカルの小型モデルで処理するパイプライン、画像入力を伴うローカル推論。
- 開発者にとっての価値: 外部 API に出さずに音声出力や分類タスクをローカルで試せる。OpenAI 互換エンドポイントなので既存クライアントコードをほぼそのまま流用できる。
- 注意点: 音声出力（読み上げ）は現時点で macOS 向けの機能。d3 や Nemotron のような新モデルは初回 `pull` でダウンロードが発生する。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.11
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 前回カバーの安定版は `v0.40.8`（Flint 追加、10/22 付記事）。`v0.40.9`（10/22）は Flint の Linux / Windows 対応やストリーミング失敗の通知などを含む。

#### 使用例

```bash
# 本体を更新後、決定モデル d3 を試す
ollama pull d3:2b
ollama run d3:2b "次の文はポジティブ/ネガティブ/中立のどれ？: 期待したほどではなかった"
```

### 3. OpenAI Codex CLI / `0.164.0`（安定版）

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 2026-10-23
- 概要: 保存プロンプト／コマンドの枠、インライン引数、Enterprise 向け認証などを追加した安定版（現在の「Latest」）。直近はプレリリース alpha が続いていたが、機能を伴う安定版として公開された。
- 何が便利か: 保存したプロンプトやスラッシュコマンドを収める 10 枠の `/presets` が追加され、よく使う指示をすぐ呼び出せる。`/model` と `/permissions` にインライン引数を渡せるようになり、メニューを開かずモデルや権限を切り替えられる。Kitty / Sixel 対応端末ではフルスクリーン表示のトランスクリプトに画像プレビューが出る。Enterprise 向けにシークレットを要する OAuth クライアントを含む MCP 認証に対応し、リモートの Bash / Zsh スナップショットセッションで資格情報がマスクされる。Amazon Bedrock のセットアップウィザードがデフォルトで有効化。
- 使いどころ: 定型プロンプトを多用する日常作業、モデル・権限を頻繁に切り替えるワークフロー、社内 MCP サーバーを OAuth 認証で使う構成。
- 開発者にとっての価値: `/presets` とインライン引数で「毎回同じ指示を打ち直す」手間が減り、個人のコーディング作業にそのまま組み込める。資格情報マスクで共有・録画時の漏洩リスクも下がる。
- 注意点: alpha プレリリース（`0.165.0-alpha.1` など）は並行して進んでおり、安定運用には `0.164.0` を使うのが無難。画像プレビューは対応端末（Kitty / Sixel）に限られる。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.164.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 前回（10/23 付記事）は「Codex CLI は alpha プレリリースのみでリリースノートなし」として未採用。今回は機能付きの安定版が出たため採用。

#### 使用例

```bash
# セッション内でプリセットや権限をインラインで扱う例
codex
# /presets  … 保存済みプロンプト/コマンドを呼び出す（10枠）
# /model gpt-5.4  … メニューを開かずモデルを指定
# /permissions ...  … インライン引数で権限を切り替え
```

### 4. LiteLLM / `v1.106.3`（＋ 1.104〜1.105 系バックポート）

- 種別: OSS / Python SDK / プロキシ
- 関連: LiteLLM / OpenRouter / 各種モデルプロバイダ
- 公開・更新日: 2026-10-24
- 概要: Docker イメージ・Helm チャートの署名鍵変更（要対応）と証明書バンドルの整理を中心にした安定版。あわせて課金・トークンカウント・ストリーミングの修正を複数の系列にバックポート。
- 何が便利か: 1.104 系バックポート（`v1.104.6`）で実運用バグを多数修正。モデルエイリアス経由のストリーミングが $0 で課金される問題、`openai/responses/*` 系モデルへの大きな非ストリーミングリクエストが二重課金される問題、失敗・タイムアウト・キャンセル・スピルオーバーしたリクエストの価格計算が誤る問題、DeepSeek / Qwen3.5 のトークンカウントずれ、`extra_body` がクライアントのキャッシュマークを上書きしたときに余分なキャッシュマークが付く問題などを解消。gpt-5.4+ でツール呼び出しが `choices[1]` に乗る不具合や、Bedrock / Vertex の適応的思考中に `message_start` が数分滞留する問題も修正。
- 使いどころ: 複数プロバイダをまたぐ API ゲートウェイ運用、正確なコスト追跡・課金集計、Docker / Helm での自動デプロイ。
- 開発者にとっての価値: 見えにくい課金・トークンカウントのズレが修正され、コスト管理の精度が上がる。マルチプロバイダ構成の信頼性改善。
- 注意点: Docker イメージ・Helm チャートの署名鍵（cosign）が変更された。署名検証をしている場合はコミット `e82a3c6` の新しい `cosign.pub` に差し替えが必須（旧鍵では検証が通らない）。証明書バンドルから eMudhra ルート CA が除去された。`/v1/messages/count_tokens` はローカル推定値ではなく HTTP 400 を返すようになった。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.106.3
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 前回カバーの安定版は `v1.106.2`（10/22 付記事）。

#### 使用例

```bash
# 最新版へ更新
pip install -U litellm
```
