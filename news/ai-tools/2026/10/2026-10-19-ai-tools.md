### 1. LiteLLM / `v1.106.0`（安定版）・`v1.107.0-rc.1`（プレリリース）

- 種別: OSS / API ゲートウェイ（プロキシ）
- 関連: OpenAI / Anthropic / Bedrock / MCP
- 公開・更新日: 安定版 `v1.106.0`（2026-10-18 05:53、GitHub Releases で「Latest」）。プレリリース `v1.107.0-rc.1`（2026-10-18 08:00）。前回の AI ツール記事での LiteLLM 本文採用は 10-13 版の `v1.105.0` で、`v1.106.0` は本記事が初出。
- 概要: 100 以上のモデルプロバイダを OpenAI 互換の単一エンドポイントに集約するプロキシ／SDK。今回は破壊的変更として stdio 方式の MCP サーバーがデフォルト無効化された。加えて、ゲートウェイ本体・Postgres・管理 UI を 1 コマンドで立ち上げる Docker クイックスタート、Claude Agent SDK のトレーシング対応（エージェント名・ロゴ・チャット内容を記録）、Bedrock での GPT-5.6+ chat completions のネイティブ処理、JWT を既存の仮想キーにマッピングする機能などが入った。
- 何が便利か: 複数プロバイダを 1 エンドポイントに束ね、コスト計測・キー管理・トレーシングをまとめて行える。Docker クイックスタートで検証環境の立ち上げが速い。
- 使いどころ: 社内／個人プロジェクトで複数の LLM を切り替えて使う際の共通ゲートウェイ。Claude Agent SDK を使う構成では今回のトレーシング対応で可観測性が上がる。
- 開発者にとっての価値: プロバイダ差異を吸収する層を自前実装せずに済む。モデル横断のコスト・利用状況を一元管理できる。
- 注意点: stdio MCP がデフォルト無効になったため、MCP を stdio で接続していた構成は明示的な有効化が必要（破壊的変更）。`rc.1` は検証用で本番運用は `v1.106.0` を推奨。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.106.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 変更点はリリースページの「What's Changed」から確認。stdio MCP の扱いは必ず自環境で挙動確認すること。

#### 使用例

```bash
# インストール
pip install litellm

# プロキシ起動（設定ファイルで複数プロバイダ/MCP を集約）
litellm --config config.yaml

# バージョン確認（v1.106.0 を確認）
litellm --version
```

### 2. Claude Code / `2.1.302`（公式 CHANGELOG 最新）・`2.1.303`（npm 公開）

- 種別: CLI
- 関連: Claude / Anthropic
- 公開・更新日: `2.1.302`（npm `@anthropic-ai/claude-code` 公開時刻 2026-10-16 16:48 UTC = 10-17 01:48 JST、公式 CHANGELOG の最新エントリ）。`2.1.303`（npm 公開 2026-10-18 21:15 UTC = 10-19 06:15 JST、本記事時点では CHANGELOG 未反映のため内容は未確定）。前回（10-16 版）記事では `2.1.301` までを扱っていたため、`2.1.302` 以降は本記事が初出。
- 概要: `2.1.302` では `claude -p`・Agent SDK・デスクトップアプリ・VS Code でフォークサブエージェントがデフォルト有効化。`/config` に「Idle compaction（アイドル時圧縮）」の ON/OFF 行が追加され、サードパーティプロバイダでのパーミッション未指定時は `default` モードで開始するよう変更。クライアント側オートモード分類器のモデルを選ぶ `CLAUDE_CODE_AUTO_MODE_MODEL` が追加された。
- 何が便利か: サブエージェントのフォークが標準化され、非対話（`-p`）実行やデスクトップでもエージェント分割が使いやすくなる。Read ツールは 128MB 超の巨大ファイルを拒否するよう修正され、メモリ枯渇を避けられる。
- 使いどころ: 自動化スクリプトや CI での `claude -p` 実行、サブエージェントを使った並列作業。長時間アイドルする対話を自動圧縮したい場合は `/config` で切り替え。
- 開発者にとっての価値: オートモードがサーバー側分類器で改善され、長い会話を毎回ツール呼び出し拒否する代わりに圧縮するようになった。Vertex／Bedrock へ途中切り替えした際の「Extra inputs are not permitted」エラーも修正。
- 注意点: `2.1.303` は npm には出ているが公式 CHANGELOG に項目が未反映のため、変更内容はリリース反映後に確認すること。スタンドアロンの Claude Design が 2026-12-14 に終了する旨が `/design-sync`・`/design-login` に告知された。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://www.npmjs.com/package/@anthropic-ai/claude-code
- メモ: バージョンにより日付が CHANGELOG に明記されないため、公開日は npm の publish 時刻を併記した。

#### 使用例

```bash
# インストール / 更新（npm 経由）
npm install -g @anthropic-ai/claude-code@latest

# バージョン確認
claude --version

# アイドル時圧縮の ON/OFF を切り替え（対話セッション内）
# /config の「Idle compaction」行で設定

# オートモード分類器のモデルを指定
export CLAUDE_CODE_AUTO_MODE_MODEL=claude-haiku-5-5
```

### 3. Ollama / `v0.40.6`（安定版）・`v0.40.7-rc0`（プレリリース）

- 種別: OSS / ローカル LLM ランタイム
- 関連: Google AI / OpenAI 互換 / ローカルLLM
- 公開・更新日: 安定版 `v0.40.6`（2026-10-16 22:00 UTC = 10-17 07:00 JST、GitHub Releases で「Latest」）。プレリリース `v0.40.7-rc0`（2026-10-18 00:28 UTC = 10-18 09:28 JST）。前回（10-16 版）記事では安定版 `v0.40.5` を扱っていたため、`v0.40.6` 以降は本記事が初出。
- 概要: `v0.40.6` は GGUF の `q2_0` テンソル／ファイル型に対応、Ollama クラウドでの clef 起動を追加、`--ask` モードで質問キーに識別子を使用、Windows で孤児化したランナープロセスが残る不具合を修正。`v0.40.7-rc0` は非 thinking モデルでも OpenAI Responses API の reasoning effort を許容、llama-server が draft（投機的デコード）型を推定、MLX の PPLX Decider v1.2 対応を追加。
- 何が便利か: `q2_0` 対応で、より低ビットの量子化モデルをローカルで動かせる。OpenAI 互換 API 経由の構成で reasoning effort を渡せる範囲が広がる（rc）。
- 使いどころ: ローカルでの LLM 実験、OpenAI 互換クライアント（Claude Code や各種 SDK）からローカルモデルへ接続する構成。
- 開発者にとっての価値: ローカル推論のモデル選択肢と互換性が増え、クラウドに出さずに検証できる範囲が広がる。
- 注意点: `v0.40.7-rc0` は RC で通常の自動更新には乗らない。安定運用は `v0.40.6` を使用。新モデルの有無は公式モデルライブラリで確認すること。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.6
- 参考リンク: https://github.com/ollama/ollama/releases/tag/v0.40.7-rc0
- メモ: `v0.40.6` のリリースノートは PR タイトル中心で、詳細はリンク先 PR を参照。

#### 使用例

# モデルを実行（モデル名は公式のモデルライブラリで確認）

### 4. Cline / Desktop `v0.0.48`・CLI `v3.0.73`・SDK `v0.0.95`

- 種別: 拡張機能 / CLI / SDK
- 関連: OpenAI / Claude / Gemini / VS Code
- 公開・更新日: いずれも 2026-10-17 公開（Desktop `v0.0.48` 04:34 UTC、CLI `v3.0.73` 03:59 UTC、SDK `v0.0.95` 03:00 UTC）。前回（10-14 版）記事では拡張 `v4.1.24`・CLI `v3.0.71`・SDK `v0.0.93` 系を扱っていたため、本バージョン群は初出。
- 概要: OpenAI および Azure OpenAI 互換エンドポイントで GPT-6 系モデルが誤ったトークンパラメータで拒否されていた不具合を修正（新しい completion-token パラメータを使用、Azure の gpt-35-turbo は従来型を維持）。Cline プロバイダのデフォルトモデルを Claude Sonnet 5.5 に戻し、モデルカタログを更新（SDK では 6,952→7,041 モデル）。CommandCode・Reflection プロバイダを追加。前日（10-16）には拡張 `v4.1.25` で Cline Cloud sessions（ホスト型サンドボックスで指定リポジトリ／ブランチ上のタスクを実行、段階ロールアウト）が追加されている。
- 何が便利か: GPT-6 系をエラーなく使えるようになり、デフォルトモデルが安定版の Sonnet 5.5 に戻った。

- 開発者にとっての価値: プロバイダ互換の不具合が解消され、モデルカタログが最新化。CLI／SDK からも同じ修正を利用できる。

- 参考リンク: https://github.com/cline/cline/releases/tag/v3.0.73
- メモ: Desktop／CLI／SDK／拡張でバージョン体系が分かれている点に注意。
