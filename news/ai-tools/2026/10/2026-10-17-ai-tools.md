### 2. Cline / 拡張機能 `v4.1.25`・SDK `v0.0.94`・CLI `v3.0.72`・Desktop `v0.0.47`

- 種別: OSS / VS Code 拡張機能・SDK・CLI・デスクトップ
- 関連: Cline / Google（Gemini 4 Argon）
- 公開・更新日: 2026-10-16（GitHub Releases。Desktop `v0.0.47` が「Latest」タグ）。前回（10-16 版）記事は Cline を「10-14〜10-16 に新規リリースなし、最新は 10-13 の v4.1.24（既報）」として見送っていたため、`v4.1.25` 系は本記事が初出。
- 概要: 拡張機能 `v4.1.25` が Cline Cloud sessions を追加（段階ロールアウト）。タスクを選んだリポジトリ／ブランチのホスト型サンドボックス上で実行できる。あわせて Cline プロバイダのデフォルトモデルを Gemini 4 Argon に変更し、モデルカタログを更新。長いプロンプトでのローカルモデルのタイムアウト、OpenAI 互換の base URL の扱い、Cline の質問への回答に付けた添付ファイルなどを修正し、ストリーム途中のプロバイダエラーは最大 3 回までリトライするようになった。SDK `v0.0.94` は `in_process` プラグインモードを廃止し、プラグインはワーカースレッドまたはサブプロセスのサンドボックスでのみ動く。同じ 3 回リトライと、失敗ログへのプロバイダのリクエスト ID 記録、hub デーモンランチャー／接続ヘッダのオプションも入った。CLI `v3.0.72` もプラグインをワーカーで実行し `in_process` を廃止、`cline hub` 系に `--json`・`--allow-port-fallback`・`--no-connectors`・`--login-shell-path` を追加。Desktop `v0.0.47` は `v0.0.46` で発生していたマーケットプレイスプラグインの `@cline/sdk` モジュール不足を修正し、設定から Cloud sessions トグルを撤去（利用可能な環境では常時オン）。
- 何が便利か: Cline Cloud sessions は、手元の環境を占有せずにタスクをホスト型サンドボックスへ逃がせるため、長時間タスクや破壊的になりうる操作を隔離環境で試せる。プラグインのワーカー／サブプロセス実行（`in_process` 廃止）は、プラグインが拡張機能本体のプロセスを巻き込んで落とすリスクを下げる。ストリーム途中エラーの 3 回リトライは、ネットワークやプロバイダの一時障害での作業中断を減らす。
- 使いどころ: ホスト型サンドボックスでのエージェント実行（Cloud sessions）、プラグインを多用する VS Code／CLI 運用、OpenAI 互換エンドポイントやローカルモデルを併用する構成、`cline hub` を使った自動化。
- 開発者にとっての価値: VS Code 拡張としてすぐ更新でき、Cloud sessions という実行基盤の選択肢と、プラグイン分離による安定性向上がまとまって入る。デフォルトモデルの Gemini 4 Argon 化で、初期設定のまま最新世代モデルを試せる。
- 注意点: Cline Cloud sessions は段階ロールアウトのため、全ユーザーで即利用できるとは限らない。`in_process` プラグインモードの廃止は、その前提のプラグインに影響する可能性がある。Gemini 4 Argon はアカウント側の利用可否を確認。
- 公式リンク: https://github.com/cline/cline/releases
- 参考リンク: https://github.com/cline/cline
- メモ: `v4.1.24`（10-13）は 10-16 版記事で既報。Desktop が「Latest」タグのため、拡張機能の版番号は Releases 一覧で確認。

### 3. Vercel AI SDK / `ai@7.0.143`

- 種別: OSS / SDK
- 関連: Vercel AI SDK
- 公開・更新日: `ai@7.0.143`（npm 公開時刻 2026-10-16 20:10 UTC＝JST 2026-10-17 05:10）。同時刻帯の `ai@6.0.309`（10-16 19:04 UTC）は依存更新のみ。前回（10-16 版）記事は `ai@7.0.142`／`ai@6.0.308` を扱っていたため、`ai@7.0.143` は本記事が初出。
- 概要: `streamText` に実験的オプション `experimental_lowMemory: true` を追加。単一コンシューマ（single-consumer）のストリーミング向けに、リプレイバッファと最終コンテンツ結果の保持を省くことでメモリ使用量を抑える。`useChat()` は初回アクセス時にデフォルトのチャット ID を生成するようになり、レンダリング中に使われないかもしれないランダム値を読まずにプリレンダリングできる。TypeSafe AI 向けに画像境界を持つ `box` decision question type も追加。あわせて `@ai-sdk/provider`・`provider-utils`・`gateway` の依存を更新。
- 何が便利か: `experimental_lowMemory` は、ストリームを 1 箇所でしか消費しないサーバ実装（単純なチャット API など）で、リプレイ用のバッファを持たない分メモリを節約できる。`useChat()` のデフォルト ID 生成は、SSR／プリレンダリング時にランダム値由来の不整合を避けられる。
- 使いどころ: Vercel AI SDK v7 で `streamText` を単一コンシューマで使うサーバサイド実装、Next.js などでチャット UI をプリレンダリングする構成。
- 開発者にとっての価値: ストリーミングのメモリ特性を明示的に選べるようになり（既定は従来どおり）、高トラフィックや大きな生成を扱うエンドポイントの資源効率を調整しやすい。`useChat()` の変更は SSR 時の安定性に効く。
- 注意点: `experimental_lowMemory` は実験的オプションで、リプレイバッファを省くためストリームを複数箇所で再消費する構成には向かない（単一コンシューマ前提）。`ai@6.0.309` は依存更新のみで実挙動の変更はない。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://www.npmjs.com/package/ai
- メモ: 10-16 版記事で扱った `ai@7.0.142`／`ai@6.0.308`（カスタムツール入力ストリーミングの `inputEncoding: 'text'`）とは別の変更。

#### 使用例

```ts
// streamText で低メモリ・ストリーミング（単一コンシューマ向け）
import { streamText } from 'ai';

const result = streamText({
  model,
  prompt,
  experimental_lowMemory: true,
});
```
