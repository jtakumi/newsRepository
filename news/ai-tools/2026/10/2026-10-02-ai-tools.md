# 2026-10-02 AI Tools News

## 今日の要点

- **Claude Code が `v2.1.287` で「Claude Mods」を本格導入**。TypeScript で書くプラグインから、プロンプト書き換え・ツール呼び出しのブロック/リトライ・UI 差し替えなど、ハーネス自体の挙動を深くカスタマイズできるようになった。組み込みの **「You should know」mod（サイドエージェントでセッションを監視）**、エージェント一覧の **`n:<text>` 名前フィルタ**、**MCP サーバー発の URL プロンプト対応（2025-11-25 プロトコル）**、`rm` のパスリダイレクト時に安全装置が外れる不具合の修正なども追加。公式 CHANGELOG: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md 。
- **Ollama が `v0.35.0`（9/28）で Decision Models（決定モデル）API `/v1/systemone` を追加**。自由生成ではなく **選択肢・確率・スコアを返す** 軽量 API で、チケット振り分け・モデルルーティング・分類に向く（対応モデル: Nimble / Tev1）。翌 `v0.35.1`（9/29, pre-release）では **1 応答あたり最大 10 回の Web 検索** や MLX/llama.cpp のバージョン更新も。ローカルで「判断」を安く速く回せる点が実務的。
- **JetBrains Air（9/22 発表）の「Air in IDEs」が EAP / Marketplace プラグインで試用可能に**。IDE 内でエージェントを指揮・検証する体験で、同社の Junie エージェントを各サーフェスで利用できる。チーム向け「Air Teams」、統制向け「Air Governance（旧 JetBrains Central）」とセットのエコシステム。

## 今日の注目

### 1. Claude Code / `v2.1.287`（Claude Mods）

- 種別: CLI / 拡張機能（プラグイン基盤）
- 関連: Anthropic / Claude / Claude Code
- 公開・更新日: 2026-09-30〜10-01（`v2.1.286`（9/30）の次リリース）
- 概要: Claude Code のプラグイン機構 **「Claude Mods」** を本格導入したリリース。Mods は **TypeScript の関数フック** として書き、プロンプトの書き換え、ツール呼び出しのブロック/リトライ、UI 要素の再描画、`/diff` など組み込み機能の差し替えまでできる。あわせて組み込み mod **「You should know」（サイドエージェントがセッションを見て気づきを知らせる）**、エージェントビューで **セッション名・タスク名に一致する `n:<text>` フィルタ**、**MCP サーバーからの URL プロンプト（2025-11-25 プロトコル対応）**、ヘッドレス時の MCP 起動リトライ、`rm` の一部パスリダイレクトで安全装置が外れる不具合の修正、Bedrock/Vertex の `availableModels` 判定修正などを含む。
- 何が便利か: これまで hook / 設定でしか触れなかった挙動を、**コードでハーネスごと作り替えられる**。社内規約の自動適用、独自 UI、ツール実行ポリシーの強制などを 1 つの仕組みで表現できる。
- 使いどころ: チーム共通のガードレール（危険コマンドの追加ブロック、レビュー必須化）、独自の差分表示や通知、ツール呼び出しのログ/監査を差し込みたい運用。
- 開発者にとっての価値: エージェント CLI を「設定する」から「プログラムする」へ広げる拡張点。mod を配布すればチーム全体の Claude Code 体験を統一できる。
- 注意点: Mods / 関数フックは **早期アクセス扱いで、リリース間で仕様が変わり得る**と公式が注意喚起。本番運用に組み込む前に対象バージョンで動作確認を。`rm` 安全装置の修正を含むため、旧版利用中なら早めの更新を推奨。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://docs.claude.com/en/docs/claude-code/overview
- メモ: 9/14 に Boris Cherny が「Claude Mods are landing now」と予告（anthropics/claude-code#91870）していた機能の、CLI 本体への正式統合にあたる。10/1 以降、コミュニティで動く mod の共有も始まっている。

#### 使用例

```bash
# 更新
claude update
claude --version          # v2.1.287 以降であること

# 組み込み mod や読み込み状況の確認（プラグイン/skill 管理コマンド経由）
claude                    # 起動後にプラグイン/mods 設定を確認

# エージェント一覧を名前で絞り込む（新フィルタ）
# 一覧ビューで:  n:refactor   のように入力して該当セッション/タスクを抽出
```

### 2. Ollama / `v0.35.0`・`v0.35.1`（Decision Models API ほか）

- 種別: OSS / ローカル LLM ランタイム / API
- 関連: Ollama / ローカル LLM
- 公開・更新日: 2026-09-28（`v0.35.0`）・2026-09-29（`v0.35.1`, pre-release）
- 概要: `v0.35.0` で **決定モデル（Decision Models）向けの新 API `/v1/systemone`** を追加。テキストを生成する代わりに **「選択肢・確率・スコア」** を返すエンドポイントで、チケットのトリアージ、モデルルーティング、コンテンツ分類といった「有限の選択から 1 つ選ぶ」用途に特化。対応モデルとして **Nimble（Bespoke Labs）** と **Tev1（Together AI）** が利用できる。あわせて設定画面がモデル探索を待たずに開くよう改善、macOS の更新メニュー不具合や MLX モデルのダウンロード停止の修正、`typical_p` の非推奨化など。`v0.35.1`（pre-release）では **1 応答あたり最大 10 回の Web 検索**、MLX / llama.cpp のバージョン更新、`create` でのモデル能力明示指定を追加。
- 何が便利か: ローカルで **分類・ルーティングの「判断」を安定した構造化出力** として得られる。LLM に無理やり JSON/enum を守らせるより壊れにくく、レイテンシも低い。
- 使いどころ: 問い合わせの自動振り分け、エージェントの次アクション選択、安いローカル判定で前段フィルタを作り LLM 呼び出しを節約したいケース。Web 検索付き応答はローカル RAG 的な調べ物にも。
- 開発者にとっての価値: ネットワークに出さず **手元で決定ロジックを回せる**ため、コスト・プライバシー・速度の面で既存ワークフローに組み込みやすい。
- 注意点: `v0.35.1` は pre-release。本番は安定版（`v0.35.0`）を基本に。Web 検索機能は外部通信を伴うため、オフライン前提の環境では利用可否を確認。決定モデルは対応モデルの取得（pull）が前提。
- 公式リンク: https://github.com/ollama/ollama/releases
- 参考リンク: https://ollama.com/
- メモ: 9/29 の OpenAI DevDay で発表された **Decisions API（クラウド）** と同じ「選択肢からの判断」という流れを、**ローカル実行** で扱えるようにした点が対照的で面白い。

#### 使用例

```bash
# 更新後、決定モデルを取得して起動
ollama pull nimble            # または tev1
ollama serve

# 決定モデル API を叩く（選択肢・確率・スコアが返る）
curl http://localhost:11434/v1/systemone \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nimble",
    "input": "このチケットを分類して",
    "options": ["bug", "feature", "question"]
  }'
```

### 3. JetBrains Air（Air in IDEs が EAP で試用可能）

- 種別: IDE / エージェント開発環境
- 関連: JetBrains / Junie / 開発者エコシステム
- 公開・更新日: 2026-09-22 発表（Air in IDEs は 2026.3 系 EAP / Marketplace プラグインで試用可能）
- 概要: JetBrains が、**IDE・チーム・組織をまたいでエージェント駆動開発を扱う製品群「JetBrains Air」** を発表。構成は 3 つで、(1) **Air in JetBrains IDEs**（IDE 内でエージェントを指揮・オーケストレーション・検証する開発体験）、(2) **Air Teams**（開発者と自律エージェントが関わるソフトウェア配信ワークフローの調整・自動化）、(3) **Air Governance**（旧 JetBrains Central。組織ポリシー・可視化・監査・コスト管理）。同社のコーディングエージェント **Junie** を各サーフェスで利用できる。
- 何が便利か: エージェントを「個人の便利ツール」から **チーム/組織の運用対象** へ引き上げ、指揮・検証・統制を一貫した仕組みで扱える。IDE に閉じず配信フローやガバナンスまで地続き。
- 使いどころ: 複数のエージェントを同一コードベースで走らせるチーム、エージェントの実行コスト・権限・監査を管理したい組織、既存の JetBrains IDE ワークフローにエージェントを足したい個人開発。
- 開発者にとっての価値: 今日から **IDE の EAP / Marketplace プラグイン** で Air in IDEs を試せる。Junie と組み合わせ、エージェントの作業を IDE 内でレビュー・検証する運用を評価できる。
- 注意点: EAP（早期アクセス）段階のため仕様変更あり。Air Teams / Governance は組織向けで、適用範囲・プラン・コストは要確認。発表（9/22）から日が浅く、安定版の提供時期は公式を確認。
- 公式リンク: https://blog.jetbrains.com/blog/2026/09/23/introducing-jetbrains-air/
- 参考リンク: https://www.jetbrains.com/air/
- メモ: 2026/3 の「JetBrains Central」から半年の公開実験（Central CLI、共有コンテキスト、クラウドエージェント、ガバナンス、AI コスト管理）を 1 つの体系にまとめ直したもの。

### 4. Perplexity API（Agent API への移行 / chat completions 非推奨）

- 種別: API / ドキュメント更新
- 関連: Perplexity
- 公開・更新日: 2026-09-27（chat completions API の非推奨化が告知）
- 概要: Perplexity が **従来の chat completions API を非推奨化**し、**Agent API** への移行を案内。Agent API では **Skills（合成可能な専門能力）** とインラインの指示を組み合わせ、検索・推論などの組み込み能力をワークフロー単位で扱える。周辺ツール（例: `llm-perplexity` プラグイン）も Agent API ベースへ更新が進んでいる。
- 何が便利か: 単発の補完呼び出しから、**検索つきエージェント + Skill 合成** という形に移行でき、調べ物・要約・リサーチ系の自動化を API 一本で組みやすい。
- 使いどころ: Perplexity を使った自動リサーチ、引用つき要約の生成、既存の chat completions 連携のアップデート。
- 開発者にとっての価値: 非推奨化スケジュールが明示されたため、**依存コードの移行計画を今のうちに立てられる**。Skill ベースで能力を足し引きでき、用途ごとの作り込みが減る。
- 注意点: 非推奨 API を使っている連携は早めに Agent API へ移行を。Skills の仕様・料金・レート制限は公式ドキュメントで確認。移行時は出力フォーマットの差分に注意。
- 公式リンク: https://docs.perplexity.ai/
- 参考リンク: https://github.com/hex/llm-perplexity/releases
- メモ: 「補完 API」から「エージェント + Skill」への移行は、各社に共通する流れ（OpenAI Agents API、Anthropic の skill/MCP 等）と同方向。
