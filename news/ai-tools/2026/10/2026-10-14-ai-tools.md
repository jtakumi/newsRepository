### 1. GitHub Copilot CLI / `v1.0.97`（安定版）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.97`（2026-10-13 18:37 UTC、GitHub Releases で「Latest」）。プレリリース `v1.0.98-0`（2026-10-13 21:45 UTC）。前回記事（10-13 版）では `v1.0.96` が安定版 Latest、`v1.0.97-0`〜`-3` はプレリリースとして言及していた段階だったため、`v1.0.97` の安定版昇格内容は本記事が初出。
- 概要: `v1.0.97-x` 系で進んでいた変更が安定版に集約された。カスタムエージェントごとにスコープを限定した宣言的フック（agent-scoped declarative hooks）が正式版に入り、対応ターミナルではインライン画像がデフォルト表示になった（`/settings inlineImages false` で無効化可）。Autopilot は preToolUse の「ask」判断を許可ダイアログで待たずに拒否するようになった。managed（組織）権限ルールは読み取り専用になり、組織が設定した場合を除き `/config` から隠れる。`/usage` はトークン課金セッションで請求対象の AI Credits を表示する。そのほか、HTTPS 認証失敗後に GitHub トークンでリモートプラグイン/プラグイン取得を 1 回リトライ、close_notify を送らない TLS 傍受プロキシ越しのストリーム応答を完了できるよう修正、絶対パスを含む GitHub SCP リモートのパース修正、エージェントファイルが 100 個超または深くネストしたリポジトリでも全カスタムエージェントを発見、無効な `config.json` エントリがあっても他の保存済み設定を保持、など多数の修正を含む。
- 何が便利か: agent-scoped hooks が安定版に入ったことで、特定のカスタムエージェントだけに実行前チェックや後処理を限定する運用を本番で組める。Autopilot の「ask→拒否」化は、無人・自動実行で許可ダイアログ待ちにより止まる事態を避けられる。managed 権限ルールの読み取り専用化は、組織ポリシー下で設定が意図せず上書きされない安全性に効く。`/usage` の AI Credits 表示でコスト把握がしやすくなる。
- 使いどころ: カスタムエージェントを役割ごとに定義して前後処理を分けたい運用、CI など無人・半自動でのエージェント実行、エンタープライズポリシー下でのチーム運用、TLS 傍受プロキシ配下の企業ネットワーク。
- 開発者にとっての価値: 10-13 版でプレリリース扱いだった目玉機能（agent-scoped hooks・インライン画像）が安定版で使えるようになり、`npm install -g @github/copilot` だけで本番運用に乗せられる。無人実行・企業ネットワーク・監査まわりの実務的な詰まりが減る。
- 注意点: `v1.0.98-0` はプレリリース（内容は「Fixes and changes」のみで詳細非公開）。業務利用は安定版 `v1.0.97` を基本に。インライン画像は対応ターミナルのみで、不要なら `/settings inlineImages false`。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.97
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: `v1.0.96`（`/add-dir` のサンドボックスアクセス・権限タイムラインの判断主体表示）は 10-13 版記事で既報。本記事は `v1.0.97` 安定版昇格以降の差分を扱う。

### 2. Gemini CLI / `v0.64.0`（安定版）

- 種別: CLI
- 関連: Google AI / Gemini
- 公開・更新日: 安定版 `v0.64.0`（2026-10-13 20:44 UTC、GitHub Releases で「Latest」）。プレリリース `v0.65.0-preview.0`（2026-10-13 20:27 UTC）および nightly 系が並行中。過去の AI ツール記事では安定版 `v0.62.0`（09-29、10-05 版記事で見送りとして言及）以降 nightly のみだったため、安定版の本文採用は本記事が初。
- 概要: 信頼性・データ安全性まわりの改善が中心。ファイル書き込みをアトミックにし、ファイルツールの操作を直列化（同時実行による競合を避ける）。状態保存もバックアップ復旧付きのアトミック保存になり、Ctrl+C の緊急中断を修正した。使用量（usage）データを ACP（Agent Client Protocol）経由で報告し、headless モードではフォルダ信頼（folder trust）が伝播する。a2a-server の設定を V1 から V2 へ移行。Windows の ConPTY 上での IME カーソル位置、選択リストでの Enter/Space による確定、スクロール位置の保持なども修正された。
- 何が便利か: ファイル書き込みのアトミック化と操作の直列化により、エージェントが複数ファイルを触る最中にクラッシュや中断が起きても、中途半端な書き込みで壊れにくくなる。状態保存のバックアップ復旧で、セッション状態の破損から戻しやすい。headless モードでのフォルダ信頼の伝播は、CI など非対話実行で信頼設定を前提にした動作を安定させる。
- 使いどころ: Gemini CLI をエージェント的に使ってコードを編集する日常作業、CI/非対話（headless）での実行、Windows 環境での日本語入力（IME）を伴う対話利用。
- 開発者にとっての価値: 新機能より「壊れにくさ」を底上げする安定版で、既存の Gemini CLI ワークフローにそのまま乗せられる。ファイル操作の信頼性が上がるため、自動編集を任せる用途で安心感が増す。
- 注意点: より新しい機能は `v0.65.0-preview.0` や nightly（プレリリース）側にあり、業務利用は安定版 `v0.64.0` を基本に。a2a-server 設定の V1→V2 移行は、既存設定を使っている場合に確認が必要。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.64.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 更新後は `gemini --version` で `0.64.0` を確認。インストール手順は公式 README に従う。

#### 使用例

```bash
# インストール / 更新（npm 経由）
npm install -g @google/gemini-cli

# バージョン確認（0.64.0 を確認）
gemini --version
```

### 3. Cline / 拡張 `v4.1.24`・CLI `v3.0.71`・SDK `v0.0.93`・Desktop `v0.0.46`

- 種別: 拡張機能 / CLI / SDK
- 関連: Cline / Claude（Sonnet 5.5）/ OpenRouter
- 公開・更新日: いずれも 2026-10-13 公開（VS Code 拡張 `v4.1.24` 15:02 UTC、CLI `v3.0.71` 08:56 UTC、SDK `v0.0.93` 08:26 UTC、Desktop `v0.0.46` 15:03 UTC）。過去の AI ツール記事での Cline 本文採用は 8〜9 月で、本バージョン群は初出。
- 概要: プラグイン機構とモデル既定の刷新が中心。プラグインをプロセス内の単一レジストリでロードする方式になり（`CLINE_PLUGIN_MODE=sandbox` で従来のサブプロセス・サンドボックスを維持）、CLI はプラグインを hub 内でロードするため Node/Bun が PATH になくても動くようになった。`cline`・`openrouter` プロバイダの既定モデルが Claude Sonnet 5.5 になり、reasoning-off（推論オフ）が全プロバイダで使えるようになった。拡張側ではシンボリックリンクのルールファイルの読み込み、`.claude/skills` 配下のスキル検出に対応。スクリーンショットがトークン見積りを膨らませてオートコンパクトが早すぎる問題や、引退済みモデル ID の 404 をサインイン問題と誤表示する問題も修正。CLI では `--thinking` が ACP モード（`--acp`）でも効くようになった。Desktop では会話左端のアウトラインで送信済みプロンプト間をジャンプできる。
- 何が便利か: CLI が Node/Bun 非依存でプラグインを動かせるため、ランタイム環境を整えずに導入・配布しやすい。既定モデルが Claude Sonnet 5.5 になり、明示指定なしでも品質の高いモデルで始められる。`.claude/skills` のスキル検出は、Claude Code 系のスキル資産を Cline からも活用しやすくする。
- 使いどころ: VS Code 上でのエージェント的コーディング、CLI をスクリプトや CI に組み込む運用、OpenRouter 経由でモデルを切り替える構成、`.claude/skills` でスキルを共有しているチーム。
- 開発者にとっての価値: 拡張・CLI・SDK・Desktop が同じ方向（プロセス内プラグイン・モデル既定・reasoning 制御の整理）で揃い、どの入口から使っても一貫した挙動になる。CLI のランタイム非依存化は自動化導入の敷居を下げる。
- 注意点: バージョンがコンポーネントごとに分かれている（拡張 `v4.1.24` / CLI `v3.0.71` / SDK `v0.0.93` / Desktop `v0.0.46`）ため、更新時は使っている入口のバージョンを個別に確認する。プラグインをサンドボックスで隔離したい場合は `CLINE_PLUGIN_MODE=sandbox` を明示する。
- 公式リンク: https://github.com/cline/cline/releases
- 参考リンク: https://github.com/cline/cline
- メモ: VS Code 拡張はマーケットプレイスから、CLI は公式手順で更新。各コンポーネントのタグはリリースページで確認できる。

#### 使用例

```bash
# CLI のバージョン確認
cline --version

# プラグインをサンドボックス隔離で動かす（従来挙動を維持）
CLINE_PLUGIN_MODE=sandbox cline

# ACP モードで推論（thinking）を有効化
cline --acp --thinking
```

### 4. Vercel AI SDK / `@ai-sdk/workflow@2.0.71`

- 種別: OSS / SDK
- 関連: Vercel AI SDK
- 公開・更新日: `@ai-sdk/workflow@2.0.71`（2026-10-13 16:12 UTC）。同日に `ai@7.0.139`／`ai@6.0.305`／`ai@5.0.275` など多数のパッチが出ているが、それらは依存更新中心で、実挙動の変更は workflow パッケージ。
- 概要: ワークフロー実行時に、URL で指定した画像・ファイル入力をワークフローのコンテキストでダウンロードしなくなった。代わりにモデルステップが、対応していない URL を `stream()`／`generate()` の両方でダウンロードするようになった。カスタムの `experimental_download` 関数はモデルステップ内で実行されるようになり、`'use step'` マーカーを付ける必要がある。
- 何が便利か: URL 入力のダウンロードがワークフロー全体ではなくモデルステップ内に閉じるため、ダウンロードの責務と実行位置が明確になり、ステップ単位の制御（並列・リトライなど）と整合する。
- 使いどころ: Vercel AI SDK の workflow 機能で、画像や外部ファイルを URL 渡しするマルチステップのエージェント/パイプラインを組んでいる場合。
- 開発者にとっての価値: ダウンロードの実行場所が変わったことで、ワークフローのステップ境界と副作用の扱いが整理される。既存コードの互換性に関わる変更のため、早めに把握しておく価値がある。
- 注意点: 破壊的変更の可能性あり。カスタム `experimental_download` を使っている場合、`'use step'` マーカーを付けないと期待どおり動かない。アップデート時は workflow を使う箇所の挙動を確認すること。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://github.com/vercel/ai
- メモ: `ai@x.y.z` 本体のパッチ（`7.0.139` ほか）は依存更新が中心。挙動変更は workflow パッケージに限られる。
