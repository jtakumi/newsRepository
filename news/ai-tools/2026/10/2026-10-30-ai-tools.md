# 2026-10-30 AI Tools News

## 今日の要点

- OpenAI Codex CLI が安定版 `0.166.0` を公開。キーボード操作でトランスクリプトを選択・検索でき、TUI の質問/回答/返信が Markdown で一貫表示されるように。`codex queue --resume` や `codex doctor --network-only`、`GPT-6.1 Terra` のカタログ追加も。

## 今日の注目

### 1. OpenAI Codex CLI / `0.166.0`

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 2026-10-29（GitHub Releases, Latest）
- 概要: ターミナル向けコーディングエージェント Codex CLI の安定版。キーボードでトランスクリプトを単語・行・ページ単位で選択・移動でき、検索もできるように。非同期の質問・選択・回答・トランスクリプト返信が Markdown で一貫してレンダリングされるようになった。`GPT-6.1 Terra` をバンドル / Vertex AI / Amazon Bedrock のモデルカタログに追加。
- 何が便利か: メッセージをキューに入れたあと、アンロードされたスレッドを `codex queue --resume` で再開できる。安全ブロックの説明が分かりやすくなり、TUI でより安全な代替プロンプトを選べる。`codex doctor --network-only` で設定・接続・WebSocket 診断を絞って実行できる。
- 使いどころ: 長い対話ログを見返して特定箇所を探す作業、ネットワーク疎通だけを切り分けたいトラブルシュート、GCP（Vertex）や Bedrock 上のモデルを使う運用。
- 開発者にとっての価値: resume / fork をまたいでも承認・権限設定や推論トークンの会計が保持され、途中で不要なコンパクションが起きにくくなった。長い作業を分断せず続けやすい。
- 注意点: タグ名は `rust-v0.166.0`。`0.166.0-alpha` 系（〜alpha.6）は同系列のプレリリースで、本番は安定版を推奨。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.166.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 2026-10-28 版で扱ったのは安定版 `0.165.0`（Vertex AI プロバイダ追加）と `0.166.0-alpha` 系プレリリース。本項は新規の安定版 `0.166.0` を扱う。

#### 使用例

```bash
# インストール / 更新
npm install -g @openai/codex

# ネットワーク疎通だけを診断
codex doctor --network-only

# キュー投入後にスレッドを再開
codex queue --resume
```

### 2. OpenCode / `v2.2.1`（＋ `v2.2.2`）

- 種別: OSS / CLI（ターミナル型コーディングエージェント）
- 関連: sst(anomalyco) / opencode
- 公開・更新日: 2026-10-29（GitHub Releases）
- 概要: `/goal <目標>` を TUI / Desktop で実行すると、レビュー側が目標達成を確認するまでセッションが作業を続ける新コマンドを追加（`pause` / `resume` / `clear` で制御、TUI はプロンプト下に状態表示）。オプトインの画像生成ツール `image_generate`（`experimental.image_generate`）で、エージェントがバックグラウンドで画像を生成・編集できる。`/schedule` によるスケジュール実行、OpenRouter / DigitalOcean / Venice の Responses API 対応も入った。`v2.2.2` では接続プロバイダが画像モデルを持つ場合に追加設定なしで画像生成が使える、新規セッション画面で現在の Git ブランチをクリックするとワークツリー選択が開く、などの改善。
- 何が便利か: `/goal` は「達成条件を満たすまで走り続ける」エージェント運用を1コマンドで組める。プラグイン向けに、セッションがアイドルになる前に作業を継続できる実験的フック `experimental.idle` も追加。
- 使いどころ: 明確な完了条件がある反復タスク（テストが全部通るまで、指定の仕様を満たすまで等）を半自律で回したいとき。画像アセットの生成・編集をエージェントの作業に組み込みたいとき。
- 開発者にとっての価値: OSS で自前運用しやすく、`/goal` によって「人がこまめに介入しなくても目標ベースで前進させる」ワークフローを試せる。画像生成はモデル未指定なら自動選択で、`experimental.image_generate.model` で既定を固定も可能。
- 注意点: `@opencode/ai` を直接 import しているコードには破壊的変更あり（一部プロバイダの削除、エントリポイントのリネーム/削除）。`image_generate` と `/schedule`、`/goal` の `experimental.idle` は実験的機能でオプトイン。リポジトリは `sst/opencode` から `anomalyco/opencode` へ移行済み（旧URLはリダイレクト）。
- 公式リンク: https://github.com/sst/opencode/releases/tag/v2.2.1
- 参考リンク: https://github.com/sst/opencode/releases/tag/v2.2.2 / https://opencode.ai/
- メモ: 本リポジトリでの OpenCode 単体採用は 2026-09 系（`v1.18.x`）以来。本項はメジャーが進んだ `v2.2.x` の新機能（`/goal`・`image_generate`・`/schedule`）を新規として扱う。

#### 使用例

```bash
# 更新後、目標ベースでセッションを走らせる
opencode
# TUI 内で
/goal すべての単体テストが通る状態にする
```

### 3. Ollama / `v0.40.13`

- 種別: OSS / ローカルLLMランタイム
- 関連: Ollama / Liquid AI
- 公開・更新日: 2026-10-28〜29（GitHub Releases, Latest）
- 概要: Liquid AI の LFM3 モデル群、特に `lfm3-audio`（テキスト読み上げ / TTS）と `lfm3-omni` が、これまでの Apple シリコン限定から Linux / Windows でも動作するように拡大。macOS / Linux（amd64 / arm64 / ROCm / MLX）向けビルドを同梱。
- 何が便利か: マルチモーダル（特に音声 TTS と omni）の軽量モデルを、Apple 以外の環境でもローカル完結で試せるようになった。
- 使いどころ: Linux サーバや Windows ワークステーションでの音声生成・マルチモーダル検証、オフライン / プライバシー重視のプロトタイピング。
- 開発者にとっての価値: クラウドに出せないデータでの検証を無料でローカル完結でき、対応プラットフォームが広がったことで CI や社内サーバへも載せやすくなった。
- 注意点: 直前の `v0.40.12`（10/27）では LFM3 / d1 2b が Apple ハードウェア限定だった。本リリースはその制約を解消する差分。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.13
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 2026-10-28 版は `v0.40.12`（LFM3 の Apple シリコン対応）まで。本項は新規の `v0.40.13`（Linux / Windows 対応）を扱う。

#### 使用例

```bash
# 本体を更新後、LFM3 系をローカルで実行（Linux / Windows でも可に）
ollama run lfm3-audio
```

### 4. Vercel AI SDK / `ai@7.0.157`

- 種別: OSS / SDK
- 関連: Vercel AI SDK
- 公開・更新日: 2026-10-29（GitHub Releases）
- 概要: `LanguageModelStreamPart` を正式 API に昇格し、`Experimental_LanguageModelStreamPart` を非推奨化。`filterActiveTools` を正式化（`experimental_` 名はエイリアスとして非推奨で残置）。Next.js の Edge Runtime でテレメトリのトレースが出していた警告を修正。あわせて `@ai-sdk/xai@5.0.33` で、トップレベルの `reasoning` マッピングをプロバイダ間で一貫化（未対応レベルは最も近いレベルへ、推論を無効化できないモデルでの `'none'` は最低レベル＋警告へ）。
- 何が便利か: ストリームパート処理とツールの絞り込み（`filterActiveTools`）が experimental でなくなり、プロダクションコードで安定して使える。Edge Runtime での不要な警告が消える。
- 使いどころ: ストリーミング応答をパートごとに処理する実装、呼び出し可能ツールを動的に絞るエージェント、Next.js Edge 上のデプロイ。
- 開発者にとっての価値: experimental 依存を外せるため API 破壊変更のリスクが下がり、プロバイダ横断で推論設定の挙動が揃う。
- 注意点: 6.x 系は同日 `ai@6.0.318` / `6.0.319`（依存更新のみ）。`Experimental_LanguageModelStreamPart` などの旧名は非推奨のため、将来の移行を見据えて正式名へ切り替え推奨。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.157
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 2026-10-28 版は `ai@7.0.155`（実行時のメッセージ再検証削減）まで。本項は新規の `ai@7.0.157` を扱う。

#### 使用例

```bash
# 最新版へ更新
npm install ai@latest
```
