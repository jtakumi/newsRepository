- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.98`（2026-10-14 19:52、GitHub Releases で「Latest」。ページ表記は日付のみ・タイムゾーン明記なしだが GitHub 表示は通常 UTC）。前回記事（10-14 版）では安定版 `v1.0.97`（10-13）までを扱い、`v1.0.98-0` はプレリリースとしてのみ言及していたため、`v1.0.98` 安定版の内容は本記事が初出。
- 概要: 新モデル Gemini 4 Argon に対応。`/ask` の回答まわりの操作が拡充され、Ctrl+E で回答を展開、Ctrl+Y で全文をコピー、`/ask`（や `/btw`）でセッション内の直前の有効な完了回答を再表示できる。信頼性修正として、子プロセスの終了シグナルが失われてもコマンドフックが確実に完了するように修正、分割ビューでセッションを切り替えても MCP ステータスと `/mcp` が現在のセッションと同期するように修正、セッション再開時に放棄された保留中パーミッションは無視して有効なパーミッション要求のみ継続、入力ボックス初期化中にタイプした通常文字を取りこぼさず保持、を含む。

### 2. Claude Code / `v2.1.299`・`v2.1.300`

- 種別: CLI
- 関連: Claude / Anthropic
- 公開・更新日: `v2.1.299`（2026-10-14 02:49 UTC）、`v2.1.300`（2026-10-14 18:24 UTC、GitHub Releases で「Latest」）。前回の AI ツール記事（10-12 版）は `v2.1.296`（10-09）までの既報で、`v2.1.297`〜`v2.1.298` は公開リリース一覧に現れず、`v2.1.299`・`v2.1.300` の内容は本記事が初出。
- 概要: `v2.1.299` は、200K トークン超の会話がキャッシュ期限近くでアイドルのときに自動圧縮する「アイドルコンパクション」（しきい値は設定可能）、`@` ファイル参照を内容展開せずパス文字列としてモデルに渡す `CLAUDE_CODE_DISABLE_FILE_MENTIONS`、エージェントビューでの `/effort`・`/fast`、バックグラウンドセッションのセーフモード表示、`claude plugin eval` の `--disallow-tools`、MCP 接続/再接続やサンドボックスのパス処理・夏時間をまたぐスケジュールタスクなど広範な修正を含む。`v2.1.300` は、大きな API リクエストの既定 gzip 化（`CLAUDE_CODE_GZIP_REQUEST_BODIES=0` で無効）、終了要求後 1.5 秒でのバックグラウンドコマンド強制終了、`claude remote-control` の `--sandbox`/`--no-sandbox` をエラー化、AWS 上の Claude Platform での `/advisor`、mods 向けの各種追加、クラウドセッション/バックグラウンドエージェント/`/tasks` などの修正を含む。
- 何が便利か: アイドルコンパクションは、長い会話を放置してキャッシュ失効する前に自動で圧縮し、再開時のコスト・コンテキスト膨張を抑える。`CLAUDE_CODE_DISABLE_FILE_MENTIONS` は、巨大ファイルを `@` 参照した際に内容を丸ごと展開せずパスだけ渡せるため、意図せぬコンテキスト消費を避けられる。エージェントビューの `/effort`・`/fast` は、タスクごとに推論の重さ/速さを切り替えやすくする。リクエストの既定 gzip 化は大きな入力の転送を軽くする。
- 使いどころ: 長時間・大規模な会話を続ける開発作業、巨大ファイルを参照しつつコンテキストを節約したいケース、サブエージェント/バックグラウンド実行を多用する運用、転送量を抑えたい環境。
- 開発者にとっての価値: 新機能より「コンテキスト管理・コスト・安定性」を底上げする実務寄りの更新で、既存の Claude Code ワークフローにそのまま乗る。`/effort`・`/fast` やアイドルコンパクションは日々の体感に効き、環境変数での挙動制御が増えたことで自動化・CI 運用を細かく調整できる。
- 注意点: `v2.1.297`・`v2.1.298` は公開リリース一覧に現れず欠番（詳細は確認できない）。`CLAUDE_CODE_DISABLE_FILE_MENTIONS` を有効にすると `@` はパス渡しになるため、従来の「内容を自動展開」前提のワークフローは挙動が変わる。`--sandbox`/`--no-sandbox` を `remote-control` で使っていた場合はエラーになるため見直しが必要。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.300
- 参考リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- メモ: 更新は `claude` の通常アップデート手順に従う。`v2.1.296`（`autoCompactWindow` など）は 10-12 版記事で既報。

#### 使用例

```bash
# @ ファイル参照を内容展開せずパスのまま渡す
export CLAUDE_CODE_DISABLE_FILE_MENTIONS=1

# 大きな API リクエストの gzip 化を無効にしたい場合
export CLAUDE_CODE_GZIP_REQUEST_BODIES=0

# エージェントビュー内で推論の重さ/速さを切り替え
/effort
/fast
```

- 使いどころ: Vercel AI SDK でツール/関数呼び出しを多用するエージェントやワークフローを組んでいて、外部サービスのレート制限・コスト・レイテンシを調整したい場合。
- 開発者にとっての価値: これまで暗黙だったツール実行の並列度を設定値として扱えるようになり、レート制限超過やバースト負荷を避ける制御を実装に組み込める。既存のツール呼び出しコードへ段階的に適用しやすい。
- 注意点: リリースノート上は「Patch Changes」に記載されるが、コミットは feature 扱い。既定の同時実行数や既存コードへの影響はチェンジログ/ドキュメントで確認を。メジャー系列（`7.x`／`6.x`／`5.x`）が並行しているため、使っている系列のバージョンを確認して更新すること。

- メモ: 前回記事（10-14 版）の `@ai-sdk/workflow@2.0.71`（URL 入力のダウンロードをモデルステップ内に移動）に続く更新。`ai@6.0.306`/`ai@5.0.276` 等は依存更新中心。

### 4. Ollama / `v0.40.4`（安定版）

- 種別: CLI / ローカル LLM ランタイム
- 関連: Ollama / ローカルLLM
- 公開・更新日: `v0.40.4`（タグ公開は 2026-10-12 19:00、現在 GitHub Releases で「Latest」=安定版）。前回記事（10-14 版）時点では安定版は `v0.40.3`、`v0.40.4` は rc（プレリリース）扱いで本文非採用だったが、その後 `v0.40.4` が安定版「Latest」に昇格したため本記事で採用。

- 何が便利か: 分類・yes/no 判定・スコアリングといった「構造化された判断」を、プロンプト整形に悩まず `ollama run <model> --ask` の 1 行でローカル実行できる。入力はファイルをパイプで渡せるため、チケットやログの一次トリアージをその場で回せる。
- 使いどころ: 問い合わせチケットの振り分け、ログやテキストのラベル付け、簡易な合否/該当判定をローカルで試す場面。クラウドに投げたくないデータの判定にも向く。
- 開発者にとっての価値: 分類・判定タスクを外部 API なしにローカルで即試せるため、前処理やルーティングの試作が速い。`ollama launch codex` のモデルピッカー対応で、ローカルモデルをコーディングツールから選びやすくなる。
- 注意点: タグ公開日は 2026-10-12 だが安定版「Latest」への昇格は直近。decision models の rc0 相当の内容は 10-13 版記事で既報で、本記事は安定版（stable channel）で利用可能になった点が差分。`nimble` が何のモデルか・他に対応するモデルは公式ドキュメントで要確認。最新の `v0.40.5-rc0`（10-14）はプレリリースのため本文非採用。

- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: rc0 段階の内容（EmbeddingGemma 2・llama.cpp 更新など）は 10-13 版で既報。本記事は安定版昇格と `ollama run --ask` の決定モデル実行に焦点。
