## 今日の注目

### 1. Claude Code / `v2.1.293`

- 種別: CLI / 拡張機能
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-10-06〜10-07 頃（JST。公式 CHANGELOG 最新。`v2.1.292` までは 10-07 版記事で既報）
- 概要: `v2.1.292` に続く更新。目玉は Claude Haiku 5.5（`claude-haiku-5-5`）が Anthropic API の既定 Haiku モデルになったこと。1M コンテキスト対応かつトークン単価が下がった。開発者向けには、`subagentStatusLine` のペイロードに `agentType` が入り、ステータスライン用スクリプトでカスタムサブエージェントの種別を判別できるようになった。Mod では `$.tool.register` に `isDeferred` が追加され、ツールのスキーマを起動時に読み込むか、ツール検索の背後に遅延ロードするかを制御できる。あわせて、コンパクション後に完了済みの作業をやり直す/取り消す不具合、HTTP MCP 接続でリクエストを保持し続けるメモリリーク、`/model` の effort 操作で誤って Low を既定保存してしまう問題など、多数の修正が入った。
- 何が便利か: API 側の既定 Haiku が 5.5（1M コンテキスト・低価格）になったことで、軽量・大量処理やサブエージェントのコストを下げやすい。`agentType` でサブエージェント種別ごとにステータス表示を出し分けられ、`isDeferred` でツール定義の読み込みを必要時だけに絞れる。
- 使いどころ: Claude Code を日常的に使い、サブエージェントや Mod、MCP を組み合わせて回しているチーム。Haiku を使った安価な前処理・分類・要約パイプラインを組んでいる場合。
- 開発者にとっての価値: モデル既定の更新（コスト/コンテキスト）と、サブエージェント表示・Mod ツール登録という拡張ポイントの実用強化、さらにコンパクション周りの安定化がまとまって入り、`claude update` だけで既存ワークフローに乗る。
- 注意点: Mod 関連のインターフェースは引き続き早期アクセスで、リリース間で変わり得る。CHANGELOG はバージョンごとに日付が付かないため、公開日は直近のリリース間隔からの概算。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://code.claude.com/docs/en/overview
- メモ: 更新は `claude update`（または再インストール）後に `claude --version` で `2.1.293` 以上を確認。

#### 使用例

```bash
# 更新してバージョン確認
claude update
claude --version   # 2.1.293 以上を確認

# API で既定の Haiku（5.5）を明示指定したい場合のモデル ID
# claude-haiku-5-5
```

### 2. OpenAI Codex CLI / `v0.161.0`

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 安定版 `0.161.0`（2026-10-07、GitHub Releases で「Latest」）。`0.160.1` は 10-07 版記事で既報。
- 概要: 既定モデルが `GPT-6.1 Sol` に切り替わった（バンドルおよび Amazon Bedrock のモデルカタログ）。TUI から `/mcp login <name>` で MCP サーバーのログインができるようになり、音声入力でマイク/スピーカーのデバイス選択が追加された。`codex exec` にはターンごとの「Cyber access program」オプション、オプトインの「Daybreak」も追加（いずれも公式リリースノート記載のオプトイン項目）。修正はファイルシステムのエスカレーション、ターミナル再接続、貼り付け後の Enter、SQLite 破損からの復旧、リトライ処理など。
- 何が便利か: 既定モデルが新しい `GPT-6.1 Sol` になり、追加設定なしで最新モデルを使える。`/mcp login <name>` で MCP の認証を TUI 内で完結でき、複数 MCP を使う構成の取り回しが軽くなる。音声のデバイス選択で入出力環境を選べる。
- 使いどころ: Codex CLI を常用し、MCP サーバーを複数つないで運用する開発者。Bedrock 経由で動かしているチームも既定モデル更新の恩恵を受ける。
- 開発者にとっての価値: モデル既定の更新と、MCP ログインの TUI 対応という日常操作に効く追加がまとまって入る。安定版なので業務運用に乗せやすい。
- 注意点: 既定モデルが変わるため、特定モデルを前提にした挙動・コストは再確認が望ましい。`0.162.0-alpha` 系はプレリリースのため、業務利用は安定版（`0.161.0`）を基本に。「Daybreak」「Cyber access program」はオプトイン項目で、必要な場合のみ有効化する。
- 公式リンク: https://github.com/openai/codex/releases
- 参考リンク: https://github.com/openai/codex
- メモ: 更新は `npm install -g @openai/codex`（または `brew upgrade codex`）後に `codex --version` で確認。

#### 使用例

```bash
# 更新してバージョン確認

codex --version   # 0.161.0 以上を確認

# TUI 内で MCP サーバーにログイン（v0.161.0）
```

### 3. GitHub Copilot CLI / `v1.0.93`

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 安定版 `v1.0.93`（2026-10-07、GitHub Releases で「Latest」）。`v1.0.92` は 10-07 版記事で既報。
- 概要: コマンドのサンドボックス実行が `/sandbox`・`--sandbox` で全ユーザーに開放された。MCP サーバー設定の変更が、セッションを再起動しなくてもターン間に反映されるようになった。モデルピッカーは `GPT-6.1 Sol`、`GPT-6 Astra/Luna`、`Claude 5.5` 系を優先表示。エンタープライズ向けに `permissions.limitTo`（ネットワークリクエストの許可ドメイン境界を管理ポリシーで強制）を追加。ユーザー設定の読み取り元は `~/.copilot/settings.json` に一本化され、`~/.copilot/config.json` のキーは無視されるようになった。
- 何が便利か: `/sandbox` でコマンド実行をサンドボックス化でき、エージェントに任せる実行の安全性を上げられる。MCP 設定変更がターン間に反映されるため、設定を試しながらセッションを止めずに回せる。
- 使いどころ: Copilot CLI をエージェントとして常用する開発者。MCP を調整しながら使うチームや、組織でネットワーク境界を管理したいエンタープライズ利用。
- 開発者にとっての価値: サンドボックス実行の一般開放は、エージェントにコマンドを委ねる運用の実用的な安全策。設定一本化（`settings.json`）で設定の所在が明確になる。
- 注意点: ユーザー設定の読み取り元変更により、`~/.copilot/config.json` に書いていた設定は `~/.copilot/settings.json` へ移す必要がある。さらに先の機能はプレリリース（`v1.0.94` 系）側にある。
- 公式リンク: https://github.com/github/copilot-cli/releases
- 参考リンク: https://github.com/github/copilot-cli
- メモ: 変更内容は Releases の各タグのノートで確認できる。インストール手順は公式 README に従う。

#### 使用例

```bash
# バージョン確認（安定版 v1.0.93 を確認）
copilot --version

# サンドボックスを有効にして起動（全ユーザーで利用可能）
copilot --sandbox

# セッション中にサンドボックスを切り替え
/sandbox
```
