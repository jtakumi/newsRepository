## 今日の注目

### 1. OpenHands / v1.9.0

- 種別: OSS（自律型コーディングエージェント／Web UI・Agent-server）
- 関連: Devin 代替 OSS ／ Agent Framework
- 公開・更新日: 2026-08-03（18:49 UTC / JST 08-04 03:49）
- 概要: エージェントの実行状況を可視化し、UI をマニフェスト駆動へ整理した安定版更新。旧称 OpenDevin 系の OSS エージェント。
- 何が便利か:
  - **チャット内でのライブ・エージェント活動表示**: 何をしているか（実行中の操作）がチャット上でリアルタイムに見えるようになり、長時間タスクの進行を追いやすい。
  - **ドメイン非依存の拡張マニフェスト・ホスト**: 拡張／自動化 UI を「インターフェース・マニフェスト」で定義できるようになり、拡張の追加や自動化画面の構成が宣言的に。
  - **Cloud／Agent-server のバックエンド選択 UI を整理**: どの実行バックエンドで動かすかの切り替えが分かりやすくなった。
  - 失敗した保留メッセージの破棄、CANCELLED／SKIPPED の自動化ステータス表示、既定プロファイル LLM 参照まわりの composer ゲーティング修正など、実運用のUXバグを多数修正。
- 使いどころ:
  - Issue 対応やリファクタなどを丸ごとエージェントに任せ、**進捗をチャットで監視しながら回す**ワークフロー。
  - 複数の自動化（automations）を UI から管理し、Cloud とローカル Agent-server を使い分けたいチーム。
- 開発者にとっての価値: OSS で自己ホスト可能な自律エージェントとして、**「投げて待つ」から「動作を見ながら任せる」**へ運用性が上がった。ライブ表示は暴走・空回りの早期発見にも効く。
- 注意点: エージェントはファイルシステムに広くアクセスするため、**サンドボックス（Docker 実行）を推奨**。npm／ソース直実行はホストに直接影響する点に注意。導入手順・実行イメージは版で変わるので必ず公式ドキュメントを参照。
- 公式リンク: https://github.com/All-Hands-AI/OpenHands/releases/tag/v1.9.0
- 参考リンク: https://github.com/All-Hands-AI/OpenHands
- メモ: 本リポジトリで OpenHands を単体採用するのは今回が初。Aug 3 安定版で live agent activity と extension-manifest host を新規導入したため採用。

### 2. Qwen Code / v0.21.4（＋ v0.21.3）

- 種別: CLI（ターミナル・コーディングエージェント／Gemini CLI 派生）
- 関連: Qwen ／ ローカル・OpenAI 互換プロバイダ対応 CLI
- 公開・更新日: v0.21.4 = 2026-08-03（安定版）、v0.21.3 = 2026-08-01（安定版）
- 概要: Web Shell のデスクトップアプリ化とサブエージェント隔離・キャッシュ再利用を入れた安定版更新。Qwen 系モデルや OpenAI 互換エンドポイント向けの CLI エージェント。
- 何が便利か:
  - **Web Shell のデスクトップアプリ化（v0.21.4）**: 単一インスタンス動作・自動更新付きで、ネイティブのライフサイクル管理に対応。
  - **フォーク・サブエージェントの隔離（v0.21.4）**: 並列に切ったフォーク同士が**他ブランチの指示を参照しない**ため、並行タスクの相互汚染を防げる。
  - **チャット圧縮でプロンプトキャッシュを再利用（v0.21.4）**: 対応プロバイダで**ツール実行なしに本会話のキャッシュを使い回し**、圧縮時の遅延を削減。
  - **`/review` の出力言語追従（v0.21.4）** と、前々日 **v0.21.3 の `/review` テスト計画検証・失敗の帰属測定・検証レンズ追加**で、レビュー系スキルが実用的に。
  - Windows で API キーなど機微設定の貼り付けが無視される不具合（複数文字ペースト）を修正。
- 使いどころ:
  - Qwen 系や OpenAI 互換 API を使い、**ターミナルからコード生成・レビュー・修正**を回したい個人開発。
  - 複数タスクをフォークで並行させ、**指示の混線なく**同時進行させたいエージェント運用。
- 開発者にとっての価値: `npm install -g` で入る軽量 CLI ながら、**フォーク隔離・キャッシュ再利用・レビュー検証**まで揃い、日常の実装〜レビュー往復を CLI 完結で組みやすい。
- 注意点: Qwen ブランドの CLI だが利用にはプロバイダ設定（`/auth`）が必要。挙動はモデル・プロバイダ側の対応にも依存する。Session Workflow は実験的機能。
- 公式リンク: https://github.com/QwenLM/qwen-code/releases/tag/v0.21.4
- 参考リンク: https://github.com/QwenLM/qwen-code
- メモ: 本リポジトリで Qwen Code を採用するのは今回が初。v0.21.4（Aug 3）安定版と直近 v0.21.3（Aug 1）をまとめて採用。

#### 使用例

```bash
# インストール／更新
npm install -g @qwen-code/qwen-code@latest

# 起動（対話 TUI）
qwen

# セッション内でプロバイダ／APIキーを設定
/auth

# 変更レビュー（テスト計画検証つき）
/review
```

### 3. llama.cpp / b10236〜b10244（DeepSeek V3.2・Qwen3-Next MTP ほか）

- 種別: OSS（ローカル推論エンジン）
- 関連: ローカル LLM関連ツール
- 公開・更新日: 2026-08-03（b10236 = 05:11 UTC、b10237 = 07:50 UTC、b10238 = 08:56 UTC、b10240 = 11:24 UTC、b10241 = 14:58 UTC、b10242 = 17:22 UTC、b10244 = 22:13 UTC）
- 概要: 新モデルの MTP 対応、Metal の長コンテキスト最適化、CUDA の競合修正、サーバ既定ポート変更予告を同日ビルドでまとめて投入。
- 何が便利か:
  - **DeepSeek V3.2 / Qwen3-Next の MTP（Multi-Token Prediction）実装（b10237・b10238）**: 最新アーキテクチャのローカル推論下地が入った。モデル種別の自動判別も改善。
  - **Metal「Lightning Indexer」（b10236）**: タイル化カーネルで**長コンテキスト処理を大幅高速化**。Apple シリコンでの長文推論に効く。
  - **CUDA block_reduce のデータ競合修正（b10241）**: softmax／正規化のダブルバッファリングで競合を解消。NVIDIA GPU での安定性向上。
  - **CUDA 側のペナルティ・サンプラ（b10242）**: `common_sampler_init` のペナルティ処理を強化し top-k ペナルティに対応。
  - **llama-server 既定ポートの 8080→9931 変更予告（b10240）**: 近く既定ポートが変わる告知。**起動スクリプトや逆プロキシ設定の見直しが必要**。
- 使いどころ:
  - Apple シリコンや各種 GPU で DeepSeek V3.2 系・Qwen3-Next 系を**手元で検証**したいとき。
  - `llama-server` を常駐運用しており、**ポート変更の影響を事前に確認**しておきたいとき。
- 開発者にとっての価値: クラウド API に依存せず**最新アーキテクチャを手元で試せる**。長コンテキストの Metal 最適化はローカル RAG／長文処理の実用性を押し上げる。ポート変更予告は運用事故の予防に直結。
- 注意点: llama.cpp は日次で多数のビルド（bXXXXX）が出る。特定モデルの動作は量子化・モデルファイル側の対応にも依存するため実モデルで要検証。MTP／Lightning Indexer は実装直後のため挙動確認を推奨。
- 公式リンク: https://github.com/ggml-org/llama.cpp/releases
- 参考リンク: https://github.com/ggml-org/llama.cpp
- メモ: 前回記事（08-02）は b10227〜b10232（DeepSeek V4／Qwen3 パーサ）まで。今回は b10236〜b10244 の DeepSeek V3.2／Qwen3-Next MTP・Lightning Indexer・ポート変更予告を新規採用。

#### 使用例

```bash
# ソースからビルド（例）
git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build && cmake --build build --config Release

# サーバ起動（近く既定ポートが 8080→9931 に変わる予定。--port を明示推奨）
./build/bin/llama-server -m ./models/your-model.gguf --port 8080
```
