### 1. Claude Code / v2.1.232・v2.1.233

- 種別: CLI（ターミナル・コーディングエージェント／安定版）
- 関連: Anthropic / Claude / Claude Code
- 公開・更新日: v2.1.232 = 2026-08-13 23:29 UTC（JST 08-14 08:29）、v2.1.233 = 2026-08-14 22:20 UTC（JST 08-15 07:20）
- 概要: サブエージェント運用とセッション間連携を強化しつつ、GitLab 連携の拡充と複数の権限バイパス修正を入れた安定版の連続更新。
- 何が便利か:
  - **サブエージェントのフォークがデフォルト有効（v2.1.232）**: フォーク時に親の会話・プロンプトキャッシュを丸ごと継承する。文脈を積み直さずに分岐タスクを走らせられ、長い調査からの派生作業が速くなる。
  - **`@mention` でセッション間メッセージング（v2.1.232）**: 別セッションに向けてメッセージを送れる。複数セッションを並行運用するワークフローの受け渡しに使える。
  - **プラグインマーケットプレイスの GitLab 対応（v2.1.232）＋ MR URL 対応（v2.1.233）**: プラグイン供給元に GitLab を追加。`--worktree` や `claude agents` ビューで GitLab のマージリクエスト URL を `!N` 形式で扱える。GitLab を使う組織での運用性が上がる。
  - **セキュリティ修正（v2.1.232）**: PowerShell の変数書き込みパラメータによる権限バイパス、Cygwin 形式シンボリックリンクによる権限バイパス、入れ子 git リポジトリが親ディレクトリの信頼を継承する問題を修正。GitLab トークン系（`glrt-`／`gloas-`／`glptt-` など）のリダクションも追加。
  - **Windows NT デバイスプレフィックス（`\??\`）の NTLM 資格情報漏洩ベクタを修正（v2.1.233）**。
  - **Linux の Bash ツールにメモリ cgroup 制限（オプトイン）を追加（v2.1.233）**: `CLAUDE_CODE_TOOL_MEMORY_LIMIT` でコマンドのメモリ上限を設定できる。
  - **apps ゲートウェイに `forward_user_identity`（オプトイン）を追加（v2.1.233）**: ユーザ単位の spend attribution が可能に。
- 使いどころ:
  - **サブエージェントで分岐タスクを多用する**調査・実装ワークフロー（フォークのキャッシュ継承が効く）。
  - **GitLab を主管理にしている組織**でプラグイン供給や MR 参照を Claude Code に統合したいケース。
  - Windows／PowerShell／シンボリックリンクまわりの**権限・資格情報の安全性を重視する**運用。
- 開発者にとっての価値: `npm i -g @anthropic-ai/claude-code` のターミナルエージェントで、サブエージェント運用の効率・GitLab 連携・セキュリティが底上げされた。特に**複数の権限バイパス修正**は、自動承認を絡めた運用の事故防止に直結する。
- 注意点: v2.1.233 では **新しめのモデルで Todo／タスク追跡ツール（TaskCreate/Get/Update/List・TodoWrite）が既定で無効化**された。従来の TODO 機能に依存している場合は `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` で再有効化する。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.233
- 参考リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.232 / https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- メモ: 本リポジトリでは v2.1.229（JST 08-13）まで採用済み。v2.1.232・v2.1.233 を新規採用。

#### 使用例

- 関連: Ollama / ローカルLLM / DeepSeek / Meta（Muse）/ Qwen

  - Apple Silicon で **Qwen 3.8 27B をローカルのコーディング／アシスタント用途**に回したい人。

### 3. Cline / v4.1.10・SDK v0.0.75・CLI v3.0.55・Desktop v0.0.13（Web検索・Crusoe追加）

- 種別: 拡張機能（VS Code）＋ SDK／CLI／Desktop
- 関連: Cline / Crusoe / 各種プロバイダ
- 公開・更新日: v4.1.10 = 2026-08-14 17:16 UTC（JST 08-15 02:16）、SDK v0.0.75・CLI v3.0.55・Desktop v0.0.13 = 2026-08-14（JST 08-14〜08-15）
- 概要: 対応モデルでの Web 検索（provider-executed）を追加し、Hub デーモンの安定化・アイドルプロセス回収・モデルカタログ更新を入れた更新。
- 何が便利か:
  - **タスク中の Web 検索（v4.1.10）**: 対応モデルがタスク実行中に Web 検索でき、Feature Settings のトグルで有効化する。**検索呼び出しと結果は会話に表示され、リロードをまたいで保持される**。SDK v0.0.75 でも「provider-executed web search」としてセッション履歴に残る形で提供。
  - **Hub デーモンの相互終了ループを修正（v4.1.10）**: 異なるビルドの Cline が互いの Hub デーモンを落とし合い、ライブセッションが異常終了する問題を修正（ビルド同一性を全順序で比較し、片側だけが引退を判断できるようにした）。稼働中の Hub はアイドルになるまで置き換えないよう変更。
  - **アイドルのプラグインサンドボックスプロセスを回収（v4.1.10）**: セッション寿命の間ずっと残っていたアイドルプロセスを解放。
  - **モデルカタログを更新し Crusoe をプロバイダ追加（v4.1.10）**、プロバイダ別の既定モデルも更新。
  - **CLI v3.0.55**: Hub にアタッチ中の自動更新インストールを抑止し、終了時まで遅延。ストリーミング Markdown 描画を改善。
- 使いどころ:
  - **エディタ内エージェントに「調べながら実装」させたい**個人・チーム（検索結果が会話に残るのでレビューしやすい）。
  - 複数バージョンの Cline を並行利用していて **Hub デーモンの競合でセッションが落ちていた**利用者。
  - **Crusoe など新しいプロバイダ**を Cline から試したいケース。
- 開発者にとっての価値: VS Code 拡張・CLI・SDK・Desktop を同日でそろえ、Web 検索という実務直結の機能を追加。検索の呼び出しと結果が履歴に残るため、エージェントの根拠を後追いしやすい。
- 注意点: Web 検索は「対応モデル」に限られ、Feature Settings での明示的なトグルが必要。SDK／CLI／拡張／Desktop でバージョンが分かれるため、組み合わせに注意。
- 公式リンク: https://github.com/cline/cline/releases/tag/v4.1.10
- 参考リンク: https://github.com/cline/cline/releases
- メモ: 本リポジトリで既採用の v4.1.8（JST 08-11）からの継続更新。Web 検索と Crusoe 追加を新規トピックとして採用。
