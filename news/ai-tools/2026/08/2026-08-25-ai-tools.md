### 1. Claude Code / v2.1.239・v2.1.240・v2.1.241

- 種別: CLI
- 関連: Claude / Anthropic
- 公開・更新日: 2026-08-21（v2.1.239）／08-22（v2.1.240）／08-23（v2.1.241）
- 概要: 8/20 の v2.1.236 以降の連続更新。v2.1.239 が機能追加の本体で、v2.1.240・241 はバグ修正と安定性向上。
- 何が便利か:
  - `/cost`・ステータスライン・`--max-budget-usd` のコスト見積りが、データレジデンシー用ワークスペースの 1.1× 米国内推論プレミアムを反映して実額に近づいた。
  - `/claude-api upgrade` で Python プロジェクトの `anthropic` 0.x → 1.x 移行を自動実行。
  - Bedrock / Vertex / Foundry など従来対象外だった環境でもフルスクリーンレンダラーの提案が出るように。
  - Bedrock のプロキシ経由ストリーミングで Content-Type が落ちる不具合、HTTPS プロキシ+Bedrock SSO 起動時ハングを修正。
- 使いどころ: コスト上限を設けた自動実行や CI 連携で、見積り精度が上がる。旧 SDK に依存した既存 Python コードの棚卸しを `/claude-api upgrade` で片付けられる。
- 開発者にとっての価値: 予算管理と SDK 移行という「後回しにしがちな運用作業」をコマンド一発に落とし込める。
- 注意点: v2.1.242 以降は未確認。プレミアム反映はデータレジデンシー対象ワークスペースのみ。
- 公式リンク: https://code.claude.com/docs/en/changelog
- 参考リンク: https://releasebot.io/updates/anthropic/claude-code
- メモ: 直近は機能追加 → 連日パッチという流れ。まず更新して `/cost` の値が変わったか確認するとよい。

#### 使用例

```bash
# 更新してバージョン確認
npm install -g @anthropic-ai/claude-code@latest
claude --version

# 予算上限つきで起動（見積りに米国内推論プレミアムが反映される）
claude --max-budget-usd 5

# Python プロジェクトの anthropic SDK を 1.x へ移行
claude
> /claude-api upgrade
```

### 2. OpenAI Codex CLI / 0.149.1（安定版）＋ 0.150.0-alpha 系

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 2026-08-24（0.149.1 安定版）／0.150.0-alpha.8 も 08-24 にプレリリース
- 概要: 8/19 の rust-v0.148.0 以降で安定版が 0.149.x へ前進。v0.149.0 でエージェント運用系が大きく拡充した。
- 何が便利か:
  - 対話型エージェントの一覧ダッシュボード（検索・開始・オープン・リネーム・停止をショートカットで操作）。
  - TUI での作業ディレクトリ操作 `/cd`・`/pwd`・`/cwd`。
  - `codex queue` で既存のローカル／リモートセッションにメッセージを送信。
  - `codex doctor` がエンドポイント保護・ネットワーク/プロキシ障害・更新接続性を診断。
- 使いどころ: 複数タスクを並行で回すエージェント運用の起点になる。プロキシ環境で繋がらないときの一次切り分けに `codex doctor`。
- 開発者にとっての価値: 「立てたエージェントを見失う」問題をダッシュボードで解消し、ターミナル内で作業ディレクトリまで完結できる。
- 注意点: `codex mcp-server` サブコマンドは非推奨の方向で、Codex app server への移行が案内されている。0.150.0 系は alpha。MCP 連携を組んでいる場合は移行手順を確認すること。
- 公式リンク: https://github.com/openai/codex/releases
- 参考リンク: https://developers.openai.com/codex/changelog
- メモ: 安定版を使うなら npm の安定チャネルで 0.149.1 を指定。alpha は挙動が変わりうる。

#### 使用例

```bash
# npm 経由でインストール／更新（安定チャネル）
npm install -g @openai/codex@latest
codex --version

# 環境診断（プロキシ・更新接続性などをチェック）
codex doctor

# 既存セッションにメッセージを送る
codex queue "add tests for the parser module"
```

### 3. LiteLLM / v1.98.0

- 種別: OSS / AI ゲートウェイ
- 関連: OpenAI 互換 / Anthropic / Bedrock / Gemini / Grok ほか
- 公開・更新日: 2026-08-23（v1.98.0、rc.1 は 08-16）
- 概要: 8/18 の v1.97.0 以降のマイナー更新。ルーティングとコスト管理まわりが強化された。
- 何が便利か:
  - ルーティンググループを「仮想モデル」として扱え、`/v1/models` に一覧表示できる。
  - Gemini 3.7-flash / Grok 4.6 の day-0 価格を同梱、コスト計算がすぐ効く。
  - Bedrock 上の GLM 5 / DeepSeek V3.2 でネイティブ構造化出力に対応。
  - キー単位のプロンプトキャッシュ切替、デプロイ単位の SSE keepalive でロードバランサのタイムアウトを回避。
- 使いどころ: 複数プロバイダを OpenAI 形式で束ねるゲートウェイとして、モデル追加や価格反映を待たずに切り替えられる。
- 開発者にとっての価値: アプリ側は OpenAI SDK のまま、`base_url` 差し替えだけで最新モデルと構造化出力を使える。
- 注意点: 新モデルの価格・機能は各社の一次情報で最終確認を。UI は shadcn への移行が進行中で見た目が変わる。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.98.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: proxy 起動 → OpenAI SDK の base_url を差し替える基本形は従来通り。

#### 使用例

```bash
# インストール
pip install "litellm[proxy]"==1.98.0

# プロキシとして起動（OpenAI 互換エンドポイントを提供）
litellm --config config.yaml

# アプリ側は OpenAI SDK のまま base_url を差し替え
#   base_url="http://localhost:4000"
```
