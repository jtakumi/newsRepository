### 1. Vercel AI SDK / ai@7.0.85・ai@6.0.272（画像生成の個別呼び出し露出・tool choice 強制）

- 種別: OSS ライブラリ（TypeScript／安定版）
- 関連: Vercel AI SDK / Agent Framework
- 公開・更新日: `ai@7.0.85` は 2026-08-30 08:04 UTC（JST 08-30 17:04）、`ai@6.0.272` は 2026-08-30 08:52 UTC（JST 08-30 17:52）
- 概要: 主要な TypeScript 向け AI アプリ開発キットの安定版が、7 系・6 系ともに前進。前回この SDK を扱った 08-28（`ai@6.0.271` / `ai@5.0.249`：永続化した型付きツール呼び出しのスキーマ検証）以降の新しい実務更新。
- 何が便利か:
  - **画像生成の個別呼び出しを露出（7 系）**: `feat(ai): expose individual image generation calls`。複数枚生成やバッチ画像生成で、**各生成呼び出しを個別に扱える**ようになり、結果やコストを枚数単位で追跡しやすい。
  - **Gateway 画像生成コストの分割合算（7 系）**: `fix(ai): sum Gateway image-generation costs across split requests`。リクエストが分割された場合でも**画像生成コストを正しく合算**し、課金計上のズレを防ぐ。
  - **Anthropic バッチの整合性（7 系）**: バッチリクエストの**件数メタデータをプロバイダメタデータに保持**し、バッチでも**言語モデルオプションの全面をサポート**。
  - **tool choice 違反の拒否＋回復（6 系 `ai@6.0.272`）**: `generateText` が **tool choice の要求に反する応答をエラー回復付きで拒否**。ツール強制が期待どおり効かない事故を防ぐ。
  - **ツール承認シークレット（6 系）**: `ToolLoopAgent` の設定と `prepareCall` で**ツール承認シークレットを許可**。人手承認（human-in-the-loop）を要するツール実行を安全に組める。
- 使いどころ:
  - **画像生成 API をアプリに組み込み**、枚数単位でコスト・結果を管理したいとき（7 系）。
  - **ツール強制（tool choice: required など）を厳密に効かせたい**エージェント実装（6 系）。
  - 破壊的操作を伴うツールに**承認フローを挟みたい**エージェント（6 系の `ToolLoopAgent`）。
- 開発者にとっての価値: `npm i ai@7.0.85`（または 6 系継続なら `npm i ai@6.0.272`）で今日すぐ試せる安定版。7 系は最新ライン、6 系は移行途中プロジェクト向けの保守ラインとして**両系統が同日更新**されており、どちらの利用者も恩恵を受けられる。
- 注意点: 7 系と 6 系はメジャーが異なるため、プロジェクトの採用ラインに合わせてバージョンを選ぶこと。画像生成の個別呼び出し露出は API サーフェスの追加で、既存コードへの破壊的変更は告知されていないが、詳細は各タグのリリースノートで確認のこと。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.85
- 参考リンク: https://github.com/vercel/ai/releases/tag/ai%406.0.272 / https://github.com/vercel/ai/releases
- メモ: 前回採用（08-28）は `ai@6.0.271` / `ai@5.0.249`。今回は `ai@7.0.85` / `ai@6.0.272` を新規採用（バージョン・内容ともに別）。

#### 使用例

```bash

npm i ai@7.0.85

# 移行途中のプロジェクトは 6 系保守ラインを継続
```

### 2. Pydantic AI / v2.36.0（@durable_operation・持続実行エンジンの公開バックエンド API）

- 種別: OSS ライブラリ（Python／安定版）
- 関連: Pydantic AI / Agent Framework
- 公開・更新日: 2026-08-29 01:25 UTC（JST 2026-08-29 10:25）※ v2.36.0（安定版）
- 概要: Python の型安全なエージェントフレームワーク Pydantic AI の安定版。**外部の持続実行（durable execution）エンジンを組み込むための公開 API** が入り、長時間・耐障害なエージェント実行を標準化しやすくなった。
- 何が便利か:
  - **`@durable_operation` デコレータ**: 任意の処理を持続実行の「オペレーション」として宣言でき、**サードパーティの durable execution エンジン向けの公開バックエンド API** が用意された。Temporal / Prefect / DBOS のような外部エンジンを、フレームワーク統一の作法で接続できる。**明示的なオペレーション名の指定が必須**。
  - **`InstructionPart.id` の安定 ID**: 指示（instruction）パートに**安定した ID** が付与され、再実行やトレースでの追跡・突き合わせがしやすい。
  - **`RealtimeSession.send_audio()` が async イテラブルを受理**: 音声をストリームで逐次送出でき、リアルタイム音声エージェントの実装が素直になる（音声サンプルも移設）。
  - **CLI（`clai`）強化**: **MCP 設定サポート**と**ツール呼び出しストリーミング**を追加。ターミナルから MCP サーバを設定しつつ、ツール実行の進行を逐次確認できる。
  - **バグ修正**: `TestModel` の狭い排他的数値境界での生成を改善、素の `ToolDefinition` の Prefect キャッシュキーへの射影を修正。
- 使いどころ:
  - **中断・再開に耐えるエージェント**（長時間タスク、外部イベント待ち、ワークフロー分割）を Temporal/Prefect などの上で走らせたいとき。
  - **リアルタイム音声エージェント**を async ストリームで実装したいとき。
  - `clai` から **MCP サーバを試しつつツール実行を観察**したいとき。
- 開発者にとっての価値: `pip install -U pydantic-ai` で今日すぐ試せる安定版。持続実行の「接続口」が公式 API 化されたことで、耐障害なエージェント基盤を**特定ベンダにロックインされず**構築しやすくなる。
- 注意点: `@durable_operation` は**オペレーション名の明示が必須**になった点に注意（旧コードからの移行時に確認）。実際の耐障害保証は接続する外部エンジン側の機能に依存する。
- 公式リンク: https://github.com/pydantic/pydantic-ai/releases/tag/v2.36.0
- 参考リンク: https://github.com/pydantic/pydantic-ai/releases / https://ai.pydantic.dev/
- メモ: NewsRepository の既存 ai-tools 記事に Pydantic AI / `@durable_operation` の記載なし（新規）。

#### 使用例

```bash
# 導入・更新
pip install -U pydantic-ai
python -c "import pydantic_ai; print(pydantic_ai.__version__)"  # 2.36.0

# CLI（MCP 設定・ツール呼び出しストリーミング対応）
clai --help
```

### 3. LiteLLM / v1.100.0-rc.1（エージェントレジストリの意味検索・MCP セッション署名）

- 種別: OSS ライブラリ／ゲートウェイ（Python／pre-release・RC）
- 関連: LiteLLM / OpenRouter 的ゲートウェイ / MCP
- 公開・更新日: 2026-08-30 03:26 UTC（JST 2026-08-30 12:26）※ v1.100.0-rc.1（pre-release）
- 概要: 多数の LLM プロバイダを OpenAI 互換 API で束ねる LiteLLM の、新 `v1.100.0` ラインの RC。ゲートウェイ運用・エージェント管理まわりに実務的な追加が入った。前回（08-30）は `v1.100.0-dev.2` の dev のみだったが、今回は **RC まで前進**。
- 何が便利か:
  - **エージェントレジストリの意味検索**: `GET /v1/agents?query=...` で**登録エージェントを意味検索**できる。エージェントが増えたときの発見性が上がる。
  - **`/public/v1/model_hub` のページネーション付き GET**: モデル一覧を**ページ単位で取得**でき、大量モデルを扱う UI/自動化に効く。
  - **Anthropic thinking ブロックの自動修復**: `/v1/messages` で**空の thinking ブロックを落として自己修復**。推論系モデルの応答不整合を吸収。
  - **複雑度ルータの最適化**: **client housekeeping 呼び出しを最安ティアへ**振り分け。オートルータの UI からカスタム分類ティアを編集可能。
  - **予算・セキュリティ**: `LiteLLM_BudgetWindowSpend` テーブルで**ウィンドウ単位の予算消費**を追跡、モデルアクセスグループへの共有予算適用。**MCP ゲートウェイのセッショントークンに非対称署名（RS256）**、CyberArk Conjur 連携、Anthropic MCP コネクタの一括インポート。
- 使いどころ:
  - 複数モデル・複数エージェントを**ゲートウェイ集約**し、コスト・予算・アクセスを一元管理したいとき。
  - **MCP ゲートウェイを RS256 署名で安全に運用**したいエンタープライズ構成。
  - Anthropic 推論系モデルの**応答不整合を吸収**したいとき。
- 開発者にとっての価値: `pip install litellm==1.100.0rc1` で検証導入でき、ゲートウェイ運用の実利ある機能を先取りできる。エージェントレジストリ検索・予算ウィンドウ・MCP 署名は、AI をチーム／本番で回す運用チームに効く。
- 注意点: **RC（pre-release）** のため本番投入は要検証。安定版は前回採用の `v1.98.0`（08-23）で、`.100` ラインはまだ安定版が出ていない。導入時はバージョン固定を推奨。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.100.0-rc.1
- 参考リンク: https://github.com/BerriAI/litellm/releases / https://docs.litellm.ai/
- メモ: 過去記事では LiteLLM の dev/rc ラインは調査メモ止まりが多かったが、今回は `.100` ラインの新機能（エージェントレジストリ意味検索・MCP セッション署名）が実利ある新規性のため本文採用（RC 明記）。

#### 使用例

```bash

pip install "litellm==1.100.0rc1"

# ゲートウェイ起動後、エージェントレジストリを意味検索
curl "http://localhost:4000/v1/agents?query=code%20review" \
  -H "Authorization: Bearer $LITELLM_API_KEY"
```
