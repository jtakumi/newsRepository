## 今日の注目

### 1. Cline / 拡張 v4.1.3・CLI v3.0.49・Desktop v0.0.8・SDK v0.0.68〜v0.0.69

- 種別: VS Code 拡張 ／ CLI ／ Desktop ／ SDK（安定版）
- 関連: Cline
- 公開・更新日: 拡張 v4.1.3 = 2026-08-02（05:41 UTC / JST 14:41）、Desktop v0.0.8 = 05:04 UTC（JST 14:04）、CLI v3.0.49 = 04:52 UTC（JST 13:52）、SDK v0.0.69 = 04:26 UTC（JST 13:26）、SDK v0.0.68 = 08-01 05:29 UTC（JST 14:29）
- 概要: チェックポイント（作業復元）まわりを大きく作り直し、会話分岐・巻き戻し・エラー表示を実運用水準に引き上げた一連の同日更新。
- 何が便利か:
  - **真のワークスペース巻き戻し（true workspace rewinding）**: チェックポイント復元時に、**タスク中に新規作成されたファイルまで含めて**ワークスペースを巻き戻す。これまで取りこぼしていた「新規ファイル」を正しく戻せる。
  - **メッセージ編集による会話分岐（Desktop v0.0.8）**: 過去のメッセージを編集して会話を fork し、そこからワークスペースごと巻き戻して別案を試せる。
  - **`/undo` がツール使用と併用しても正しく動作（CLI v3.0.49）**: これまで tool 使用が絡むと不安定だった取り消しが安定。
  - **上流プロバイダの実エラーを表示（SDK v0.0.68）**: 汎用的なダンプではなく、実際のプロバイダのエラーメッセージを見せる。原因切り分けが速くなる。
  - **Ollama のタイムアウトを 5 分に延長（SDK v0.0.69）**: 大きいモデルのロード時にタイムアウトで失敗しにくくなる。モデル境界での空応答はリトライ。
  - Windows PowerShell が UTF-8 stdin を使うようになり、非 ASCII 入力・長いコマンドに対応（SDK v0.0.68）。
- 使いどころ:
  - 大きめの改修で「途中まで戻して別方針」をワークスペースごとやり直したいとき（新規ファイルの取りこぼしなし）。
  - ローカル Ollama の大型モデルを Cline から使っていて、ロード待ちでタイムアウトしていたケース。
  - CLI で `/undo` を多用する自動化・対話フロー。
- 開発者にとっての価値: **「試す→戻す→分岐する」というエージェント編集の中核操作**が信頼できる水準になり、失敗を恐れず大きめの変更をエージェントに任せやすくなる。エラー可視化とローカルモデル対応の改善も日常運用に直結。
- 注意点: 拡張は前回 v4.1.0 からの段階ロールアウト（Legacy／Next の A/B）の系譜。どの系統が有効かは設定画面で確認できる。SDK の一部は API 変更の可能性がある実装更新を含む。
- 公式リンク: https://github.com/cline/cline/releases/tag/v4.1.3
- 参考リンク: https://github.com/cline/cline/releases
- メモ: 前回（08-01）記事は拡張 v4.1.2・CLI v3.0.48・SDK v0.0.67 まで。今回は v4.1.3／CLI v3.0.49／Desktop v0.0.8／SDK v0.0.68〜0.0.69 を新規採用。

#### 使用例

```bash
# VS Code 拡張はマーケットプレイスから自動更新。
# CLI の更新
npm install -g @cline/cli

# CLI 上で直前の変更を取り消す（ツール使用込みでも動作）
/undo
```

### 2. llama.cpp / b10227〜b10232（DeepSeek V4 対応ほか）

- 種別: OSS（ローカル推論エンジン）
- 関連: ローカル LLM関連ツール
- 公開・更新日: 2026-08-02（b10227 = 09:43 UTC / JST 18:43、b10228 = 13:28 UTC、b10232 = 18:57 UTC）
- 概要: 新アーキテクチャ対応とチャットパーサ強化を同日ビルドでまとめて投入した更新。
- 何が便利か:
  - **DeepSeek V4 アーキテクチャの実装**: MTP（Multi-Token Prediction）と DSpark を実装し、**Metal 向けに hyper-connections を SIMD グループ最適化**。Apple シリコンでの DeepSeek V4 系ローカル推論の下地が入った。
  - **Qwen3 専用チャットパーサ（b10227）**: **タグ付き thinking とツール呼び出し**をパースできる。ローカルの Qwen3 でツール実行・思考分離を扱いやすくなる。
  - **DSpark サイドカーの自動発見（b10231）**: 投機デコード用のスペキュレイティブ・サイドカーモデルを自動選択。手動指定の手間が減る。
  - あわせて OpenCL（GLU のローカルワークグループサイズ制限）や SYCL（iGPU 判定修正）などバックエンド最適化も継続。
- 使いどころ:
  - Apple シリコンや各種 GPU で DeepSeek V4 系・Qwen3 系のモデルをローカルで動かしたいとき。
  - ローカル LLM でツール呼び出し（関数実行）や thinking 分離を使うエージェント構成を組むとき。
- 開発者にとっての価値: クラウド API に依存せず、**最新アーキテクチャのモデルを手元で検証・組み込みできる**。プライバシー要件やコスト制約のあるローカル推論ワークフローに直接効く。
- 注意点: llama.cpp は日次で多数のビルド（bXXXXX）が出る。特定モデルの動作は量子化・モデルファイル側の対応にも依存するため、実モデルで要検証。DeepSeek V4 対応は実装直後のため挙動確認を推奨。
- 公式リンク: https://github.com/ggml-org/llama.cpp/releases
- 参考リンク: https://github.com/ggml-org/llama.cpp
- メモ: 過去記事では Ollama のエンジン更新の文脈で llama.cpp に言及済み（07-24）だが、llama.cpp 単体の DeepSeek V4／Qwen3 パーサ対応は今回が新規。

#### 使用例

```bash

git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build && cmake --build build --config Release

# 推論（GGUF モデルを指定）
./build/bin/llama-cli -m ./models/your-model.gguf -p "hello"
```

### 3. opencode / v1.18.11
