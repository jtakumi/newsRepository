### 3. OpenAI Codex / rust-v0.149.1（安定版が前進）

- 種別: CLI（ターミナル・コーディングエージェント／安定版）
- 関連: OpenAI / Codex
- 公開・更新日: 2026-08-24 UTC（JST 2026-08-24〜25）
- 概要: 前回記事の安定版 rust-v0.148.0 から rust-v0.149 系へ安定版が前進。スレッド分類オプションの追加と、compaction（履歴圧縮）での画像予算計上の修正が入る。
- 何が便利か:
  - **`codex exec --thread-source <SOURCE>` グローバルオプション**: `codex exec` で新規作成・フォークするスレッドの「発生源」を分類できる（省略時は `user`）。自動化やメモリ統合（`memory_consolidation`）など、**呼び出し元をメタデータで区別したいスクリプト運用**で役立つ。
  - **リモート compaction の画像予算計上修正**: 画像の多い履歴が予算計算からこぼれて文脈を抱え込みすぎる問題を修正。切り詰め時に**画像をアトミックに保つ**オプションも追加され、長い会話でのコンテキスト管理が読める挙動に近づく。
- 使いどころ:
  - `codex exec` を **CI やバッチから呼び出し**、ユーザ起点／自動起点のスレッドをメタデータで仕分けたいとき。
  - スクリーンショットや図を多く貼る作業で、**compaction 後にコンテキストが膨らむ**挙動に悩んでいたケースの検証。
- 開発者にとっての価値: `codex exec` の非対話実行は自動化に組み込みやすく、`--thread-source` はスレッドの由来をログ・メトリクスで追跡する足がかりになる。安定版ラインでの提供なので本番運用にも載せやすい。
- 注意点: 窓内には alpha ライン（0.150.0-alpha.x）も併走しているが、本項は**安定版 rust-v0.149.1** を採用。リリースページ本文が比較生成待ちで全文取得しづらく、要約は commit 差分ベース。詳細は各自公式で確認のこと。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.149.1
- 参考リンク: https://github.com/openai/codex/releases / https://github.com/openai/codex/compare/rust-v0.149.0...rust-v0.149.1
- メモ: 前回記事は安定版 rust-v0.148.0 を採用済み。0.149 系への安定版前進を新規採用。

#### 使用例

```bash

npm install -g @openai/codex
codex --version

# スレッドの発生源を分類して非対話実行（例）

```

### 5. LiteLLM / v1.98.0（安定版が前進）

- 種別: OSS／LLM ゲートウェイ・プロキシ（安定版）
- 関連: LiteLLM / OpenRouter 的なマルチプロバイダ・ルーティング
- 公開・更新日: 2026-08-23 UTC（JST 2026-08-23〜24）
- 概要: 前回記事時点で据え置きだった安定版が v1.97.0 から v1.98.0 へ前進。長時間ストリームの安定化、ルーティングの露出、コスト計上まわりの更新が中心。
- 何が便利か:
  - **デプロイ単位の keepalive SSE ハートビート**: `keepalive_seconds` で長いストリーム中に heartbeat を送り、**ロードバランサのアイドル・タイムアウトによる切断を防ぐ**。長い生成やエージェント実行をプロキシ越しに流す構成で効く。
  - **ルーティンググループを仮想モデルとして露出**: ルーティンググループを仮想モデルとして呼び出し、`/v1/models` にも列挙できる。**クライアントからは単一モデル名で叩ける**抽象化になる。
  - **キー単位の prompt caching トグル**: `enable_prompt_caching` をキー単位で切り替え、キャッシュ書き込みプレミアムを差し引いた**正味の節約額**を計上。コスト最適化の可視化が進む。
  - **PTU（プロビジョンドスループット）コスト対応**: モデルデプロイごとの定額コストを設定し、アクティブ時間単位で日次ロールアップ。UI にも表示。
- 使いどころ:
  - 複数 LLM プロバイダを **1 ゲートウェイに集約**し、ロードバランサ越しの長時間ストリームで切断に悩んでいる構成。
  - キー単位でキャッシュや予算を管理し、**チーム／タグ別にコストを追跡**したい運用。
- 開発者にとっての価値: セルフホストの LLM ゲートウェイとして、`pip install litellm` または Docker で導入でき、OpenAI 互換 API でマルチプロバイダを束ねられる。今回の更新は本番運用の安定性とコスト可視化に直結する。
- 注意点: 公開は JST 08-23〜24 で、直近 24〜48 時間の縁にあたる（新しめの stable として採用）。窓内には v1.99.0-rc.1／dev 系も併走するが、本項は**安定版 v1.98.0** を採用。Day-0 対応モデル名などリリースノートの一部表記は公式で最終確認のこと。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.98.0
