# 2026-08-08 AI Tools News

## 今日の要点

- Claude Code `v2.1.225` が公開。ゲートウェイの**支出上限（spend limit）**を使用量警告に反映し、`claude agents` に未信頼ディレクトリ向けのワークスペース信頼プロンプトを追加。長期トークン（`CLAUDE_CODE_OAUTH_TOKEN`）が一時的な 401 で置き換えられ、ヘッドレスセッションが壊れる問題などを修正。

## 今日の注目

### 1. Claude Code / v2.1.225

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-08-07（UTC 23:08 / JST 08-08 08:08）
- 概要: `v2.1.224` の翌日に出た小規模更新。LLM ゲートウェイの支出上限に達した際のメッセージに、上限額・リセット時刻・運用者のメッセージを表示（ゲートウェイ側も 2.1.225 が必要）。`claude agents` が未信頼ディレクトリで信頼プロンプトを出すようになり、`claude` 本体と挙動が揃った。修正では、一時的な 401 で長期の `CLAUDE_CODE_OAUTH_TOKEN` が保存済みログインの短命トークンに置換されヘッドレスセッションが再起動まで壊れる問題、macOS で Keychain 読み取りがタイムアウトした後に MCP OAuth サーバーが 401 を連発する問題、auto モード自身の権限チェックが安全フィルタに拒否された場合の連続ブロック数カウント、Remote Control の大規模会話圧縮後の再開不具合を直した。SendMessage は Remote Control の他マシンのセッションへ、`ListAgents` に出る `name [ref]` で会話を開始できるようになった。
- 何が便利か: CI やヘッドレス実行で長期トークンが意図せず入れ替わる事故が減り、ゲートウェイ運用者は支出上限の到達を利用者に分かりやすく伝えられる。
- 使いどころ: ゲートウェイ経由で利用上限を管理している組織、長期 OAuth トークンで CI から Claude Code を動かす構成、macOS で MCP OAuth サーバーを多用する環境。
- 開発者にとっての価値: 無人運用での認証まわりの取りこぼし（401 でのトークン置換、Keychain タイムアウト）が直る。
- 注意点: 支出上限の表示はゲートウェイ側も `2.1.225` が必要。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.225
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 前日の `v2.1.224`（セルフホスト環境・クロスセッション連携）と合わせて確認するとよい。
