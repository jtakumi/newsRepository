## 今日の注目

### 1. Ollama / v0.32.10（既定パラメータ変更・ローカル推論高速化）

- 種別: CLI／ローカル LLM ランタイム（安定版）
- 関連: Ollama / ローカルLLM / OpenAI 互換 API
- 公開・更新日: 2026-08-13 18:32 UTC（JST 08-14 03:32）
- 概要: モデル既定の生成パラメータを見直し、MLX 系の推論性能を改善した安定版。
- 何が便利か:
  - **`repeat_penalty` の既定値を 1.1 → 1.0 に変更**: モデル側で明示していない場合の既定を他エンジンに合わせた。反復抑制の強さが変わるため、これまでの出力傾向が変化しうる。
  - **NVFP4 の MLX モデルで prefill が約 7〜8% 高速化**: Apple Silicon 上での初回応答（プロンプト処理）が速くなる。
  - **OCI マニフェストのダイジェスト共有時の検証バグを修正**: 同一ダイジェストを共有するイメージの取得・検証が安定。
- 使いどころ: コーディングエージェントや RAG のバックエンドにローカルモデルを使う構成。アップグレード後は、繰り返し・冗長さが増減していないかを実タスクで確認する。
- 開発者にとっての価値: 既定変更は「上流を変えていないのに出力が変わる」典型例。ローカル LLM を業務フローに組み込んでいる場合、リグレッション確認の実務ポイントになる。
- 注意点: 旧来の挙動に戻したい場合は、モデル単位で `repeat_penalty` を明示指定する（例: Modelfile の `PARAMETER repeat_penalty 1.1` や API リクエストの `options`）。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.32.10
- 参考リンク: https://github.com/ollama/ollama/releases/tag/v0.32.9
- メモ: 本リポジトリは v0.32.9 まで採用済み。v0.32.10 を新規採用。

#### 使用例

```bash
# バージョン確認
ollama --version

# 旧挙動に合わせたい場合はモデル単位で明示（Modelfile）
cat > Modelfile <<'EOF'
FROM llama3.1
PARAMETER repeat_penalty 1.1
EOF
ollama create mymodel -f Modelfile

# API リクエストで一時的に上書き
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.1",
  "prompt": "簡潔に説明して",
  "options": { "repeat_penalty": 1.1 }
}'
```

### 2. Cline / v4.1.9・SDK v0.0.74・CLI v3.0.54・Desktop v0.0.12

- 種別: VS Code 拡張／CLI／SDK／デスクトップ（コーディングエージェント）
- 関連: Cline / Claude Code / Anthropic / Vertex
- 公開・更新日: SDK v0.0.74 = 2026-08-13 05:59 UTC（JST 14:59）、Desktop v0.0.12 = 05:52 UTC（JST 14:52）、CLI v3.0.54 = 06:19 UTC（JST 15:19）、v4.1.9 = 07:40 UTC（JST 16:40）
- 概要: SDK の Claude Code プロバイダ強化とトークン計測の正確化を中心とした複数サーフェスの同時更新。

  - v4.1.9 では diff 表示に「エディタの前景色」を使用し、フォントを Inter／Geist Mono に統一。長時間アイドル後のトークンリフレッシュ不具合も修正。
- 使いどころ: Cline を自前の CI／自動化に SDK/CLI で組み込むケース、Claude Code をバックエンドに使う構成、トークン課金を精緻に把握したいチーム。
- 開発者にとっての価値: 計測の正確化は「見かけのコスト」ではなく「実コスト」を把握できる点で実務的価値が高い。SDK/CLI/拡張でバージョンが分かれるため、組み合わせを揃えると挙動が安定する。
- 注意点: SDK・CLI・拡張・デスクトップで版が別管理。自動化に組み込む場合はバージョンの整合を確認する。
