# 2026-08-07 AI Tools News

## 今日の要点

- **Claude Code v2.1.223（JST 2026-08-06 公開）** が安定版で登場。19 件の CLI 変更のうち複数が**セキュリティ修正**で、特に **Bash 権限チェックをすり抜ける細工コマンド**、**不可視 Unicode で承認プロンプトの内容を隠す問題**、**workflow スクリプトが動的 `import()` でサンドボックスを脱出できた問題**、**エージェント定義の `bypassPermissions` が組織ポリシーの無効化設定を無視していた問題**を修正。あわせて **`/review` を `/code-review` のエイリアス化（PR レビュー対応）** など実用改善も入っており、既存ユーザは早めの更新が望ましい。前回記事（08-06）は v2.1.222 までの採用だったため新規採用。
- **Gemini CLI v0.54.0（JST 2026-08-06 01:35、初の 0.54 系安定版）** を初採用。**モデルフォールバック時のセッション ID ローテーション**、**資格情報の HTTPS 強制**、**thought パートのフィルタリング／改行正規化の修正**が中心。これまで本リポジトリでは v0.54.0 は preview / nightly のみで見送っていたため、安定版として今回採用。
- **Cline v4.1.6 / SDK v0.0.71 / CLI v3.0.51（いずれも JST 2026-08-06）** が公開。**推論（reasoning）設定を全プロバイダで一貫化**し、従来の「プロバイダごとの thinking オーバーライド」を廃止。effort レベルと有効/無効フラグを各社（Ollama 含む）のネイティブ機能へマッピングし、テレメトリの誤帰属も修正。前回は v4.1.4 / v4.1.5 まで採用済みで、SDK / CLI 側の一貫化が今回の主眼。
- 開発者向けエコシステムでは、**GitHub Copilot cloud agent にタスク委譲時の reasoning level 選択（JST 2026-08-03）** と、**OpenAI「Sign in with ChatGPT」ベータ（2026-08-02 開始、Vercel / Supabase などパートナーで順次拡大）** が引き続き注目。いずれも直近 48 時間の外だが本リポジトリ未採用かつ開発者価値が高いため採用し、日付を明記した。
- 継続更新として **OpenAI Codex 0.146.1（安定版）と 0.147.0-alpha 系**、**opencode v1.18.14**、**Ollama v0.32.6**、**LiteLLM は v1.95.0 が最新安定版（v1.96.0 は RC 止まり）** は既採用または未確定のため調査メモに記載。

## 今日の注目

### 1. Claude Code / v2.1.223

- 種別: CLI（ターミナル・コーディングエージェント／安定版）
- 関連: Anthropic / Claude / Claude Code
- 公開・更新日: JST 2026-08-06
- 概要: 19 件の変更を含む安定版。セキュリティ修正が中心で、権限チェックやサンドボックス境界の抜け穴を複数ふさいだ。あわせて `/review` を `/code-review` のエイリアスにして PR レビューへ対応、`/code-review` は前回の effort レベルを既定で再利用するようになった。
- 何が便利か: 権限バイパス系の脆弱性が複数修正され、エージェントに広い権限を与えて運用している環境ほど恩恵が大きい。`/review` で PR を直接レビューでき、レビュー動線が短くなる。marketplace 設定で `"owner/*"` のワイルドカード一括許可/ブロックが可能に。
- 使いどころ: 自動化・背景セッション・サブエージェントを多用する CI/日常運用での安全性向上。PR レビューを Claude Code に任せる運用。
- 開発者にとっての価値: 「細工した Bash コマンドが権限チェックから一部を隠す」「不可視 Unicode で承認プロンプトを偽装」「workflow が動的 `import()` でサンドボックス脱出」「`bypassPermissions` が組織の無効化ポリシーを無視」といった、権限モデルの信頼性に関わる修正。セキュリティ更新として扱う価値が高い。
- 注意点: 権限まわりの挙動が変わるため、独自のフック/権限設定を持つ環境は更新後に一度動作確認を推奨。コミュニティでは「Permission Bypass Regression Checklist」など回帰確認の話題も出ている（参考リンク）。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md ／ https://code.claude.com/docs/en/changelog
- 参考リンク: https://dev.to/ahab_indieseek/claude-code-21223-permission-bypass-regression-checklist-58n9
- メモ: 日付は公開告知（ClaudeCodeLog 等）に基づく。CHANGELOG 本体には日付表記がないため公開日は二次情報で確認。

#### 使用例

```bash
# 更新
claude update            # もしくは
npm i -g @anthropic-ai/claude-code

# PR をそのままレビュー（/code-review のエイリアス）
/review
```

### 2. Gemini CLI / v0.54.0

- 種別: CLI（安定版・OSS）
- 関連: Google / Google AI / Gemini CLI
- 公開・更新日: JST 2026-08-06 01:35
- 概要: 0.54 系として初の安定版。モデルフォールバック時にセッション ID をローテーション、資格情報通信の HTTPS 強制、thought パートのフィルタリング不具合と改行正規化の修正などを含む。
- 何が便利か: フォールバック（容量枯渇や一時エラー時の別モデル切替）まわりの堅牢性が上がり、長時間セッションでの取り違えや無限リトライを避けやすくなる。資格情報の HTTPS 強制はセキュリティ面の底上げ。
- 使いどころ: Gemini を CLI からスクリプト/自動化で常用している環境の安定版更新。
- 開発者にとっての価値: preview / nightly を避けて安定版で運用したい層向けに、フォールバック・セッション管理の改善が正式版に入った。
- 注意点: 直後に v0.55.0-preview.1 も出ているが、こちらはプレリリースのため常用は非推奨。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.54.0
- メモ: 本リポジトリの安定版採用は v0.53.x 以来。v0.54.0-preview 系は過去記事で見送り済み。

#### 使用例

### 3. Cline / v4.1.6・SDK v0.0.71・CLI v3.0.51

- 種別: 拡張機能（VS Code）＋ SDK ＋ CLI
- 関連: Cline
- 公開・更新日: JST 2026-08-06
- 概要: 推論設定（effort レベルと有効/無効フラグ）を全プロバイダで一貫化。従来の「プロバイダごとの thinking オーバーライド」を廃止し、各社（Ollama を含む）のネイティブ reasoning 機能へ統一マッピング。テレメトリのモデル誤帰属を修正。`meta/muse-spark-1.2-contributor` モデルにも対応。
- 何が便利か: プロバイダを乗り換えても reasoning の指定方法が変わらず、設定の使い回しが効く。無料モデルの提供終了時には汎用エラーではなく「別モデルを選ぶボタン付きの通知」が出る（v4.1.5）。
- 使いどころ: 複数プロバイダ（クラウド + ローカル Ollama など）を切り替えて Cline を使う開発ワークフロー。
- 開発者にとっての価値: reasoning の効き方をプロバイダ横断で揃えられるため、モデル比較や自動化での再現性が上がる。
- 注意点: 個々の変更はインクリメンタル。VS Code 拡張・SDK・CLI で版番号が別系統なので、使っている入口ごとに更新確認が必要。
- 公式リンク: https://github.com/cline/cline/releases
- 参考リンク: https://github.com/cline/cline/releases/tag/v4.1.6
- メモ: 前回記事では v4.1.4 / v4.1.5 まで採用。今回は SDK/CLI 側の reasoning 一貫化が新規点。

### 4. Sign in with ChatGPT（ベータ）

- 種別: API / 認証（クロスプラットフォーム ID）
- 関連: OpenAI / ChatGPT / Codex
- 公開・更新日: 2026-08-02 ベータ開始（以降パートナーで順次拡大）
- 概要: OpenAI 初のクロスプラットフォーム ID。ユーザが対応サービス上で「Sign in with ChatGPT」を押すと、少ない手順でアカウント作成/連携ができる。ローンチ時のパートナーは Airtable / GitLab / HubSpot / Notion / Supabase / Vercel。連携アプリには名前・メールアドレス・プロフィール画像が渡される。
- 何が便利か: ChatGPT / Codex から対応サービスへの接続がスムーズになり、ユーザのアカウント作成の摩擦が減る。プラグインディレクトリ経由でもパートナーサイト上でも利用可能。
- 使いどころ: 自社サービスへの「ChatGPT でサインイン」導線を（現状はパートナー枠として）検討する場面。ChatGPT/Codex ワークフローと外部 SaaS を横断させたいケース。
- 開発者にとっての価値: OAuth 系の追加ログイン手段として、ChatGPT ユーザ基盤に対する導線を用意できる。Vercel / Supabase が既に統合しており、実装リファレンスとして参照しやすい。
- 注意点: **ユーザの実メールがデフォルトで共有される**点はプライバシー上の考慮が必要。まだベータで対応先はパートナー中心。公開が 08-02 で本記事の 24〜48 時間窓の外である点に注意（未採用かつ開発者価値が高いため採用）。
- 公式リンク: https://vercel.com/changelog/sign-in-with-chatgpt-is-now-available-on-vercel ／ https://supabase.com/blog/sign-in-with-chatgpt-beta
- 参考リンク: https://www.techtimes.com/articles/322791/20260803/sign-chatgpt-launches-what-openai-retains-not-what-gets-shared.htm
- メモ: OpenAI 公式ヘルプ（ChatGPT release notes）でも「Sign in with ChatGPT beta を一部プラグイン/パートナーで開始」と告知。

### 5. GitHub Copilot cloud agent / reasoning level 選択

- 種別: Web サービス機能（SaaS）
- 関連: GitHub Copilot
- 公開・更新日: JST 2026-08-03
- 概要: Copilot cloud agent にタスクを委譲する際、対応モデルの reasoning level（推論量）を選べるようになった。モデル選択と同じタイミングで指定し、その実行に適用される。
- 何が便利か: 複雑な課題では高レベルで精度を上げ、単純な作業では低めに抑えてトークン/クレジット消費を節約する、という制御ができる。
- 使いどころ: Copilot にバックグラウンドでコーディングタスクを委任する運用で、タスクの難易度に応じてコストと品質を調整する場面。
- 開発者にとっての価値: エージェント委譲のコスト/品質トレードオフを実行単位で調整可能に。
- 注意点: 高レベルはトークン（=クレジット）消費が増える。対象は Copilot Pro / Pro+ / Business / Enterprise / Max の有料プラン。公開が 08-03 で 24〜48 時間窓の外（未採用のため採用）。
- 公式リンク: https://github.blog/changelog/2026-08-03-customize-the-reasoning-level-for-copilot-cloud-agent/
- 参考リンク: https://github.blog/changelog/
- メモ: 併せて GitHub は 2026-07-31 に Gemini 2.5 Pro / Gemini 3 Flash を全 Copilot 体験で非推奨化している（仕様変更として参考）。
