### 1. Claude Code / v2.1.233・v2.1.234

- 種別: CLI（ターミナル・コーディングエージェント／安定版）
- 関連: Anthropic / Claude / Claude Code
- 公開・更新日: v2.1.233 = 2026-08-14 22:20 UTC（JST 08-15 07:20）、v2.1.234 = 2026-08-17 20:20 UTC（JST 08-18 05:20）
- 概要: GitLab 連携の追加、利用上限リセット時のセッション自動継続、Windows パス経由の資格情報漏えい対策、多数の運用性改善とクラッシュ修正を入れた安定版の連続更新。
- 何が便利か:
  - **GitLab マージリクエスト連携（v2.1.233・v2.1.234）**: フッター／ステータスラインに `MR !N` バッジ（draft／pending／green の状態表示）を追加。`--worktree` フラグと `claude agents` ビューが GitLab MR の URL を受け付けるように。GitHub だけでなく GitLab を使うチームでも、MR 状態を見ながら作業できる。
  - **利用上限リセット時のセッション自動継続（v2.1.234）**: claude.ai の使用量上限に達しても、リセット後に自動でセッションを続行（`/config` で設定）。上限で作業が止まる待ち時間を減らせる。
  - **NT 名前空間パス拒否のセキュリティ強化（v2.1.234）**: リモートファイル読み込み・セッション復元・CLAUDE.md インクルード・ワークフロースクリプト・ファイルアップロードで Windows の `\??\` パスを拒否。v2.1.233 で塞いだ UNC 検証すり抜け（NTLM 資格情報漏えいの経路）をさらに広範に強化。
  - **`claude-api` スキルのコンテキストコスト削減（v2.1.234）**: 約 200k → 約 25k トークンへ。Claude API を扱う作業でスキル読み込みの負担が大幅に軽くなる。
  - **Linux の Bash コマンドにメモリ cgroup（opt-in、v2.1.233）**: `CLAUDE_CODE_TOOL_MEMORY_LIMIT` でツール実行のメモリ上限を設定でき、暴走コマンドがマシンを圧迫するのを抑えられる。
  - そのほか、`CLAUDE_CODE_PROJECT_DIR_NAME`（プロジェクト別トランスクリプトディレクトリ）、`/permissions`・`/add-dir` を作業中に開けるように、Remote Control のファイルアップロード修正、多数のクラッシュ・描画修正。
- 使いどころ:
  - **GitLab を使うチーム**が、CI/MR の状態を Claude Code のフッターで確認しながらエージェント作業を回すケース。
  - **利用上限に当たりやすい長時間・大量タスク**を、途中で止めずに回したい個人・チーム。
  - Windows・企業環境で **資格情報漏えいリスクを気にする運用**。
- 開発者にとっての価値: `npm i -g @anthropic-ai/claude-code` の 1 コマンドで更新でき、GitLab 連携・上限リセット自動継続・セキュリティ強化・スキルの軽量化と、日常運用に効く改善がまとまっている。特に **NT パス拒否は実害（NTLM 漏えい）に直結する修正**で、Windows 利用者は早めの更新が望ましい。
- 注意点: 利用上限リセット時の自動継続は既定挙動が変わるため、意図せぬ継続実行を避けたい場合は `/config` を確認。GitLab 連携はリポジトリのリモート設定に依存する。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.234
- 参考リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.233 / https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- メモ: 本リポジトリは v2.1.229（JST 08-13）まで採用済み。v2.1.233・v2.1.234 をまとめて新規採用。

- 関連: Ollama / Qwen / ローカルLLM / エージェント
- 公開・更新日: v0.32.12 = 2026-08-14 16:37 UTC（JST 08-15 01:37）、v0.32.13 = 2026-08-14 19:16 UTC（JST 08-15 04:16）、v0.32.14 = 2026-08-15 19:41 UTC（JST 08-16 04:41）

### 3. LiteLLM / v1.97.0

- 種別: OSS（LLM ゲートウェイ／プロキシ・Python SDK）
- 関連: OpenAI / Anthropic / Vertex AI ほかマルチプロバイダ・Cursor・MCP
- 公開・更新日: 2026-08-16 02:51 UTC（JST 08-16 11:51、安定版）
- 概要: 100 以上の LLM プロバイダを OpenAI 互換の単一 API で束ねるゲートウェイの更新。Cursor 連携、ルーティングの可観測性、UI、認証・性能の強化が中心。
- 何が便利か:
  - **Cursor 連携（`/cursor/chat/completions`）**: Cursor のモデル名サフィックスを解決し、解決後の Cursor モデル変種に対して予算（budget）を強制。Cursor 経由の利用もゲートウェイのコスト管理に載せられる。
  - **Auto-Router の節約額トラッキング**: コスト最適化ダッシュボードに Auto-Router による節約分を表示。ルーティングの費用対効果が可視化される。
  - **Playground の非ストリーミング応答トグル**: 管理 UI で応答をストリーミングせず一括受信に切り替え可能。デバッグ・検証がしやすい。
  - **性能・DB 改善**: Redis 接続に hiredis C パーサを採用、フィルタされたログのメッセージ構築を遅延化、ツール呼び出し引数の組み立てを線形時間化、MCP セッショントークンを共有ストレージ経由でルーティング。
  - **認証・セキュリティ**: 既存ユーザの null な user_email を JWT 認証でバックフィル、リクエストログからの資格情報ヘッダーの秘匿、OAuth2 エンタープライズゲートの 403 応答。
  - **モデル追加**: `gemini-robotics-er-2-preview` ／ `gemini-robotics-er-1.6-preview`。
- 使いどころ:
  - **Cursor を含む複数の利用経路を 1 ゲートウェイに束ね、予算・コストを一元管理**したいチーム。
  - Auto-Router でモデルを自動振り分けしつつ、**節約効果を数値で確認**したいプラットフォーム運用。
- 開発者にとっての価値: `pip install litellm` で入り、プロキシとしてもライブラリとしても使える。アプリ側を OpenAI SDK のまま保ち、裏のプロバイダ・経路（Cursor 含む）を差し替え・多重化しつつ、コストとルーティングを可視化できるのが実用的。
- 注意点: Cursor 連携や一部認証・予算機能は運用構成に依存。既存の予算・ルーティング設定を使っている場合は更新後の挙動を確認すること。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.97.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 前回採用の v1.96.0（JST 08-11）からの更新。プレリリース v1.98.0-rc.1（JST 08-16）も並行して進行中のため安定版 v1.97.0 を優先採用。

#### 使用例

```bash

pip install litellm

# プロキシとして起動（OpenAI 互換エンドポイントを提供）
litellm --config config.yaml

# アプリ側は OpenAI SDK のまま base_url を差し替えて利用
#   base_url="http://localhost:4000"
```
