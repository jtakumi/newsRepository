### 1. Cline / v4.1.0〜v4.1.2（+ CLI v3.0.48 / SDK v0.0.67）

- 種別: VS Code 拡張 ／ CLI ／ SDK（安定版）
- 関連: Cline
- 公開・更新日: 拡張 v4.1.0 = 2026-07-31（04:00 UTC / JST 13:00）、v4.1.1 = 04:30 UTC、v4.1.2 = 05:23 UTC。CLI v3.0.48 = 01:22 UTC（JST 10:22）、SDK v0.0.67 = 01:16 UTC（JST 10:16）
- 概要: 拡張の実装を **Legacy／SDK（Next）の 2 系統に切り替え可能**にし、CLI・SDK 側もセッション運用を強化した一連の更新。
- 何が便利か:
  - **Legacy と SDK ベースの拡張を 1 パッケージに同梱**: ウィンドウ単位で 1% から段階ロールアウトし、**新実装（Next）が起動に失敗したら自動で Legacy にフォールバック**。設定は両系統で共有。移行リスクを抑えつつ新実装を試せる。
  - **どの系統が有効か設定画面に表示（v4.1.2）**: 「Legacy」「Next」のどちらで動いているかが一目で分かる。不具合切り分けがしやすい。
  - **ネイティブ MCP のルーティングをサーバー名基準に（v4.1.1）**: 旧来のサーバーキー方式を廃し、**MCP サーバー再起動への耐性が向上**。
  - **SDK v0.0.67**: **セッション fork（分岐）API** を追加、推論制御を **models.dev カタログ**で正規化、**MCP サーバー単位のタイムアウト（1〜3600 秒、既定 60 秒）**を尊重、OpenRouter の既定を Claude Sonnet 5 に、Qwen・Moonshot・Z AI のエンドポイント切り替えを修正。
  - **CLI v3.0.48**: TUI に**履歴ナビゲーション（resume／delete）**を統合、コネクタスレッドが stale なバインディングから復帰。
- 使いどころ:
  - 新実装（Next）へ本格移行する前に、フォールバック付きで安全に試用する。
  - セッション fork API で「途中まで同じ、ここから別案」をプログラム的に分岐させる自動化を組む。
  - 複数 MCP サーバーを併用する構成で、遅いサーバーだけタイムアウトを個別調整する。
- 開発者にとっての価値: **拡張の作り替え（SDK ベース化）を段階ロールアウト＋自動フォールバックで進める**設計により、日常利用を止めずに新アーキテクチャへ移れる。CLI／SDK 側のセッション fork・MCP タイムアウト個別化は自動化ワークフローに直結。
- 注意点: v4.1.0 の段階ロールアウトは**リモート制御で 1% から**始まるため、全員がすぐ Next 版になるわけではない。SDK の fork API・experimental 系は API 変更の可能性がある。
- 公式リンク: https://github.com/cline/cline/releases/tag/v4.1.2
- 参考リンク: https://github.com/cline/cline/releases
- メモ: 前回（07-31）記事は拡張 v4.0.12・Desktop v0.0.7・CLI v3.0.47・SDK v0.0.66 まで。今回は v4.1.x／CLI v3.0.48／SDK v0.0.67 を新規採用。

### 2. GitHub Copilot CLI / v1.0.77

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-07-30（公式 changelog 日付）
- 概要: ログイン方式とサンドボックス管理を強化した更新。ブラウザ OAuth ログインを既定化した。
- 何が便利か:
  - **ブラウザベース（Web）OAuth ログインフロー**: `copilot login` がローカルの対話端末で**既定でブラウザ認証**に。トークンの手入力なしでログインできる。
  - **MDM によるサンドボックスポリシー強制**: **macOS / Windows のネイティブ MDM 設定**で managed サンドボックスポリシーを組織的に強制可能。企業配布での統制がしやすい。
  - **`Ctrl+G` で ask_user の自由記述をエディタ編集**: プロンプトを閉じずにエディタを開いて長文回答を編集できる。
  - **reasoning effort の省略を許可**: 明示しなければ**サーバーが既定値を選択**。モデル設定を簡素化できる。
  - autopilot の無条件承認時は、bypass 許可下で当該セッションのサンドボックスを無効化する挙動を追加。
- 使いどころ:
  - 端末での初回ログインを、トークン管理なしのブラウザ認証で済ませたいとき。
  - 組織で Copilot CLI を配布し、MDM でサンドボックスの実行制御を一括適用したいとき。
- 開発者にとっての価値: 導入の入口（ログイン）と運用統制（サンドボックス／MDM）が実務水準で整い、**個人の手軽さと企業の統制**の両方が前進した。
- 注意点: 公式 changelog は日付ベース（時刻表記なし）。MDM／サンドボックスの挙動は管理者ポリシー依存。autopilot の無条件承認は権限設定に注意。
- 公式リンク: https://github.com/github/copilot-cli/blob/main/changelog.md
- 参考リンク: https://github.blog/changelog/label/copilot/
- メモ: 前回（07-31）記事は v1.0.76（Sessions サイドバー／grok-4.5 対応）。今回はブラウザ OAuth ログイン既定化・MDM サンドボックスの v1.0.77 を新規採用。

#### 使用例

```bash
# 更新
npm install -g @github/copilot

# ブラウザ OAuth でログイン（対話端末では既定でブラウザが開く）
copilot login
```

### 3. Vercel AI SDK / ai@7.0.45

- 種別: OSS（TypeScript SDK）
- 関連: Vercel AI SDK
- 公開・更新日: 2026-07-31（17:46 UTC / JST 08-01 02:46）
- 概要: エージェント／テキスト生成のツール実行を差し替え可能にする実験的フックを追加した npm リリース。
- 何が便利か:
  - **`streamText` と `ToolLoopAgent` で `experimental_toolCallers` をサポート**: ツール呼び出しの実行主体（caller）を差し替えられる実験的 API。ツール実行のルーティングやラップを外側から制御できる。
  - **ストリーミング専用タイムアウトの誤用に警告**: `firstChunkMs`／`chunkMs`（ストリーミング用の設定）を非ストリーミングの `generateText` に渡すと警告を出す。設定ミスに早く気づける。
  - 直後の `ai@7.0.46`（JST 08-01 05:03）は依存更新（`@ai-sdk/gateway@4.0.35` など）中心のパッチ。
- 使いどころ:
  - エージェント（ToolLoopAgent）で、ツール実行にロギング・レート制御・サンドボックス等を挟みたいとき。
  - `streamText` を使うストリーミング UI でツール実行の挙動を細かく制御したいとき。
- 開発者にとっての価値: TypeScript でエージェントを組む際、**ツール実行レイヤに介入する拡張点**が公式に用意され、可観測性やガードレールの実装がやりやすくなる。
- 注意点: `experimental_` 接頭辞のとおり実験的 API で、今後の破壊的変更があり得る。本番投入は挙動をピン留めして検証してから。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.45
- 参考リンク: https://github.com/vercel/ai/releases ／ https://ai-sdk.dev/
- メモ: 前回記事では Vercel AI SDK は扱っていない。`experimental_toolCallers` 追加を含む 7.0.45 を新規採用。
