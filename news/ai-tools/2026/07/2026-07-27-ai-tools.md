## 今日の注目

### 1. Ollama / v0.32.4

- 種別: CLI / ローカル LLM ランタイム（OSS）
- 関連: Ollama / ローカルLLM / Apple MLX
- 公開・更新日: 2026-07-25（02:22 UTC / JST 11:22）
- 概要: ローカルで LLM を動かす Ollama の安定版アップデート。**Apple GPU 上で MLX エンジンを使う Laguna モデルのサポート**、**投機的デコードのドラフトモデル出力ヘッドの量子化**、**Qwen3 MoE デコードの修正と高速化**が入った。
- 何が便利か:
  - **Apple Silicon（MLX）で Laguna が動く**: Mac の GPU を MLX 経由で活かして対象モデルをローカル実行できる。
  - **投機的デコードのドラフトヘッドを要求型で量子化**: 投機的デコード利用時のメモリ／速度バランスを調整しやすくなる。
  - **Qwen3 MoE のデコード修正 + ~4〜9% 高速化（M5 Max 計測）**: 異なる量子化のエキスパートが混在する MoE でのデコード不具合を修正し、gate/up 射影のパック処理を高速化。
- 使いどころ:
  - Mac ローカルでコード補助・要約・分類などを回すオフライン／低コストなワークフロー。
  - Qwen3 MoE 系モデルをローカルで使っていて、デコードが不安定・遅かった環境の改善。
  - 投機的デコードでレイテンシを詰めたいローカル推論の検証。
- 開発者にとっての価値: `ollama` を更新するだけで、Apple GPU 対応と MoE デコードの安定化・高速化がそのまま効く。クラウド API を使わずに手元で試せるため、コストゼロで導入検証しやすい。
- 注意点: MLX 経由の Laguna サポートは **Apple GPU 環境が前提**。高速化の数値は M5 Max での計測で、環境によって差が出る。モデルの再取得が必要な場合がある。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.32.4
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 07-24 記事で扱った v0.32.3（ダウンロード stall 修正など）の次の安定版。v0.32.4 は未掲載のため新規採用。

#### 使用例

```bash
# 更新後にバージョン確認
ollama --version   # 0.32.4 であることを確認

# ローカルでモデルを取得して実行（例）
ollama pull qwen3
ollama run qwen3 "このコードのバグを指摘して"
```

### 2. Vercel AI SDK / プロバイダーパッケージ更新（@ai-sdk/anthropic@4.0.21 ほか）

- 種別: OSS ライブラリ（npm パッケージ）
- 関連: Vercel AI SDK / Claude / Anthropic / Amazon Bedrock
- 公開・更新日: 2026-07-26（02:52 UTC / JST 11:52）
- 概要: Vercel AI SDK の **プロバイダーパッケージ**が更新。Claude の推論（thinking）トークンの計測と、Bedrock 上での Claude ツール呼び出しに関する修正が入った。
- 何が便利か:
  - **`@ai-sdk/anthropic@4.0.21`: thinking トークンを reasoning トークン使用量として計上**。Claude の拡張思考を使うアプリで、使用量メトリクスが実態に合うようになる（コスト計測・トークン監視が正確に）。
  - **`@ai-sdk/amazon-bedrock@5.0.32`: Bedrock の Claude が拒否する `strict` / `output_config.format` をツール定義から除外**。Bedrock 経由の Claude でツール呼び出し（function calling）が通らなかった問題を回避。
  - **v3 系へのバックポート**（`@ai-sdk/anthropic@3.0.103`、`@ai-sdk/google-vertex@4.0.172`、`@ai-sdk/amazon-bedrock@4.0.142` など）も同時公開で、メジャーを上げずに同じ reasoning トークン修正を取り込める。
- 使いどころ:
  - AI SDK で Claude の thinking／reasoning を使い、トークン使用量やコストをダッシュボード化しているアプリ。
  - Amazon Bedrock 経由で Claude を呼び、ツール（tool/function calling）を使っていて呼び出しが弾かれていた構成。
- 開発者にとっての価値: SDK のプロバイダーパッケージだけを上げれば、コア（`ai`）を無理に上げずに Claude 周りのトークン計測とツール呼び出しの実務的な不具合を潰せる。v3/v4 両系統にバックポートがあるため移行負担が小さい。
- 注意点: これは **プロバイダーパッケージ（`@ai-sdk/anthropic` / `@ai-sdk/amazon-bedrock` / `@ai-sdk/google-vertex`）の更新**で、コアの `ai` 本体の機能追加ではない。自分が使っているメジャー（v3 / v4 / v5）に合ったバージョンを選ぶこと。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://sdk.vercel.ai/
- メモ: 過去記事ではコアの `ai@7.0.x` を扱っていた。今回はプロバイダー側の修正で内容が異なるため新規採用。

#### 使用例

```bash
# Bedrock 経由の Claude を使う場合（ツール呼び出しの修正を取り込む）
npm i @ai-sdk/amazon-bedrock@5.0.32

# 拡張思考のトークン計測を正す場合
npm i @ai-sdk/anthropic@4.0.21
# v3 系を維持したいなら:
# npm i @ai-sdk/anthropic@3.0.103
```
