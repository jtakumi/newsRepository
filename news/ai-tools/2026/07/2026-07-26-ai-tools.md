## 今日の注目

### 1. Ollama / v0.32.4

- 種別: OSS / CLI（ローカル LLM ランタイム）
- 関連: Ollama / ローカルLLM / Apple Silicon（MLX）
- 公開・更新日: 2026-07-25（02:22 UTC / JST 07-25 11:22）※安定版
- 概要: Apple Silicon 向けの MLX エンジンと投機的デコード・MoE デコードまわりを改善したパッチリリース。ローカルで LLM を動かす開発者の実効速度と正確性を底上げする。
- 何が便利か:
  - **MLX エンジンで Laguna を Apple GPU 対応**。対応アーキテクチャのモデルを Mac の GPU で回せるようになり、ローカル推論の選択肢が広がる。
  - **投機的デコードのドラフトモデル出力ヘッドを要求された型で量子化**。ドラフト＋検証方式の高速化で、メモリと速度のバランスを取りやすくなる。
  - **Qwen3 MoE の「異なる量子化のエキスパート」でのデコード不具合を修正**し、あわせて **パックした gate/up 射影を高速化（M5 Max で約 4〜9%）**。混在量子化の MoE モデルを正しく・速く動かせる。
- 使いどころ:
  - Mac（特に M5 系）でローカル LLM を常用していて、**API コストをかけずに手元で推論**したい開発検証・オフライン作業。
  - Qwen3 MoE 系モデルをローカルで使っていて、出力の不安定さや速度に悩んでいたケース。
  - 投機的デコードでドラフトモデルを併用し、**生成レイテンシを下げたい**ローカル推論パイプライン。
- 開発者にとっての価値: クラウド API に依存せず手元で試せるローカル LLM の速度・正確性が、**更新するだけ**で改善する。RAG やエージェントの前段をローカルで回す構成では実効コストとレスポンスに直接効く。
- 注意点: 高速化の数値（約 4〜9%）は **M5 Max 基準**で、他チップでは差が異なる。MLX 経由の Laguna 対応は Apple GPU 前提のため、非 Mac 環境では恩恵がない。パッチ版のため、本番導入前に自分のモデル・量子化で挙動を確認すること。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.32.4
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 07-25 記事では v0.32.3（07-23）を採用済み。本記事は 07-25 公開の v0.32.4 を新規採用。

#### 使用例

```bash
# 既存インストールを更新（macOS はアプリ側の自動更新、Linux は再インストールスクリプト）
curl -fsSL https://ollama.com/install.sh | sh

# バージョン確認（v0.32.4 になっていること）
ollama --version

# Qwen3 MoE 系モデルをローカルで実行して挙動を確認
ollama run qwen3
```

### 3. Vercel AI SDK / @ai-sdk/harness@1.0.43

- 種別: OSS（TypeScript SDK パッケージ）
- 関連: Vercel AI SDK / Agent Framework
- 公開・更新日: 2026-07-24（17:25 UTC / JST 07-25 02:25）
- 概要: AI SDK の harness パッケージのパッチ。エージェントの **turn ライフサイクルとテレメトリ**まわりの不具合を修正し、マルチステップ実行の観測性と中断制御を安定させる。
- 何が便利か:
  - **マルチステップ turn のテレメトリ終了イベントが `final-step` のテキストと推論を正しく報告**するよう修正。複数ステップにまたがるエージェント実行のログ・計測が正確になる。
  - **turn が途中で suspend された際に `onTurnFinished` / `onTurnFailed` を誤って発火しない**よう修正。中断・再開を伴うフローでのイベント整合性が改善。
  - 壊れていた **bridge の `channel.interrupt()` 層とその利用を除去**し、不要な中断経路を取り除いた。
- 使いどころ:
  - Vercel AI SDK でマルチステップのエージェント／ツール実行を組んでいて、**テレメトリやコールバックの発火タイミングがずれて困っていた**ケース。
  - 途中で一時停止（suspend）して後で再開するワークフローを扱っている場合の、イベント整合性の改善。
- 開発者にとっての価値: 派手な新機能ではないが、**エージェント実行の観測性（telemetry）と中断制御の信頼性**は本番運用で効く部分。マルチステップ turn を扱っているなら追随しておきたい修正。
- 注意点: harness は AI SDK の内部寄りのパッケージで、**単純なチャット用途では直接の影響は小さい**。多くの周辺パッケージは同時刻に依存更新のみのパッチが出ているため、実質的な変更はこの harness 修正が中心。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://ai-sdk.dev/
- メモ: 07-25 記事では `ai@7.0.37`（依存更新のみ）と 07-24 の security 修正 `7.0.36` を扱った。本記事は同 07-24（JST 07-25）に出た harness の実装修正を新規採用。
