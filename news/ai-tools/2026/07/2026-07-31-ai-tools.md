### 1. OpenAI Codex / rust-v0.146.0

- 種別: CLI（安定版）
- 関連: OpenAI / Codex
- 公開・更新日: 2026-07-29（01:42 UTC / JST 07-29 10:42）※安定版
- 概要: Codex CLI の新しい安定版。**マルチセッションのワークフロー管理**を大きく強化し、プラグイン／マーケットプレイスの土台を広げた。
- 何が便利か:
  - **セッションに名前を付けて整理**: `/new` または `/clear` で新しいセッションに名前を付けられる。作業ごとに履歴を分けやすい。
  - **スレッドのピン留めとサイド会話の切り替え**: 重要なスレッドをピン留めし、**別の会話を閉じずに行き来**できる。並行タスクを 1 つの CLI 内で回せる。
  - **スレッドの fork（分岐）**: ページ送り付きの履歴でスレッドを分岐でき、**一覧に出ない一時 fork** も作れる。「途中まで同じ、ここから別案」を安全に試せる。
  - **Agent Plugins マニフェスト＋ワークスペース公開＋マーケットプレイス**: プラグインをワークスペースに公開でき、**Amazon Bedrock / Claude Code 向けのプラグインマーケットプレイス**にも対応。
  - プロキシ設定・MCP サーバーの認証変更時の安定性・Windows のサンドボックス終了処理などの修正も含む。
- 使いどころ:
  - 複数の作業（実装・調査・レビュー）を並行で進める際に、セッション名とピン留めで文脈を混ぜずに切り替える。
  - 「本命の実装」と「試験的なリファクタ」を fork で分け、一時 fork で捨て試しをする。
  - チーム共通のプラグインをワークスペースへ公開し、Codex の挙動を標準化する。
- 開発者にとっての価値: エージェント CLI の弱点だった**長時間・複数タスクの文脈管理**が実用レベルに近づいた。安定版なので日常利用に組み込みやすい。
- 注意点: プラグイン公開やマーケットプレイスは組織設定・権限に依存する。最新は `v0.147.0-alpha.x`（プレリリース）なので、常用は安定版 v0.146.0 を推奨。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.146.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 前回（07-25）記事では Codex の安定版は v0.145.0（07-21）まで。今回は新しい安定版 v0.146.0 を新規採用。

#### 使用例

```bash
# インストール／更新（npm 経由）
npm install -g @openai/codex

# 起動して名前付きセッションを作成
codex
> /new refactor-auth      # 新規セッションに名前を付ける
> /clear billing-review   # クリアして別作業に名前を付ける
```

### 2. Gemini CLI / v0.53.0

- 種別: CLI（安定版）
- 関連: Google AI / Gemini / Gemini CLI
- 公開・更新日: 2026-07-28（21:45 UTC / JST 07-29 06:45）※安定版
- 概要: セキュリティ・ハードニングを主眼にした安定版。エージェントの暴走ループとプロンプトインジェクション、そしてワークスペース経由の RCE を防ぐ。
- 何が便利か:
  - **無限 ReAct ループ／プロンプトインジェクションのループを緩和**: 悪意ある入力でツール呼び出しが延々と続く事故を抑える。
  - **ワークスペーストラストとタスク分離を強制**: 信頼していないワークスペースからの**リモートコード実行を防止**。他人のリポジトリを開くときの安全側の既定になる。
  - **macOS Seatbelt を deny-default に再整備**: 許可を明示しない操作は既定で拒否。サンドボックスの穴を塞ぐ。
  - キャンセルされたツール応答のグルーピング修正で **400 Bad Request の発生を低減**、資格情報の逐次検証と `GOOGLE_APPLICATION_CREDENTIALS` フォールバック復活も含む。
- 使いどころ:
  - 信頼できない・外部由来のリポジトリを Gemini CLI で開いて調査するとき（ワークスペーストラストが効く）。
  - CI や自動実行で Gemini CLI を回す環境の、既定セキュリティを引き上げたいとき。
- 開発者にとっての価値: エージェント CLI の**実運用リスク（暴走・注入・RCE）に正面から対処した安定版**。機能追加より安全性を優先したい環境で、まず上げておきたいバージョン。
- 注意点: v0.54.0-preview.0 や nightly はプレリリースのため常用は非推奨。ワークスペーストラスト強制で、これまで通っていた操作が拒否される場合があるので信頼設定を確認すること。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.53.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 前回（07-25）記事では安定版は v0.52.0 まで、v0.53.0-preview.0 はプレリリース扱いで見送り。今回 v0.53.0 が安定版として確定したため新規採用。

#### 使用例

```bash
# 更新
npm install -g @google/gemini-cli

# バージョン確認（v0.53.0 であること）
gemini --version
```

- 関連: Cline

- 概要: 無料の Cline モデルへ横断対応し、デスクトップ／CLI／SDK のセッション体験を底上げした一連の更新。

  - **無料の Cline モデルに対応**: モデル選択に **「(free)」表示**、上限到達時は**リセット時刻付きのエラーカード**を表示。まず無償で試せる導線ができた。
  - **Claude Code の応答保全**: CLI が max-turns エラーで終了しても、**それまでにストリームされた有効な応答を失わない**ように修正。
  - **Desktop v0.0.7**: システムトレイにアプリ状態とアクティブなエージェントセッションを表示、**セッション履歴を 10 件単位でページ送り**、お気に入り登録、Qwen・Moonshot・Z AI・MiniMax の地域エンドポイント修正。

- 使いどころ:
  - まず無料モデルで Cline のエージェント挙動を試し、良ければ有料プロバイダーへ切り替える。
  - Desktop でトレイからセッション状況を確認しつつ、複数タスクを履歴のページ送りで管理する。
- 開発者にとっての価値: **無料枠という試用の入口**と、Desktop／CLI／SDK 横断のセッション永続化・再接続で、個人でも継続運用しやすくなった。
- 注意点: 無料モデルには利用上限があり、到達時はリセット待ちが必要。Desktop はまだ v0.0.x の初期段階。
- 公式リンク: https://github.com/cline/cline/releases/tag/v4.0.12
- 参考リンク: https://github.com/cline/cline/releases
- メモ: 前回（07-25）記事では v4.0.11（Opus 5 対応）・Desktop v0.0.4 を採用。今回は無料モデル対応の v4.0.12 と Desktop v0.0.7 ほかを新規採用。

### 5. LiteLLM / v1.94.0

- 種別: OSS（LLM ゲートウェイ／プロキシ）
- 関連: LiteLLM / OpenRouter 的なマルチプロバイダー・ルーティング
- 公開・更新日: 2026-07-28（安定版）
- 概要: ルーティングとガバナンス（予算・キー・チーム）を強化した安定版。
- 何が便利か:
  - **Auto-Router v2 の適応ルーティング（adaptive routing）** と、**複雑度ティアのランダム選択**。リクエストの難易度に応じてモデルを振り分ける制御が細かくなった。
  - **チームキーへのユーザー予算の強制適用**（UI からオプトアウト可）。チーム単位のキーでも個々のユーザー予算を効かせられる。

- 使いどころ:
  - 複数モデル／プロバイダーを 1 エンドポイントに束ねて、コストと品質でルーティングを最適化したいとき。
  - チーム配布キーで、ユーザーごとの利用予算を運用ルールとして強制したいとき。
- 開発者にとっての価値: 自前の LLM ゲートウェイとして、**ルーティングの賢さ**と**予算ガバナンス**が実務水準で強化された安定版。既存の LiteLLM 運用にそのまま乗せやすい。
