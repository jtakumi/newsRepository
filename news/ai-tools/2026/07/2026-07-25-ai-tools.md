### 1. Claude Opus 5 / claude-opus-5

- 種別: モデル（API / 各種プロバイダー）
- 関連: Claude / Anthropic / Claude Code / OpenRouter
- 公開・更新日: 2026-07-24（JST 07-24〜07-25 にかけて各プロバイダーへ展開）
- 概要: Anthropic の新しいフラッグシップ級モデル。**価格を前世代 Opus 4.8 と同じに保ったまま**コーディング・ナレッジワークの評価で性能を引き上げた。推論エフォートを段階的に選べるのが特徴。
- 何が便利か:
  - **価格据え置きで性能向上**: 入力 $5 / 出力 $25 per Mtok（Opus 4.8 と同額）。既存の Opus 予算のまま、より強いモデルに乗り換えられる。
  - **1M トークンのコンテキスト**（最大出力 128K）。大規模リポジトリ・長い設計ドキュメントをまとめて扱える。
  - **推論エフォートの切り替え（low / medium / high）**。簡単なタスクは低エフォートで安く速く、難しいコーディング／調査は高エフォートで、と**コストと能力を用途ごとに調整**できる。
  - **高速版（Fast）** も用意され、入力 $10 / 出力 $50 per Mtok でレイテンシを優先できる。
  - Claude Max の**新しい既定モデル**、Pro でも最上位として利用可能。
- 使いどころ:
  - Opus 4.8 を使っていたエージェント／自動化パイプラインを、コスト増なしで Opus 5 に切り替えて品質を底上げする。
  - 長大なコードベースの読解・リファクタ提案、設計レビュー、調査タスクなど 1M コンテキストを活かす作業。
  - タスクの難易度に応じてエフォートを絞り、日常のバッチ処理コストを抑える。
- 開発者にとっての価値: 「同じ価格でより賢い Opus」に置き換えられるのは実務インパクトが大きい。多くの AI コーディングツール（Claude Code / Copilot CLI / Cline など）が**当日中に対応**したため、既存ワークフローへ即日組み込める。
- 注意点: サイバーセキュリティ系タスクなど一部領域では他社最上位モデルに劣るとの評価もある。エフォート設定や Fast 版で実効コストが変わるため、本番投入前に自分のワークロードで課金と品質を実測すること。
- 公式リンク: https://platform.claude.com/docs/en/about-claude/models/whats-new-opus-5
- 参考リンク: https://www.anthropic.com/news/claude-opus-5 ／ https://openrouter.ai/anthropic/claude-opus-5
- メモ: 過去記事では Opus 4.8 系を扱っていた。Opus 5 の正式公開は未掲載のため新規採用。API モデル ID は `claude-opus-5`。

#### 使用例

claude
> /model claude-opus-5

# API から直接（Messages API のモデル指定）

### 2. Claude Code / v2.1.219

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-07-24（17:14 UTC / JST 07-25 02:14）※安定版
- 概要: Opus 5 を既定 Opus に採用し、サブエージェントのネスト実行・サンドボックスの厳格な許可リスト・`DirectoryAdded` フックなどを追加した安定版。
- 何が便利か:
  - **Opus 5 が既定の Opus モデルに**。`/fast`（Fast モード）は Opus 5 と Opus 4.8 に適用され、Opus 4.7 は Fast 対象から除外。
  - **サブエージェントが既定でネスト可能に（深さ 3 まで、従来は 1）**。親エージェントが子を、子がさらに孫を起動でき、複雑なタスク分解を 1 セッションで組みやすい。
  - **`sandbox.network.strictAllowlist` 設定**: サンドボックス実行のコマンドが許可リスト外ホストへアクセスしようとした際、**プロンプトを出さずに拒否**する。CI や自動実行での安全側の既定を作れる。
  - **`DirectoryAdded` フック**: `/add-dir` や SDK の `register_repo_root` 実行後に発火。ディレクトリ追加時の初期化処理を自動化できる。
  - ヘッドレスの stream-json 初期化イベントに **`mcp_server_errors`** を追加し、MCP サーバーの起動失敗を機械的に検知しやすくなった。
- 使いどころ:
  - 大きめのタスクをサブエージェントで分割し、さらに各サブエージェントが専門処理を子エージェントに委譲する多段ワークフロー。
  - サンドボックス実行を CI に組み込み、外部ホストへの意図しない通信を既定で遮断したいとき。
- 開発者にとっての価値: 既定モデルの引き上げ（Opus 5）と、エージェントのネスト・サンドボックス強化・フック追加という「自動化の土台」がまとめて入る安定版。破壊的変更なしで `claude update` から導入できる。
- 注意点: サブエージェントのネストが既定で有効になるため、多段起動でトークン消費が増えやすい。`strictAllowlist` は許可リスト外を無音で拒否するため、必要なホストは事前に許可リストへ追加すること。
- 公式リンク: https://github.com/anthropics/claude-code/releases
- 参考リンク: https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md
- メモ: 07-24 記事では v2.1.218 まで採用。今回は 07-24 リリースの v2.1.219 を新規採用。

#### 使用例

```bash
# 更新して Opus 5（既定 Opus）を利用
claude update

# サンドボックスの厳格許可リストを設定（settings.json）
# "sandbox": { "network": { "strictAllowlist": true } }

# /add-dir 後に DirectoryAdded フックで初期化処理を走らせる
claude
> /add-dir ../shared-lib
```

- 関連: Cline / Claude / Anthropic / OpenRouter

  - Bedrock / Vertex 経由で Anthropic モデルを使う企業環境で、Cline から Opus 5 を検証するとき。

- 注意点: Cline Desktop はまだ v0.0.x の初期段階で、現時点では macOS のみ。本格運用よりは評価用途向け。
