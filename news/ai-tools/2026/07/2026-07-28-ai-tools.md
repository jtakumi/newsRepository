### 1. OpenAI Codex / `codex` CLI（`/import` 拡張・スレッド履歴）

- 種別: CLI / ドキュメント更新（実験的機能）
- 関連: OpenAI / Codex / Cursor / Claude Code / MCP
- 公開・更新日: 2026-07-26（公式 changelog）。CLI は `v0.146.0-alpha.10〜13`（07-25〜07-27、いずれもプレリリース）
- 概要: Codex の `/import` が **Cursor と Claude Code の設定を丸ごと取り込める**ように拡張された。MCP サーバー、プラグイン、過去セッション、カスタムコマンド、プロジェクト単位のメモリまで移行対象。加えてスレッド履歴がページング対応になり、大量の会話を効率的に resume・検索できる。
- 何が便利か:
  - **乗り換えコストの削減**: すでに Cursor / Claude Code で整えた MCP サーバーやコマンド、メモリを手作業で作り直さずに Codex へ持ち込める。
  - **スレッド履歴の実用化**: 効率的な resume・検索・名前付き保存・サブエージェント対応で、長期プロジェクトの文脈を追いやすい。
  - **Amazon Bedrock ログイン／カスタムエンドポイント対応**で、社内 Bedrock 経由の運用にも組み込みやすい。
  - **音声入力・リアルタイム V3 会話**、**マルチエージェント V2 の安定化**、ターミナル UI のインライン可視化リンクのクリック対応。
- 使いどころ:
  - Cursor / Claude Code を主に使ってきたチームが、既存資産を活かしたまま Codex を評価・並行運用する。
  - 複数リポジトリ・長期タスクで、名前付きスレッド履歴を使って作業文脈を整理する。
- 開発者にとっての価値: 「設定移行の面倒さ」が乗り換え・併用の最大の障壁になりがちな中、`/import` はその障壁を直接下げる。MCP・プラグイン・メモリまで含めて移せる点が実務的。
- 注意点: 記載機能の多くは**実験的（experimental）**扱いで、対応 CLI は現時点で**プレリリース（`v0.146.0-alpha`）**。安定版ではないため、本番導入前に検証環境で挙動を確認すること。移行時は取り込んだ MCP サーバーの権限・認証情報の扱いにも注意。
- 公式リンク: https://developers.openai.com/codex/changelog
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 過去記事では Codex のプレリリース CLI 単体は見送っていたが、今回は**公式 changelog に日付付きで明記された機能追加**であり、開発者価値が高いため採用。CLI の安定版が出た際は改めて追跡する。

### 2. Ollama v0.32.4 / v0.32.5

- 種別: OSS / ローカル LLM ランタイム（CLI）
- 関連: Ollama / ローカルLLM / Apple Silicon（MLX）
- 公開・更新日: 2026-07-25（v0.32.4）／ 2026-07-27（v0.32.5）※いずれも安定版
- 概要: ローカルで LLM を動かす Ollama の連続アップデート。**Apple GPU（MLX エンジン）での Laguna 対応**、**投機的デコードの量子化改善**、**Qwen3 MoE のデコード高速化**を中心に、実行速度と出力品質を底上げした。
- 何が便利か:
  - **Apple Silicon での高速化**: MLX エンジンで Laguna をサポート。Qwen3 MoE のデコードは gate/up 射影のパッキングにより **M5 Max で約 4〜9% 高速化**。
  - **投機的デコードの品質・速度改善**: ドラフトモデルの出力ヘッドを要求された型で量子化し、メモリと速度のバランスを改善。
  - **v0.32.5 のバグ修正**: NVFP4 系モデル（Laguna 等）で出力品質を劣化させ得た MLX Metal の不具合を修正。ローカル推論の信頼性が向上。
- 使いどころ:
  - Mac（Apple Silicon）でローカル LLM を常用している開発者が、アップデートするだけで体感速度と品質を改善する。
  - Qwen3 系や Laguna をローカルで動かすコード補完・要約・RAG のバックエンドとして。
- 開発者にとっての価値: クラウド API に依存しないローカル実行の速度・品質は日常の開発効率に直結する。**`ollama` を更新するだけ**で恩恵を受けられ、導入障壁が低い。
- 注意点: MLX 経由の高速化は主に Apple Silicon 向け。NVFP4 系モデルを使う場合は品質修正が入った **v0.32.5 以上**へ更新すること。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.32.5
- 参考リンク: https://github.com/ollama/ollama/releases/tag/v0.32.4
- メモ: 過去記事では v0.32.3（07-23）まで扱い。v0.32.4 / v0.32.5 は新バージョンのため採用。

#### 使用例

```bash
# 最新版へ更新（macOS: 公式インストーラ or Homebrew）
brew upgrade ollama   # Homebrew の場合
ollama --version      # v0.32.5 以上を確認

# ローカルでモデルを実行
ollama run qwen3
```

### 3. Vercel AI SDK `ai@7.0.38`（実験的な音声翻訳）

- 種別: OSS / SDK（npm）
- 関連: Vercel AI SDK / OpenRouter・各種プロバイダー
- 公開・更新日: 2026-07-27（22:02 UTC / JST 07-28 07:02 頃）
- 概要: TypeScript/JavaScript 向け AI SDK の最新版。**実験的な音声翻訳モデル抽象（`Experimental_SpeechTranslationModelV4`）** と **ストリーミング音声翻訳（`experimental_streamTranslate`）** を追加し、音声→音声の翻訳を SDK から統一的に扱えるようにした。
- 何が便利か:
  - **音声翻訳を SDK 標準の型で扱える**: `experimental_streamTranslate` でストリーミングの音声翻訳を組み込みやすい。
  - **不具合修正**: プロバイダー実行ツールの不正なツール呼び出しに対して、クライアント側でツールエラーを合成しないよう修正され、ツール呼び出しの挙動がより素直に。
  - gateway / provider / provider-utils など関連パッケージの依存更新も同日にそろって公開。
- 使いどころ:
  - リアルタイム字幕・音声通訳・音声アシスタントなど、音声入出力を伴うアプリのプロトタイプ。
  - 既存の Vercel AI SDK アプリで、ツール呼び出し周りの挙動改善を取り込む定期アップデート。
- 開発者にとっての価値: Web/Node のエコシステムでプロバイダーを抽象化したまま音声翻訳へ手を伸ばせる。実験的 API のため小さく試すのに向く。
- 注意点: 音声翻訳は **`Experimental_` プレフィックス付きの実験的 API**。将来的にインターフェースが変わり得るため、本番採用は慎重に。バージョン系列は `ai@7.x`（`6.x` / `5.x` は依存更新のみの同日リリース）。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.38
- 参考リンク: https://ai-sdk.dev/
- メモ: 過去記事の `ai@7.0.37`（07-23）は依存更新のみで見送り。今回は新機能（音声翻訳）追加のため採用。

#### 使用例

```bash
# インストール / 更新
npm install ai@7.0.38
```

### 4. GitHub Copilot CLI v1.0.76-0（MCP 高速ロード・Autopilot 維持）

- 種別: CLI（プレリリース）
- 関連: GitHub Copilot / MCP
- 公開・更新日: 2026-07-27（プレリリース `v1.0.76-0`）
- 概要: GitHub Copilot CLI の最新プレリリース。**MCP ツールを「定義スコープのスナップショット」から高速ロード**する仕組みを追加し、起動やツール読み込みを軽くした。
- 何が便利か:
  - **MCP ツールの高速ロード**: 定義スコープのスナップショットから読み込み、**プロセス全体／サーバー単位でキャッシュを opt-out** も可能。MCP サーバーを多数つないだ環境の立ち上がりを改善。
  - **Autopilot の維持**: タスク完了後も Autopilot 選択が既定で維持され、`stayInAutopilot` 設定で挙動を制御できる。連続タスクでの操作を減らせる。
  - **不具合修正**: `/worktree` で新しい worktree に切り替えた後、セッションの作業ディレクトリが意図せず戻る問題を修正。回収不能なコンテキストが上限に近づいた際の早期警告も復活。
- 使いどころ:
  - 複数の MCP サーバーを常用していて、CLI 起動やツール読み込みの重さが気になる開発者。
  - Autopilot で連続的にタスクを回すワークフロー、`/worktree` を使った並行作業。
- 開発者にとっての価値: MCP を多用するほど効くパフォーマンス改善と、Autopilot の使い勝手向上。日常のエージェント運用の摩擦を減らす。
- 注意点: **プレリリース（`-0` サフィックス）**であり安定版ではない。本番運用は安定版リリースを待つか、検証のうえで。
- 公式リンク: https://github.com/github/copilot-cli/releases
- 参考リンク: https://github.com/github/copilot-cli/blob/main/changelog.md
- メモ: 過去記事では v1.0.75（07-24、Opus 5 対応）まで扱い。v1.0.76-0 は新規のため採用（プレリリース明記）。
