### 1. Gemini CLI / v0.53.0

- 種別: CLI（OSS）
- 関連: Gemini / Google AI
- 公開・更新日: 2026-07-28（21:45 UTC / JST 07-29 06:45）※安定版（Latest）
- 概要: Google 公式のターミナル向け AI エージェント CLI の新しい安定版。ツール応答周りの API エラー修正に加え、エージェント実行のセキュリティ（信頼境界・サンドボックス・ループ／インジェクション対策）を大きく固めた。
- 何が便利か:
  - **グループ化・キャンセルされたツール応答と連続ロールの整形を修正**し、**400 Bad Request エラーを防止**。長い複数ツール呼び出しのセッションが落ちにくくなる。
  - **ワークスペースの信頼（workspace trust）とタスク隔離をサーバー側で強制**し、リモートコード実行（RCE）を防ぐ。信頼していないディレクトリでの不用意なコマンド実行を抑止できる。
  - **無限 ReAct ループとプロンプトインジェクションを緩和**。エージェントが同じ思考を延々と繰り返す事故や、外部入力に誘導される事故を減らす。
  - **macOS の Seatbelt プロファイルを deny-default（既定拒否）モデルへ刷新**。サンドボックス実行の安全側の既定が強化された。
  - **評価カバレッジレポートのコマンドを追加**し、エージェント評価（eval）のカバレッジを可視化できる。
  - 認証まわりの検証順序を修正し、フォールバック認証を復旧。
- 使いどころ:
  - CI やスクリプトから Gemini CLI をヘッドレスで回していて、複数ツール呼び出しで 400 エラーに悩まされていた場合の更新。
  - 信頼できないリポジトリやクローンしたばかりのコードに対してエージェントを走らせる際、workspace trust とサンドボックス既定拒否で安全に試す。
- 開発者にとっての価値: 機能追加というより「エージェントを安全・安定に回すための地盤固め」の安定版。API エラー削減とインジェクション／ループ対策は、自動化パイプラインに組み込んでいるほど効いてくる。
- 注意点: v0.54.0 は preview / nightly（プレリリース）で、安定運用には v0.53.0 を使うこと。deny-default 化やワークスペース信頼の強制で、これまで通っていた操作が拒否される場合があるため、信頼設定・許可リストを見直す。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.53.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 前回（07-25）記事では安定版 v0.52.0、v0.53.0-preview.0 はプレリリースとして見送り。今回 v0.53.0 が安定版（Latest）になったため新規採用。

#### 使用例

```bash
# 更新（グローバルインストールの場合）
npm install -g @google/gemini-cli

# バージョン確認
gemini --version   # 0.53.0 を確認

# 起動（対話）
gemini
```

### 3. Ollama / v0.32.4・v0.32.5

- 種別: CLI / ローカル LLM 実行基盤（OSS）
- 関連: Ollama / ローカル LLM
- 公開・更新日: v0.32.4: 2026-07-25、v0.32.5: 2026-07-27
- 概要: ローカルで LLM を動かす Ollama の連続パッチ。Apple GPU 対応モデルの拡充と、推論速度・出力品質の改善が中心。
- 何が便利か:
  - **Apple GPU で MLX エンジン経由の Laguna をサポート**（v0.32.4）。Mac のローカル実行で対応モデルが増えた。
  - **投機的デコードでドラフトモデルの出力ヘッドを量子化**（v0.32.4）。速度と省メモリの両立に寄与。
  - **Qwen3 MoE のデコードを高速化**（パックした gate/up 射影で M5 Max で約 4〜9% 改善）。手元で MoE 系を回す際のスループット向上。
  - **v0.32.5: NVFP4 モデル（Laguna 等）の出力品質を損なう MLX Metal のバグを修正**。Apple GPU での品質劣化を解消。
- 使いどころ:
  - Mac（Apple Silicon）でローカル LLM を常用していて、対応モデルや推論速度を上げたい場合の更新。
  - オフライン／機密環境で Qwen3 MoE などを回すワークロードの実効速度改善。
- 開発者にとっての価値: ローカル実行はコスト・プライバシー・オフライン性で価値が高く、対応モデル拡充と速度改善は日常のローカル開発に直接効く。v0.32.5 は品質バグ修正なので、Apple GPU 利用者は優先して上げたい。
- 注意点: v0.32.2 は取り下げ済み。v0.32.3 以降（できれば v0.32.5）へ更新すること。MLX 経由の恩恵は主に Apple Silicon 環境。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.32.5
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 前回（07-25）記事では v0.32.3（07-23）まで採用。今回は v0.32.4・v0.32.5 を新規採用。

# モデルを取得して実行（例）

### 4. Vercel AI SDK / ai@7.0.39（+ 7.0.40 / 7.0.41）

- 種別: OSS ライブラリ（TypeScript）
- 関連: Vercel AI SDK
- 公開・更新日: ai@7.0.39: 2026-07-28（03:08 UTC / JST 07-28 12:08）、ai@7.0.41: JST 07-29 02:40
- 概要: TypeScript 向け AI SDK のパッチ群。実験扱いだった構造化出力の修復オプションが正式化され、CLI 出力汚染の修正も入った。
- 何が便利か:
  - **`generateObject` / `streamObject` の `repairText` オプションが正式（stable）化**。モデルが返した壊れた・不完全なテキストを**構造化パース前に修復**できるフックが安定利用可能に。JSON が時々崩れて `generateObject` が失敗する問題への実用的な対処になる。
  - **`ai@7.0.41`: 警告の情報バナーを stderr に出力**するよう変更し、**stdout に書くアプリ出力が汚染されない**ように修正。CLI ツールやパイプ処理で AI SDK を使う際の地味だが効く改善。
  - `ai@7.0.40` では `Experimental_GeneratedImage` を `GeneratedFile` へ寄せる整理（非推奨化）も実施。
- 使いどころ:
  - LLM に構造化出力（オブジェクト／JSON）を生成させるアプリで、たまに壊れる出力を `repairText` で修復してから通す運用。
  - AI SDK を組み込んだ CLI で、標準出力にデータを流しつつ警告表示も出したいケース（7.0.41 で stdout が汚れなくなる）。
- 開発者にとっての価値: `repairText` の stable 化は、構造化出力の信頼性を上げる実務的な機能。実験フラグ依存を外せるので本番投入しやすくなった。
- 注意点: v6 系（`ai@6.0.237`）や v5 系（`ai@5.0.222`）にも同日並行でパッチが出ている。使用中のメジャーバージョンに合わせて更新すること。パッチ内容は細かいので、破壊的でないか各リリースノートで確認を。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://ai-sdk.dev/
- メモ: 過去記事では AI SDK は依存更新のみのパッチを見送っていた。今回は `repairText` の stable 化という実機能があるため新規採用。
