### 1. OpenAI Codex / 0.146.0

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 2026-07-29（01:42 UTC / JST 10:42）※安定版
- 概要: OpenAI のコーディング CLI「Codex」の安定版。セッション（会話スレッド）管理を強化し、複数の作業を並行して行き来しやすくした。
- 何が便利か:
  - **`/new`・`/clear` で新規セッションに名前を付けられる**。あとから「認証リファクタ」「調査メモ」などの名前で見分けられる。
  - **重要スレッドのピン留めをアプリサーバー側で永続化**。よく使う会話を上部に固定でき、再起動をまたいでも残る。
  - **スレッドを切り替えても横の会話（side conversation）を開いたまま保持**。別スレッドに移っても元の会話コンテキストを閉じずに戻れる。
  - あわせてプロキシ処理・MCP 接続管理・ターミナル応答性が改善。
- 使いどころ:
  - 1 つのリポジトリで「実装」「デバッグ」「調査」など複数の会話を並行させ、名前とピン留めで整理しながら進める。
  - 長時間の作業で会話が増えても、目的別に切り替えつつ文脈を失わない運用。
- 開発者にとっての価値: これまで単線になりがちだった CLI の会話が、名前付き・ピン留め・並行保持でエディタのタブのように扱えるようになる。日常のマルチタスク作業の摩擦が減る。
- 注意点: 安定版と同時に `0.147.0-alpha.1` などプレリリースも出ている。安定運用は `0.146.0` を使うこと。ピン留めはアプリサーバー側の永続化に依存する。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.146.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 過去記事では v0.146.0-alpha 系（プレリリース）のみ言及。今回は安定版 0.146.0 を新規採用。安定版の直近は 07-21 の v0.145.0。

#### 使用例

```bash
# 更新
npm install -g @openai/codex@latest   # または codex 内で /update

# 新しいセッションに名前を付けて開始
codex
> /new 認証リファクタ

# 会話をリセットしつつ名前を付け直す
> /clear
```

### 2. Gemini CLI / v0.53.0

- 種別: CLI
- 関連: Gemini / Google AI
- 公開・更新日: 2026-07-28（21:45 UTC / JST 07-29 06:45）※安定版
- 概要: Google の Gemini CLI 安定版。ツール応答の堅牢化、LLM ベースのトリアージ、セキュリティ（ワークスペース信頼・Seatbelt 強化）、eval 機能を追加。
- 何が便利か:
  - **キャンセルされたツール応答をまとめ、連続するロールを結合して 400 Bad Request を防止**。ツールを多用するセッションで会話が壊れにくくなった。
  - **LLM トリアージ・オーケストレーター**を追加（caretaker-triage）。Issue などの振り分けを LLM で自動化する土台。
  - **a2a サーバーでワークスペース信頼とタスク分離を強制し RCE を防止**、**macOS の permissive Seatbelt プロファイルを deny-default モデルに整合**。エージェント実行のサンドボックスが安全側に。
  - **無限 ReAct ループ／プロンプトインジェクションループを緩和**、キャッシュ済み資格情報の逐次検証と `GOOGLE_APPLICATION_CREDENTIALS` フォールバックを復旧。
  - **`evals` に eval カバレッジレポートコマンド**を追加し、評価の網羅度を可視化。
- 使いどころ:
  - MCP／ツールを多用するエージェント運用で、ツール応答起因の 400 エラーやループに悩まされていたケースの安定化。
  - a2a（agent-to-agent）サーバーを立てる構成で、信頼境界とタスク分離を効かせたいとき。
- 開発者にとっての価値: プレビュー段階だった v0.53 系が安定版に到達。ツール実行の堅牢性とサンドボックスのセキュリティ強化がまとまって入り、エージェント運用の土台が固くなる。
- 注意点: 同時期に v0.54.0-preview.0 や nightly も出ているがいずれもプレリリース。安定運用は v0.53.0 を使う。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.53.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 過去記事では安定版 v0.52.0（07-22）と v0.53.0-preview.0（プレリリース）を扱っていた。今回は安定版 v0.53.0 を新規採用。

#### 使用例

```bash
# 更新して安定版へ
npm install -g @google/gemini-cli@latest
gemini --version   # v0.53.0

# eval カバレッジレポートを出力

```

### 3. Cline / 無料モデル対応（v4.0.12・CLI v3.0.47・SDK v0.0.66・Desktop v0.0.7）

- 種別: VS Code 拡張 ／ CLI ／ SDK ／ デスクトップアプリ
- 関連: Cline / OpenRouter / models.dev
- 公開・更新日: v4.0.12: 2026-07-28（23:01）、CLI v3.0.47: 2026-07-28（22:44 UTC）、SDK v0.0.66: 2026-07-28（22:35 UTC）、Desktop v0.0.7: 2026-07-29（01:43 UTC）
- 概要: Cline が「無料 Cline モデル（`(free)`）」に横断対応。モデルピッカーで無料モデルを選べ、上限到達時はリセット時刻を表示する。あわせて自動要約（agentic compaction）が既定戦略になった。
- 何が便利か:
  - **モデルピッカーに `(free)` 表示の無料 Cline モデル**が並ぶ。API キーの課金を気にせずエージェント型コーディングを試せる。
  - **無料枠の上限到達時に、リセット時刻を示す専用エラーカード**を表示。いつ再び使えるかが分かる。
  - **agentic compaction（会話の自動要約）が既定戦略に昇格**し、長いセッションでもコンテキスト超過を起こしにくい。OpenAI 互換プロバイダーでのフォールバックや、ツール多用時の要約カットポイント探索も修正。
  - **各種トグル（plan/act モード、ツール自動承認など）が再起動をまたいで永続化**。models.dev 由来のプロバイダー一覧も拡充。
  - Desktop 版はシステムトレイでアプリ状態とアクティブなエージェントセッションを表示、履歴のページネーションやセッションのお気に入り登録に対応。
- 使いどころ:
  - まず無料モデルで Cline のエージェント動作（計画→編集→実行）を体験し、良ければ有料モデルに切り替える導入フロー。
  - 長時間タスクで自動要約に任せ、コンテキスト管理の手間を減らしたいとき。
- 開発者にとっての価値: 「まず無料で試す」導線が公式に整い、個人開発でエージェント型コーディングを始める敷居が下がった。自動要約の既定化で長時間セッションの安定性も上がる。
- 注意点: 無料モデルには利用上限がある（到達時はリセット時刻を確認）。Desktop 版は依然 v0.0.x の初期段階。バージョンが VS Code 拡張・CLI・SDK・Desktop で分かれているため、使う経路に対応した最新版へ更新すること。
- 公式リンク: https://github.com/cline/cline/releases
- 参考リンク: https://github.com/cline/cline/releases/tag/v4.0.12
- メモ: 過去記事では Opus 5 対応の v4.0.11（07-24）まで採用。今回は「無料 Cline モデル」対応と agentic compaction 既定化を新規採用。

#### 使用例

```bash
# CLI を最新へ更新（無料モデル対応）
npm install -g @cline/cli@latest

# VS Code 拡張ではモデルピッカーで "(free)" 付きモデルを選択
# コマンドパレット → Cline: Open → モデル選択 → (free) を選ぶ
```

### 4. LiteLLM / v1.94.0

- 種別: OSS（LLM ゲートウェイ / プロキシ）
- 関連: LiteLLM / OpenRouter / Bedrock / MCP
- 公開・更新日: 2026-07-28（21:26 UTC / JST 07-29 06:26）※安定版
- 概要: マルチプロバイダー LLM ゲートウェイ LiteLLM の安定版。ルーティングの拡張性、コスト最適化、ガードレール、MCP OAuth を強化。
- 何が便利か:
  - **ルータープラグイン・パイプライン**を導入。ルーティング処理を段階的なプラグインとして差し込める設計になり、独自のルーティングロジックを組み込みやすい。
  - **複雑度ルーターの soft-floor アダプティブモード（Auto-Router v2）**。タスクの複雑度に応じてモデル階層をアダプティブに選び、コストと品質のバランスを取る。
  - **Cost Optimization ページ（beta）** で、ツール別のスペンドやキャッシュリーク（cache leakage）を可視化。無駄な支出を洗い出せる。
  - **MCP OAuth の issuer-anchored discovery** と、SSO 版不一致時の CLI エラーメッセージ改善。
  - **新ガードレール**として Straiker 連携と、文脈圧縮向けの **Compresr** を追加。
- 使いどころ:
  - 複数プロバイダー／モデルを 1 エンドポイントに束ね、複雑度に応じて自動でモデルを振り分けたいとき。
  - チームの LLM 利用コストを可視化し、ツール単位で支出やキャッシュ効率を点検したいとき。
- 開発者にとっての価値: 前回まで RC / dev 止まりだった v1.94.0 系が安定版に到達。ルーティングの拡張性・コスト可視化・MCP OAuth の実運用機能がまとまって入り、ゲートウェイ運用の本番採用がしやすくなった。
- 注意点: Cost Optimization ページは beta。150+ の PR を含む大型リリースのため、本番反映前に自分の構成での回帰確認を推奨。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.94.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 過去記事では v1.94.0-rc.1〜rc.3（RC）・v1.95.0-dev 系（dev）のみ言及。安定版は 07-19 の v1.93.0 が既出。今回は安定版 v1.94.0 を新規採用。

#### 使用例

```bash
# 更新
pip install -U litellm

# プロキシを起動（設定で router プラグイン / 複雑度ルーターを指定）
litellm --config config.yaml
```

### 5. Ollama / v0.32.4・v0.32.5（Laguna on Apple GPU / MLX）

- 種別: OSS（ローカル LLM ランタイム）
- 関連: Ollama / ローカルLLM / Apple Silicon（MLX）
- 公開・更新日: v0.32.4: 2026-07-25、v0.32.5: 2026-07-27（JST 07-28）
- 概要: ローカル LLM ランタイム Ollama の更新。Apple GPU 向けの MLX エンジンで Laguna を動かせるようになり、続く修正で MLX Metal の出力品質バグを解消した。
- 何が便利か:
  - **v0.32.4: Apple GPU 上で Laguna を MLX エンジン経由で実行可能に**。Apple Silicon での対応モデルが広がった。
  - **投機的デコード（speculative decoding）のドラフト作成時に、ドラフト出力ヘッドを要求された型で量子化**し、**Qwen3 MoE のデコード性能を改善**。
  - **v0.32.5: MLX Metal の NVFP4 モデル（特に Laguna）の出力品質バグを修正**。品質劣化を伴わずに MLX を使える。
- 使いどころ:
  - Apple Silicon の Mac でローカルに Laguna 系モデルを動かし、クラウドに投げずに手元で推論・検証したいとき。
  - 投機的デコードや Qwen3 MoE をローカルで使い、速度を稼ぎたいとき。
- 開発者にとっての価値: ローカル推論の対応モデルと Apple GPU（MLX）まわりの品質が一段進んだ。オフライン／プライバシー重視の開発・検証環境を手元で完結させやすくなる。
- 注意点: NVFP4 の品質修正は v0.32.5 で入ったため、Laguna を MLX で使うなら v0.32.5 以降へ更新すること。前身の v0.32.2 は取り下げ済み。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.32.5
- 参考リンク: https://github.com/ollama/ollama/releases/tag/v0.32.4
- メモ: 過去記事は v0.32.3（07-23）まで採用。今回は v0.32.4 / v0.32.5 を新規採用。

#### 使用例

```bash
# 更新後、Apple Silicon でローカルにモデルを起動
ollama --version   # v0.32.5 以降
ollama run laguna
```
