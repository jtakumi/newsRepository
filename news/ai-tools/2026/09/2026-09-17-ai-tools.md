### 2. Vercel AI SDK / ai@7.0.103〜ai@7.0.104（ネイティブ tool search・会話途中のツール発見）

- 種別: OSS / TypeScript AI SDK（安定版）
- 関連: Vercel AI SDK / ツール利用（tool use）/ エージェント
- 公開・更新日: 2026-09-16 ※`ai@7.0.104`（GitHub Releases 表示）
- 概要: TypeScript 向け AI SDK の連続パッチ。`ai@7.0.103` で **code-mode 向けに会話途中でのツール発見/更新（mid conversation tool discovery/updates）**を追加し、`experimental_evaluate`（隔離された評価用モデル指定と型付き検証）を導入、UI メッセージパートの `rawInput` を非推奨化。`ai@7.0.104` で **ネイティブの tool search ツール**と**直接ツール呼び出しでの tool search 対応**を追加し、評価用モデルのエイリアス/レジストリ解決（`customProvider` が `evaluationModels` を受け付け、`experimental_evaluate` が文字列 ID を受理）を追加。リアルタイム WebSocket の異常クローズ診断を `onError` から通知するよう修正。
- 何が便利か: ツールが多数あるエージェントで、全ツール定義を毎回コンテキストに載せず **必要なツールを検索して呼び出す**設計が SDK 標準で書ける。会話の途中でツール集合を差し替え/追加でき、code-mode のような動的なツール構成に向く。`experimental_evaluate` で評価用モデルを本番モデルと分離して回せる。
- 使いどころ: ツール数が多くコンテキスト肥大が問題になるエージェント。MCP などで動的にツールが増減する構成。出力品質を別モデルで評価（LLM-as-judge 的）したいとき。
- 開発者にとっての価値: `npm i ai@7.0.104` で今日から。tool search が SDK ネイティブになったことで、自前のツールルーティング実装を減らせる。
- 注意点: tool search / 評価まわりは新規追加のため、詳細 API はリリースノートと公式ドキュメントで最新仕様の確認を推奨。`rawInput` を使う UI 実装は非推奨化に伴う移行が必要。`experimental_` 接頭辞の機能は仕様変更の可能性あり。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://ai-sdk.dev/
- メモ: 前回までの採用は `ai@7.0.92`（9/4）・`ai@7.0.93`（9/5）で、9/14 記事は `ai@7.0.99`（既出）を確認済みとしていた。本記事の `ai@7.0.103`〜`7.0.104`（tool search 追加）は新機能を伴う新規採用。内容は GitHub Releases で確認。

### 4. Ollama / v0.34.1（安定版・MLX safetensors 正式化・/api/tags 大幅高速化）

- 種別: OSS / ローカル LLM ランタイム（安定版）
- 関連: Ollama / ローカル LLM / Apple Silicon（MLX）
- 公開・更新日: 2026-09-14 22:14 UTC（JST 2026-09-15 07:14）※`v0.34.1`
- 概要: ローカル LLM ランタイム Ollama の新安定版（`v0.34` ラインの安定リリース）。**MLX safetensors の `ollama create` が実験的機能ではなくなり正式化**（一方で GGUF モデル作成は safetensor 変換/量子化に llama.cpp ツールが必要になった）。**Apple Silicon での MLX メモリ処理を改善**。**暴走的なリピートトークン検出のしきい値を 100 トークンへ引き上げ**（OCR などでの誤検知低減）。**`/api/tags` が大きなモデルライブラリで大幅高速化（テストで 3.1s→294ms コールド）**し、モデルの capabilities 報告が一貫化。`typical_p` を非推奨化（新規モデル作成時は設定不可、既存 GGUF は維持）。MLX / llama.cpp の依存更新。
- 何が便利か: `/api/tags` の高速化で、モデル一覧を叩く UI/オーケストレータの初回応答が体感で改善する。MLX safetensors 作成が正式機能化され、Apple Silicon でのモデル取り込みが安定して使える。リピート検出の是正で OCR 等の正常な繰り返しが誤って打ち切られにくい。
- 使いどころ: Apple Silicon 上でローカルモデルを日常的に回す開発。多数のモデルを登録し `/api/tags` をポーリングするツール連携。OpenAI 互換 API 経由でローカル LLM をワークフローに組み込む構成。
- 開発者にとっての価値: `brew upgrade ollama`（または公式インストーラ）で今日すぐ更新でき、体感速度と安定性が上がる。ローカル実行のため API コストなしで検証を回せる。
- 注意点: **GGUF モデルの作成は llama.cpp ツール前提**に変わったため、従来 GGUF を直接扱っていたワークフローは手順の見直しが必要。`typical_p` を使う設定は新規作成で不可。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.34.1
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 前回までの採用は安定版 `v0.33.3`（9/4）と `v0.34.0-rc1`（9/7、pre-release）。本記事の安定版 `v0.34.1` は新規採用。`/latest` が指す最新安定版であることを確認済み。内容は GitHub Releases で確認。

#### 使用例

```bash

# 高速化された一覧取得を確認
```
