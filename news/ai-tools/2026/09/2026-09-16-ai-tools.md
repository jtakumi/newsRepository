### 2. LiteLLM / v1.101.0（/v1/responses/input_tokens・タイミングヘッダー・OIDCトークン交換・複雑度ルーター）

- 種別: OSS / LLM ゲートウェイ・プロキシ（安定版）
- 関連: LiteLLM / OpenAI / MCP
- 公開・更新日: 2026-09-15
- 概要: 100 以上の LLM プロバイダーを OpenAI 互換 API に統一する LiteLLM の安定版リリース。`/v1/messages` と `/v1/responses` でタイミングヘッダーとオーバーヘッドを出力するようにし、応答ペイロードのトークン数を数える `/v1/responses/input_tokens` エンドポイントを追加。OpenAI 向けに Workload Identity Federation（OIDC トークン交換）をサポートし、長期の API キーに依存しない資格情報交換を可能にした。複雑度ルーターに `classification_mode` を追加して継続ターンでは分類器をスキップできるようにし、収まらない大きなプロンプトをディスパッチ前にフィットするティアへエスカレーションする挙動、画像リクエストのモダリティに基づく能力ルーティングを追加。ほかに OTel v2 の LLM スパンへのキャッシュトークン数記録、Bedrock Converse 設定の扱い改善、GigaChat のネイティブ passthrough とスペンドログ、Docker イメージ更新（glibc 2.44 / Python 3.13）などが入った。
- 何が便利か: ゲートウェイ経由でも `/v1/messages`・`/v1/responses` の所要時間とオーバーヘッドがヘッダーで見え、遅延の切り分けがしやすい。OIDC トークン交換により、静的な API キーを配らずにワークロード ID で OpenAI へ認証できる。複雑度ルーターの `classification_mode` で、継続ターンごとの分類器コストを削減できる。
- 使いどころ: 複数プロバイダーを 1 つのプロキシに集約し、レイテンシ監視・課金集計・キー管理を一元運用している構成。CI/クラウド上のワークロードに静的キーを置きたくない環境。プロンプト長やタスク種別でモデルを振り分けたいルーティング運用。
- 開発者にとっての価値: 自前でプロバイダー差異・トークン計測・資格情報配布を書かずに済む範囲が広がる。安定版のため本番投入しやすく、直近で扱った `v1.100.0`（9/7）以降の実務改善がまとまっている。
- 注意点: Workload Identity Federation は OIDC 発行体（クラウドの ID プロバイダー等）の設定が前提。複雑度ルーターやモダリティルーティングは設定次第で挙動が変わるため、導入時はルーティング設定を確認のこと。前回 9/14 記事で扱った `v1.102.0-rc.1` は事前リリースで、本項は安定版 `v1.101.0`。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.101.0
- 参考リンク: https://docs.litellm.ai/
- メモ: リリース内容は該当タグのページで確認。過去の AI Tools News が採用した安定版は `v1.100.0`（9/7）で、`v1.101.0` は新規採用。

### 3. Ollama / v0.34.1（MLX safetensors の ollama create 標準化・/api/tags 高速化・リピート検出しきい値）

- 種別: OSS / ローカル LLM ランタイム（安定版）
- 関連: Ollama / ローカルLLM / Apple Silicon（MLX）
- 公開・更新日: 2026-09-14
- 概要: ローカルで LLM を実行する Ollama の安定版リリース。MLX safetensors の `ollama create` が実験的機能ではなくなり標準機能になった（GGUF モデルの作成は safetensor の変換・量子化に llama.cpp ツールの利用が必要）。Apple Silicon での MLX メモリ処理を改善。暴走リピートトークン検出は、誤検知（OCR など）を減らすため 100 リピートトークンを要求するように変更。大規模なモデルライブラリで `/api/tags` を大幅に高速化（「3.1s → 294ms（コールド計測）」）。モデルの能力（capabilities）の報告を一貫化。`typical_p` を非推奨化し、新規モデル作成時に設定できなくなった（既存 GGUF モデルは引き続きサポート）。MLX と llama.cpp の更新を同梱。
- 何が便利か: `/api/tags` の高速化で、多数のローカルモデルを持つ環境でも一覧取得が体感で速くなる。MLX safetensors からの `ollama create` が標準化され、Apple Silicon 上での自作モデル登録の導線が安定する。リピート検出しきい値の引き上げで、OCR のような正当な反復を含む出力の誤打ち切りが減る。
- 使いどころ: Mac（Apple Silicon）でローカル LLM を多数管理し、UI やスクリプトからモデル一覧を頻繁に叩く構成。safetensors 形式の重みを Ollama に取り込みたいとき。ローカルモデルをアプリのバックエンドに据えたオフライン/低コスト運用。
- 開発者にとっての価値: ローカル実行の実務的なボトルネック（一覧の遅さ、誤った出力打ち切り、モデル作成の実験扱い）が解消され、日常の検証ループが軽くなる。安定版なのでそのまま更新して試せる。
- 注意点: GGUF モデルの作成は safetensor の変換・量子化に llama.cpp ツールが必要になった点に注意。`typical_p` は新規モデルで設定不可（既存 GGUF は維持）。直後に出た `v0.34.2` は llama.cpp 更新中心の事前リリース（pre-release）。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.34.1
- 参考リンク: https://ollama.com/
- メモ: 変更内容は該当タグのページで verbatim 確認。過去の AI Tools News は `v0.34.0-rc1`（9/7）を扱っており、本項は安定版 `v0.34.1` の新規分。

### 4. Gemini CLI / v0.60.0（MCP OAuth の RFC 9207 発行体確認・拡張ローダのパス境界強化）

- 種別: CLI（安定版アップデート）
- 関連: Google AI / Gemini / Gemini CLI / MCP
- 公開・更新日: 2026-09-15
- 概要: Google 公式の Gemini CLI の安定版リリースで、セキュリティ強化が中心。MCP の OAuth フローで RFC 9207 の発行体識別（issuer identification）を強制。拡張ローダのパス解決と境界検証を強化し、システム全体の設定パスに対して厳格な権限・所有者チェックを強制。NTFS の 8.3 短縮名（SFN）を用いたパスの回避を緩和。信頼できないツール出力にエンベロープのメタデータ来歴（provenance）を強制。ほかに、web fetch ユーティリティの宛先検証と接続経路の改善、chrome-devtools MCP コンポーネントからのハードコードされた API キーの除去、ワークスペースのパス境界チェックとシンボリックリンク解決の改善、環境変数変更への同意プロンプト、サンドボックスコンテナ互換のための一時/設定ディレクトリ分離が入った。
- 何が便利か: MCP を OAuth で外部サーバーへ繋ぐ際、発行体識別の強制でトークンのすり替え・混同を防ぎやすい。拡張ローダやシステム設定パスの権限チェック強化で、悪意ある拡張や設定改ざんの経路を狭められる。信頼できないツール出力に来歴が付くことで、間接プロンプトインジェクションの検知・抑止につながる。
- 使いどころ: 外部 MCP サーバーや拡張を組み合わせて使うエージェント運用でのセキュリティ確保。共有マシンやコンテナ上で Gemini CLI を回し、設定・一時ファイルの分離を効かせたいとき。
- 開発者にとっての価値: エージェント CLI の攻撃面（MCP OAuth、拡張ローダ、パス解決、ツール出力の来歴）を公式が体系的に締めており、追加設定なしで安全側に寄る。
- 注意点: 本リリースは機能追加よりセキュリティ強化が主体。RFC 9207 発行体識別の強制により、対応していない OAuth 発行体との接続が弾かれる可能性がある。`v0.61.0-preview.0` / nightly は事前リリースで、安定版は `v0.60.0`。
