- OpenAI が **GPT-6 Sol / GPT-6 Luna** を 9/22〜9/23 に公開。GPT-6 Astra 系の派生で高速・低コスト化し、API 価格は Sol が入力 $2 / 出力 $10、Luna が入力 $0.10 / 出力 $0.50（いずれも 1M トークンあたり、恒久価格とされる）。API・Codex・ChatGPT で利用でき、GitHub Copilot にも同日追加された。

### 1. GPT-6 Sol / GPT-6 Luna

- 種別: モデル / API
- 関連: OpenAI / ChatGPT / Codex / GitHub Copilot
- 公開・更新日: 2026-09-22〜2026-09-23
- 概要: GPT-6 ファミリーの新モデル 2 種。フラッグシップの GPT-6 Astra に対し、Sol は「対話・エージェント的コーディング向けのバランス型」、Luna は「小さく速いタスク向けの軽量・最低コスト型」と位置づけられる。キャッシュと推論効率の改善により、GPT-5.6 の販促価格比でも 50% 安い API 価格を実現したと説明されている。価格は 1M トークンあたり Sol が入力 $2 / 出力 $10、Luna が入力 $0.10 / 出力 $0.50 で、OpenAI 広報は「恒久価格（販促ではない）」としている。
- 何が便利か: タスクの重さで Sol / Luna を使い分けられ、軽量処理を Luna に振ればコストを大きく圧縮できる。API・Codex・ChatGPT・GitHub Copilot と主要な開発面から同時に選べるため、既存ワークフローにモデル名の差し替えだけで載せやすい。
- 使いどころ: 分類・要約・整形など数の多い軽処理は Luna、マルチステップの検証を伴うコーディングやエージェントは Sol、という二段構え。Codex / Copilot のエージェントの既定モデルをコスト最適化したい場面。
- 開発者にとっての価値: Luna の入力 $0.10 / 出力 $0.50 は大量リクエストのバッチ処理やログ解析、テスト生成のような「量で効く」用途の単価を下げる。Sol はエージェント的コーディングの品質とコストのバランスを取りやすい。
- 注意点: 価格・ベンチはベンダー公表値・二次情報での確認が中心（`openai.com` はネットワーク制限で本文取得不可、公式リンクは併記）。コンテキスト長や詳細ベンチは自分のワークロードで検証してから本番採用するのが安全。ChatGPT 側は Free/Go でも Luna を試せるが、Sol の提供範囲は有料プラン中心。
- 公式リンク: https://openai.com/index/introducing-gpt-6-sol-and-luna/
- 参考リンク: https://community.openai.com/t/announcing-gpt-6-sol-and-gpt-6-luna-in-the-api-codex-and-chatgpt/1399925 / https://github.blog/changelog/2026-09-22-openais-gpt-6-sol-and-gpt-6-luna-now-available/
- メモ: 直近の記事（2026-09-23）は Anthropic Opus 5.5 が中心で、GPT-6 Sol / Luna は未掲載。本項が新規。GPT-5.6 系の Sol/Terra/Luna とは別世代なので名称の混同に注意。

#### 使用例

```bash
# Chat Completions でモデル名を差し替えるだけ（curl 例）
curl https://api.openai.com/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-6-luna",
    "messages": [{"role": "user", "content": "この差分を1行で要約して"}]
  }'
```

### 2. OpenAI Codex CLI / `rust-v0.156.1`（GPT-6 Sol / Luna をモデルピッカーに追加）

- 種別: CLI（OSS）
- 関連: OpenAI / Codex / GPT-6
- 公開・更新日: 2026-09-23
- 概要: `rust-v0.156.0`（フルスクリーン `/tui`・音声既定オン・`/usage`）に続くホットフィックス。モデルピッカーから **GPT-6 Sol / GPT-6 Luna を選択可能**にし、レート制限到達時の切り替えプロンプトが **GPT-6 Luna を推奨**するように変更された。単一 PR による小規模な追従リリース。
- 何が便利か: 新モデルをターミナルのエージェントからすぐ選べる。レート制限に当たったときに、より安価で速い Luna へ誘導されるため、長時間のセッションでコストと待ち時間を抑えやすい。
- 使いどころ: Codex を常駐エージェントとして回している開発環境で、重い処理は Sol、軽い処理やレート制限回避に Luna、と使い分ける運用。
- 開発者にとっての価値: モデル選択が CLI 側に組み込まれるため、環境変数や設定ファイルをいじらずにコスト最適なモデルへ切り替えられる。`rust-v0.156.0` の `/usage` ダッシュボードと組み合わせると消費トークンの管理がしやすい。
- 注意点: これは 0.156.0 の追従ホットフィックスで、機能追加はモデルカタログ中心。フルスクリーン TUI や音声などの主要機能は `rust-v0.156.0`（2026-09-23 の記事で既出）を参照。

### 3. Claude Code / `v2.1.281`（Bedrock ガードレール・assume_role・MCP エリシテーション）

- 種別: CLI（安定版）
- 関連: Anthropic / Claude / Claude Code / Amazon Bedrock
- 公開・更新日: 2026-09-23
- 概要: `v2.1.280`（Opus 5.5 既定化）に続く更新。Amazon Bedrock アップストリーム向けに **STS の `assume_role`**（AWS アカウントをまたいだロール引き受け）と **`guardrail: {id, version}`**（Bedrock ガードレール適用）を追加。新しい Claude Desktop キー向けに `blockReadsOutsideWorkingDirectories` / `disableBypassPermissionsMode` を持つ Claude apps ゲートウェイ対応、2026-07-28 プロトコル接続での **MCP URL モードのエリシテーション**、`/insights` に許可プロンプト削減を見積もる auto モード推奨を追加。バグ修正として、API リトライ中のセッションクラッシュ、`--max-turns` を無視する無限リトライ、再開セッションが過去ターンを別形で再送する問題、MCP サーバー切断時のプロンプトキャッシュ喪失、プロキシ/ゲートウェイで途中で切れた応答が完了扱いになる問題、巨大な初回プロンプトでの「Prompt is too long」からの回復を修正。
- 何が便利か: Bedrock 経由で Claude を使う組織で、クロスアカウントのロール引き受けとガードレールを Claude Code の設定で完結できる。MCP 切断時にキャッシュが飛ばなくなり、長いエージェントセッションのコストと安定性が改善する。
- 使いどころ: AWS Bedrock をバックエンドにしたエンタープライズ運用、多数の MCP サーバーを常時接続するエージェント構成、`--max-turns` で上限を切って自動実行させるバッチ的な使い方。
- 開発者にとっての価値: リトライ・再開・キャッシュまわりの修正は、長時間・多ターンのエージェント運用でのコスト超過や暴走を直接防ぐ。Bedrock ガードレールをコマンドラインの設定で適用できるため、コンプライアンス要件のあるチームで導入しやすい。
- 注意点: Bedrock 関連機能は Bedrock アップストリーム利用時のみ有効。`disableBypassPermissionsMode` 等はセキュリティ設定なので、既存の権限運用と整合するか確認してから有効化する。
- 公式リンク: https://github.com/anthropics/claude-code/releases
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 直近記事（2026-09-23）は `v2.1.280`（Opus 5.5 既定化）を掲載。本項は `v2.1.281` の Bedrock 強化・MCP エリシテーション・リトライ/キャッシュ修正が新規。

### 4. GitHub Copilot for JetBrains `1.18.0`（AI 支援のツール承認・共有スキル/指示）

- 種別: 拡張機能（IDE プラグイン）
- 関連: GitHub Copilot / JetBrains（IntelliJ 系 IDE）
- 公開・更新日: 2026-09-22
- 概要: JetBrains 版 Copilot の更新。**AI 支援のツール承認**がパブリックプレビューで追加され、Copilot エージェントのセッションで **低リスクなツール呼び出しは自動承認、高リスクな操作はユーザーに確認**を求める。あわせて、エージェントとの会話をより細かく制御する機能と、組織で共有できるスキル・指示（instructions）に対応した。
- 何が便利か: エージェントの一つ一つの操作をすべて手動承認しなくても、危険度に応じて自動/確認が振り分けられるため、承認の手間と暴走リスクのバランスを取りやすい。組織共通のスキル・指示を配ることで、チーム全体のエージェント挙動を揃えられる。
- 使いどころ: IntelliJ / PyCharm など JetBrains IDE で Copilot エージェントを使う開発チーム、エージェントの権限管理をチームポリシーとして統一したい組織。
- 開発者にとっての価値: ツール承認の自動化は、エージェント運用の「確認疲れ」を減らしつつ、破壊的操作の歯止めを残せる。共有スキル/指示は個人設定に依存しない再現性のあるエージェント運用につながる。
- 注意点: AI 支援のツール承認はパブリックプレビュー段階のため、挙動の変化や制限がある前提で使う。何を「低リスク」と判定するかは要検証で、重要な操作は確認要求が出るか事前にテストするのが安全。
- 公式リンク: https://github.blog/changelog/2026-09-22-new-features-and-improvements-in-copilot-for-jetbrains/
- 参考リンク: https://github.blog/changelog/
- メモ: 同日 9/22 の GitHub Changelog では Copilot への Opus 5.5 追加・GPT-6 Sol/Luna 追加・Copilot アプリの OpenTelemetry 対応も告知。本項は JetBrains 版のツール承認・共有スキルを新規として採用。
