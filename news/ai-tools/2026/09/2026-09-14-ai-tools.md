## 今日の注目

### 1. Anthropic Python SDK / anthropic v1.5.0（公開GitHubリポジトリのマウント・auto権限・to_param）

- 種別: OSS / Python SDK（安定版）
- 関連: Anthropic / Claude / Managed Agents
- 公開・更新日: 2026-09-10
- 概要: Anthropic 公式 Python SDK のリリース。Managed Agents セッションで、認可トークン（`authorization_token`）なしに公開 GitHub リポジトリをマウントできるようになった（`support mounting public GitHub repositories without an authorization_token in Managed Agents sessions`）。Managed Agents 向けに `auto` モードのツール権限を追加（サーバー側が各ツール呼び出しを評価して実行・拒否・承認待ちに振り分ける仕組みの SDK 側対応）。`Message.to_param()` / `BetaMessage.to_param()` を追加し、受け取ったメッセージを次のリクエストの入力へそのまま戻せる。`messages.create` / `parse` / `stream` / `count_tokens` でツールオブジェクトを直接受け付けるように変更。`web_fetch` ツールに `content_too_large` エラーコード、`user-profiles-2026-09-04` ベータ値と `external_user_details`、`CredentialsError` / `IdentityTokenFileError` も追加。バグ修正では、クライアントフックの実行前に `extra_body` をマージ、グループ/他ユーザーから読める資格情報ファイルを拒否、部分的なツール入力 JSON をコンテンツブロックに載せない、などが入った。
- 何が便利か: エージェント実行環境に「公開リポジトリを認証なしで持ち込む」導線が公式 SDK で整い、サンプルや OSS を対象にしたエージェント検証がしやすい。`to_param()` で往復のメッセージ整形コードを書かずに会話を継続でき、ツールオブジェクトを直接渡せるためツール定義の取り回しが簡潔になる。
- 使いどころ: Managed Agents で公開 OSS リポジトリを対象にコード調査・改修を試すとき。マルチターンのツール利用エージェントで、直前の応答を次リクエストへ戻す実装を短く書きたいとき。資格情報ファイルのパーミッションを厳格化したいセキュリティ運用。
- 開発者にとっての価値: 公式 SDK の安定版で、Managed Agents とツール利用まわりの定型コードを減らせる。資格情報ファイルの権限チェック強化はそのまま安全性向上につながる。
- 注意点: 公開 GitHub リポジトリのマウントと `auto` 権限は Managed Agents が前提。`auto` 権限ポリシー自体は 9/10 の Claude Developer Platform 更新（前回9/11記事で既出）で、本項はその Python SDK 側の対応にあたる。ベータ機能（user-profiles など）は仕様変更の可能性あり。
- 公式リンク: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v1.5.0
- 参考リンク: https://github.com/anthropics/anthropic-sdk-python/blob/main/CHANGELOG.md
- メモ: 変更内容は公式 CHANGELOG.md で verbatim 確認済み。過去の AI Tools News では anthropic Python SDK 単体を扱っておらず、新規採用。

#### 使用例

```bash
# 公式 Python SDK を最新化
pip install --upgrade "anthropic>=1.5.0"
```

### 2. pydantic-ai / v2.41.0〜v2.43.0（画像生成 ImageGenerator・Codex/Copilot プロバイダー・clai バナー）

- 種別: OSS / Python エージェントフレームワーク（安定版）
- 関連: Pydantic / OpenAI / GitHub Copilot
- 公開・更新日: 2026-09-07〜2026-09-12（v2.41.0=9/7、v2.42.0=9/8、v2.43.0=9/11〜12）
- 概要: 型安全なエージェントフレームワーク pydantic-ai の連続リリース。`v2.41.0` で画像生成 API `ImageGenerator` を追加し、OpenAI Codex プロバイダー（サブスクリプション認証で Codex を利用）を導入。あわせて `fallback_model` を非推奨とし `fallback_subagent_model` へ移行した。`v2.42.0` で GitHub Copilot プロバイダー（OpenAI 互換 API 経由で Copilot のモデルにアクセス）を追加し、`DeferredToolResults.approvals` の検証強化と Bedrock のサンプリング設定の扱いを改善。`v2.43.0` は CLI `clai` に「その実行内容を説明する初回バナー」を追加してセッションを開くようにし、`OpenAIChatModel` でツール呼び出し後のテキスト境界を保持するよう修正、時刻系ツールのオプトアウト判定を操作種別ベースに是正した。
- 何が便利か: エージェント定義に画像生成を組み込め、OpenAI Codex や GitHub Copilot のモデルを既存のサブスクリプション/互換 API 経由で呼び分けられる。フォールバックがサブエージェント単位で指定でき、多段構成でモデル切替を制御しやすい。`clai` を使えばターミナルからそのままエージェントを試せる。
- 使いどころ: 複数プロバイダー（OpenAI / Codex / Copilot / Anthropic など）を横断してエージェントを組み、コスト・可用性でフォールバックさせたいとき。画像生成をツールの一部に混ぜたいとき。CLI で素早くプロトタイプを回したいとき。
- 開発者にとっての価値: プロバイダー抽象が広がり、型安全なまま「どのモデルで動かすか」を差し替えられる。CLI `clai` により導入コストが低く、その日のうちに試せる。
- 注意点: `fallback_model` は非推奨化されたため、既存コードは `fallback_subagent_model` への移行が必要。GitHub Copilot / OpenAI Codex プロバイダーはそれぞれの契約・認証が前提。バージョンの刻みが速いので利用時は最新のリリースノートを確認のこと。
- 公式リンク: https://github.com/pydantic/pydantic-ai/releases
- 参考リンク: https://ai.pydantic.dev/
- メモ: 各バージョンの内容は GitHub Releases ページで確認。過去の AI Tools News では pydantic-ai を扱っておらず、新規採用。

#### 使用例

```bash
# インストール（CLI clai も同梱）
pip install --upgrade pydantic-ai

# clai を起動（v2.43.0 以降は初回に実行内容を説明するバナーが出る）
clai
```

### 3. LiteLLM / v1.102.0-rc.1（AWS Secrets Manager 顧客管理 KMS・Agent Skills インデックス・MCP認可）

- 種別: OSS / LLM ゲートウェイ・プロキシ（事前リリース / RC）
- 関連: LiteLLM / AWS / MCP
- 公開・更新日: 2026-09-13
- 概要: 100 以上の LLM プロバイダーを OpenAI 互換 API に統一する LiteLLM の事前リリース（RC）。AWS Secrets Manager での顧客管理 KMS キー対応、Agent Skills の well-known インデックスエンドポイント、MCP（Model Context Protocol）まわりでプロキシのログ・認可カバレッジ保持を追加。パフォーマンス面では、プロバイダー passthrough ルートの遅延ロード、post-call スペンドカウンタでの単一 MGET / パイプライン化、認証データのDBクエリ削減が入った。安定性では Redis のサーキットブレーカ挙動の改善、Bedrock ストリームのスペンド解析最適化、失敗リクエストのスペンドログ処理の是正など。UI では Key Activity をエイリアス/ハッシュ/ユーザーID/メールで検索できるようになった。前リリース以降で 101 コミットを含む。
- 何が便利か: シークレット管理を顧客管理 KMS キーで固められ、MCP 利用時のプロキシのログ・認可が抜け落ちないため、ゲートウェイ経由でも監査・課金の追跡が安定する。スペンド集計の Redis 最適化で高トラフィック時の負荷が下がる。
- 使いどころ: 複数プロバイダーを 1 つのプロキシに集約し、キー管理・コスト集計・MCP ツール利用を一元運用している構成。エンタープライズのシークレット/監査要件を満たしたいとき。
- 開発者にとっての価値: 自前でプロバイダー差異やキー管理・スペンド集計を書かずに済む範囲が広がる。MCP と Agent Skills 対応が進み、エージェント基盤のハブとして使いやすくなる。
- 注意点: これは事前リリース（`v1.102.0-rc.1`）で本番向け安定版ではない。検証用に `--pre` で明示インストールする想定で、本番では安定版（直近では `v1.100.1`）の利用を推奨。RC は仕様が変わる可能性がある。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.102.0-rc.1
- 参考リンク: https://docs.litellm.ai/
- メモ: リリース内容は該当タグのページで確認。前回までの AI Tools News が採用した安定版は `v1.100.0`（9/7記事）で、`v1.101.x` / `v1.102.0` 系は RC/dev のみが進行中。本記事では「今日から検証できる直近リリース」として RC を明記の上で採用した。

# 本番運用は安定版を推奨
