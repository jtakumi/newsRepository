## 今日の注目

### 1. OpenAI Codex / rust-v0.153.4（GPT-6-Astra をバンドル既定に、ピッカー表示を修正）

- 種別: CLI（安定版）
- 関連: OpenAI / Codex / GPT-6-Astra
- 公開・更新日: 2026-09-04 23:27 UTC（JST 2026-09-05 08:27）※ `rust-v0.153.4`
- 概要: OpenAI のコーディングエージェント Codex CLI の連続パッチ。前回 09-05 記事で扱った `rust-v0.153.3`（GPT-6-Astra を Amazon Bedrock ピッカーへ追加）の直後の増分で、今回はバンドル同梱のモデルピッカーまわりを整備。
- 何が便利か:
  - **GPT-6-Astra をバンドルのモデルピッカーで正しく表示**する不具合を修正。Astra を選びたいのに一覧に出てこない、という問題が解消される。
  - **モデル未設定時のバンドル既定を GPT-6-Astra に変更**。明示的にモデルを指定していないユーザーは、更新後そのまま Astra で動く。
  - **Astra の非同期質問（async question）ガイダンスを修正**：対応ツールがセッションにある場合にのみ非同期質問を使うよう挙動を明確化。
- 使いどころ:
  - **GPT-6-Astra を既定モデルとして Codex を回したい**とき（`0.153.4` に上げれば未設定でも Astra が既定）。
  - モデルピッカーに Astra が出ない・選べないという **表示不具合を踏んでいる**とき。
- 開発者にとっての価値: `npm i -g @openai/codex@0.153.4` で今日すぐ更新できる。新モデル GPT-6-Astra を「明示設定なしで既定利用」できるようになり、切り替えの手間が減る。機能追加というより新モデルへの導線整備が中心。
- 注意点: 既定モデルが Astra に変わるため、これまで別モデルを暗黙に使っていた場合は挙動・コストが変わりうる。モデルを固定したい場合は明示指定する。タグは `rust-v0.153.4`。`0.154.0-alpha.*` は pre-release のため対象外。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.153.4
- 参考リンク: https://github.com/openai/codex/releases/tag/rust-v0.153.3
- メモ: 前回 09-05 記事は `rust-v0.153.2` / `0.153.3` を採用。今回は `0.153.4` を新規採用（Astra を既定化するパッチ）。

#### 使用例

```bash
npm i -g @openai/codex@0.153.4
codex --version
# 未設定なら GPT-6-Astra が既定で使われる。
# モデルを固定したい場合は明示指定（例）:
#   codex --model gpt-6-astra
```

### 2. opencode / v1.18.29（Codex OAuth のモデルフィルタが gpt-6 を認識、Astra の表示不具合を修正）

- 種別: CLI / OSS（コーディングエージェント）
- 関連: sst / opencode / OpenAI Codex / GPT-6-Astra
- 公開・更新日: 2026-09-04 23:47 UTC（JST 2026-09-05 08:47）※ `v1.18.29`
- 概要: ターミナル型のオープンソース・コーディングエージェント opencode の新パッチ。前回 09-05 記事で扱った `v1.18.28`（Copilot リクエスト追跡ヘッダー・デスクトップ認証修正）の次のパッチで、こちらも GPT-6 系モデルの認識まわりを修正。
- 何が便利か:
  - **Codex の OAuth モデルフィルタが `gpt-6` のような整数バージョン表記を認識**：これまで弾かれていた `gpt-6` 系のモデル名が正しく通るようになる。
  - **OpenAI サブスクリプション利用者で `gpt-6-astra` が表示されない問題を修正**：opencode 側でも Astra を選べるようになる。
  - コミュニティ貢献として、**中国語表示のドキュメント修正**、**コンソールのクォータリセット対応**が入った。
- 使いどころ:
  - **opencode から OpenAI（Codex OAuth）経由で GPT-6 / GPT-6-Astra を使いたい**が、モデル一覧に出てこない・選べないとき。
  - OpenAI サブスクリプションで opencode を運用しているとき。
- 開発者にとっての価値: OSS のため自前運用しやすく、`v1.18.29` に上げるだけで GPT-6 系モデルの認識・表示不具合が解消する。新モデルを opencode の既存ワークフローに載せるための実務的な修正。
- 注意点: 今回は表示・フィルタ系のバグ修正が中心で、機能追加は限定的。前回 09-05 記事で `v1.18.28` を扱っているため、差分は `v1.18.29`。

### 3. Vercel AI SDK / @ai-sdk/openai@4.0.60（GPT-6 の reasoning 設定オプションを追加）

- 種別: OSS ライブラリ（npm・プロバイダパッケージ）
- 関連: Vercel / AI SDK / OpenAI / GPT-6
- 公開・更新日: 2026-09-05 18:26 UTC（JST 2026-09-06 03:26）※ `@ai-sdk/openai@4.0.60`
- 概要: Vercel AI SDK の OpenAI プロバイダパッケージの新パッチ。変更点は **「GPT-6 の reasoning（推論）設定アップデートを追加」**。同種の更新は `@ai-sdk/azure` / `@ai-sdk/amazon-bedrock` などの兄弟パッケージにも同日展開された。
- 何が便利か:
  - **GPT-6 の reasoning 設定を AI SDK 側から指定できる**ようになる。新モデルの推論まわりの挙動をコードから制御しやすくなる。
  - AI SDK 本体（`ai@7.0.93`）を据え置いたまま、**プロバイダパッケージだけ上げれば GPT-6 対応が入る**。プロバイダ層に閉じた更新なのでアプリ全体の破壊的変更リスクが小さい。
- 使いどころ:
  - AI SDK で **OpenAI / Azure OpenAI / Bedrock 経由の GPT-6 を使うアプリ**を組んでいて、推論設定を明示したいとき。
  - 既存の `ai` アプリで **GPT-6 に載せ替える**際のプロバイダ更新。
- 開発者にとっての価値: `npm i @ai-sdk/openai@4.0.60` で今日すぐ更新できる。新モデルの推論オプションをアプリのコードから扱えるようになり、GPT-6 を使う実装の見通しが良くなる。
- 注意点: これは AI SDK 本体（`ai`）ではなく **OpenAI プロバイダパッケージ**の更新。GitHub のリリースページは一時的に読み込みエラーを出しており、詳細な設定キー名は公式ドキュメント側で確認するのが確実。`4.0.x` 系のほか `3.0.x` / `2.0.x` 系にも同日パッチが出ている。
