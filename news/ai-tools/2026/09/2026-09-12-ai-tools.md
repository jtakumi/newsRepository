# 2026-09-12 AI Tools News

## 今日の要点

- Claude Code が `v2.1.269`（9/11 UTC 公開・日本時間 9/12 未明）で `claude plugin eval`（プラグインの eval スイート実行）、`/focus`・`/output-style` の新コマンド、Bash が変更したファイルの差分表示、並行エージェント上限を上げる `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` を追加。プラグイン開発と長時間セッションの制御が一段強化された。
- OpenAI Codex の Python SDK（`openai-codex`）が `0.154.0`（9/10 公開）で reasoning-effort に `max` / `ultra` を追加し、`ExternalMessage` によって外部コンテンツからツール権限付きでターンを開始・合流できるようになった。エージェントをコードから組み込む用途に効く。
- Vercel AI SDK が `ai@7.0.98`（9/11 UTC 公開・日本時間 9/12 未明）で、バッチ処理内での画像生成対応、`embed` / `embedMany` / `rerank` への runtime context 付与、ツール出力エラー用の安定した UI メッセージ型・型ガードを追加した。

## 今日の注目

### 1. Claude Code / v2.1.269（`claude plugin eval`・`/focus`・`/output-style`・並行エージェント上限）

- 種別: CLI / コーディングエージェント（安定版）
- 関連: Anthropic / Claude Code
- 公開・更新日: 2026-09-11（UTC 18:12、日本時間 9/12 未明）
- 概要: 直近リリース。`claude plugin eval` でプラグインの eval スイートを実行し、スコア付き・再現可能な結果を得られる。`/output-style [name]` で出力スタイルの一覧・切り替えをセッションをまたいで行え、`/focus` はプロンプトと応答サマリに絞った表示に切り替える。Bash コマンドが変更したファイルの差分をファイル編集の扱いの中で表示するようになり、`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（1〜256）で並行エージェント数の上限を引き上げられる。OpenTelemetry メトリクスにリポジトリ属性を付ける `OTEL_METRICS_INCLUDE_REPOSITORY`、ゲートウェイのモデル探索タイムアウトを調整する `CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS` も追加。加えて、出力トークン上限で切れた後の prompt cache 無効化や、割り込み後のセッション再開でキャッシュ再利用を損なうコンテキスト再送などのキャッシュ回りの不具合を多数修正した。
- 何が便利か: プラグイン作者は `claude plugin eval` で品質を数値化し、CI 的に回帰を検出できる。`/focus` は長い履歴で要点だけを見たいときに視認性を上げ、`/output-style` は用途ごとの出力形式を素早く切り替えられる。Bash 変更ファイルの差分表示で、コマンド実行による変更も編集と同じ粒度でレビューできる。
- 使いどころ: プラグイン開発の品質担保、複数エージェントを束ねる Workflow のスループット調整、長時間セッションでの表示整理。
- 開発者にとっての価値: プラグインの検証手段が標準コマンド化され、テレメトリ・並行度・キャッシュ安定性という運用面がまとめて底上げされる。
- 注意点: クラウド同期のスキルは `anthropic-skills:<name>` 形式の命名に変更された。既存の参照名を使っている場合は追従が必要。並行エージェント上限は環境のリソースに見合う値に設定すること。
- 公式リンク: https://code.claude.com/docs/en/changelog
- 参考リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- メモ: 9/11公開の `2026-09-11-ai-tools.md` は `v2.1.268` までを扱ったため、`v2.1.269` を新規採用。npm の公開時刻（`2026-09-11T18:12Z`）で日付を確認済み。

#### 使用例

```bash
# プラグインの eval スイートを実行してスコア付き結果を得る
claude plugin eval

# 出力スタイルを一覧・切り替え
/output-style

# プロンプトと応答サマリに絞った表示へ
/focus

# Workflow の並行エージェント上限を引き上げる（settings.json など）
# "CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS": 16
```

### 2. OpenAI Codex Python SDK / openai-codex 0.154.0（`max`/`ultra` エフォート・`ExternalMessage`）

- 種別: OSS / Python SDK（安定版）
- 関連: OpenAI / Codex
- 公開・更新日: 2026-09-10
- 概要: ターミナル型 Codex とは別配布の Python SDK（PyPI パッケージ `openai-codex`、Python 3.10+）。reasoning-effort に `max` と `ultra` の値を追加。同期・非同期の `run()` / `turn()` に `ExternalMessage` を導入し、「外部コンテンツがターンを開始する、あるいは実行中の通常ターンにツールレベルの権限で合流する」ことができる。再開・フォーク時に履歴の取り込みを制御する `include_turns`、新規ターンの `turn_service_tier`、`source` メタデータの追跡も追加。生成プロトコルモデルと通知を刷新し、turn-start 応答より前に完了イベントが届くケースの扱いを改善した。
- 何が便利か: エフォートの上限に `max` / `ultra` が入ったことで、難しいタスクに計算量を寄せる制御がしやすくなる。`ExternalMessage` により、Webhook やキュー等の外部入力を起点にエージェントのターンを駆動しつつ、必要なツール権限を与えられる。
- 使いどころ: 自前のアプリ・バックエンドに Codex エージェントを組み込み、外部イベント起点で自律実行させたいとき。難易度に応じてエフォートを段階的に上げたいとき。
- 開発者にとっての価値: CLI ではなくコードから Codex を制御する経路が強化され、外部システム連携とエフォート制御の粒度が上がる。
- 注意点: 破壊的変更あり。`HookMetadata` は `.root` 経由でアクセスする形（例: `hook.root.command`）に変わり、通知はタイプ付きペイロードになった。カスタム CLI オーバーライドを使う場合は `0.151.0` 以降が必要。CLI 側（`rust-v0.154.0`）とはバージョン体系が別なので混同しないこと。
- 公式リンク: https://github.com/openai/codex/releases/tag/python-v0.154.0
- 参考リンク: https://pypi.org/project/openai-codex/
- メモ: 9/11記事で扱ったのは Codex CLI（Rust 配布 `rust-v0.154.0`）で、本項はそれとは別の Python SDK。PyPI で最新版が `0.154.0` であることを確認済み。

#### 使用例

```bash
# Python SDK を最新へ更新
pip install --upgrade openai-codex==0.154.0
```

### 3. Vercel AI SDK / ai@7.0.98（バッチ内画像生成・埋め込みへの runtime context・ツール出力エラーの型）

- 種別: OSS / TypeScript ライブラリ（安定版パッチ）
- 関連: Vercel / AI SDK
- 公開・更新日: 2026-09-11（UTC 18:56、日本時間 9/12 未明）
- 概要: バッチリクエスト内での画像生成をサポート。`embed` / `embedMany` / `rerank` の各操作に runtime context の属性付与を追加。ツール出力エラー用に安定した UI メッセージ型と型ガードを導入し、`validateUIMessages` で推論されたツールを受け付けるようにした。あわせて、未対応のバッチリクエスト種別を拒否する修正、reranking のプロバイダーインデックスが不正な場合に拒否する修正、gateway / provider / provider-utils 依存の更新が入っている。
- 何が便利か: これまでテキスト中心だったバッチ処理で画像生成も投入でき、埋め込み・再ランク処理に実行時コンテキストを紐付けて観測・制御しやすくなる。ツール出力エラーの型が安定したことで、UI 側でのエラーハンドリングを型安全に書ける。
- 使いどころ: 大量の画像生成をバッチで回す処理、RAG の埋め込み・再ランク処理を runtime context 付きで運用する場面、ツール実行結果の UI 表示。
- 開発者にとっての価値: バッチ・埋め込み・UI メッセージ型という利用頻度の高い箇所が同時に底上げされ、独自の型定義や回避コードを減らせる。
- 注意点: パッチリリースの積み上げで単体では小さめの追加。バージョンは頻繁に更新されるため、利用時に最新を確認すること。
- 公式リンク: https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md
- 参考リンク: https://ai-sdk.dev/
- メモ: 9/11記事は `7.0.97` までを扱ったため `7.0.98` を新規採用。npm の公開時刻（`2026-09-11T18:56Z`）で日付を確認済み。

#### 使用例

```bash
# 最新パッチへ更新
npm install ai@7.0.98
```
