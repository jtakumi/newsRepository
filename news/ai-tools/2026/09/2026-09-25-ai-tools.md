- OpenAI が **GPT-6 Sol / GPT-6 Luna**（API ID `gpt-6-sol` / `gpt-6-luna`）を 9/22 に公開。**API 価格を約 50% 引き下げ**（Sol: 入力 $2 / 出力 $10、Luna: 入力 $0.10 / 出力 $0.50 per 1M）、しかもこれは恒久価格。Sol はコード生成・レビュー・デバッグなど反復的な開発作業向け、Luna は抽出・要約など大量ルーチン処理向け。API・ChatGPT Work・Codex・GitHub Copilot で利用可能。
- Claude Code が **`v2.1.281`（9/23）・`v2.1.282`（9/24）** を連続公開。`settings.json` の **`"attribution": false`**（コミット/PR 帰属表記の全非表示）、Bedrock アップストリームの **`assume_role`（クロスアカウント IAM）**、`claude plugin validate` の **MCP サーバー検証**、ワイド端末で本文幅を抑える **`maxProseWidth`**、Web 検索結果を含む会話が 400 エラーになる不具合修正などを追加。
- Gemini CLI が **安定版 `v0.61.0`（9/23）** を公開。**ビルドファイル改変や信頼できないフラグ経由の間接プロンプトインジェクション対策**、ファイルシステム境界の強化とランタイム状態の分離、明示的なバージョン付き Flash モデル ID の保持など、**セキュリティ強化が中心**。

## 今日の注目

### 1. GPT-6 Sol / GPT-6 Luna / `gpt-6-sol`・`gpt-6-luna`

- 種別: モデル / API
- 関連: OpenAI / ChatGPT / Codex / GitHub Copilot
- 公開・更新日: 2026-09-22
- 概要: OpenAI の新しいコスト効率重視モデル 2 種。既存の GPT-6-Astra 系と同様の手法で、専門作業・事実性・コーディング・コンピュータ操作・アライメントを改善したとされる。**GPT-6 Sol** は機能実装・コードレビュー・デバッグ・データ分析といった「開発者/ナレッジワーカーが繰り返す複雑な作業」向け、**GPT-6 Luna** は情報抽出・文書要約・単純な問い合わせ対応など「目的が狭く予測しやすい大量ルーチン処理」向け。Sol は GPT-5.6 Sol 比で「ミスが約半分」と説明されている。
- 何が便利か: **API 価格が前世代比で約 50% 下がり**（Sol: 入力 $2 / 出力 $10、Luna: 入力 $0.10 / 出力 $0.50 per 1M トークン）、かつ OpenAI はこれを「プロモーションではなく恒久価格」と明言。モデル ID を差し替えるだけで既存の OpenAI API 実装に載せ替えできる。
- 使いどころ: コードレビュー・リファクタ・バグ修正など反復的なエージェント処理は Sol、ログ要約・データ抽出・分類・大量の定型応答は Luna、というように**タスクの複雑さでモデルを使い分けてコスト最適化**する構成。Codex や GitHub Copilot ではモデルピッカーから選択可能。
- 開発者にとっての価値: 出力トークン単価が Sol で $20→$10、Luna で $1.20→$0.50 と大きく下がるため、出力量の多いエージェントやバッチ処理の実効コストが下がる。Luna は特に単価が低く、抽出・分類・要約の大量ジョブを安価に回せる。
- 注意点: ベンチ改善やスピードの数値はベンダー公表値のため、自分のワークロードで検証してから本番採用するのが安全。EU データレジデンシーは Standard 処理のみ対応で、リージョナル処理エンドポイントは 10% の上乗せ課金がある点に注意。9/22 時点では ChatGPT の Chat モードには未提供（Work / Codex 側から）。
- 公式リンク: https://openai.com/index/introducing-gpt-6-sol-and-luna/
- 参考リンク: https://techcrunch.com/2026/09/22/openai-launches-gpt-6-sol-and-luna/ , https://developers.openai.com/api/docs/pricing
- メモ: 過去記事（09-05〜09-11）で扱った「GPT-6 / GPT-6-Astra」とは別の新モデル（Sol / Luna）。安価な下位ティアで Astra 系の改善を取り込みつつ価格を半減させた点が新規。

#### 使用例

```bash
# OpenAI API でモデル ID を差し替えるだけ（curl 例）
# 反復的な開発作業は Sol
curl https://api.openai.com/v1/responses \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-6-sol",
    "input": "Review this diff for correctness bugs."
  }'

# 大量の抽出・要約など安価に回したいときは Luna
# -> "model": "gpt-6-luna"
```

### 2. Claude Code / `v2.1.281`・`v2.1.282`（attribution 非表示・Bedrock クロスアカウント・maxProseWidth）

- 種別: CLI（安定版）
- 関連: Anthropic / Claude / Claude Code
- 公開・更新日: 2026-09-23（`v2.1.281`）／2026-09-24（`v2.1.282`）
- 概要: 09-23 記事で扱った `v2.1.280`（Opus 5.5 既定化）の後続 2 リリース。`v2.1.281` は `settings.json` に **`"attribution": false`** を追加してコミット/PR の帰属表記を全非表示にでき、Claude apps gateway の Bedrock アップストリームに **`assume_role`（クロスアカウント IAM ロール引き受け）** と Amazon Bedrock ガードレール（`guardrail: {id, version}`）を適用、`claude plugin validate` に **MCP サーバー検証**、MCP の URL-mode elicitation（2026-07-28 プロトコル）、クラウドセッションへの**別 GitHub オーナーのリポジトリ添付**を追加。`v2.1.282` はワイド端末で本文の折返し幅を抑える **`maxProseWidth`**（表・コードブロックは全幅維持）、無視/無効化されたテレメトリ変数を起動時・`/status`・`claude doctor` で通知、**Web 検索結果を含む会話が毎回 400 エラーになる不具合**や `redacted_thinking` ブロック関連の API エラー、再開セッションが過去メッセージを改変して再送する不具合などを修正。
- 何が便利か: `"attribution": false` により、社内規約で自動生成の帰属行を付けたくないチームがコミット/PR をクリーンに保てる。`maxProseWidth` はワイドディスプレイで長文が横に伸びすぎて読みにくい問題を解消。`assume_role` はゲートウェイ経由で複数 AWS アカウントの Bedrock を跨いで使う構成を簡素化する。
- 使いどころ: 帰属表記のポリシーがあるチーム、ワイドモニタで Claude Code を使う開発者、Bedrock をクロスアカウントで運用する組織、プラグイン/MCP を検証・CI に組み込みたい場面。
- 開発者にとっての価値: `claude plugin validate` の MCP 検証はプラグイン配布前の品質チェックを自動化できる。Web 検索結果を含む会話の 400 エラー修正や再開セッションの改変再送修正は、長時間セッションの信頼性に直結する重要な修正。
- 注意点: `"attribution": false` はチームの貢献可視化ポリシーと矛盾しないか要確認。`v2.1.281` の「auto モードを直接 Anthropic API 接続かつテレメトリ off のときサーバー側分類器を既定化」など既定挙動の変更を含むため、独自設定がある場合は再確認するとよい。
- 公式リンク: https://github.com/anthropics/claude-code/releases
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 09-23 記事は `v2.1.280`（Opus 5.5 既定化・MCP 説明長制御）まで。本項の `v2.1.281`（attribution 非表示・Bedrock クロスアカウント・MCP 検証）と `v2.1.282`（maxProseWidth・400 エラー修正）は新規。

#### 使用例

```bash
# 最新へ更新
claude update

# コミット/PR の帰属表記を全非表示にする（settings.json）
# { "attribution": false }

# ワイド端末で本文幅を抑える（settings.json）
# { "maxProseWidth": 100 }

# プラグインを配布前に検証（MCP サーバー検証を含む）
claude plugin validate
```

### 3. Gemini CLI / 安定版 `v0.61.0`（プロンプトインジェクション対策・境界強化）

- 種別: CLI（OSS）
- 関連: Google / Gemini / Gemini CLI
- 公開・更新日: 2026-09-23
- 概要: Google のターミナル型エージェント Gemini CLI の**安定版 `v0.61.0`**。**ビルドファイルの改変や信頼できないフラグ経由の間接プロンプトインジェクションを防止**、ファイルシステム境界の強化とランタイム状態の分離、明示的なバージョン付き Flash モデル ID の保持、`AgentLoopContext` のプロパティがオブジェクトスプレッド越しに保持されるよう修正、などセキュリティ・堅牢性の改善が中心。
- 何が便利か: エージェントにコード生成・実行を任せる際、リポジトリ内のビルド設定ファイルや外部から渡されるフラグを悪用した間接的な指示注入への耐性が上がる。バージョン付き Flash モデル ID を保持するため、意図したモデルが勝手に置き換わらない。
- 使いどころ: CI や自動化パイプラインで Gemini CLI を回す構成、外部リポジトリや PR の内容をエージェントに読ませる場面など、**信頼できない入力を扱うエージェント運用**。
- 開発者にとっての価値: 間接プロンプトインジェクションはエージェント運用で現実的な脅威であり、境界強化・ランタイム状態分離を含む安定版が出たことで、本番寄りの環境に載せやすくなる。nightly/preview ではなく安定版タグである点も採用しやすい。
- 注意点: セキュリティ修正が中心のため、大きな新機能を期待する更新ではない。既存のフラグやビルドファイル経由の挙動に依存した独自運用がある場合は、境界強化で挙動が変わらないか確認する。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.61.0
- 参考リンク: https://geminicli.com/docs/changelogs/
- メモ: 09-23 記事では「`v0.61.0` は nightly のみで安定版未確認のため見送り」としていたが、9/23 に安定版 `v0.61.0` が公開されたため本項で採用。安定版 `v0.60.0` は 09-21 記事で既出。

### 4. Cursor / Rollouts・Security Review（デプロイ監視とPRセキュリティレビューのBot）

- 種別: Web サービス（IDE Bot 機能）
- 関連: Cursor
- 公開・更新日: 2026-09-23
- 概要: Cursor が「コードを出荷する最後の一手」を担う 2 つの Bot を公開。**Rollouts** は各 PR に監視を紐づけ、変更がデプロイされる様子を追跡して**環境ごとの変更ヘルス（healthy / regression detected / inconclusive）を報告**する。PR が開くと差分と関連システムを読み、**リスク・意図した効果・監視するシグナル・計装のギャップを PR コメントに監視プランとして書き出す**。**Security Review** は各 PR で**悪用可能なバグを報告**する。いずれも Firetiger の Change Monitors を Cursor の Bot Development Kit で作り直したもの。
- 何が便利か: PR ごとに「デプロイ後に何が壊れうるか・何を監視すべきか」を自動でコメント化してくれるため、レビュアーがリリース観測の観点を明文化する手間が省ける。Security Review は実際に悪用可能な脆弱性に絞って報告する。
- 使いどころ: 継続的デプロイを回しているチームで、PR 段階からデプロイ後の観測性とセキュリティを組み込みたい場面。
- 開発者にとっての価値: 変更のヘルスを環境別に自動判定する仕組みを自前構築せずに使える。PR 上で監視プランとセキュリティ指摘が可視化されるため、レビュー→デプロイの導線が締まる。
- 注意点: **Teams / Enterprise プラン限定**の機能。監視プランやセキュリティ指摘は自動生成のため、実際の計装・アラート設計は人手での確認が必要。
- 公式リンク: https://cursor.com/changelog
- 参考リンク: https://cursor.com/changelog
- メモ: 過去記事で「Rollouts / Security Review」の Cursor Bot は未掲載のため新規。
