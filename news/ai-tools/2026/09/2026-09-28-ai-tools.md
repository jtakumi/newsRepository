### 2. langchain-litellm / `v0.10.0`（`tool_choice` 仕様変更・Responses API 反映）

- 種別: OSS / ライブラリ（LangChain 連携）
- 関連: LangChain / LiteLLM / OpenAI Responses API
- 公開・更新日: 2026-09-26 21:28 UTC 作成 → 2026-09-27 マージ・公開（JST 9/27）
- 概要: LangChain から LiteLLM を使う `ChatLiteLLM` 連携の更新。**破壊的変更**として、`tool_choice` に `auto` / `none` / `required` / `any` 以外の文字列を渡すと**ツール名として解釈**され、`bind_tools` でバインド済みの関数ツール名でなければ `ValueError` を送出するようになった。`mistral/`・`codestral/`・Vertex AI Mistral のモデルでは、ツール名を指定しても**強制ツール呼び出しにはならない**（LiteLLM 側が function choice を落とすため）。これまで無視されていた **`use_responses_api=True` が実際に Responses API へ送られる**ように修正。
- 何が便利か: ツール選択の挙動が明確になり、Responses API への切り替えが意図どおり効くようになる。
- 使いどころ: LangChain + LiteLLM で複数プロバイダーをまたいでツール呼び出しを制御している構成、OpenAI Responses API に寄せたいエージェント。
- 開発者にとっての価値: 曖昧だった `tool_choice` の意味が固定され、プロバイダー差（特に Mistral 系）の落とし穴が明文化された。移行時の想定外挙動を減らせる。
- 注意点: **破壊的変更**を含むため、`tool_choice` に自由文字列を渡していたコードは事前に見直しが必要。バージョン固定運用のプロジェクトは影響範囲を確認のうえ更新を。
- 公式リンク: https://github.com/langchain-ai/langchain-litellm/releases/tag/langchain-litellm%3D%3D0.10.0
- 参考リンク: https://github.com/langchain-ai/langchain-litellm/releases ／ https://pypi.org/project/langchain-litellm/
- メモ: 本体 LiteLLM / LlamaIndex 本体には同期間の該当リリースは確認できず、本項は LangChain 連携パッケージが対象。

#### 使用例

```bash
# 更新
pip install -U langchain-litellm
```

### 4. Ollama / `v0.40.0-rc0`（Apple Silicon で MLX ランタイムを自動選択）

- 種別: CLI / OSS（ローカル LLM ランタイム）
- 関連: Ollama / ローカル LLM / MLX / Apple Silicon
- 公開・更新日: 2026-09-25（`v0.40.0-rc0`、プレリリース）
- 概要: これまで一部モデルで `-mlx` 変種として提供していた MLX 実行を、**MLX ランタイムが対応するモデルアーキテクチャは自動的に MLX で動く**方向へ変更。ユーザーは従来どおり `ollama pull` / `ollama run` するだけで、対応モデルは最適化された MLX バックエンドにルーティングされる。直前の安定版 `v0.34.4`（9/23）では thinking モデルの structured output が単一パスで高速・安定化、大規模ライブラリでのモデル探索の不具合修正、Apple Silicon での Qwen 3.8／Gemma 4 画像処理の改善も入っている。
- 何が便利か: Apple Silicon 上でモデルごとに MLX 変種を選ぶ手間が減り、既定で MLX 最適化の恩恵を受けやすくなる。
- 使いどころ: Mac（Apple Silicon）でローカル LLM を推論バックエンドに使う個人開発・検証環境。
- 開発者にとっての価値: 「Apple Silicon なら MLX を明示指定」という運用が、既定挙動に寄る。ローカルエージェントの体感速度・省メモリに効きやすい。
- 注意点: **プレリリース（rc0）**。安定運用は `v0.34.x` 系を推奨。MLX 関連は Apple Silicon 前提で、対応アーキテクチャの範囲はリリースノートで要確認。公開日は 9/25 で、本日基準では直近ウィンドウ（24〜48h）のやや外側寄り。
- 公式リンク: https://github.com/ollama/ollama/releases
- 参考リンク: https://github.com/ollama/ollama/releases/tag/v0.40.0-rc0
- メモ: 過去記事ではモデル別 MLX 変種（`:*-mlx`）を扱ってきたが、本項は「MLX を既定ランタイムに寄せる」挙動変更が新規点。

#### 使用例

```bash
# プレリリースを試す場合（安定運用は v0.34.x を推奨）
# 対応アーキテクチャのモデルは自動で MLX ランタイムに載る
ollama pull qwen3.8
ollama run qwen3.8
```

### 5. Claude Code / `v2.1.283`（利用可能モデルの制御・`/doctor prompt-audit`）

- 種別: CLI / 拡張機能
- 関連: Anthropic / Claude Code
- 公開・更新日: 2026-09-25 21:50 UTC（JST 9/26 早朝）
- 概要: チームで使えるモデルを絞る管理設定を追加。`availableModelsMatch`（`"exact"` で明示列挙したモデルにロック）と `deniedModels`（特定モデルをブロック）を導入。`/doctor prompt-audit` で **CLAUDE.md・スキル・エージェント・コマンドの古いプロンプト記法を点検**できる。ゲートウェイのヒントヘッダーにリクエストをグルーピングする `x-claude-code-prompt-id`（オプトイン）、MCP ツール／WebFetch／WebSearch 出力の OpenTelemetry スパンイベント化（`OTEL_LOG_TOOL_CONTENT=1`）なども追加。SDK セッションの遅延ツール呼び出し欠落や `/model` ピッカーの不具合修正、起動性能改善も含む。
- 何が便利か: 組織で「使ってよいモデル」を固定・除外でき、既存の指示ファイルの陳腐化を機械的にチェックできる。
- 使いどころ: モデルのバージョンを固定したいチーム運用、CLAUDE.md やスキルが増えて記法が古びていないか点検したいリポジトリ。
- 開発者にとっての価値: モデルガバナンスとプロンプト資産の保守という、規模が大きくなるほど効いてくる管理機能。`/doctor prompt-audit` は個人リポジトリでもすぐ使える。
- 注意点: `availableModelsMatch` / `deniedModels` は管理設定（managed settings）。公開は JST 9/26 早朝で、本日基準では直近ウィンドウの端。9/25 記事は v2.1.282 までを既報のため本項は新規。
- 公式リンク: https://github.com/anthropics/claude-code/releases
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: `/doctor prompt-audit` はローカルの指示ファイル群を対象にした点検で、追加設定なしで試せる。

#### 使用例

```bash
# 最新へ更新
claude update

# 指示ファイル・スキル・エージェントの古いプロンプト記法を点検
/doctor prompt-audit
```
