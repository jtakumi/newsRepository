### 1. Claude Code / v2.1.269〜v2.1.270（`claude plugin eval`・`/output-style`・Bash編集差分）

- 種別: CLI / コーディングエージェント（安定版）
- 関連: Anthropic / Claude Code
- 公開・更新日: 2026-09-11〜2026-09-12（直近リリース）
- 概要: `v2.1.269` が機能追加の主役。プラグインの eval スイートを Claude Code に対して実行し、採点済み・再現可能な結果（JSON と HTML レポート）を得る `claude plugin eval` を追加。出力スタイルを一覧・切替する `/output-style [name]`（Remote Control・クラウド・ヘッドレスでも動作）、Bash ツールがファイル編集を扱ったときに変更ファイルの差分を結果に含める `bashEditDiffEnabled`、Workflow ツールの並行エージェント上限を上げる `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（1〜256）などを投入。加えて出力トークン上限で応答が切れて自動再開した後のプロンプトキャッシュ部分無効化の修正、権限ルール（`!` 始まりの deny/ask ルールが自分の設定ソース外に及ぶ不具合）の修正など多数のバグ修正を含む。`v2.1.270` は `v2.1.269` の回帰（一定時間動かした後に読み取り専用の git コマンドが権限を尋ねる）を直す小修正。
- 何が便利か: プラグインの品質を「なんとなく」ではなく採点付き・再現可能なレポートで検証できる。`/output-style` でヘッドレスやクラウドでも出力スタイルを切り替えられ、Bash 編集差分でエージェントが何を書き換えたかがツール結果でそのまま確認できる。
- 使いどころ: 自作・配布プラグインのCI的な品質確認（`claude plugin eval`）。長時間走るワークフローで並行エージェント数を上げたいとき。スクリプト/ヘッドレス運用での出力整形。
- 開発者にとっての価値: プラグイン開発に「テスト」の考え方を持ち込める。権限ルールやプロンプトキャッシュまわりの修正で、日常運用の安全性とコスト効率も上がる。
- 注意点: `claude plugin eval` は eval スイートを用意したプラグインが前提。並行エージェント上限の引き上げは推論律速のファンアウト向けで、上げ過ぎはコスト増につながる。CHANGELOG はバージョンごとの日付を持たないため、公開日は 9/11 の前回記事が `v2.1.268` までを扱ったことから推定。
- 公式リンク: https://code.claude.com/docs/en/changelog
- 参考リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- メモ: リリースノートは公式 CHANGELOG.md で verbatim 確認済み。VS Code 拡張ではサブエージェントのマップ表示や Hooks/Permission rules ダイアログ、Claude Code on the web ではキュー済みメッセージの取り消しなども同時に追加された。

#### 使用例

```bash
# プラグインの eval スイートを走らせて採点レポート（JSON + HTML）を得る
claude plugin eval --help
claude plugin eval

# 出力スタイルを一覧・切替（ヘッドレス/クラウドでも可）
/output-style
/output-style <name>
```

### 2. Cline Desktop / desktop-v0.0.26（コンポーザーに GitHub PR 表示・CLI認証の導線改善）

- 種別: デスクトップアプリ / コーディングエージェント
- 関連: Cline
- 公開・更新日: 2026-09-11
- 概要: Cline のデスクトップ版アップデート。コンポーザーに現在ブランチの GitHub プルリクエスト（PR番号・マージ状態・変更行数の合計・CIチェック）を表示するようになった。Customize ビューの Tools / Skills / Rules タブが3種バラバラだったのを1つの一貫したリストに統一。認証まわりでは、ローカルCLI経由でログインするプロバイダー（Claude Code、Codex CLI、OpenCode）の認証失敗時に「そのCLIを確認せよ」と誘導。ChatGPT（Codex）からのサインアウトが確実に反映されるように修正。テキストなしの画像送信が `session input requires a prompt string` で失敗しないよう修正し、モデルパイプラインが読めない画像形式（HEIC・TIFF・SVG・BMP・ICO 等）は添付時に弾く。
- 何が便利か: エディタ/エージェントの画面を離れずに、作業中ブランチのPR状態とCIの通り具合を確認できる。ローカルCLI認証のエラーが「どこを直せばよいか」まで示され、設定の迷子になりにくい。
- 使いどころ: Cline でコードを書きながら PR のマージ可否や CI 状態を横目で追いたいとき。Claude Code / Codex CLI などのCLI認証をプロバイダーとして使う構成でのトラブル解消。
- 開発者にとっての価値: PR/CI の確認を別タブに切り替えず一元化でき、ツール横断（Cline × 各社CLI）の認証運用が分かりやすくなる。
- 注意点: これは Cline の VS Code 拡張ではなくデスクトップアプリ（`desktop-v0.0.26`）の更新。バージョン番号体系が拡張版とは別系統である点に注意。
- 公式リンク: https://github.com/cline/cline/releases/tag/desktop-v0.0.26

### 3. Vercel AI SDK / ai@7.0.98〜7.0.99（バッチでの画像生成・embed/rerank へのコンテキスト付与）

- 種別: OSS / TypeScript ライブラリ（安定版）
- 関連: Vercel / AI SDK
- 公開・更新日: 2026-09（7.0.97 以降の連続リリース）
- 概要: `7.0.98` が機能追加の中心。バッチ処理で画像生成リクエストをサポート（`feat: support image generation requests in batches`）。`embed` / `embedMany` / `rerank` にランタイムコンテキストの属性付けを追加。ツール出力エラー用に安定した UI メッセージ型と型ガードを追加（`add a stable UI message type and type guard for tool output errors`）。あわせて、サポート外のバッチリクエスト種別を拒否する修正、無効な再ランク（reranking）プロバイダーのインデックスを拒否する修正、`validateUIMessages` が推論されたツールを受け入れる修正が入った。`7.0.99` はユーティリティ入力の検証を `InvalidArgumentError` に統一し、`@ai-sdk/gateway` の依存を更新。
- 何が便利か: これまでテキスト/生成が中心だったバッチ処理で画像生成もまとめて投げられる。埋め込みや再ランクの呼び出しにコンテキストを紐付けられ、観測・課金の帰属が取りやすくなる。ツール出力のエラーを型で扱えるため、UI 側のハンドリングが安定する。
- 使いどころ: 大量の画像生成をバッチで流したいとき。RAG やランキングで embed/rerank のコスト・トレースをテナントや用途ごとに分けたいとき。
- 開発者にとっての価値: バッチのカバー範囲が広がり、埋め込み系の可観測性とツールエラーの型安全性が上がる。独自の管理・型定義コードを減らせる。
- 注意点: パッチの積み上げで、個々の追加は小粒。バージョンは頻繁に更新されるため利用時に最新を確認のこと。CHANGELOG はバージョンごとの日付を持たないため、公開日は 9/11 の前回記事が `7.0.97` までを扱ったことから直近と推定。

### 4. OpenAI Codex Python SDK / python-v0.154.0（`max`/`ultra` の reasoning-effort・ExternalMessage）

- 種別: OSS / Python SDK
- 関連: OpenAI / Codex
- 公開・更新日: 2026-09-10
- 概要: Codex の Python SDK リリース。reasoning-effort（推論の努力量）に `max` と `ultra` の値を追加。同期・非同期の `run()` / `turn()` に `ExternalMessage` を追加し、外部コンテンツがツールレベルの権限でターンを開始・参加できるようにした。resume/fork 時の `include_turns`、新規開始する1ターンだけの `turn_service_tier`、`source` メタデータを追加。生成済みのプロトコルモデルと通知を刷新し、turn-start 応答の前に届く完了イベントを保持するよう修正。
- 何が便利か: 推論の努力量を `max` / `ultra` まで上げられ、難度の高いタスクに振り切れる。`ExternalMessage` で外部システムからのメッセージをツール権限付きでターンに注入でき、エージェント連携を組みやすい。
- 使いどころ: Python から Codex をライブラリとして組み込み、難タスクで推論量を最大化したいとき。resume/fork で過去ターンを選択的に持ち込みたいとき。
