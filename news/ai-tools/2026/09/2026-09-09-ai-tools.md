### 1. Claude Code / v2.1.265（`--plugin-dir` フォルダのホットロード・ツール結果 1GB 上限・`opusplan[1m]` 修正・VS Code の自動アーカイブ）

- 種別: CLI / コーディングエージェント（安定版）+ VS Code 拡張
- 関連: Claude / Anthropic / Claude Code / VS Code
- 公開・更新日: 2026-09-08 20:37 UTC（JST 2026-09-09 05:37）※ `v2.1.265`（stable）
- 概要: Anthropic のターミナル型コーディングエージェントの新安定版。前回採用の `v2.1.263`（09-07、バグ修正中心）以降で、今回はプラグイン運用・出力保存・モデル指定まわりに実機能が入った。主な新規点は **`--plugin-dir` にプラグイン群を置いたフォルダを渡すと自動でホットロード**、**ディスクに保存するツール結果へ 1GB の上限**、**`/model opusplan[1m]` が「Model not found」で拒否される不具合の修正**。あわせてフォアグラウンドで起動したサブエージェントを再開するとツール一覧・システムプロンプト接頭辞を失う不具合、Remote Control セッションが返信の最終メッセージ前に end-of-turn を送る不具合、アイドルタイムアウト前にメッセージが届くとバックグラウンドセッションがターン途中で終了する不具合などを修正。Windows では AppContainer / 制限トークンのサンドボックス下で Read/Write/Edit が全ファイルを拒否する問題を修正。VS Code 拡張には**非アクティブセッションの自動アーカイブ（既定 14 日）**を追加。
- 何が便利か:
  - **`--plugin-dir` のフォルダ指定 + ホットロード**: プラグインを 1 つずつ登録せず、フォルダごと渡して自動読み込みできる。ローカルで自作プラグインを反復開発するときに再起動の手間が減る。
  - **ツール結果の 1GB 上限**: 巨大なツール出力でディスクを食いつぶす事故を防げる。長時間・大量出力のセッションで安定する。
  - **`opusplan[1m]` 修正**: 100 万トークン級の opusplan モデル指定が通るようになり、大きめのプランニングを回せる。
- 使いどころ: 自作プラグインをフォルダ単位で開発・検証、長時間の大量出力を伴う自動化、VS Code で多数のセッションを抱える運用（自動アーカイブで整理）。
- 開発者にとっての価値: `--plugin-dir` のホットロードはプラグイン開発の反復コストを直接下げる。出力上限とセッション再開・バックグラウンド周りの修正は、長時間運用や CI/ヘッドレス利用の信頼性に効く。
- 注意点: `--plugin-dir` はフォルダ内のプラグインを自動ロードするため、信頼できるプラグインのみ置くこと。VS Code の自動アーカイブは既定 14 日で、意図せずセッションが片付く場合は設定を確認。`v2.1.264` は欠番で `v2.1.265` が公開されている。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.265
- 参考リンク: https://github.com/anthropics/claude-code/releases / https://docs.claude.com/en/docs/claude-code/overview
- メモ: NewsRepository で採用済みの最新は `v2.1.263`（09-07）。`v2.1.265` は新規。

#### 使用例

```bash
# プラグインを入れたフォルダを指定して自動ホットロード
claude --plugin-dir ./my-plugins

# 100万トークン枠の opusplan を指定（v2.1.265 で修正済み）
claude --model opusplan[1m]
```

### 2. Gemini CLI / v0.59.0（MCP OAuth の SSRF 防止・制限モードで fail-closed のワークスペース信頼）

- 種別: CLI / コーディングエージェント（安定版）
- 関連: Gemini / Google AI / Gemini CLI / MCP
- 公開・更新日: 2026-09-08 21:13 UTC（JST 2026-09-09 06:13）※ `v0.59.0`（stable）
- 概要: Google のターミナル型 AI エージェント Gemini CLI の新安定版。これまで NewsRepository では安定版 `v0.58.0` が長く据え置きだったが、`v0.59.0` でセキュリティ面を中心に更新。主な新規点は **MCP の OAuth メタデータ探索と認証における SSRF（サーバサイドリクエストフォージェリ）の防止**、**制限モード（restricted mode）でワークスペースの信頼判定を fail-closed（既定で拒否）にし、`mcpServers` をフィルタ**。MCP サーバ連携時の悪用経路をふさぐ内容で、外部 MCP を使う開発者に直接効く。
- 何が便利か:
  - **MCP OAuth の SSRF 防止**: MCP サーバの OAuth メタデータ探索を悪用した内部リソースへの不正リクエストを防げる。第三者製の MCP サーバを扱うときの安全性が上がる。
  - **fail-closed のワークスペース信頼**: 制限モードで信頼が確認できないワークスペースを既定で拒否し、`mcpServers` をフィルタする。信頼できない環境での事故を減らせる。
- 使いどころ: 外部・第三者製の MCP サーバを Gemini CLI に接続する運用、信頼境界の曖昧なワークスペース（クローンしたばかりのリポジトリ等）での作業、CI や共有環境での安全側の既定設定。
- 開発者にとっての価値: MCP エコシステムを日常的に使う場合、`v0.59.0` に上げるだけで OAuth 探索の SSRF とワークスペース信頼の抜けをふさげる。機能追加より運用安全性の底上げが主眼で、導入コストは低い。
- 注意点: 制限モードの信頼判定が fail-closed になるため、これまで暗黙に信頼していたワークスペースで挙動が変わる可能性がある。信頼設定を明示しておくとよい。`v0.60.0` 系は preview / nightly のため今回は対象外（安定版は `v0.59.0`）。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.59.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: NewsRepository で採用済みの安定版は `v0.58.0`。`v0.59.0` は新規（安定版の更新）。

#### 使用例

```bash

npm install -g @google/gemini-cli@latest

# バージョン確認（v0.59.0 であること）
```

### 3. Vercel AI SDK / ai@7.0.94（バッチでリクエスト単位のモデル指定・`streamText` のツール選択強制）

- 種別: OSS / TypeScript ライブラリ（安定版パッチ）
- 関連: OpenAI / Anthropic / Gemini / Google Vertex（プロバイダ非依存）
- 公開・更新日: 2026-09-08 19:30 UTC（JST 2026-09-09 04:30）※ `ai@7.0.94`
- 概要: LLM アプリ構築向け TypeScript ツールキット Vercel AI SDK の本体 `ai` パッケージの新パッチ。前回採用の `ai@7.0.93`（09-05）以降の増分。主な新規点は **バッチ処理でリクエストごとに異なるモデルを指定できる（per-request models in batch）**、**`streamText` でツール選択（tool choice）を強制**、そして**リトライ処理の再分類**（分類不能な空の画像結果を再試行、リトライ試行回数の勘定を保持、プロバイダ非依存の再試行可否判定を追加、Google / Google Vertex のプロンプトブロックを terminal 扱いに）。依存も `@ai-sdk/provider@4.0.11`・`@ai-sdk/gateway@4.0.76`・`@ai-sdk/provider-utils@5.0.37` に更新。
- 何が便利か:
  - **バッチでモデル混在**: 1 回のバッチ内でリクエストごとにモデルを変えられる。安価なモデルと高性能モデルを混ぜて処理を最適化しやすい。
  - **`streamText` のツール選択強制**: ストリーミング時に特定ツールの呼び出しを強制でき、エージェントの挙動を確定させやすい。
  - **リトライの堅牢化**: 空の画像結果の再試行やプロバイダ非依存の再試行判定で、マルチプロバイダ運用時の失敗が減る。
- 使いどころ: モデルを混在させたバッチ推論、ツール呼び出しを確定させたいストリーミングエージェント、複数プロバイダをまたぐアプリの安定化。
- 開発者にとっての価値: `ai@7.0.94` に上げるだけでバッチのモデル指定・ツール強制・リトライ堅牢化が入る。既存の `streamText` / バッチのコードに小さな追記で恩恵を得られ、導入コストが低い。
- 注意点: パッチリリースのため差分は限定的。`streamText` のツール選択強制は挙動が変わる可能性があるため、既存のツール制御ロジックと合わせて検証する。本体 `ai@6.0.278`（v6 系の維持更新）も同日公開されているが、機能追加は v7 系（`ai@7.0.94`）が中心。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.94
- 参考リンク: https://github.com/vercel/ai/releases / https://ai-sdk.dev/
- メモ: NewsRepository で採用済みの最新は `ai@7.0.93`（09-05）・`@ai-sdk/openai@4.0.60`（09-06）。`ai@7.0.94` は新規。
