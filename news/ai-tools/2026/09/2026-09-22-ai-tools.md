### 1. Vercel AI SDK / ai@7.0.108（ツール実行のセキュリティ・整合性修正）

- 種別: OSS / TypeScript SDK（安定版）
- 関連: Vercel / AI SDK / xAI
- 公開・更新日: 2026-09-21
- 概要: TypeScript 向け AI SDK のパッチリリース。`ai@7.0.108` は主にツール実行の安全性・整合性に関する修正で、(1) **tool caller の管理下にあるツールを直接実行させない**（`prevent direct execution of tools governed by tool callers`）、(2) 生成がキャンセルされたときに**保留中の tool-call 修復（repair）を止める**、(3) v3 言語モデルへ適応する際に**ファイルデータを保持する**、(4) **`streamText` が tool choice に反する tool call を実行しないようにする**、の 4 点。依存する `@ai-sdk/gateway@4.0.88` も更新。あわせて周辺パッケージも同日更新され、`@ai-sdk/vue@4.0.108` は `useChat` のメッセージ更新スロットリングを設定可能にし、`@ai-sdk/xai` 系（`5.0.5` / `3.0.134`）は grok 4.7 のモデル識別子を追加している（後述の注意点参照）。
- 何が便利か: tool choice 制約に反するツール実行や、tool caller 管理下ツールの直接実行を SDK 側で防ぐことで、エージェントが意図しないツールを呼ぶ事故を減らせる。生成キャンセル時に repair が走り続ける問題も解消され、human-in-the-loop でツールを止める UI の挙動が安定する。
- 使いどころ: `streamText` / `generateText` でツール呼び出しを伴うエージェントを AI SDK で実装している構成。tool choice で呼べるツールを制限している、あるいはユーザー承認を挟んでツールを実行する UI を持つプロジェクトの更新。
- 開発者にとっての価値: 破壊的変更を伴わないパッチで、ツール実行の安全側の挙動が既定で強化される。前回記事の `ai@7.0.107`（9/18）から一段進んだ修正で、そのまま上げてよい。
- 注意点: `@ai-sdk/xai` に grok 4.7 の識別子が入ったが、**xAI は Grok 4.7 を正式リリースしていない（9 月時点で公式のモデルページ・API 識別子・価格は未公表）**ため、本記事では SDK 側の識別子追加という事実に留める。バージョンの刻みが速いので、利用時は最新リリースノートで差分を確認すること。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.108
- 参考リンク: https://ai-sdk.dev/ ／ https://github.com/vercel/ai/releases
- メモ: 変更内容は GitHub Releases（`ai@7.0.108`）で確認。前回 AI Tools News（9/21 記事）は `ai@7.0.107` まで掲載済みで、`7.0.108` と同日の v5/v6 系バックポートは未掲載の新規。

### 2. LangChain / langchain-openai 1.6.3・langchain-core 1.6.4（Responses API ルーティング公開・GPT-6 対応・履歴API非推奨）

- 種別: OSS / Python フレームワーク（安定版）
- 関連: LangChain / OpenAI
- 公開・更新日: 2026-09-21（`langchain-openai==1.6.3`／`langchain-core==1.6.4`）、2026-09-18（`langchain==1.4.2`）
- 概要: LangChain エコシステムの連携パッケージ更新。`langchain-openai==1.6.3` は、**初期化時に推論された Responses API のルーティングを公開**（`expose inferred Responses API routing at initialization`）し、**GPT-6 のリクエスト制約に対応**（`support GPT-6 request constraints`）、依存の anyio を更新した。同日の `langchain-core==1.6.4` は**旧 chat message history 機能を非推奨化**し、`ToolMessage` 周りの整理と依存更新を行った。少し前の `langchain==1.4.2`（9/18）では **human-in-the-loop のツール編集時にモデル生成の tool call を保持**する修正、`langchain==1.4.1`（9/16）では MCP のオブジェクト引数を保持する修正が入っている。
- 何が便利か: Chat モデル初期化時にどのモデルが Responses API 経由でルーティングされるかを判定できるようになり、Chat Completions と Responses API のどちらに乗るかをコード側で把握しやすい。GPT-6 のリクエスト制約に対応したことで、新モデルを LangChain 経由でそのまま扱える。履歴 API の非推奨化は、LangGraph ベースの状態管理へ移行する方針を明確にする。
- 使いどころ: LangChain / LangGraph で OpenAI モデルを使っており、Responses API と Chat Completions を混在運用している構成。GPT-6 を LangChain 経由で試すとき。human-in-the-loop でツール引数を人が編集するフローを組んでいるプロジェクト。
- 開発者にとっての価値: OpenAI の API 差異（Responses / Chat Completions）とモデル更新（GPT-6）への追随を、フレームワーク側の更新で吸収できる。非推奨化の告知が出たことで、履歴管理の移行を前もって計画できる。
- 注意点: `langchain-core` の chat message history 非推奨化は将来的な破壊的変更につながるため、当該 API に依存しているコードは移行先（LangGraph の永続化など）を確認しておくこと。パッケージが細かく分かれているので、`langchain` 本体・`langchain-core`・`langchain-openai` のバージョン整合に注意。
- 公式リンク: https://github.com/langchain-ai/langchain/releases/tag/langchain-openai%3D%3D1.6.3
- 参考リンク: https://github.com/langchain-ai/langchain/releases ／ https://python.langchain.com/
- メモ: 変更内容は GitHub Releases（`langchain-openai==1.6.3` / `langchain-core==1.6.4`）で確認。本シリーズで LangChain のこれらのバージョンは未掲載の新規。GPT-6 対応は SDK 側の対応事実として記載（モデル自体の詳細仕様は本記事では扱わない）。

### 3. LlamaIndex / v0.14.25（RAG・セキュリティ修正・失敗ツールの再試行抑止）

- 種別: OSS / RAG フレームワーク（安定版）
- 関連: LlamaIndex / RAG
- 公開・更新日: 2026-09-21
- 概要: RAG フレームワーク LlamaIndex の保守リリース。**セキュリティ修正が中心**で、多数の連携パッケージにわたる Dependabot アラートを解消（90 以上のサブパッケージのマニフェスト更新）。機能面では `StructuredLLMRerank` の**ネイティブ async 対応を復活**、**失敗した function ツールを再試行しない**修正、compact/refine のストリーミング修正、メタデータ置換で対象値が `None` のときの不具合修正を含む。`ipex-llm` と `optimum-intel` の IPEX 連携は非推奨化された。
- 何が便利か: `StructuredLLMRerank` の async 復活で、非同期パイプラインでの構造化リランクがブロッキングにならず組める。失敗した function ツールを再試行しないようになったことで、ツール実行が繰り返し失敗して無駄なコスト・遅延を生む挙動を避けられる。多数のセキュリティアラート解消で、依存を最新に保ちやすい。
- 使いどころ: LlamaIndex で RAG パイプラインやエージェントを本番運用しており、依存パッケージのセキュリティアラートを整理したいとき。非同期処理でリランクを使う検索構成。ツール実行の再試行でコストが膨らんでいた環境の更新。
- 開発者にとっての価値: 大きな新機能はないが、セキュリティと安定性の底上げが中心で、依存の多い RAG スタックを安全に保てる。async リランクやツール再試行の修正は、実運用の細かな不具合に効く。
- 注意点: 機能追加より保守・修正が中心のリリース。`ipex-llm` / `optimum-intel` の IPEX 連携を使っている場合は非推奨化に注意し、代替を検討すること。サブパッケージが多いので、依存の整合を確認してから上げること。
- 公式リンク: https://github.com/run-llama/llama_index/releases
- 参考リンク: https://docs.llamaindex.ai/
- メモ: 変更内容は GitHub Releases（`v0.14.25`）で確認。本シリーズで LlamaIndex の当該バージョンは未掲載の新規。

#### 使用例

```bash
# コアを更新
pip install --upgrade "llama-index-core==0.14.25"
```

- 種別: OSS / Python ライブラリ・CLI（安定版）
- 関連: Hugging Face
- 公開・更新日: 2026-09-17
