### 1. Ollama / v0.34.0-rc1（ローカルモデルを ChatGPT Desktop で直接利用・OpenAI 互換の tool search / compaction）

- 種別: OSS / ローカルLLMランタイム（pre-release / RC）
- 関連: Ollama / OpenAI（ChatGPT Desktop・OpenAI 互換 API）
- 公開・更新日: 2026-09-05 23:49 UTC（JST 2026-09-06 08:49）※ `v0.34.0-rc1`（pre-release）
- 概要: ローカルLLMを動かす Ollama の次期 `v0.34` ライン最初の RC。目玉は **ChatGPT Desktop から Ollama のローカルモデルを直接呼べる**連携で、既存の ChatGPT Desktop のワークフローを保ったままオープンモデルをローカル実行できる（macOS の Ollama アプリからセットアップ）。あわせて OpenAI 互換クライアント向けに **tool search** と **レスポンス compaction** を追加し、compaction 済み応答で画像が正しく扱われるよう修正。Apple Silicon での構造化出力性能も改善。
- 何が便利か:
  - **ChatGPT Desktop × ローカルモデル**: クラウドに出せないコード・データを、慣れた ChatGPT Desktop の UI からローカルモデルで扱える。
  - **tool search / compaction**: OpenAI 互換のツール利用・長い応答の圧縮に対応し、既存の OpenAI SDK ベースのクライアントをローカル向けに流用しやすい。
- 使いどころ: 機密コードのローカル要約・リファクタ相談、オフライン／閉域環境での試作、OpenAI 互換クライアントをローカルモデルへ切り替えての検証。
- 開発者にとっての価値: `ollama` を更新するだけでローカルモデルの利用導線が ChatGPT Desktop まで広がり、クラウド課金なしで実験を回せる。OpenAI 互換のまま tool 呼び出しを試せるのも移行コストが低い。
- 注意点: **RC（pre-release）** のため本番運用は要検証。ChatGPT Desktop 連携は macOS の Ollama アプリ側の対応が前提。RC の仕様は正式版で変わる可能性あり。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.34.0-rc1
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: NewsRepository の既存 ai-tools 記事で採用済みの安定版は `v0.33.3`（09-02）まで。`v0.34.0-rc1` は新規。

#### 使用例

```bash
# RC を含めて最新を導入（macOS は公式アプリ経由を推奨）
# 既存環境の更新後、モデルを取得して起動
ollama pull llama3.3
ollama run llama3.3

# OpenAI 互換エンドポイントとしてローカル起動（既存クライアントから利用）
#   base_url: http://localhost:11434/v1
#   api_key : ollama（ダミーでも可）
```

### 2. LiteLLM / v1.100.0（安定版・`previous_response_id` の会話保持・Azure AI Foundry の OAuth 認証・チーム別トレース）

- 種別: OSS / LLM ゲートウェイ（安定版）
- 関連: OpenAI 互換 API / Azure AI Foundry / Anthropic / Gemini / New Relic
- 公開・更新日: 2026-09-06 05:33 UTC（JST 2026-09-06 14:33）※ `v1.100.0`（stable）
- 概要: 多数のLLMプロバイダを OpenAI 互換 API で束ねる LiteLLM の `.100` ラインが**安定版**に到達。RC（`v1.100.0-rc.1`、08-31 に既報）から実運用向けの機能が追加・安定化された。主な新規点は **Responses API で `previous_response_id` をチェーンする際に会話コンテキストを保持**、**Azure AI Foundry の全ルートで Entra ID / OAuth 認証（API キー不要）**、**チーム単位の New Relic トレース・コスト／使用量計測**。ほかに Gemini 3.5 の文字起こしモデル対応、Microsoft Teams へのネイティブアラート、Admin UI からの Anthropic コネクタ一括インポート、モデルアクセスグループへの共有予算適用、予算のロールオーバーなど。
- 何が便利か:
  - **応答チェーンで会話が切れない**: `previous_response_id` で応答をつなぐとき、ブリッジ経由でも会話が保持され、マルチターンの取り回しが安定する。
  - **Azure を OAuth で束ねられる**: Azure AI Foundry の各ルートに Entra ID / OAuth を使え、API キー配布・ローテーションの運用負荷が下がる。
  - **チーム別の可観測性**: New Relic トレースとコストをチーム単位で振り分けでき、社内・複数チーム運用の按分がしやすい。
- 使いどころ: 複数プロバイダを 1 ゲートウェイに集約する社内 AI 基盤、Azure 中心の組織での認証統合、チーム別のコスト管理・監視。
- 開発者にとっての価値: RC で先取りしていた `.100` 系機能が安定版で使えるようになり、`pip install litellm==1.100.0` で本番検証に進める。認証・予算・可観測性の運用機能が個人の自作ゲートウェイでも流用しやすい。
- 注意点: 1,712 コミット規模の大型更新のため、既存設定（コールバック・予算・ルーティング）は段階的に検証してから適用するのが安全。RC 段階の機能（08-31 既報のエージェントレジストリ意味検索・MCP セッション RS256 署名など）と本記事の新規点を混同しないこと。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.100.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 08-31 記事は `v1.100.0-rc.1`（RC）を採用済み。本記事は**安定版 `v1.100.0` への到達**と RC 以降の新規機能を採用。次期 `v1.101.0-rc.1`（09-06）も公開されているが RC のため今回は見送り。

#### 使用例

```bash
# 安定版を導入
pip install "litellm==1.100.0"

# OpenAI 互換ゲートウェイとして起動（config で複数プロバイダを集約）
litellm --config config.yaml
```
