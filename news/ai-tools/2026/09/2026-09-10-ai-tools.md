### 1. Claude Code / v2.1.267（`maxEffortLevel` で effort 上限・`--system-prompt-snapshot off`・ゲートウェイ回帰修正）

- 種別: CLI / コーディングエージェント（安定版）
- 関連: Claude / Anthropic / Claude Code / Amazon Bedrock / Google Vertex / Azure Foundry
- 公開・更新日: 2026-09-09 19:58 UTC（JST 2026-09-10 04:58）※ `v2.1.267`（stable）。`v2.1.266` は 2026-09-08 23:55 UTC（JST 09-09 08:55）
- 概要: Anthropic のターミナル型コーディングエージェントの新安定版。前回採用の `v2.1.265`（09-09）以降で、`v2.1.266` → `v2.1.267` の 2 版が積み上がった。`v2.1.267` の主な新規点は **`maxEffortLevel` 設定（トップレベル、または `modelSettings` 配下のモデルごと）で effort レベルの上限を全プロバイダで指定できる**こと、**`--system-prompt-snapshot off` でシステムプロンプトのスナップショットを使わずリクエストごとに都度レンダリングする**こと。加えて大量のバグ修正が入り、`/compact` 再開後に出る余計な「Continue from where you left off.」ターンの除去、5MB 超の大きなトランスクリプトで `--resume` 時に並列ツール呼び出しが落ちる不具合の修正、macOS/Linux でのマーケットプレイス・エントリのパス封じ込めチェックのバイパス修正、期限切れの AWS / Google Cloud 認証情報のリトライ修正などを含む。`v2.1.266` は **`CLAUDE_CODE_USE_GATEWAY` を API キーや `apiKeyHelper`・独自認証ヘッダと併用したときにゲートウェイ／プロキシ構成が壊れる回帰の修正**が主眼。
- 何が便利か:
  - **`maxEffortLevel`**: 高 effort による無駄なトークン消費・遅延を組織／モデル単位で頭打ちにできる。コスト暴走を防ぎつつ運用を安定させられる。
  - **`--system-prompt-snapshot off`**: システムプロンプトを都度レンダリングでき、動的に差し替わる前提の検証やデバッグで期待どおりの内容を毎回反映できる。
  - **ゲートウェイ回帰修正（`v2.1.266`）**: 社内 LLM ゲートウェイ／プロキシ経由で API キー運用している環境の不具合が解消し、更新するだけで復旧する。
- 使いどころ: 複数プロバイダ（Bedrock / Vertex / Foundry）をまたぐチーム運用での effort 上限管理、CI／ヘッドレスでの大規模セッション再開、社内ゲートウェイ経由の API キー運用。
- 開発者にとっての価値: `maxEffortLevel` はコストと応答時間の上限を明示的に握れる運用ノブで、共有環境・チーム運用に直接効く。大きなトランスクリプトの `--resume` 修正やゲートウェイ回帰修正は、長時間・自動化運用の信頼性を底上げする。
- 注意点: `maxEffortLevel` は上限のため、既存のモデル設定で高 effort を前提にしていた場合は挙動が変わる可能性がある。ゲートウェイ経由の回帰は `v2.1.265` 以前で発生し得るので、該当構成なら `v2.1.267` まで上げること。`v2.1.266` は主に回帰修正版。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.267
- 参考リンク: https://github.com/anthropics/claude-code/releases / https://docs.claude.com/en/docs/claude-code/overview
- メモ: NewsRepository で採用済みの最新は `v2.1.265`（09-09）。`v2.1.266` / `v2.1.267` は新規。


### 2. Vercel AI SDK / ai@7.0.97（バッチの cancel / list API・Cloudflare Workers 互換・空 embeddings の拒否）

- 種別: OSS / TypeScript ライブラリ（安定版パッチ）
- 関連: OpenAI / Anthropic / Gemini / Cloudflare Workers（プロバイダ非依存）
- 公開・更新日: 2026-09-09 20:26 UTC（JST 2026-09-10 05:26）※ `ai@7.0.97`。`ai@7.0.96`（09-09 18:16 UTC）・`ai@7.0.95`（09-09 13:46 UTC）
- 概要: LLM アプリ構築向け TypeScript ツールキット Vercel AI SDK の本体 `ai` パッケージの新パッチ群。前回採用の `ai@7.0.94`（09-09）以降の増分で、`7.0.95` → `7.0.96` → `7.0.97` が同日に積み上がった。主な新規点は **バッチ処理に cancel（キャンセル）と list（一覧）API を追加**、**Cloudflare Workers 互換のため `atob` をレシーバなしで呼ぶよう修正**、**動画 webhook レシーバの未処理 rejection を防ぐ改善**、そして `ai@7.0.95` の **埋め込みが 1 件も含まれないモデルレスポンスを拒否**（不正な空応答を早期に弾く）。同日には保守ライン `ai@6.0.280` / `ai@6.0.279` も公開され、Cloudflare Workers 互換や空画像結果のリトライ改善が v6 系にもバックポートされた。
- 何が便利か:
  - **バッチの cancel / list**: 送信済みバッチの一覧取得と途中キャンセルができ、長時間のバッチ推論をプログラムから制御しやすくなる。
  - **Cloudflare Workers 互換**: `atob` の呼び出し修正で、Workers 上での実行時エラーを回避できる。エッジ環境へのデプロイが安定する。
  - **空 embeddings の拒否**: 埋め込みが空のレスポンスをそのまま通さず弾くため、ベクトル生成パイプラインの静かな失敗を早期に検知できる。
- 使いどころ: 大量データのバッチ埋め込み・バッチ生成の運用制御、Cloudflare Workers など Edge ランタイムでの LLM アプリ、RAG のベクトル生成パイプラインの堅牢化。
- 開発者にとっての価値: `ai@7.0.97` に上げるだけでバッチ制御 API・Edge 互換・埋め込みの防御的検証が入る。既存の埋め込み／バッチ処理コードに小さな追記で恩恵を得られ、導入コストが低い。
- 注意点: パッチリリースのため差分は限定的。空 embeddings を拒否する挙動は、これまで空応答を握りつぶしていたコードで例外が顕在化する可能性があるため、エラーハンドリングを見直すこと。Edge 対応が主目的なら v6 系（`ai@6.0.280`）にも同修正が入っている。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.97

- メモ: NewsRepository で採用済みの最新は `ai@7.0.94`（09-09）。`ai@7.0.95` / `7.0.96` / `7.0.97` は新規。
