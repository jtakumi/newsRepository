- 種別: CLI（Node.js／安定版）
- 関連: Google AI / Gemini CLI / MCP
- 公開・更新日: 2026-09-01 20:51 UTC（JST 2026-09-02 05:51）※ v0.58.0（Latest / 安定版）
- 概要: Google の Gemini CLI の新安定版。前回この CLI を扱った時点の安定版 `v0.57.0`（08-25）以来のバージョンで、サンドボックスと書き込みポリシーの安全側の修正が中心。
- 何が便利か:

  - **a2a サーバの取り消しエラー整理**: 新しいメッセージターンで**古いキャンセルエラーをクリア**（`clear stale cancellation error on new message turns`）。
- 使いどころ:
  - **macOS でサンドボックス運用**しつつ、コンテナソケット経由の権限漏れを避けたいとき。
  - **書き込み操作にポリシーを課したい**チーム・自動化用途。
  - シンボリックリンクを含むリポジトリで **ignore 設定の一貫性**を担保したいとき。
- 開発者にとっての価値: `npm i -g @google/gemini-cli@0.58.0` で更新できる安定版。派手な新機能より、**エージェントにファイル操作を任せる際の安全境界**を固める修正がまとまっており、実運用者向け。

### 3. Vercel AI SDK / ai@7.0.89（FilesV4 のファイル操作・ストリーミングアップロード）

- 種別: OSS ライブラリ（TypeScript／安定版）
- 関連: Vercel AI SDK / Agent Framework
- 公開・更新日: 2026-09-01 18:31 UTC（JST 2026-09-02 03:31）※ ai@7.0.89
- 概要: TypeScript 向け AI アプリ開発キットの 7 系安定版。前回採用の `ai@7.0.85`（08-30）以降、`7.0.88`（tool choice 違反の拒否・バッチのツール呼び出し対応）を経て、`7.0.89` で**ファイル管理 API サーフェス**が拡張された。
- 何が便利か:
  - **FilesV4 のファイル操作拡張**: `getFileMetadata` / `downloadFile`（**ストリーミング**）/ `deleteFile` をオプション操作として追加。アップロードだけでなく**取得・削除・メタデータ参照**まで一貫した API で扱える。
  - **ストリーミングのマルチパートアップロード**: `{ type: 'stream' }` のアップロードデータ種別と `postMultipartStreamToApi` を追加。**大きなファイルをストリームで分割アップロード**できる。
  - **アップロード結果のメタデータ**: 結果に `byteSize` / `createdAt` / `expiresAt` を露出。**サイズ・作成時刻・失効時刻**を後段でそのまま利用できる。
  - **呼び出しオプションの追加**: `abortSignal`・`headers` に対応し、`deleteFromApi`・`createBinaryStreamResponseHandler` などの provider-utils を追加。
- 使いどころ:
  - **添付ファイルや生成物をプロバイダ側に保存・取得・削除**するエージェント／アプリの実装。
  - **大容量ファイルのアップロード**を中断可能・ストリーミングで扱いたいとき（`abortSignal`）。
  - 失効時刻（`expiresAt`）を使った**一時ファイルのライフサイクル管理**。
- 開発者にとっての価値: `npm i ai@7.0.89` で今日すぐ試せる。プロバイダをまたいで**ファイルの CRUD 相当**を統一 API で書けるため、マルチプロバイダ構成のアプリで実装が素直になる。あわせて `@ai-sdk/xai@4.0.52` でも同等のファイル操作（`expiresAfter` の TTL 指定など）が実装されている。
- 注意点: FilesV4 のファイル操作は**オプション**であり、対応状況はプロバイダ実装に依存する。破壊的変更の告知は確認されていないが、詳細は各タグのリリースノートで確認のこと。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.89
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 前回採用（08-31）は `ai@7.0.85` / `ai@6.0.272`。今回は `ai@7.0.89` を新規採用（ファイル操作の拡張が主眼で内容が別）。同窓では `ai@6.0.274`（承認記述子の保持修正）も公開。

#### 使用例

```bash
# 7 系最新ラインを導入
npm i ai@7.0.89
```

- 種別: OSS ライブラリ／API ゲートウェイ（Python／安定版）
- 関連: LiteLLM / OpenRouter 的ゲートウェイ / MCP
- 公開・更新日: 2026-09-01 04:50 UTC（JST 2026-09-01 13:50）※ v1.99.0（Latest / 安定版）

  - **バッチのエンキュートークン・レート制限（返金付き）**: バッチ投入時に**トークンを予約してレート制限**し、**完了時に返金**。バッチ運用のレート管理が現実的になる。

  - **Async Rust OCR ブリッジ / MCP OAuth UI 復元**: OCR 経路の非同期化と、MCP の OAuth 設定 UI の復元。
  - **新規プロバイダ/モデル**: Cognition（`swe-1.7` / `swe-1.7-lightning`）、Bedrock 上の Grok 4.6・GPT-5.6 クロスリージョン推論プロファイル、Mistral の GLM-5-2 系価格などを追加。
- 使いどころ:
  - **複数チーム／プロジェクトで LLM ゲートウェイを共有**し、クォータとコストを分けたいとき。
  - **モデル廃止の影響を事前に洗い出す**運用（`/model/deprecations` を CI や監視に組み込み）。
  - バッチ推論を**レート制限内で安全に流し込みたい**とき。
- 開発者にとっての価値: `pip install "litellm==1.99.0"` で導入できる安定版。ゲートウェイのガバナンス（廃止アラート・プロジェクトクォータ）が固まり、**本番のマルチテナント運用**に一歩近づく。
