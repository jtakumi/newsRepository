### 1. Claude プラグインディレクトリ提出ポータル

- 種別: Web サービス（開発者向け配布ポータル）/ ドキュメント更新
- 関連: Anthropic / Claude / Claude Code / MCP
- 公開・更新日: 2026-09-25
- 概要: Claude 向けの第三者拡張を公式ディレクトリへ申請・公開できる**提出ポータル**が公開された。Anthropic はプラグインを「**MCP コネクタ、Agent Skills、またはその両方をまとめたパッケージ**」と定義し、これが第三者拡張を配布する主な手段だとしている。提出形態は 2 種類で、(1) リモート MCP サーバーを指す **単一 MCP コネクタ**、(2) **MCP サーバーと Skills を組み合わせたプラグインバンドル**（GitHub リポジトリとして提出）。Claude Code 向けにはさらに LSP・コマンド・フック・エージェントを同梱できる。提出物は自動でバリデーションと安全性スキャンにかけられ、開発者は承認・公開前に**ステータス・スキャン結果・推奨修正**を確認できる。公開後は**表示数、流入につながった検索、製品面/プラグインバージョン別のインストール数**といったアナリティクスが得られる。
- 何が便利か: これまで各自の marketplace やリポジトリ配布に頼りがちだった Claude プラグイン/スキルを、**公式ディレクトリで発見・インストールしてもらえる導線**に乗せられる。「表示は多いがインストールされない」といった**発見とコンバージョンの切り分け**がアナリティクスで可能。
- 使いどころ: 社内・OSS で作った MCP サーバーや Agent Skills を広く配布したいチーム、Claude Code 向けにコマンド/フック/エージェントを束ねたツールキットを公開したい個人開発者。
- 開発者にとっての価値: 提出前の**安全性スキャンと互換性レビュー**が組み込まれているため、配布物の品質チェックを自前で用意しなくてよい。公開後のインストール計測で、ドキュメントや説明文の改善サイクルを回せる。
- 注意点: **有料 Claude プラン向け**。審査は安全性・セキュリティ・互換性の観点で行われるため、公開までにレビュー時間がかかる可能性がある。MCP サーバーをリモートでホストする場合は可用性・認証の設計が必要。
- 公式リンク: https://claude.com/blog/build-plugins-for-claude
- 参考リンク: https://claude.ai/directory/manage/new , https://github.com/anthropics/claude-plugins-community , https://claude.com/docs/directory/publish
- メモ: 過去記事の「directory」言及（08-13 の Cline/Codex 更新）や、Claude Code のプラグイン機能そのものとは別。**公式ディレクトリへの提出ポータル公開**は新規トピック。

### 2. OpenAI Codex CLI / `rust-v0.157.0`（GPT-6 Sol / Luna の Amazon Bedrock 対応）

- 種別: CLI（OSS）
- 関連: OpenAI / Codex / GPT-6 Sol / GPT-6 Luna / Amazon Bedrock
- 公開・更新日: 2026-09-25
- 概要: 09-25 記事で扱った `rust-v0.156.1`（Sol/Luna をモデルピッカーへ追加）の後続安定版。**GPT-6 Sol / Luna を Amazon Bedrock 経由で利用**できるようになり、旧モデルからの**移行プロンプト**を追加（PR #47332 / #47347）。あわせて**フルスクリーン transcript の既定化**、対象セッションでの**バックグラウンドサーバー自動起動**、会話フォークのショートカット（`f` キー、下書き保持）、remote/daemon セッションでの `/import`、Unicode 対応のターミナル描画改善、リアルタイム接続・Web 検索のプロキシルーティング修正、**ファイルアップロードのタイムアウトを 60 秒→5 分に延長**などを含む。
- 何が便利か: 既に Bedrock を採用している組織が、**AWS のガバナンス配下のまま GPT-6 Sol / Luna を Codex で使える**。ファイルアップロードのタイムアウト延長は大きめの添付を扱うワークフローで実効的。
- 使いどころ: モデル利用を AWS Bedrock に集約している企業の Codex 運用、コスト効率重視の Sol（反復的な開発作業）/ Luna（大量ルーチン）をエンタープライズ環境で使い分けたい場面。
- 開発者にとっての価値: `npm i -g @openai/codex@0.157.0` で今日更新でき、Bedrock 経由の認証・課金・データ境界を維持したまま新しい低コストモデルへ載せ替えられる。移行プロンプトにより旧モデル設定からの切替がスムーズ。
- 注意点: パッチ寄りの安定版で、機能の中心は Bedrock 対応と移行導線。Bedrock 側で対象モデルのリージョン提供状況・有効化が別途必要。Sol/Luna のベンチ値やコストは自分のワークロードで検証してから本番採用するのが安全。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.157.0
- 参考リンク: https://developers.openai.com/codex/changelog
- メモ: 09-25 記事は `rust-v0.156.1`（Sol/Luna のモデルピッカー追加）まで。本項の `rust-v0.157.0`（Sol/Luna の Bedrock 対応・移行プロンプト）は新規。

#### 使用例

```bash
# 更新
npm i -g @openai/codex@0.157.0

# 起動してモデルピッカーから GPT-6 Sol / Luna（Bedrock 経由）を選択
codex
/model
```

### 3. Google Antigravity マネージドエージェント / `antigravity-preview-09-2026`（Gemini API + Files/Credentials API）

- 種別: API / モデル（マネージドエージェント・ハーネス）
- 関連: Google AI / Gemini API / Google AI Studio / Antigravity / MCP
- 公開・更新日: 2026-09（`antigravity-preview-09-2026` ハーネス、AI Studio / Interactions API で提供開始）
- 概要: Google が **Antigravity コーディングエージェントのツールと挙動を Gemini API のマネージドエージェント**として提供。新ハーネス `antigravity-preview-09-2026` は、Google がホストする**隔離された Linux サンドボックス内**で計画・推論・コード実行・ファイル操作・Web 検索を行う。あわせて 2 つの API を新設: エージェント環境へデータを出し入れする **Files API** と、MCP サーバーや外部 API の認証情報を安全に渡す **Credentials API**。**Gemini 3.8 Flash** 上で動作し、モデルは interaction 単位で設定可能。プロンプトキャッシュは前ハーネス比で**約 22% 改善**、ネイティブのコード検索ツールや行範囲指定の効率的なファイル編集も含む。
- 何が便利か: サンドボックス・ツール実行・ファイル管理を**自前構築せずに API から呼べる**ため、コーディングエージェントをアプリに組み込む手間が下がる。Credentials API により、エージェントに MCP サーバーや外部サービスの認証情報を**安全に**渡せる。
- 使いどころ: 自前のアプリやワークフローに「コードを読んで・編集して・実行する」エージェントを組み込みたい場面、AI Studio 上でエージェントの挙動を素早く試作したい場面。
- 開発者にとっての価値: `antigravity-preview-05-2026` で動くリクエストは新ハーネスでもそのまま動作するため移行が容易。キャッシュ改善で反復的なエージェント処理の実効コスト・レイテンシが下がる。
- 注意点: **プレビュー**であり本番採用は検証前提。旧ハーネス `antigravity-preview-05-2026` は **2026-10-05 に廃止**され、以降のリクエストは新ハーネスへリダイレクトされるため、明示指定している場合は切替確認が必要。
- 公式リンク: https://ai.google.dev/gemini-api/docs/models/antigravity-preview-09-2026
- 参考リンク: https://aistudio.google.com/learn/managed-agents-updated-harness-files-credentials , https://ai.google.dev/gemini-api/docs/changelog
- メモ: 過去記事（07-09 / 07-14）で触れた「Antigravity CLI（旧 Gemini CLI 後継）」や「Antigravity 2.0」とは別。**Gemini API のマネージドエージェント・ハーネス更新（Files/Credentials API 新設）**は新規トピック。

### 4. Ollama / `v0.34.4`（thinking モデルの構造化出力を単一パス化）

- 種別: CLI / ローカル LLM ランタイム（OSS）
- 関連: Ollama / ローカル LLM
- 公開・更新日: 2026-09-23
- 概要: ローカル LLM ランタイム Ollama の安定版 `v0.34.4`。**thinking（推論）モデルでの構造化出力が単一パスで適用**されるよう改善し、Apple Silicon 上の **Qwen 3.8 の処理が高速化**、**Gemma 4 の画像解像度選択**を改善、モデルライブラリの断続的なエラーを修正。前バージョン `v0.34.3`（9/19）は API 経由の thinking コントロール（`GET /api/show` がレベルと既定値を提示）、Apple Silicon + MLX での Nemotron H ビジョン対応、Hugging Face からのモデル pull 修正などを含む。
- 何が便利か: 構造化出力（JSON スキーマ等）を thinking モデルで使うときに**二段実行が不要**になり、ローカルでの抽出・分類ジョブが素直に書ける。Apple Silicon ユーザーは Qwen 3.8 の体感速度が向上。
- 使いどころ: ローカルでプライバシーを保ちつつ JSON 構造化出力を返させたいバッチ処理、Mac 上での推論モデル検証。
- 開発者にとっての価値: `ollama` を最新へ上げるだけで、thinking モデル + 構造化出力の組み合わせが安定・高速になる。ローカル完結のためコストゼロで反復検証できる。
- 注意点: 直近 24〜48 時間の窓からはやや外れる（JST 09-23 リリース）。09-25 記事の調査メモでは「新しい安定版が未確認」としていたが、`v0.34.4` は未掲載の新規安定版のため本項で採用。大きな新機能というより安定性・速度の改善が中心。
- 公式リンク: https://github.com/ollama/ollama/releases
- 参考リンク: https://github.com/ollama/ollama/releases/tag/v0.34.4
- メモ: `v0.34.3-rc1`（9/19）系は 09-25 記事の調査メモで言及済みだが、**安定版 `v0.34.4`（9/23）は未掲載**のため新規採用。
