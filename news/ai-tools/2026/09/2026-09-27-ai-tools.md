## 今日の注目

### 1. Claude Code / `v2.1.283`（`/doctor prompt-audit`・利用可能モデル制限・ゲートウェイ強化）

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-09-25
- 概要: `/doctor prompt-audit` を追加し、CLAUDE.md・スキル・エージェント・コマンドを、古いモデル向けに書かれたパターンがないか監査できるようになった。管理設定として `availableModelsMatch`（`"exact"` で特定バージョンのみ許可）と `deniedModels`（特定モデルをブロック）を追加。ゲートウェイ側では、1つのユーザープロンプトに紐づくリクエストをまとめる `x-claude-code-prompt-id` ヒントヘッダー（`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` でオプトイン）や、MCP ツール／WebFetch／WebSearch の出力を OpenTelemetry の `tool.output` スパンイベントに含める対応（`OTEL_LOG_TOOL_CONTENT=1`）を追加。
- 何が便利か: モデルを新世代へ切り替える際、指示ファイルが旧モデル前提のまま放置されがちな問題を、コマンド一発で洗い出せる。企業配布では利用モデルをホワイトリスト／ブラックリストで固定できる。
- 使いどころ: Opus 5.5 や GPT 世代更新などモデルを乗り換えたタイミングでの CLAUDE.md・スキルの棚卸し。組織で使えるモデルを固定したいときの管理設定。OTel でツール実行の可観測性を上げたいチーム。
- 開発者にとっての価値: 指示ファイルの陳腐化という見えにくい負債を自動監査でき、モデル移行の品質を保ちやすい。管理設定と OTel 連携でチーム運用の統制・監視がしやすくなる。
- 注意点: `availableModelsMatch` / `deniedModels` は managed（管理）設定で、個人設定より運用ポリシー向け。ヒントヘッダーや OTel ツール出力は環境変数でのオプトインが必要。
- 公式リンク: https://code.claude.com/docs/en/changelog
- 参考リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- メモ: `v2.1.282`（9/24, `maxProseWidth` など）は 09-25 号で既報。本号は `v2.1.283` の新機能のみを対象。

#### 使用例

```bash
# 最新へ更新
npm install -g @anthropic-ai/claude-code

# CLAUDE.md・スキル・エージェント・コマンドを古いモデル向け記述の観点で監査
claude
> /doctor prompt-audit

# （管理設定 例）利用可能モデルを完全一致のみ許可し、特定モデルをブロック
# settings.json (managed)
# {
#   "availableModelsMatch": "exact",
#   "deniedModels": ["<blocked-model-id>"]
# }
```

### 2. OpenAI Codex CLI / `rust-v0.157.0`・`rust-v0.157.1`（フルスクリーン transcript 既定・会話フォーク `f`・background-server 自動起動）

- 種別: CLI / OSS
- 関連: OpenAI / Codex
- 公開・更新日: 2026-09-25（`rust-v0.157.0`） / 2026-09-26（パッチ `rust-v0.157.1`）
- 概要: フルスクリーン transcript を既定で有効化し、Shift+クリックでテキスト選択を拡張できるように。対象となる対話セッションで background-server の自動起動を有効化し、サーバー設定が非互換のときの復旧選択肢を提示。`f` ショートカットで別アプリで開いている会話をフォークでき、下書きやキュー済みプロンプトを保持。リモートセッションおよびローカル background-server セッションでも `/import` が利用可能に。ターミナル描画も Unicode の箇条書き・チェックボックス・整列した数式表示などで改善。`0.157.1` は後続の小規模パッチ。
- 何が便利か: 長い作業ログをフルスクリーンで追いやすく、会話のフォークで「別案を試す／並行で進める」がしやすい。background-server 自動起動でセッション立ち上げの手数が減る。
- 使いどころ: 長時間のエージェント作業の transcript 確認、既存会話から分岐して別アプローチを試す運用、リモート/バックグラウンドセッションへのコンテキスト取り込み（`/import`）。
- 開発者にとっての価値: TUI とセッション管理まわりの実務的な使い勝手が上がり、日常的なコーディングエージェント運用の摩擦が減る。
- 注意点: GPT-6 Sol / Luna 対応・Amazon Bedrock 対応は前バージョン系（`rust-v0.156.1`, 09-25 号既報）からの流れで、本号の主眼は TUI・セッション運用の改善。`0.157.1` の詳細な差分はリリースページ上で明示が少ない小規模パッチ。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.157.0
- 参考リンク: https://github.com/openai/codex/releases/tag/rust-v0.157.1
- メモ: 変更点の裏取りは GitHub Releases（一次情報）で確認。

#### 使用例

```bash
# 更新
npm install -g @openai/codex

# 起動（フルスクリーン transcript が既定で有効）
codex

# セッション内: f で会話をフォーク、/import でコンテキストを取り込み
```

### 3. Ollama / `v0.40.0-rc0`（Apple Silicon で MLX ランタイムが既定に）

- 種別: OSS / CLI（ローカルLLMランタイム）
- 関連: Ollama / ローカルLLM
- 公開・更新日: 2026-09-25（プレリリース rc0）
- 概要: Apple Silicon デバイスでは、MLX ランタイムがサポートするアーキテクチャのモデルが自動的に MLX 上で実行されるようになった。リリースノートでは Qwen 3.8 が対応モデル例として挙げられており、rc 期間中に対応モデルを順次追加・検証していくとされる。`v0.34.x` 安定系からの大きめのジャンプ。
- 何が便利か: Mac 上でのローカル推論が MLX 経路で走るため、Apple Silicon 向けの実行効率改善が期待できる。既定化により、ユーザーが個別に切り替えなくても対応モデルで MLX が使われる。
- 使いどころ: Mac（Apple Silicon）でローカルLLMを動かす個人開発・オフライン検証環境。対応モデル（例: Qwen 3.8）を Mac で試すとき。
- 開発者にとっての価値: ローカル推論のパフォーマンス最適化を、ランタイム切り替えの手間なく受けられる。
- 注意点: `v0.40.0-rc0` は**リリース候補（プレリリース）**。rc 段階のため対応モデルは順次拡大中で、本番運用は安定版（`v0.34.4` 系）での確認が無難。挙動が既定で変わるため、既存の Mac 環境では推論経路の変化を確認すること。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.0-rc0
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 「既定で MLX」という挙動変更が要点。安定版に降りてくる前の rc で先行確認する位置づけ。

#### 使用例

```bash
# プレリリース（rc）を試す場合は Releases から該当バージョンを取得
# https://github.com/ollama/ollama/releases/tag/v0.40.0-rc0

# Apple Silicon 上で対応モデルを実行（MLX 経路が既定で使われる）
ollama run qwen3.8
```

### 4. langchain-litellm / `0.9.0`（Python 3.11+ が必須に）

- 種別: OSS ライブラリ（LangChain × LiteLLM 連携アダプタ）
- 関連: LangChain / LiteLLM
- 公開・更新日: 2026-09-24
- 概要: LangChain から LiteLLM（多数のLLMプロバイダーを統一インターフェースで呼び出すライブラリ）を使うためのアダプタパッケージ。`0.9.0` で **Python 3.11 以上が必須**という破壊的変更が入った。Python 3.10 を使い続ける場合は `0.8.x` 系に留める必要がある。
- 何が便利か: LangChain のチェーン/エージェント構成の中から、LiteLLM 経由で複数プロバイダーのモデルを統一的に呼び出せる。
- 使いどころ: LangChain + LiteLLM のスタックで、OpenAI・Anthropic・ローカルなど複数プロバイダーを1つの経路で切り替えている構成。依存更新のタイミングでの Python バージョン要件確認。
- 開発者にとっての価値: マルチプロバイダー構成の保守で、ランタイム要件の変化を早めに把握でき、依存アップグレードの事故を避けられる。
- 注意点: 主眼は Python 3.10 サポート打ち切りという互換性変更で、機能的な新規性は限定的。CI/本番の Python バージョンを確認してから上げること。
- 公式リンク: https://github.com/langchain-ai/langchain-litellm/releases/tag/langchain-litellm==0.9.0
- 参考リンク: https://github.com/langchain-ai/langchain-litellm/releases
- メモ: メンテナンス／互換性リリースとして採用。使っていないなら急ぐ必要はない。
