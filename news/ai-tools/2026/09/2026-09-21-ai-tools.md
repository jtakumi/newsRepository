### 2. LiteLLM / v1.101.0（安定版・Workload Identity Federation・classification_mode・input_tokens）

- 種別: OSS / LLM ゲートウェイ・プロキシ（安定版）
- 関連: LiteLLM / OpenAI / MCP
- 公開・更新日: 2026-09-15
- 概要: 100 以上の LLM プロバイダーを OpenAI 互換 API に統一する LiteLLM の安定版リリース。OpenAI 向けに **Workload Identity Federation（OIDC トークン交換）**を追加し、API キーを直接保存せずに資格情報を交換できるようにした。complexity router に **`classification_mode`** を追加し、継続ターンでは分類器をスキップしてマルチターン時の遅延・コストを削減。**`/v1/responses/input_tokens` トークンカウントエンドポイント**を追加。auto-router 面では UI でのコンテキストウィンドウ超過時のエスカレーション制御、画像リクエストのモダリティ別ルーティング、セッションアフィニティ TTL、実行時に配信されるプリセットカタログを追加。MCP のセマンティックツール検索、GigaChat のネイティブ passthrough（スペンドログ付き）、オフピーク料金のコスト計算対応も入った。Bedrock Converse がストリーミングのバッファ/サンプリング設定を正しく尊重するよう修正。全体で 300 以上の修正を含む。
- 何が便利か: OIDC トークン交換で長期 API キーの保管を避けられ、資格情報管理が安全になる。`classification_mode` により、ルーター利用時のマルチターン会話で毎ターンの分類器呼び出しを省けて速く・安く回せる。トークンカウント用エンドポイントで事前見積もりが取りやすい。
- 使いどころ: 複数プロバイダーを 1 プロキシに集約し、キー管理・コスト集計・ルーティングを一元運用している構成。OIDC 基盤（クラウドの Workload Identity）を持つ環境で、静的 API キーを排除したいとき。ルーターでモデル自動振り分けをしつつ会話継続時のオーバーヘッドを抑えたいとき。
- 開発者にとっての価値: プロバイダー差異・キー管理・ルーティング・課金集計を自前実装せずに済む範囲が安定版で広がる。RC 系（v1.102/v1.103）が並走する中、**本番投入できる安定版**として使える。
- 注意点: これは安定版だが、Workload Identity Federation の利用にはクラウド側の OIDC 設定が前提。auto-router / complexity router 系の機能は設定が前提で、既存構成に入れる際は挙動確認が必要。RC/dev 版（v1.102.0-rc.x、v1.103.0-dev/-rc.1）は別系統でまだ検証段階。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.101.0

- メモ: リリース内容は該当タグページで確認。前回までの安定版採用は `v1.100.1`（9/14 記事）で、`v1.101.0` は未掲載の新規安定版。
