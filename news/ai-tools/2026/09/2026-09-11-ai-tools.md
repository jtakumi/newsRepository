## 今日の注目

### 1. OpenAI Codex CLI / rust-v0.154.0（worktree 分離セッション・インライン応答）

- 種別: CLI / コーディングエージェント（安定版）
- 関連: OpenAI / Codex
- 公開・更新日: 2026-09-09
- 概要: ターミナル型コーディングエージェント Codex CLI の安定版。`--worktree` / `/worktree` で新規・フォークしたセッションごとに独立した git worktree のチェックアウトを作成し、後から一覧・再開できる。実行中に作業ドラフトを失わずに質問へインラインで答えられる機能や、Windows でのバックグラウンドサーバー共有（デーモンのライフサイクル管理）も追加。
- 何が便利か: 複数のタスクを別々の worktree に隔離して並行で走らせられるため、片方の変更がもう片方を汚さない。エージェントが確認を求めてきたときも、メインのドラフトを保ったまま選択肢や自由入力で即答できる。
- 使いどころ: 1つのリポジトリで「バグ修正」と「機能追加」を同時に別セッションで進める、フォークして実験的な変更を試す、といった並行開発。
- 開発者にとっての価値: 手動で `git worktree add` を管理する手間が減り、エージェント主導の並行開発がCLI標準機能として使える。
- 注意点: worktree サポートは「実験的（experimental）」。挙動が変わる可能性があるため本番運用前に検証を。GPT-6-Astra がモデルピッカーと Amazon Bedrock カタログに追加された旨も同リリースノートに記載。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.154.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: リリースノートは verbatim で確認済み。セキュリティ関連では「信頼確立前にワークスペース管理下のヘルパーを実行しない」「macOS サンドボックスがターミナル入力インジェクションをブロック」といった修正も含む。

#### 使用例

```bash
# 新しい隔離チェックアウト（worktree）でセッションを開始
codex --worktree

# セッション中に worktree を作成・切り替え
/worktree
```

### 2. Claude Code / v2.1.266〜v2.1.268（effort 上限設定・MCP資格情報漏洩修正・ゲートウェイ制御）

- 種別: CLI / コーディングエージェント（安定版）
- 関連: Anthropic / Claude Code
- 公開・更新日: 2026-09-09〜2026-09-10
- 概要: 直近3リリースでの更新。`v2.1.267` は全プロバイダーで effort レベルの上限を決める `maxEffortLevel` 設定と、リクエストごとにシステムプロンプトを再生成する `--system-prompt-snapshot off` を追加。`v2.1.268` は Claude apps ゲートウェイの料金連携、`gatewayInternalNetworks` 管理設定、および MCP サーバーの資格情報がエラーメッセージに露出する不具合の修正など。`v2.1.266` は `CLAUDE_CODE_USE_GATEWAY` が API キーやカスタム認証と併用時に誤ってクラウドゲートウェイ・サインインを強制していた回帰を修正。
- 何が便利か: `maxEffortLevel` でコスト暴走を組織的に抑えられる。MCP資格情報のエラー漏洩やゲートウェイ強制サインインの修正で、認証まわりの安全性と設定の再現性が上がる。
- 使いどころ: チーム/組織で effort（＝コスト）に上限を敷きたいとき。独自ゲートウェイや API キーを併用する環境での認証トラブル解消。
- 開発者にとっての価値: 個人・組織どちらでも、コスト制御と資格情報の安全な取り扱いという運用面が強化される。
- 注意点: `gatewayInternalNetworks` は管理設定（managed setting）。組織のポリシーとして配布する前提の項目。
- 公式リンク: https://code.claude.com/docs/en/changelog
- 参考リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- メモ: 9/9公開の `2026-09-09-ai-tools.md` では `v2.1.265` までを扱ったため、266以降を新規採用。

#### 使用例

```bash
# effort の上限を組織/セッションで固定（例）
# settings.json に "maxEffortLevel" を設定して全プロバイダーに適用

# 毎リクエストでシステムプロンプトを再生成（スナップショットを使わない）
claude --system-prompt-snapshot off
```

### 3. Anthropic `ant` CLI / Claude Managed Agents（ターミナル接続・auto 権限ポリシー）

- 種別: CLI / API（Managed Agents）
- 関連: Anthropic / Claude Developer Platform
- 公開・更新日: 2026-09-10
- 概要: `ant` CLI に `ant beta:sessions connect` が追加。ターミナルから Claude Managed Agents のセッションにアタッチし、ライブで追跡・メッセージ送信・承認待ちツール呼び出しの許可/拒否ができる。`--web` を付けると Claude Console のセッションビューアをローカルで開ける。あわせて Managed Agents の権限ポリシーに `auto` が追加され、サーバーが各エージェント/MCP ツール呼び出しを評価して実行・拒否・承認待ちに振り分ける。
- 何が便利か: サーバー側で走る自律エージェントの挙動を、手元のターミナルから割り込んで監視・介入できる。`auto` により、毎回の手動承認と全自動の中間（サーバー判定＋必要時のみ承認）が選べる。
- 使いどころ: 長時間走るエージェントの途中経過を見張りつつ、危険な操作だけ承認したいとき。CIやサーバー上のエージェント運用。
- 開発者にとっての価値: エージェント運用の可観測性と安全弁が上がる。`agent.tool_use` / `agent.mcp_tool_use` イベントに `evaluation` フィールドが載り、判定理由を追える。
- 注意点: `ant beta:sessions connect` はベータ機能。Managed Agents を前提とする。
- 公式リンク: https://platform.claude.com/docs/en/cli-sdks-libraries/cli/sessions-connect
- 参考リンク: https://platform.claude.com/docs/en/managed-agents/permission-policies#let-the-server-evaluate-each-call-with-auto
- メモ: 9/3には同CLIにリポジトリのファイルからリソースを作成/更新する `ant apply`（`claude-lock.json` ロックファイル）も追加済み。

#### 使用例

```bash
# 稼働中の Managed Agents セッションにターミナルから接続
ant beta:sessions connect

# ローカルで Console のセッションビューアを開く
ant beta:sessions connect --web
```

### 4. Vercel AI SDK / ai@7.0.95〜7.0.97（バッチの cancel / list API 追加）

- 種別: OSS / TypeScript ライブラリ（安定版パッチ）
- 関連: Vercel / AI SDK
- 公開・更新日: 2026-09（7.0.94 以降の連続パッチ）
- 概要: `feat: add batch cancel and list APIs`（バッチ処理のキャンセルと一覧取得のAPI）を追加。あわせて、生成開始前に video webhook レシーバーの拒否を検知して未処理の rejection を防ぐ修正、埋め込みが空のレスポンスを拒否する修正、Cloudflare Workers 互換のための `atob` 修正などが入った。
- 何が便利か: これまで送信・確認が中心だったバッチ処理を、途中でキャンセルしたり実行中のバッチを一覧で把握したりできる。運用中のバッチジョブを制御しやすくなる。
- 使いどころ: 大量の生成をバッチ投入する処理で、誤投入のキャンセルや進行状況の棚卸しをしたいとき。
- 開発者にとっての価値: バッチのライフサイクル管理がSDK標準でできるため、独自の管理コードを減らせる。
- 注意点: パッチリリースの積み上げで、単体では小さな追加。バージョンは頻繁に更新されるため利用時に最新を確認のこと。
- 公式リンク: https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md
- 参考リンク: https://ai-sdk.dev/
- メモ: 9/9公開記事では `ai@7.0.94`（バッチのリクエスト単位モデル指定）を扱ったため、95〜97を新規採用。
