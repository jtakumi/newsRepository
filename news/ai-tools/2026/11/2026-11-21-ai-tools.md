- 何が便利か: `/tasks` が**スケジュールタスク・`/loop`・フォークまで一覧**するようになり、無人運用で「何が走っているか」を 1 画面で把握して不要なものを止められる。`~/.claude.json` の初期化事故や macOS の Keychain サインアウト連発が直り、長時間セッションの信頼性が上がる。`/code-review <pr number>` が確実に PR の差分を見るようになり、CI 連携でのレビュー取り違えが減る。
- 使いどころ: スケジュールタスクや `/loop` を常用する自動化運用（本ニュース生成ジョブもこれに該当）。macOS で Keychain 権限が絞られた環境。CI から `/code-review <pr number>` を回す構成。OpenTelemetry でエージェントを可観測化しつつ Code Mode を使う構成。
- 開発者にとっての価値: バックグラウンドタスク・リモートコントロール・コンパクション後のメモリ保持など、無人・長時間・複数セッションでの取りこぼしを減らす修正が集中している。`/tasks` の可視化は、スケジュール実行を運用に組み込むときの定番確認コマンドになる。
- 注意点: スケジュールタスクの扱いが変わり、旧バージョンで保存したものの多くは新しいサインイン済みセッションで**再スケジュールが必要**（自分のセッションの `--resume` では従来通り動く）。auto モードは変更破棄系の git コマンドを作業ツリー確認まで一時ブロックすることがある。リリースノートは Added/Fixed/Changed/Improved に多数の項目を含む。

- 種別: CLI
- 関連: OpenAI / Codex

### 3. LiteLLM / `v1.110.2`（Latest）＋ `v1.109.3`・`1.108.13`（LTS）・`1.106.12`

- 種別: OSS（LLM プロキシ／SDK, Python）
- 関連: Anthropic（Claude）/ OpenAI（GPT-6.2）/ Vertex AI / Azure AI / その他
- 公開・更新日: 2026-11-20（`v1.110.2` が Latest、`v1.109.3`・`1.108.13` LTS・`1.106.12` も同日）
- 概要: 100+ の LLM を統一 API で扱うプロキシ／SDK のバグ修正リリース群。全ラインに共通する重要修正として、**`/key/info` が user を持たないキーに対し、他の user 未設定キーをハッシュ／エイリアスで参照できてしまう権限漏れを修正**（認証境界のバグ）。`v1.110.2`（11 PR・うち 8 件が fix）では、`v1.110.0-rc.2` 以降で **`temperature=1` が sampling パラメータを落とす Claude 系（Anthropic／Vertex AI／Azure AI）で 400 になる回帰を修正**、`/v1/responses` ストリームがクライアント到達後に再試行して重複イベント・二重課金が出る問題、reasoning 出力後にストリームが失敗してフォールバックグループで再始動し二重レスポンスが出る問題、GPT-6.2 のシステムプロンプトが `store: false` なしでプロンプトキャッシュに乗らない問題、`/v1/messages` に転送した Anthropic 資格情報がデプロイのカスタム価格を尊重しない問題（`v1.109.0` 回帰）、完了済みリクエストが GC まで常駐するメモリ問題（`v1.110.0-rc.1` 回帰）を修正。`v1.109.3`（6 PR）は上記のうちキャッシュ・JWT・`/key/info` 修正が中心で、いずれも他ラインへバックポート済み。
- 何が便利か: マルチテナント運用で効く**認証境界の権限漏れが全ラインで塞がれる**。`v1.110.0` 系へ上げた環境で `temperature=1` が Claude 系で 400 になる事故や、Responses API の二重課金・二重レスポンスといった、課金・可用性に直結する実務バグがまとめて直る。
- 使いどころ: LiteLLM プロキシで複数プロバイダ（特に Claude 系と GPT-6.2）を束ね、JWT／SSO とキー管理を運用しているチーム。`v1.110.0`/`v1.110.1` に上げて `temperature` 周りや課金の挙動変化に当たっている構成は `v1.110.2` へ。安定運用重視は LTS `1.108.13`。
- 開発者にとっての価値: 新機能より**安全性と課金正確性の修正**が主眼で、いずれも「no action needed to upgrade」と明記され当てやすい。使っているライン（Latest / 旧安定 / LTS）に応じて対応版が揃っている。
- 注意点: どのリリースも破壊的変更の記載はなし。`v1.111.0-rc.3`・`v1.112.0-dev.1` はプレリリースのため本番は非推奨。`/key/info` の権限漏れは全ライン対象なので、古い版を使っている場合も該当ラインの修正版へ上げること。

### 4. Vercel AI SDK / `ai@7.0.178`

- 種別: OSS（TypeScript/JS SDK）
- 関連: Vercel / OpenAI / Anthropic / Google AI / その他
- 公開・更新日: 2026-11-20（UTC 16:57 ごろ / JST 翌 01:57 ごろ）
- 概要: `ai@7.0.178` のパッチ更新。**セキュリティ修正**として、`experimental_toolApprovalSecret` 設定時に、ポリシーが自動拒否したツール呼び出しの承認リクエストにも署名がついており、クライアントがそれを承認レスポンスとして返すと拒否されたはずの呼び出しが実行され得た問題を修正（そうしたリクエストには署名しないようにし、該当レスポンスは `AI_InvalidToolApprovalSignatureError` で拒否。既存署名はシークレットをローテートするまで有効で、保留中の承認は取り直しが必要）。機能・修正として、`generateText`／`streamText` が `prepareStep` のメッセージ配列をツールとツール承認関数に同一参照で渡していたのをステップごとにコピーするよう変更（承認関数がどのツール呼び出しがどのモデル応答由来か判別できる）、`streamText` が provider 実行ツール結果の `preliminary` フラグを転送（OpenAI の画像生成プレビュー等が最終結果として保存されない）、`experimental_extract` にテレメトリ・ランタイムコンテキスト・ライフサイクルコールバックを追加、テレメトリ送信のダウンロードエラーからファイル URL を秘匿。依存更新として `@ai-sdk/provider-utils@5.0.83`・`@ai-sdk/gateway@4.0.151`。
- 何が便利か: ツール承認（human-in-the-loop）の**署名バイパス脆弱性が塞がれる**ため、承認フローで安全に自動拒否を担保できる。`prepareStep` メッセージのステップ別コピーで、承認関数が「どのモデル応答からのツール呼び出しか」を正しく判別できる。
- 使いどころ: `experimental_toolApprovalSecret` でツール承認を運用しているエージェント。マルチステップで `prepareStep` を使い、ステップごとに承認判断を変えたいケース。provider 実行ツール（画像生成プレビュー等）を扱う構成。
- 開発者にとっての価値: セキュリティ修正を含むため、ツール承認機能を使っている 7 系は更新推奨。承認リクエストの由来判別やプレビュー結果の扱いなど、human-in-the-loop の正確性が上がる。
- 注意点: セキュリティ修正の性質上、**既存署名はシークレットをローテートするまで有効**で、ローテート後は保留中の承認を取り直す必要がある。パッチ更新だがツール承認・steering の挙動に関わるため、該当箇所はテストしてから上げること。多数の周辺パッケージ（`@ai-sdk/*`）が同時に版上げされている。
