## 今日の注目

### 1. Ollama / `v0.40.16`

- 種別: CLI / ローカルLLMランタイム
- 関連: Ollama / ローカルLLM / Claude Code 連携
- 公開・更新日: 2026-11-09（`v0.40.17-rc0` は 11-10 のプレリリース）
- 概要: Ricursive Intelligence の **Ripple Preview**（65B の dense モデル、エージェント型コーディング向け）がローカル実行モデルとして追加された。あわせて `ollama launch claude` が選択中モデルへ Claude Code を常にルーティングするよう改善され、`/v1/responses` が `truncation` を尊重し既定で黙って切り詰めなくなった。`/v1/models` はモデル未導入時に `null` ではなく空配列を返す。
- 何が便利か: クラウドに出さずに 65B 級のコーディングモデルを手元で動かせる。OpenAI 互換の `/v1/responses` 挙動が明確になり、既存クライアントからの接続がぶれにくい。
- 使いどころ: 社外に出せないコードのリファクタや補完を手元GPU／Apple silicon で回す。`ollama launch claude` で Claude Code のバックエンドをローカルモデルに差し替えて検証する。
- 開発者にとっての価値: ローカル完結のエージェント型コーディング環境を、追加サービスなしで組める。API 互換の明確化で LiteLLM／OpenRouter 経由の切替もしやすい。
- 注意点: Ripple Preview は「Preview」。65B dense はメモリ要求が大きく、量子化と空きVRAM／RAMを確認してから。`v0.40.17` はまだ rc 段階。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.16
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 前回（11-07）は `v0.40.15`（MiMo V2.6 等）を扱った。本項は `v0.40.16` の新規追加分。

#### 使用例

```bash
# Ollama 本体を更新後、Ripple Preview をローカルで実行
ollama run ripple-preview

# Claude Code のバックエンドを選択中モデルにルーティング
ollama launch claude
```

### 2. Claude Code / `v2.1.321`・`v2.1.322`

- 種別: CLI / 拡張機能
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-09（`v2.1.321`）・2026-11-10（`v2.1.322`）
- 概要: `v2.1.321` で **Claude Fable 5.2（`claude-fable-5-2`、1M コンテキスト）が既定の Fable モデル**に。`claude remote-control --settings <file>` が全セッションへ指定設定を適用（反映は `remote-control` 再起動後）。セキュリティ修正として、MCP OAuth がサーバのリダイレクト先へリフレッシュトークンを送らない／読み取り専用 Bash がプロンプトなしでサンドボックス外実行されない／`cp`・`mv` のコピー先ディレクトリにも deny ルールが効く、などが入った。`v2.1.322` は Vertex（global／us／eu）での Fast mode に対応し、拒否時は標準速度にフォールバック。
- 何が便利か: 既定モデルが高速・大容量の Fable 5.2 になり、長い文脈のコード作業が扱いやすい。`--settings` で CI やチームの共有設定を一括適用できる。
- 使いどころ: チーム共通の権限・モデル設定を remote-control 経由で配布する。Vertex 利用組織で Fast mode を有効化してレスポンスを詰める。
- 開発者にとっての価値: 権限・サンドボックス周りのセキュリティ修正は自動化・CI 実行の安全性に直結。Fable 5.2 既定化で既存ワークフローの体感速度が上がる。
- 注意点: `--settings` の変更は `remote-control` 再起動まで反映されない。Vertex Fast mode は対応リージョン限定で、非対応時は標準速度に落ちる。
- 公式リンク: https://github.com/anthropics/claude-code/releases
- 参考リンク: https://www.anthropic.com/news/claude-fable-and-mythos-5-2
- メモ: 前回（11-07）は `v2.1.319`（`denyInsteadOfPrompting` 等）を扱った。本項は `v2.1.321`／`v2.1.322` の新規差分。

#### 使用例

```bash
# 更新して最新版を確認
claude update && claude --version

# 全セッションへ共有設定を適用（変更反映は remote-control 再起動後）
claude remote-control --settings ./team-settings.json
```

### 3. Gemini CLI / `v0.68.0`

- 種別: CLI
- 関連: Gemini / Google AI
- 公開・更新日: 2026-11-10（`v0.69.0-preview.0` は同日のプレリリース）
- 概要: 安定版 `v0.68.0` で **`SubagentStop` フック**をサポート。拡張機能の検証（validation）コマンド追加、Windows のパス判定を大文字小文字非依存に修正、429 レート制限時にクールダウンのカウントダウンを表示。Gemini 3 のマルチモーダル function 応答のモデル検出や、`@` 補完の先頭スラッシュ処理も修正。rootless Podman サンドボックス（`--userns=keep-id`）対応。`v0.69.0-preview.0` では `/stats` ヒートマップや `theme.json` 対応が先行。
- 何が便利か: サブエージェント終了時のフックで、後処理（整形・通知・検証）を差し込める。拡張機能の検証コマンドで配布前の不備を事前に検出。
- 使いどころ: マルチエージェント構成で各サブエージェント完了後にテストやリンタを自動実行する。レート制限時の待ち時間が可視化され、長時間バッチの挙動が読みやすくなる。
- 開発者にとっての価値: フック拡充でワークフローへの組み込み自由度が上がる。Podman rootless 対応はCIコンテナ内での安全な実行に効く。
- 注意点: `/stats` ヒートマップや `theme.json` は `v0.69.0-preview.0`（プレリリース）側。安定運用は `v0.68.0` を推奨。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.68.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 前回（11-07）は `v0.67.0` を扱った。本項は `v0.68.0` の新規差分。

#### 使用例


### 5. Vercel AI SDK / `ai@7.0.170`（＋ `ai@6.0.330`・`ai@5.0.289`）

- 種別: OSS / SDK
- 関連: Vercel AI SDK
- 公開・更新日: 2026-11-11
- 概要: 配列ストリーミング（`Output.array`／`streamObject`）で CPU 使用率が跳ね上がる問題を、**完了した要素を逐次パース・検証する方式**に変更して修正。さらに、停止・破棄（dispose）時にキュー済みの send-now 操作をキャンセルし、放棄されたチャットのメッセージが差し替え後の transport から送られないようにした。`@ai-sdk/gateway` も更新（7系は 4.0.143）。同修正は `ai@6.0.330`／`ai@5.0.289` にもバックポート。
- 何が便利か: 長い配列を構造化ストリーミングする UI で、CPU スパイクが抑えられ体感が安定。停止時の二重送信を防げる。
- 使いどころ: `streamObject` で長いリストや表形式データを逐次描画するチャット／エージェント UI。会話を破棄・切替した直後の不要送信を止めたいケース。
- 開発者にとっての価値: メジャー 3 系列（5／6／7）に同時対応のパッチで、どのバージョン固定でも恩恵を受けられる。
- 注意点: パッチリリースのため大きな API 変更はない。固定しているメジャーに合わせて該当パッチへ更新する。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.170
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 前回（11-03）は `ai@7.0.160`／`161` を扱った。本項は `ai@7.0.170` と同日のバックポート。

#### 使用例

```bash
# メジャー7系を使っている場合
npm install ai@7.0.170
```

### 6. GitHub Copilot CLI / `v1.0.109`

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-11-10（安定版「Latest」。`v1.0.110-0/-1` は同日プレリリース）
- 概要: 安定版 `v1.0.109` で **サンドボックスのホスト許可／拒否ルールに IPv4/IPv6 CIDR 指定**を追加し、モデルピッカーに Claude Fable 5.2 を追加。`/cd .`・`/add-dir .` が git リポジトリで現在ディレクトリを維持、prompt モードの `--output-format json` が早期失敗時にも最終 result レコードを出力、base64 `blob` リソース内のテキストがモデルに届くよう修正。プレリリース `1.0.110-0` では git/ssh/sudo のパスワード入力をマスクする実験的ダイアログ（`/experimental on`）も登場。
- 何が便利か: CIDR 指定でエージェント実行時の外部通信をネットワーク単位で許可／遮断できる。`--output-format json` が失敗時にも結果を返すため、スクリプト連携が堅くなる。
- 使いどころ: 社内ネットワーク限定でエージェントを動かす、CI から非対話で Copilot CLI を叩いて JSON を機械処理する、といった自動化。
- 開発者にとっての価値: ネットワーク境界の制御とヘッドレス出力の安定化は、CI／自動化パイプラインへの組み込みに直結。
- 注意点: パスワードマスクダイアログはプレリリース `1.0.110-0` の実験機能。安定運用は `v1.0.109`。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.109
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: 前回（11-08）は `1.0.108-1`（プレリリース）を扱った。本項は安定版 `v1.0.109`。

#### 使用例

```bash
# インストール / 更新
npm install -g @github/copilot

# 非対話実行で結果を JSON 取得（早期失敗時も result を返す）
copilot -p "run tests and summarize failures" --output-format json
```
