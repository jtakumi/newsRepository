### 1. Ollama / `v0.40.19`

- 種別: OSS / ローカル LLM ランタイム（CLI）
- 関連: Ollama / ローカルLLM
- 公開・更新日: 2026-11-27（UTC、JST 11-28 早朝）
- 概要: ローカル LLM 実行基盤 Ollama の安定版更新。短い履歴（コンテキスト）での **Inkling2 の高速化**を行い、**ドラフト提案（draft proposals）** と **会話スナップショット（conversation snapshots）** に対応（#19881）。mlxrunner 側では **Engram 履歴バッファのコンパクト化**（#19913）、さらに `llama-server` のバージョン更新（#19917）を取り込んでいる。前日の `v0.40.19-rc0`（11-26）は `llama-server` 更新のみの RC で、本安定版がその正式リリースにあたる。
- 何が便利か: 短い対話が多いローカル利用で応答の立ち上がりが速くなり、メモリ使用（履歴バッファ）も効率化される。ランタイム単体の更新なので、既存のモデル資産やワークフローをそのまま使い続けられる。
- 使いどころ: 手元のマシンで Claude 代替・補助としてローカル LLM を回している開発者。CI やオフライン環境、機密データを外部に出せない検証用途。短いプロンプトを繰り返すエージェント的ループ。
- 開発者にとっての価値: ローカル推論の速度・メモリは日常の反復作業コストに直結する。安定版かつランタイム更新のみなので導入リスクが低く、`ollama` を更新してすぐ恩恵を受けられる。
- 注意点: 高速化は「短い履歴」が主眼で、長大なコンテキストでの効果は限定的。`mlxrunner` 関連の変更は Apple Silicon（MLX）環境が対象。モデルの再取得は不要だが、ランタイム更新後に常駐プロセスの再起動が必要な場合がある。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.19
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 既存記事（11-25）では `v0.40.18` を掲載、11-27 記事では `v0.40.19-rc0`（RC）を不採用としていた。本記事は未掲載の安定版 `v0.40.19` を採用。

#### 使用例

```bash
# アップデート（macOS/Linux のインストールスクリプト or 各配布チャネル）
curl -fsSL https://ollama.com/install.sh | sh   # Linux の例
ollama --version

# 更新後にモデルを実行して応答速度を確認
ollama run llama3.2
```

### 2. LiteLLM / `v1.108.20`（LTS）

- 種別: OSS / プロキシ・ゲートウェイ
- 関連: LiteLLM / Anthropic / OpenAI / Azure
- 公開・更新日: 2026-11-27（UTC、JST 11-28 早朝）
- 概要: LTS 系のパッチ更新。計 7 PR のうち 3 件が修正で、**破壊的変更・新機能はなく「No action needed to upgrade」**。主な修正は 3 点。(1) **Anthropic 宛てのツールメッセージで `tool_call_id` が非文字列のとき 400 を返すべき箇所をそのまま通してしまう退行**（v1.108.19 で混入）の修正（#54736）。(2) OpenAI / Azure の **`/v1/responses` ストリームをキャンセルした際に課金が記録されない、または推定値になる**問題を、プロバイダ報告の使用量で記録するよう修正（#54755, #54772）。(3) **team / key 更新後に `GET /audit` が 500 を返す**問題の修正（アップグレード前に保存された行もカバー、#50929, #53305）。この `/audit` 修正は stable 系 `v1.111.0` にも入っている。バックポート #53262, #54733 も含む。
- 何が便利か: LTS を使う本番ゲートウェイで、Anthropic 連携時の 400 退行・ストリームキャンセル時の課金欠落・監査ログの 500 という運用に効く不具合がまとめて解消する。設定変更不要で取り込める。
- 使いどころ: LiteLLM を LTS タグ（`lts` イメージ）で固定運用し、Anthropic モデルや `/v1/responses` ストリーミング、`/audit` による監査を使っているチーム。
- 開発者にとっての価値: 新機能を追わず安定性だけを取りたい運用者向けに、退行修正と課金の正確性という信頼性向上が低リスクで手に入る。`tool_call_id` 退行は Anthropic 経由のツール呼び出しを壊し得るため、v1.108.19 利用中なら優先度が高い。
- 注意点: これは **LTS 系**（`v1.108.x`）のパッチ。最新機能が欲しい場合は stable 系（直近は `v1.111.0`、開発プレリリースに `v1.113.0-dev.1`）を参照。`lts` イメージタグは最新 LTS パッチを追従する。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.108.20
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 既存記事（11-27）では LTS `1.108.18` / `1.108.19` まで言及済み。本記事は未掲載の LTS `v1.108.20` を採用。stable `v1.111.0` は 11-27 記事で掲載済みのため重複として扱わない。

#### 使用例

```bash
# LTS タグで固定運用している場合はイメージを引き直す
docker pull ghcr.io/berriai/litellm:lts
# もしくは pip でパッチ指定
pip install "litellm==1.108.20"
```

### 3. OpenCode / `v2.4.2`

- 種別: CLI / OSS（ターミナル用 AI コーディングエージェント）
- 関連: OpenCode / OpenAI（GPT-6.2）
- 公開・更新日: 2026-11-26（UTC、JST 11-26〜27）
- 概要: ターミナル向け AI コーディングエージェント OpenCode の更新。**GPT-6.2 Sol / Astra 用のシステムプロンプトと `gpt-latest` エイリアス**を追加し、接続後のモデルピッカーで **OpenCode Go を先頭に表示**。入力欄が空の状態で（モデル応答やツール呼び出しの前に）**Esc を押すと直前に送ったメッセージを復元して編集**できるようになった。アップグレードノートとして、Web fetch の「Always allow」が**そのサイトにのみ適用**されるよう限定、**失敗したラン後も automation が継続**、アーカイブ済みセッションへ送信すると自動で**復帰（unarchive）**する挙動に変更。
- 何が便利か: 最新の GPT-6.2 系モデルをプリセットのシステムプロンプト込みですぐ使える。Esc でのメッセージ復元は打ち直しの手戻りを減らす。Web fetch 許可のサイト単位化は、無制限な外部取得を避けつつ使い勝手を保つ安全側の改善。
- 使いどころ: ターミナル中心で AI コーディングを回す開発者。GPT-6.2 を OpenCode から試したいケース。automation（自動化フロー）を組んでおり、単発の失敗で止めたくない運用。
- 開発者にとっての価値: モデル追従（GPT-6.2 / `gpt-latest`）と、入力復元・許可範囲の限定・automation 継続という日常運用の摩擦を減らす変更がまとまっている。CLI 1 本の更新で取り込める。
- 注意点: GPT-6.2 を使うには対応プロバイダの接続・認証が別途必要。「Always allow」の挙動変更により、以前サイト横断で許可していた前提の運用はサイトごとの再許可が必要になり得る。
- 公式リンク: https://github.com/sst/opencode/releases/tag/v2.4.2
- 参考リンク: https://github.com/sst/opencode/releases
- メモ: 既存記事では 11-20 / 11-21 記事などで OpenCode を扱っているが、本バージョン `v2.4.2`（および同系列 `v2.4.0` / `v2.4.1`・11-23）は未掲載。本記事は `v2.4.2` を採用。

### 4. goose / `v1.61.1`・`v1.61.0`

- 種別: OSS（デスクトップ / CLI の AI エージェント）
- 関連: goose（Block）/ Gemini / MCP
- 公開・更新日: `v1.61.0` 2026-11-25、`v1.61.1` 2026-11-26（UTC）
- 概要: Block の AI エージェント goose の連続更新。**`v1.61.0`** が本期間最大のリリースで、**モデル名の前にプロバイダラベルを表示**、**Gemini 4 Neon** モデル対応、ACP の `mcpServers` ヘッダをすべて秘密情報として扱う、goose-agent 向けの **MCP 拡張操作**、**MCP `server.json` のインポート**、**compaction（履歴圧縮）操作**、宣言的プロバイダ（llmman・amazee.ai）の追加などを含む（約 27 件のバグ修正、UI・ドキュメント更新あり）。翌 **`v1.61.1`** は修正中心で、**インポートしたセッションにツール承認状態が引き継がれ、読み込み時に自動でツールが実行され得る問題を修正**。インポート時の拡張・レシピデータ・プロバイダ セッション ID の扱いも変更し、デスクトップアプリから dotenv を削除。
- 何が便利か: MCP `server.json` のインポートと compaction で、MCP サーバー構成の取り回しと長い会話の履歴管理が楽になる。プロバイダラベル表示でモデルの出所が一目で分かる。`v1.61.1` の修正は、インポートセッション経由の意図しない自動ツール実行という**安全性に関わる**問題への対応。
- 使いどころ: goose をデスクトップ / CLI で使い、複数 MCP サーバーや複数プロバイダ（Gemini 4 Neon ほか）を切り替えて運用する開発者。セッションのインポート／共有を行う環境。
- 開発者にとっての価値: MCP 構成のインポートや compaction は実運用の効率に効く機能追加。`v1.61.1` のツール承認引き継ぎ修正はセキュリティ面で重要で、インポート機能を使うなら早めに上げたい。
- 注意点: セッションをインポートする運用をしている場合、`v1.61.1` 未満では読み込み時にツールが自動実行され得るため更新を推奨。Gemini 4 Neon の利用には対応プロバイダの接続・認証が必要。
- 公式リンク: https://github.com/block/goose/releases/tag/v1.61.1
- 参考リンク: https://github.com/block/goose/releases/tag/v1.61.0
- メモ: 既存記事では 11-01〜11-16 記事などで goose を扱っているが、`v1.61.0` / `v1.61.1` は未掲載。本記事は両版を採用。
