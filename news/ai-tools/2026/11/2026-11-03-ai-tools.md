- LangChain が `langchain==1.4.8` / `langchain-core==1.7.4` / `langchain-anthropic==1.7.8`〜`1.7.9`（安定版）を公開。Anthropic メッセージ変換がメッセージ内容を破壊的に書き換えない修正、compaction ブロックや null のキャッシュトークン数の扱い、ストリーミング時のトークン数をコールバックへ報告する修正を含む。あわせて「Python 3.10 サポートは `langchain-core 1.8.0` / `langchain 1.5.0` で終了」という予告が出ている。

## 今日の注目

### 1. Qwen Code / `v0.26.6`

- 種別: CLI（ターミナル向けコーディングエージェント）
- 関連: Alibaba / Qwen（Gemini CLI 派生）
- 公開・更新日: 2026-11-02（GitHub Releases, Latest）
- 概要: Mods が `prompt.submit` フックをヘッドレス（`-p`）実行や stream-json のユーザーメッセージでも実行できるようになり、自動化パイプラインにフックを差し込みやすくなった。デスクトップ版は Fedora 44 / RHEL 10 x64 の RPM インストーラを公開。Web Shell 側ではサイドバーのアクティビティビュー、セッションの「Add to Split View」、リクエスト成功率・出力速度・初回トークン遅延などを可視化するトークン使用量パネルを追加。
- 何が便利か: シェル権限チェックが `2>&1` のファイルディスクリプタ複製をファイル書き込みと誤って扱わなくなり、リダイレクトを含むコマンドが不要な権限確認で止まりにくい。MCP 検出が重複ツール名をスキップしつつ一意な名前のツールは残す修正、無効化ツール名のタイプミスを毎回の検出で警告する改善、OAuth リフレッシュロックを保有プロセスだけが解放する修正も入った。Windows インストーラは更新前に同梱ランタイムを停止してファイル差し替え失敗を減らす。
- 使いどころ: Qwen 系モデルで CLI コーディングを回す日常作業。`-p` でのヘッドレス実行にフックを絡めた CI / 自動化。Fedora / RHEL 環境へ RPM で導入したいケース。MCP サーバを複数つないだエージェント運用。
- 開発者にとっての価値: ヘッドレス実行でのフック対応で自動化に組み込みやすく、シェル権限・MCP 周りの実務的な不具合解消で日常運用の安定性が上がる。RPM 配布で RHEL 系の導入コストが下がる。
- 注意点: 本リリースは「No known breaking changes」とされるが、機能の多くは Web Shell / Managed Agent（ホスティング前提）向けで、個人の CLI 利用では使わないものも多い。Kimi K3 の生成 ID は 1,000,000 トークンのコンテキストを使い、`k3-256k` は 256K を維持する変更など、モデル固有の挙動変更がある点は確認すること。
- 公式リンク: https://github.com/QwenLM/qwen-code/releases/tag/v0.26.6
- 参考リンク: https://github.com/QwenLM/qwen-code/releases
- メモ: 2026-11-02 版の AI Tools News では安定版 `v0.26.5`（Generated UI 既定有効化ほか）を扱った。本項は新規の安定版 `v0.26.6` を扱う。

#### 使用例

```bash
# インストール / 更新
npm install -g @qwen-code/qwen-code@latest
qwen --version

# ヘッドレス実行（-p）。prompt.submit フックが走る
qwen -p "このリポジトリの変更点を要約して"
```

### 2. Vercel AI SDK / `ai@7.0.160`（＋ `ai@7.0.161`）

- 種別: OSS / SDK（AIアプリ構築用 TypeScript SDK）
- 関連: Vercel / AI SDK（各プロバイダ対応）
- 公開・更新日: 2026-11-02（GitHub Releases, Latest 系列）
- 概要: `ai@7.0.160` で、現在のタスクが終わった後にメッセージを送る `steering.queue()` を追加。あわせて `processUIMessageStream` が `dataPartSchemas` をチャンク型全体（例: `data-weather`）で引いていたために `useChat` / `Chat` でストリーミングデータパートの検証が一度も走っていなかった不具合を修正し、素のパート名（例: `weather`）で検証して不正時に `TypeValidationError` を投げるようにした。`smoothStream` の接頭辞エラーメッセージの文言も整理。`ai@7.0.161` では、クロスレルムのバイナリデータ（`Uint8Array` / `ArrayBuffer`）の扱いと、循環構造を含む `cloneModelMessages` の不具合を修正した。
- 何が便利か: `steering.queue()` により、実行中のタスクを止めずに「終わったら次のメッセージを流す」制御を素直に書ける。これまで `useChat` で機能していなかったデータパート検証が有効になり、サーバから流れてくる構造化データの型崩れを実行時に検知できる。
- 使いどころ: チャット UI でストリーミング中に追加指示を積みたいエージェント。`useChat` / `Chat` でカスタムのデータパート（`data-*`）をやり取りするアプリの型安全性チェック。ブラウザの iframe / worker 間などクロスレルムでバイナリを扱う実装。
- 開発者にとっての価値: ストリーミング制御（steering）とデータパート検証という、チャット系アプリの実装で踏みやすい箇所が改善され、UI の挙動を型安全に制御しやすくなる。`npm i ai@latest` で取り込める導入のしやすさ。
- 注意点: データパート検証がこれまで実質無効だったため、既存アプリでは今まで素通りしていた不正なデータパートが `TypeValidationError` として表面化する可能性がある。更新後は `data-*` の送受信を検証スキーマと突き合わせて確認すること。`7.0.160` / `7.0.161` は `@ai-sdk/gateway` などの依存更新も含む。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.160
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 2026-11-01 / 11-02 版では Vercel AI SDK は「依存更新のみ（`ai@7.0.159`）」として本文では見送っていた。本項は実機能追加（`steering.queue()`・データパート検証修正）を含む `ai@7.0.160` / `7.0.161` を扱う。

#### 使用例

```bash
# 更新
npm install ai@latest

# 概念例: 実行中タスクの完了後にメッセージを送る
#   steering.queue({ role: 'user', content: '次はテストも書いて' })
```

### 3. LangChain / `langchain==1.4.8`・`langchain-core==1.7.4`・`langchain-anthropic==1.7.8`〜`1.7.9`

- 種別: OSS / ライブラリ（LLM アプリ・エージェント構築フレームワーク）
- 関連: LangChain / Anthropic（provider 連携）
- 公開・更新日: 2026-11-02（GitHub Releases）
- 概要: `langchain-core==1.7.4` で Anthropic メッセージ変換がメッセージ内容を破壊的に書き換えない（mutate しない）よう修正。`langchain-anthropic==1.7.8` で compaction ブロックの index を取り除いて扱い、null のキャッシュ作成トークン数を処理。`1.7.9` でストリーミング時のコンテンツブロックのトークン数がコールバックへ正しく報告されるよう修正。`langchain==1.4.8` は `langchain-core` の更新と、脆弱性のある連携依存のパッチ（1件は revert）・サードパーティ上限の緩和など依存整理が中心。
- 何が便利か: Anthropic 連携でメッセージ内容が意図せず書き換わる問題や、ストリーミング時のトークン計上がコールバックに届かない問題が解消され、Claude をバックエンドにした LangChain アプリのトークン計測・メッセージ処理が安定する。
- 使いどころ: LangChain で Claude（Anthropic）を使っているアプリ・エージェント。ストリーミングのトークン数をコールバックで集計・課金に使っている構成。依存のセキュリティパッチを取り込みたい運用。
- 開発者にとっての価値: provider 連携まわりの地味だが実害のある不具合（メッセージ破壊的変更・トークン欠落）が直り、計測と挙動の信頼性が上がる。
- 注意点: リリースノートに「Python 3.10 サポートは `langchain-core 1.8.0` / `langchain 1.5.0` で終了」との予告があり、現行マイナーが 3.10 対応の最後になる。3.10 環境のプロジェクトは次期メジャー更新前に Python のアップグレード計画が必要。`langchain==1.4.8` では脆弱性パッチの1件が revert されている点にも留意。
- 公式リンク: https://github.com/langchain-ai/langchain/releases
- 参考リンク: https://github.com/langchain-ai/langchain/releases/tag/langchain-core%3D%3D1.7.4
- メモ: 既存の AI Tools News で当該バージョン群は未掲載。本項は 2026-11-02 公開の `langchain` / `langchain-core` / `langchain-anthropic` の安定版群（Python 3.10 終了予告を含む）を扱う。
