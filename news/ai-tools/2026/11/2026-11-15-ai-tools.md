## 今日の注目

### 1. GitHub Copilot CLI / `v1.0.112`

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-11-13（安定版・「Latest」）
- 概要: 約110件の修正を含む大型の安定版パッチ。**各モデルの推奨コンテキストウィンドウを既定で使う**ようになり、モデルごとに最適な文脈長が自動適用される。**サブエージェントが `--max-ai-credits` の上限を尊重**し、`/tasks` にサブエージェントのフォローアップ実行時間を含めるなどサブエージェント運用の整合性が向上。`/plugin` マネージャは未ロードのプラグインを「有効」と誤表示しない／古い更新バッジを消す／`@` を含むパスのインストール修正などを行い、チームプラグインを特定のブランチ・タグ・サブフォルダから取得できるようになった。MCP 周りでは、組織ポリシーで MCP が無効なとき組み込み GitHub MCP サーバを使えないようにし、壊れたローカルカタログパスが全 MCP サーバをブロックしないよう修正。入力・貼り付け（Esc／Ctrl+C／Vim モードでの貼り付け保持、`/copy` の書式維持）、狭い／短いターミナルと絵文字・CJK・アクセント文字の表示を多数修正。`/diff` が `.gitattributes` のバイナリ指定を尊重、macOS Ventura 13.5+ での起動改善なども含む。
- 何が便利か: モデルごとの推奨コンテキスト既定化で、長い入力時の切り詰め／オーバーフローの事故が減る。サブエージェントのクレジット上限尊重でコスト暴走を抑えられる。プラグイン／MCP の表示と取得が安定し、チーム配布（ブランチ・タグ・サブフォルダ指定）が実運用に乗せやすい。
- 使いどころ: 組織でプラグイン・MCP を配布して使うチーム。サブエージェントを並行実行しつつ AI クレジットを管理したいケース。CJK を含む日本語環境で狭い端末を使う日常作業。
- 開発者にとっての価値: プレリリースを追わず安定版で最新の使い勝手改善をまとめて取り込める。特にサブエージェントのクレジット上限とコンテキスト既定化は、日々の利用コストと出力品質の両面に効く。
- 注意点: 大量の修正を含むため、プラグイン構成やカスタム MCP を多用している場合は更新後に `/plugin` と `/mcp` の表示・接続を一度確認しておくとよい。組織ポリシーで MCP が無効な環境では組み込み GitHub MCP サーバが使えなくなる点に注意。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.112
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: 前回（11-14 の記事）は安定版 `1.0.110`／`1.0.111` を扱った。本項は新規の安定版 `1.0.112`（プレリリース `1.0.112-0` を経て同日公開）。

#### 使用例

```bash
# 更新してバージョン確認
npm install -g @github/copilot
copilot --version

# サブエージェントの AI クレジット上限を指定して実行
copilot --max-ai-credits 50
```

### 2. Vercel AI SDK / `ai@7.0.173`（＋ `@ai-sdk/workflow@2.0.105` ほか）

- 種別: OSS / SDK
- 関連: Vercel AI SDK
- 公開・更新日: 2026-11-13（UTC 深夜・JST 11-14 早朝）
- 概要: `WorkflowAgent` 中心のパッチ。**`toolApproval` を追加**し、コンストラクタまたは呼び出し単位でツールの承認要否を上書きできる（承認されたツールは同一ステップ内で実行、拒否は `execution-denied` 結果を返しワークフローを停止させない）。**`generate()`／`stream()` が構造化タイムアウト `timeout: { totalMs, stepMs, firstChunkMs, chunkMs }`** を受け付け（数値も従来どおり可）、プロバイダが abort シグナルを無視してもタイムアウトでモデルステップを終了できる。`prepareStep` の挙動を `ToolLoopAgent` に揃え（返した instructions／`providerOptions`／`headers` のマージ方法を統一）、各モデル呼び出しの警告を AI SDK の警告ロガー経由で出力（`AI_SDK_LOG_WARNINGS` で制御）、デフォルトのステップ上限で停止した際に警告ログを出すように変更。承認リプレイ時にスキーマ検証や入力の再整形で**承認済みのツール引数が書き換わらない**よう修正。依存の `@ai-sdk/gateway` を 4.0.146 に更新。
- 何が便利か: `toolApproval` でツールごとの承認フローをコードから明示制御でき、ワークフローを止めずに拒否を扱える。構造化タイムアウトで「全体」「ステップ」「初回チャンク」「チャンク間」を別々に制御でき、応答が詰まる／無限待ちを防ぎやすい。承認済み引数の不変保証は、人手承認を挟むエージェントの安全性に直結する。
- 使いどころ: `WorkflowAgent` でマルチステップのツール実行エージェントを組むケース。人手承認（human-in-the-loop）を挟む自動化で、承認後の引数が変わらないことを保証したいとき。長時間・不安定なプロバイダ相手に細かくタイムアウトを切りたいとき。
- 開発者にとっての価値: パッチだが、エージェント実行の「承認」「タイムアウト」という運用上重要な制御が実務的に強化される。`prepareStep` の挙動統一で `ToolLoopAgent` との移行・併用もしやすくなる。
- 注意点: `WorkflowAgent`／`extract`／`decide` 系は実験的 API のため今後も変わり得る。`timeout` に不正値を渡すと `InvalidArgumentError` を投げる。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.173
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 前回（11-14 の記事）は `ai@7.0.172` と `@ai-sdk/workflow@2.0.104` を扱った。本項は新規の `ai@7.0.173`（同系統で `@ai-sdk/workflow@2.0.105`／`ai@6.0.332`／`ai@5.0.290` も同時公開）。

#### 使用例

```bash
# メジャー7系を使っている場合
npm install ai@7.0.173
```

### 3. LiteLLM / `v1.108.9`（LTS 系）・`v1.106.10`

- 種別: OSS / LLM ゲートウェイ（プロキシ）・SDK
- 関連: LiteLLM / マルチプロバイダ
- 公開・更新日: 2026-11-14（`v1.108.9`／`v1.106.10` いずれも 11-14）
- 概要: 旧安定系列への**バックポート**中心のリリース。**`v1.106.10`** は MCP の重要修正で、**Google MCP サーバのアクセストークンが失効した際にユーザへ再サインインを求めてしまう不具合を修正**（アップグレードに action 不要）。**`v1.108.9`**（`lts/1.108.x` ブランチ）は複数のバックポート：Responses で混在した reasoning と answer のコンテンツ保持、Bedrock Converse の `s3://` メディアソース対応、Azure AI Foundry（Kimi K3）への reasoning effort 送信と reasoning 保持、Vertex AI リクエストへの caller identity ラベル付与、Chat→Responses ブリッジの cache control ブレークポイント、Azure Foundry の `/openai/v1` Responses ベース URL、Vercel AI Gateway の decision モデル、Bedrock の OpenAI ベクトルストア検索フィルタのマッピングなど。Docker イメージは cosign 署名付き。
- 何が便利か: LTS／旧安定系列を固定している運用でも、破壊的変更なしにバグ修正と一部プロバイダ対応を取り込める。特に Google MCP のトークン失効時の再サインインループ修正は、MCP を本番で使う構成に即効性がある。
- 使いどころ: 複数 LLM を OpenAI 互換エンドポイントに束ねる本番プロキシの保守更新。Google MCP サーバや Bedrock／Vertex／Azure Foundry を使う構成。
- 開発者にとっての価値: バージョンを固定したまま安全にバグ修正を適用できる。MCP トークン失効の再認証ループは該当すれば利用者体験を直接改善する。
- 注意点: いずれも旧系列へのバックポートで新機能は限定的。最新機能（Claude Fable 5.2 追加などは dev プレリリース `v1.111.0-dev.x` 側）を使いたい場合は別途検討が必要（本番は安定版／LTS 推奨）。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.108.9
- 参考リンク: https://github.com/BerriAI/litellm/releases/tag/v1.106.10
- メモ: 前回（11-14 の記事）は LTS `1.108.8` を扱った。本項は新規の `v1.108.9`（LTS 系）と `v1.106.10`（旧安定系の MCP 修正）。
