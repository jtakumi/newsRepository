### 1. Claude Code / `v2.1.330`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-20（UTC・GitHub 表示。JST 2026-11-20〜21）
- 概要: ターミナル向け AI コーディングエージェントの定期更新。追加点として、**Anthropic の Enterprise Admin Console で管理される組織へのサインイン**（`claude auth login` 後に組織設定を適用し、その組織のクラウドプロバイダ／ゲートウェイを使用）、**easel（チャートを描く組み込み mod）**（求めに応じて、また MCP メトリクス結果の下にチャートを描画。Pro / Max と、提供される場合は Team / Enterprise の macOS・Linux 対象。自動チャートは `/config` で無効化可）、短縮サインインリンクがエラー表示される・スクリプトが値を読む場合に全文を出す `CLAUDE_CODE_FULL_SIGN_IN_LINK=1`、セルフホストランナーの **`--start-dir` / `SELF_HOSTED_RUNNER_START_DIR`**（設定・フックは通常どおり読みつつ、リポジトリ内の特定フォルダから作業開始）、セルフホストランナー `/metrics` への所要時間メトリクス追加など。修正は非常に多く、**非常に長い会話のコンパクション直後に最大数分フリーズ**、**WebFetch が一部ページでセッションを数分ハングさせ別のページで空結果を返す**、`ExitWorktree`／worktree 終了ダイアログが**別の実行中セッションが作業している worktree を削除**、複数プロセス同時保存でユーザ設定が失われる、`--continue`／`--resume` が壊れたタイムスタンプで空セッションになる、API が拒否する入力スキーマを持つ MCP ツールが多いとターンが「JSON schema is invalid」で失敗しセッションファイルが肥大、`/rewind` が別ファイルの古い版を復元、などを修正。変更点として、**定期スケジュールタスクと `/loop` の最長実行がセッション継続中は 7 日→30 日に延長**（本リリース以前に作成したものは 7 日のまま）、root・home・トップレベル・作業フォルダを狙う `rm` 系の承認要求を拡大、`v2.1.329` で撤去した `max_tokens` 超過時の自動リトライを**復活**。VS Code 拡張にも `/fork`・`/workflows` 追加や多数の修正。
- 何が便利か: スケジュールタスク・`/loop` の上限が **30 日**に延びたことで、本ニュース生成のような長期の無人運用が途中で切れにくくなる。コンパクション直後フリーズ・WebFetch ハング・`ExitWorktree` の worktree 誤削除といった、**長時間・複数セッション・調査系ワークフローの実害バグ**がまとまって直る。easel で、チャートを別ツールに出さずその場で描ける。
- 使いどころ: スケジュールタスクや `/loop` を常用する自動化運用（本ジョブが該当）。worktree を併用する複数セッション開発。WebFetch で Web 調査を回す構成。Enterprise Admin Console で組織を集中管理している環境。セルフホストランナーをサブフォルダ起点で回す CI 構成。
- 開発者にとっての価値: 新機能（easel・enterprise サインイン・`--start-dir`）に加え、無人・長時間・並列セッションでの取りこぼしを減らす修正が中心。特にスケジュール上限 30 日化とコンパクションフリーズ修正は、エージェントを常駐運用する側に直接効く。
- 注意点: easel は MCP allowlist／denylist で除外していると毎回の警告は消えるがツール自体はブロックされたまま。定期タスク・`/loop` の 30 日化は**本リリース以降に作成したものだけ**が対象。`rm` 承認要求の拡大で、無人環境では答えられない `rm` が拒否されることがある。リリースノートは Added/Fixed/Changed/Improved と VS Code 項目を多数含む。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.330
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 前回記事（11-21）は `v2.1.329`。`v2.1.330` は本記事が初出。

### 2. Vercel AI SDK / `ai@7.0.179`

- 種別: OSS（TypeScript/JS SDK）
- 関連: Vercel / OpenAI（gpt-live）/ Gateway
- 公開・更新日: 2026-11-20（UTC 23:17 ごろ / JST 2026-11-21 08:17 ごろ）
- 概要: `ai@7.0.179` のパッチ更新。主要機能は **Gateway 経由の Live モデルを WebSocket で扱えるようにしたこと**。`gateway.experimental_realtime()` が `openai/gpt-live-1` / `openai/gpt-live-1.1` 向けの連続 Live モデルを返し、Gateway の Live ルートへ接続して正規化された Live プロトコルを使う（他の Live モデル ID は `{ api: 'live' }` で、`{ api: 'realtime' }` で realtime ルートを強制）。従来これらの ID は realtime ルートに回され `invalid_model` で拒否されていた。あわせて `gateway.experimental_realtime.getToken()` が **Live 用のクライアントシークレットを発行**し、`client-secret-websocket` 接続を宣言するモデルでは `experimental_useRealtime`／realtime セッションが**短命トークン（`api.token`）で provider へ直結**できる（従来は連続 WebSocket セッションにアプリ側リレーが必要だった）。依存更新として `@ai-sdk/gateway@4.0.152` など。
- 何が便利か: 音声・リアルタイム対話の Live モデルを **Gateway 越しに WebSocket で素直に扱える**。クライアントシークレットを `getToken()` で発行し、対応モデルは**自前のリレーサーバを立てずにブラウザ等から provider へ直結**できるため、低遅延の音声エージェントの構成がシンプルになる。
- 使いどころ: `openai/gpt-live-1` / `gpt-live-1.1` を使う音声・リアルタイムアプリ。Gateway でプロバイダを束ねつつ Live を使いたい構成。これまでリレー経由だった連続 WebSocket セッションを、短命トークンでクライアント直結に置き換えたいケース。
- 開発者にとっての価値: realtime ルートで `invalid_model` になっていた Live モデルが正式に通るようになり、`getToken()` と `client-secret-websocket` でリレーレスのクライアント直結が可能に。リアルタイム系の実装・運用コストを下げる実用的な追加。
- 注意点: いずれも `experimental_` 接頭辞付きの実験的 API で、仕様変更の可能性がある。クライアント直結はモデルが `client-secret-websocket` 接続を宣言している場合に限る。パッチ更新だが Live／realtime 周りの挙動に関わるため、該当構成はテストしてから上げること。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.179
- 参考リンク: https://ai-sdk.dev/
- メモ: 前回記事（11-21）は `ai@7.0.178`。`ai@7.0.179` は本記事が初出。

#### 使用例

```bash
# 7系を使っている場合
npm install ai@7.0.179
```

```ts
// Gateway の Live モデルに WebSocket で接続（概念例）
import { gateway } from '@ai-sdk/gateway'

const model = gateway.experimental_realtime('openai/gpt-live-1')
// クライアント直結用の短命トークンを発行
const { token } = await gateway.experimental_realtime.getToken()
```

### 3. LiteLLM / LTS `v1.108.14`・`v1.108.15`

- 種別: OSS（LLM プロキシ／SDK, Python・LTS ライン）
- 関連: Anthropic（Claude）/ OpenAI / Cohere / その他
- 公開・更新日: `v1.108.14` 2026-11-20（UTC 23:43 / JST 2026-11-21 08:43）、`v1.108.15` 2026-11-21（UTC 21:35 / JST 2026-11-22 06:35）。いずれも `lts/1.108.x` ライン。
- 概要: 100+ の LLM を統一 API で扱うプロキシ／SDK の **LTS 系メンテナンスリリース**。`v1.108.14`（3 PR・1 added / 1 fixed、「no action needed to upgrade」）は、**Claude のツール検索が `/v1/responses` のフォローアップターンで欠落し Anthropic から 400 を返す問題を修正**（#50821）、`/v1/decisions` で **OpenAI の `input_json` content part に対応**（#52807）。`v1.108.15` は主にバックポート・保守で、**Cohere v2 chat ルートの `tool_choice`／`reasoning_effort`／`json_schema`（`response_format`）のマッピング変更（破壊的: タイトルに `!`）**（#51851）、`ResetData` とキーレス JSON provider の 401 修正のバックポート（これも破壊的指定）（#53314）、Responses／Messages のシステムプロンプト先頭化に伴うテストのバックポート、バージョンバンプを含む。
- 何が便利か: LTS を運用するチームにとって、**Claude × `/v1/responses` のフォローアップで 400 になる実害バグが LTS にもバックポートされた**のが大きい。`/v1/decisions` の `input_json` 対応で OpenAI 由来の JSON content part を扱える。
- 使いどころ: 安定重視で `lts/1.108.x` を固定運用し、Claude 系を `/v1/responses` 経由でマルチターン利用しているプロキシ。Cohere v2 chat ルートを LTS で使っている構成は、`v1.108.15` の破壊的マッピング変更の影響確認に。
- 開発者にとっての価値: Latest ライン（前回記事の `v1.110.2` 系）で先行した修正が LTS に順次反映されており、保守運用側でも Claude フォローアップの 400 回避を取り込める。破壊的変更の所在（Cohere v2 ルート）が明示されているため、影響範囲を切り分けやすい。
- 注意点: `v1.108.15` は **Cohere v2 chat ルートのマッピングが破壊的に変わる**ため、Cohere を LTS で使っている場合は移行内容を PR（#51851）で確認してから上げること。`v1.108.14` は「no action needed」。`v1.111.0-rc.x`・`v1.112.0-dev.x` はプレリリースのため本番非推奨。

- 参考リンク: https://github.com/BerriAI/litellm/releases/tag/v1.108.14
