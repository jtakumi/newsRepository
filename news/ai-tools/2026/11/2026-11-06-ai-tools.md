### 1. Claude Code / `v2.1.318`（＋ `v2.1.317`）

- 種別: CLI
- 関連: Claude / Anthropic
- 公開・更新日: 2026-11-04（`v2.1.318`, GitHub Releases, Latest） / 2026-11-03（`v2.1.317`）
- 概要: 退行修正と運用まわりの改善が中心のパッチ。`--continue` が壊れたツール呼び出しのリトライ後に会話履歴を失う問題（`2.1.314` 由来の退行）、Bash コマンド多用時の macOS でのストール、設定書き込み失敗時に `/logout` や `claude mcp remove` が成功と誤報告する問題を修正。
- 何が便利か: `--continue` の履歴喪失が直り、長時間セッションの再開が安定する。バックグラウンドのサブエージェントは長時間シェルコマンドを3分でバックグラウンドへ退避するようになり、固まりにくい。
- 使いどころ: 日常のコーディングエージェント運用。`claude auth status` に `loginExpiresAt` が出るようになったので、CI やチームでのサインイン期限管理に使える。`claude -p`（ヘッドレス）実行では、claude.ai サインイン期限の10日前に警告が出る。
- 開発者にとっての価値: 退行修正により会話継続の信頼性が戻る。認証期限の可視化はスクリプト/自動化運用での突然の失敗を防ぐ。
- 注意点: `2.1.316` でアナウンスされた「Opus 4.8 の Fast モード非推奨（2026-10-30 付、2026-11-30 削除予定）」は引き続き有効。以降は Opus 5.5 への移行が必要。`claude -p` はディスク満杯でトランスクリプト書き込みに失敗した場合に終了コード1を返すよう `v2.1.317` で変更済み。
- 公式リンク: https://github.com/anthropics/claude-code/releases
- 参考リンク: https://docs.claude.com/en/docs/claude-code
- メモ: `v2.1.317` では `/schedule` にクラウドタスクへの意図しないコネクタ付与の警告、Agent SDK フックの `onFailure: "block"`、Read ツールの「file unchanged」スタブ廃止（再読込で常に内容が返る）なども追加。

#### 使用例

```bash
# 更新して最新版を確認
claude update
claude --version   # v2.1.318 を想定

# サインイン期限（loginExpiresAt）を確認する
claude auth status

# 中断したセッションを履歴を保ったまま再開（退行修正済み）
claude --continue
```

### 2. Gemini CLI / `v0.67.0`（安定版、＋ `v0.68.0-preview.0`）

- 種別: CLI（ターミナル向けコーディングエージェント）
- 関連: Gemini / Google AI
- 公開・更新日: 2026-11-04（`v0.67.0`, GitHub Releases, Latest / `v0.68.0-preview.0` も同日プレリリース）
- 概要: 長くナイトリー/プレビューに留まっていた `v0.67.0` がついに安定版でリリース。モデル探索用の `models` コマンドと `--list-models` フラグ、IDE コンパニオンのコンテナサンドボックスへのブリッジ、アトミックなファイル書き込みが読み取り専用ファイル/ハードリンクを尊重する修正などを含む。
- 何が便利か: `--list-models` / `models` で利用可能なモデル一覧を安定版で確認できる。これまで「nightly のみ・安定版待ち」と各所で言及されていた機能がようやく正式提供。
- 使いどころ: どのモデルが使えるかを起動前に確認したいとき。コンテナ内で IDE コンパニオンを使う開発環境。プロジェクトの支出上限エラーが終端的なクォータエラーとして分類されるようになり、CI での失敗判定が明確に。
- 開発者にとっての価値: モデル探索がスクリプト化しやすくなり、環境ごとの利用可能モデルを明示的に扱える。関数呼び出しを含む全ターンに thought signature が付与されるようになり、ツール利用の再現性が向上。
- 注意点: `v0.68.0-preview.0` は同日のプレリリースで、429 レート制限のクールダウン/カウントダウン表示、SubagentStop フックイベント、rootless Podman 用 `--userns=keep-id` などを先行投入。本番では安定版 `v0.67.0` の利用を推奨。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.67.0
- 参考リンク: https://github.com/google-gemini/gemini-cli
- メモ: 過去記事では `v0.66.0`（10/27）が安定版で、`models`/`--list-models` は nightly のみだった。今回安定版に昇格した点が最大の変化。

#### 使用例

```bash
# 更新後、利用可能なモデルを一覧表示（安定版で利用可能に）
gemini models
gemini --list-models

# 特定モデルを明示指定して起動
gemini -m gemini-2.5-flash
```

### 3. Qwen Code / `v0.26.8`（＋ `v0.26.7`）

- 種別: CLI（ターミナル向けコーディングエージェント）＋ VS Code / Desktop
- 関連: Qwen / Alibaba
- 公開・更新日: 2026-11-05（`v0.26.8`, GitHub Releases, Latest） / 2026-11-04（`v0.26.7`）
- 概要: `v0.26.8` で Qwen サブスクリプションを CLI・VS Code・Desktop 全体でサポート。ターミナル UI でのフック対応も追加。セキュリティ面では、プロジェクトのフックを承認ダイアログの背後に置くようゲートし、リポジトリ由来のフックや権限付与の実行前にフォルダの信頼（folder trust）を要求するようになった（`v0.26.7`）。
- 何が便利か: サブスクリプション認証が各クライアントで統一され、鍵管理が楽に。OpenRouter の `:exacto` モデルのコンテキストウィンドウ修正や、Hugging Face TGI のコンテキスト超過エラー認識によるコンパクション自動実行も入った。
- 使いどころ: Qwen サブスクリプションを CLI/エディタ横断で使う構成。信頼できないリポジトリを開く際、フックが勝手に走らないようにしたい場面。
- 開発者にとっての価値: リポジトリ提供のフックに対する folder trust 要求とプロジェクトフックの承認ゲートは、未知のリポジトリをクローンして試す運用のリスクを下げる。
- 注意点: フックの承認ダイアログは既存のフック利用フローに確認を挟むため、自動化スクリプトでは信頼設定の事前付与が必要になる場合がある。
- 公式リンク: https://github.com/QwenLM/qwen-code/releases/tag/v0.26.8
- 参考リンク: https://github.com/QwenLM/qwen-code
- メモ: SDK TypeScript `v0.1.28`（CLI v0.26.8 同梱）、Qwen Code Desktop `v0.26.8`（Web Shell の会話アクティビティビュー、Kimi K3 の 1M コンテキスト維持修正）も同日公開。過去記事では `v0.26.6`（11/02）まで掲載。

#### 使用例

```bash
# インストール / 更新
npm install -g @qwen-code/qwen-code
qwen --version   # v0.26.8 を想定

# 信頼できないリポジトリを開く際は folder trust を意識
#   リポジトリ由来フック/権限付与は trust 付与後にのみ実行される
```

### 4. LiteLLM / `v1.108.0`（安定版）

- 種別: OSS / LLM ゲートウェイ・プロキシ
- 関連: OpenRouter 的な統合レイヤー / 各社 LLM API
- 公開・更新日: 2026-11-04（`v1.108.0`, GitHub Releases, Latest / `v1.106.7` も同日）
- 概要: 久々の安定版 Latest。Vertex AI Interactions API のネイティブ対応、Bing 検索によるグラウンディングを検索プロバイダとして追加、Together AI のエンドポイントを既定で `api.together.ai` に変更。`prompt_token_calculator` の削除という破壊的変更を含む。
- 何が便利か: Vertex AI Interactions をプロキシ経由でそのまま扱える。Bing グラウンディングを検索プロバイダとして差し込めるため、検索付き生成の構成がプロバイダ非依存に寄せられる。
- 使いどころ: 複数の LLM プロバイダを1つの OpenAI 互換エンドポイントに集約している構成。Vertex AI や Together AI を混在させるマルチプロバイダ運用。
- 開発者にとっての価値: ゲートウェイ層での検索プロバイダ抽象化により、アプリ側のコードを変えずに検索付き生成の裏側を差し替えられる。
- 注意点: `prompt_token_calculator` が削除されたため、これに依存するコードは更新が必要。同日の `v1.106.7` では Lens ベータがプロキシパッケージ/Helm チャートから分離されたため、Helm values で `lensWorker.enabled` を設定している場合はアップグレード前に削除すること。カスタムプロバイダ向けに `/v1/videos` 対応も追加。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.108.0
- 参考リンク: https://docs.litellm.ai/
- メモ: 過去記事では安定版が `v1.106.6`（10/28）で、以降は `v1.108.0-rc` / `v1.109.0-dev` のプレリリースのみだった。今回 `v1.108.0` が安定版に昇格。

#### 使用例

```bash
# 更新（破壊的変更: prompt_token_calculator 削除に注意）
pip install -U litellm

# プロキシを起動して OpenAI 互換エンドポイントに集約
litellm --config config.yaml
```

### 5. Vercel AI SDK / `ai@7.0.163`

- 種別: OSS / SDK（AIアプリ構築用 TypeScript SDK）
- 関連: Vercel / 各社 LLM
- 公開・更新日: 2026-11-05（GitHub Releases）
- 概要: 7.x 系の大きめの更新。オプトインの型付きストリーミング「ハートビート（ping）」パート、アップロード動画を報告する `uploadedVideos` フィールド、Groq のネイティブ URL 文字起こし、文字起こしの単語タイムスタンプ公開、ストリーミング中のステアリングメッセージを UI へ流す対応などを追加。
- 何が便利か: ping パートで長時間ストリーム中の生存確認ができ、UI のタイムアウト対策になる。文字起こしの単語タイムスタンプで字幕/検索インデックス作成が容易に。
- 使いどころ: ストリーミング UI を持つ AI アプリ。音声文字起こしを扱うアプリ（Groq の URL 文字起こしで外部音声をそのまま渡せる）。
- 開発者にとっての価値: ステアリングメッセージの UI ストリーミングで、実行中タスクへの追加指示をユーザーに見せられる。Google ストリーミング応答のテキストと関数呼び出しの順序保持により、ツール併用時の表示が崩れにくい。
- 注意点: ストリームパートを網羅的に `switch` で処理しているコードは、新しい `ping` バリアントを扱う必要がある（アップグレード時の対応ポイント）。`@ai-sdk/workflow@2.0.95` では `WorkflowAgent.stream()` から `experimental_transform` が削除される破壊的変更あり。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.163
- 参考リンク: https://ai-sdk.dev/
- メモ: 過去記事では `ai@7.0.160`/`7.0.161`（11/02）まで掲載。今回は新バージョンかつ ping/動画/文字起こし系の新機能があるため採用。

#### 使用例

```bash
# 更新
npm install ai@7.0.163
```
