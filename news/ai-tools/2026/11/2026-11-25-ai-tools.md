- **OpenAI Codex `0.172.0`** が安定版として公開。スラッシュコマンドの **`Tab` 引数補完**、検索結果・履歴からの **スレッドリンクで保存済み会話を開く**、`codex exec resume` が **サンドボックス権限・作業ディレクトリ・ワークスペースルートを復元**、プロバイダエラーの即時表示と **どの API 利用上限に達したかの明示**など、ターミナル運用の使い勝手が広く改善された。

### 1. OpenAI Codex / `0.172.0`

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 2026-11-24 00:03（UTC、JST 11-24 09:03）
- 概要: 安定版の機能・修正まとめ更新。**新機能**として、検索結果・履歴中の **スレッドリンク**から保存済み会話や入れ子エージェントをターミナルで開けるように。対応スラッシュコマンドで **`Tab` が引数を補完**（例: `/mcp lo` → `/mcp login`）。`Shift+Up` / `Shift+Down` でエージェントコマンドセンターのタスクグループ間を移動。ツールリストをキャッシュした **stdio MCP サーバーを初回ツール呼び出し時に起動**（既定）。接続アプリのツールごとに承認レビュアーを `config.toml` で設定可能。アプリサーバークライアントがセットアップ／サインイン時に Amazon Bedrock Runtime を選択可能に。**バグ修正**では、`codex exec resume` が保存済みサンドボックス権限・作業ディレクトリ・ワークスペースルートを（上書きしない限り）復元、クライアントとサーバーが別 OS でもリモートセッションがそれらの設定と書き込み可能パスを維持、**プロバイダエラーが応答ストリーム到着と同時に表示され、どの API 利用上限に達したかを出力で明示**、親ターンの中断時に子エージェントのキュー済み返信を次ターンへ保持、など。`openai-docs` スキルに **GPT-6.2 Astra / Sol への移行**（エンドポイント選択・ツール呼び出し要件）を収録。**変更**として、Code Mode のホスト接続が全て gRPC になり `code_mode_host_grpc` 設定は非推奨に。
- 何が便利か: スラッシュコマンドの `Tab` 補完や過去会話へのスレッドリンクで、ターミナルでの反復作業が速くなる。`codex exec resume` のサンドボックス権限・作業ディレクトリ復元により、中断した非対話実行を正しい文脈で再開できる。プロバイダエラーの即時表示と上限の明示で、API の詰まりの切り分けが速い。
- 使いどころ: Codex を CLI で日常的に回す開発者。`codex exec` を CI やスクリプトで使い、再開時に権限・作業ディレクトリを保ちたいケース。MCP サーバーを多数つなぐ構成で、初回呼び出し時起動により起動コストを抑えたいケース。
- 開発者にとっての価値: ターミナルエージェントの操作性と非対話実行の信頼性が同時に上がる。GPT-6.2（Astra / Sol）移行ドキュメントが同梱され、モデル更新への追従がしやすい。
- 注意点: Code Mode が gRPC 専用になったため、`code_mode_host_grpc` に依存した設定は見直しが必要。多数の内部更新（Guardian ポリシー更新、Windows / macOS・Linux サンドボックス、Statsig レイテンシカウンタ）を含む。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.172.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 既存記事では安定版 `0.171.0`（11-20・11-21 記事）まで掲載済み。11-24 記事では `0.172.0-alpha.2.1` をプレリリースとして不採用とした。本記事は安定版に昇格した `0.172.0` を採用。

#### 使用例

```bash
npm install -g @openai/codex@latest   # もしくは各配布チャネルで更新
codex --version

# 中断した非対話実行を、保存済みサンドボックス権限・作業ディレクトリごと再開
codex exec resume
```

### 2. LiteLLM / `v1.110.3`

- 種別: OSS / プロキシ・ゲートウェイ
- 関連: LiteLLM / Gemini / 各種プロバイダ / MCP
- 公開・更新日: 2026-11-24 04:11（UTC、JST 11-24 13:11）
- 概要: stable 系のパッチ更新（7 PR: 修正 3・変更 1・要対応 1）。**要対応**として、新しい clientless DCR ブリッジ向けの **ゲートウェイ所有 MCP クライアント登録がオプトイン化**され、維持するには環境変数 `LITELLM_MCP_DCR_GATEWAY_CLIENT=true` の設定が必要（共有サービスキーでの `403 oauth_principal_mismatch` エラー対策、同変更は `1.108.16` / `1.109.4` にも収録）。**修正**として、`/gemini` パススルーの file get / download / delete が `/v1/files` と同じファイル所有権チェックを飛ばしていた問題、複雑度ルーティングされたリクエストがクールダウン中モデルに当たるとフォールバックせず失敗していた問題、**キーやチーム更新後に `GET /audit` が 500 を返し Admin UI の監査ログページが空になっていた問題（v1.108.0 以降）** を修正。
- 何が便利か: セルフホストの LLM ゲートウェイ運用者に直結。監査ログが空になる不具合や、複雑度ルーティング時のフォールバック欠落が直り、本番運用の観測性と信頼性が上がる。
- 使いどころ: 複数プロバイダを 1 本の OpenAI 互換エンドポイントに集約し、監査ログやルーティング・フォールバックを本番で使っている構成。MCP ゲートウェイを運用している環境。
- 開発者にとっての価値: Admin UI の監査ログ復旧とルーティングのフォールバック修正は、運用トラブルの切り分けと可用性に効く。stable 系なので比較的取り込みやすい。
- 注意点: **MCP ゲートウェイ DCR 登録がオプトイン化**されたため、この自動登録に依存している構成は `LITELLM_MCP_DCR_GATEWAY_CLIENT=true` を明示設定しないと挙動が変わる。更新前に確認すること。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.110.3
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 既存記事では LTS 系 `v1.108.16`（11-24 記事）まで掲載済み。MCP DCR オプトイン化は共通だが、本記事は未掲載の stable 系 `v1.110.3`（監査ログ 500・複雑度ルーティング・Gemini パススルーの修正を含む）を採用。同日に `v1.109.4` も公開（MCP オプトイン化を含む 2 PR）。

### 4. Ollama / `v0.40.18`

- 種別: OSS / ローカル LLM ランタイム
- 関連: Ollama / ローカル LLM / Apple Silicon
- 公開・更新日: 2026-11-24（UTC、JST 11-24）
- 概要: ローカル LLM ランタイムのパッチ更新。**Apple Silicon（Metal）向けの推論最適化**として、Inkling 系モデルの **residual mixing を融合**（#19808）、**inkling2 の decode・prefill・draft ラウンドを高速化**（#19843）。内部では mlxrunner がアーキテクチャ間でテンソルヘルパーとモデルセットアップを共有するようリファクタ（#19805）。依存の **llama.cpp を `b12651` に更新し、JetPack 5 のサポートを終了**（#19865）。
- 何が便利か: Apple Silicon の Mac で Inkling 系モデルをローカル実行する場合、decode / prefill などが速くなり応答のレイテンシ改善が見込める。
- 使いどころ: Mac（Metal / MLX）上でローカル LLM を動かし、Inkling 系モデルを使っている個人開発・ローカル検証環境。
- 開発者にとっての価値: ローカル推論の高速化はオフライン開発や機密データを外部に出さない検証で効く。llama.cpp 追従で対応モデル・修正も取り込める。
- 注意点: **JetPack 5 のサポートが終了**したため、該当する NVIDIA Jetson 環境は要確認。高速化は主に Metal / Inkling 系モデル向けで、全環境・全モデルで体感差が出るわけではない。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.18
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 既存記事では `v0.40.17`（11-10）を「直近 24〜48 時間外のため不採用」と記載（11-24 記事の調査メモ）。本記事は 11-24 公開の新しい安定版 `v0.40.18` を採用。
