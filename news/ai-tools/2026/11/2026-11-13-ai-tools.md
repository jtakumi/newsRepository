### 1. Claude Code / `v2.1.323`

- 種別: CLI / 拡張機能
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-12（「Latest」）
- 概要: **Code Mode** を実験的オプトインとして追加。Claude が自分のツールを呼び出す JavaScript を書いて実行する方式で、組織単位でオフにもできる。plugin には `engines["claude-code"]` を追加し、宣言した Claude Code の版数範囲外のプラグインはインストール・更新・ロードされず、範囲に合う最新版が選ばれる。`claude plugin validate` が plugin の TypeScript フックモジュールを型チェック（各指摘は警告、`--strict` で失敗扱い）。Artifact ツールのアセットアップロードが `.docx` に対応。ほかに Bash サンドボックス／deny・allow ルール／サインインまわりの多数のセキュリティ修正と、`/compact` の再実行・大きなファイル編集後のメモリスパイクなどの信頼性修正が入った。
- 何が便利か: Code Mode により、複数ツール呼び出しや条件分岐を JavaScript コードとして表現でき、反復的なツール操作を宣言的に書ける。`engines` 指定で非互換プラグインの誤ロードを防ぎ、`plugin validate` の型チェックで配布前にフック不備を検出できる。
- 使いどころ: 多数のツール呼び出しを伴う自動化・エージェント処理の記述、plugin/mod の開発・配布、権限・サンドボックス周りを厳しくした上でのCI自動実行。
- 開発者にとっての価値: Code Mode はエージェント型ワークフローの表現力を上げる。大量の権限・サンドボックス修正は自動化／CI 実行の安全性に直結し、`claude plugin validate` の型チェックはプラグイン配布の品質担保に効く。
- 注意点: Code Mode は実験的オプトイン。リリースノートが案内する公式ドキュメント（`code.claude.com/docs/en/code-mode`）は執筆時点で未公開（404）のことがあり、有効化手順はアプリ内設定／最新ドキュメントで確認すること。更新は `claude update`。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.323
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: 前回（11-12）は `v2.1.321`／`v2.1.322` を扱った。本項は `v2.1.323` の新規差分（July の「Code Mode」は Codex CLI の別機能で本項とは無関係）。

#### 使用例

```bash
# 更新して最新版を確認
claude update && claude --version

# plugin 開発者は TypeScript フックの型チェック（--strict で失敗扱い）
claude plugin validate --strict
```

### 2. LiteLLM / `1.109.1`・`1.109.0`

- 種別: OSS / LLM ゲートウェイ（プロキシ）・SDK
- 関連: LiteLLM / マルチプロバイダ / OpenRouter 的ルーティング
- 公開・更新日: 2026-11-11（`1.109.0`）・2026-11-12（`1.109.1`・「Latest」）
- 概要: `1.109.0` は大型機能リリースで、**ミッドストリームでのフォールバック継続（mid-stream fallback continuation）**、**`LITELLM_OFFLINE_MODE` スイッチ**、Admin UI の Chat UI を追加。破壊的変更として、文字列のフォールバック指定がリスト化、`disk` キャッシュタイプの廃止、新しい Gemini モデル向け `drop_params` が入った。`1.109.1` は **プロキシのセキュリティ修正（PR #51254）をバックポートしたパッチ**。あわせて LTS 系の `1.108.6`／`1.108.7`（11-12）も公開され、Azure／クライアント認証フィールド（`tenant_id`・`client_id`・`client_secret` など）を `metadata` 配下へ移す action-required 変更や、`/v1/batches` での Gemini バッチ対応などが入った。
- 何が便利か: マルチプロバイダのルーティングで、ストリーミング応答の途中からフォールバックを継続できるため、長い応答中のプロバイダ障害に強くなる。`LITELLM_OFFLINE_MODE` で外部通信なしの運用を明示でき、閉域・エアギャップ環境の検証に向く。`1.109.1` のセキュリティ修正は即時更新の価値がある。
- 使いどころ: 複数の LLM プロバイダを単一の OpenAI 互換エンドポイントに束ねるゲートウェイ運用。CI・閉域環境でのオフライン動作確認。可用性を上げたい本番プロキシ。
- 開発者にとっての価値: ゲートウェイを本番運用しているなら `1.109.1` のセキュリティ修正は早期更新対象。offline mode とフォールバック継続は可用性・運用性を実際に押し上げる。
- 注意点: `1.109.0` には action-required の破壊的変更（文字列フォールバックのリスト化、`disk` キャッシュ廃止、Gemini 向け `drop_params`）がある。LTS 系（`1.108.6`／`1.108.7`）は Azure 等の認証フィールドを `metadata` へ移す必要がある。アップグレード前に各リリースの action-required を確認すること。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.109.1
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: これまでの記事（11-01〜11-08 ほか）では LiteLLM は dev/rc プレリリースのみで安定版の新規なしとして見送っていた。本項は安定版 `1.109.0`／`1.109.1` の新規採用。

#### 使用例

```bash
# プロキシ用途でインストール／更新
pip install -U "litellm[proxy]"==1.109.1

# 外部通信なしのオフラインモードで起動（閉域・CI 検証向け）
LITELLM_OFFLINE_MODE=true litellm --config config.yaml
```

- 関連: OpenAI / Codex

- 注意点: 恩恵は Vertex AI 利用時が中心。オプトアウトのフラグ名 `incremental_tools_legacy_gcp` は名称が直感に反するため、意味は公式の config ドキュメントで確認すること。`0.169`／`0.170-alpha` 系は本番非推奨。

### 4. Vercel AI SDK / `ai@7.0.171`（＋ `ai@6.0.331`）

- 種別: OSS / SDK
- 関連: Vercel AI SDK
- 公開・更新日: 2026-11-12
- 概要: `7.0.171` は、**不正な UI メッセージ検証時のメモリ・CPU 過剰使用を修正**（最初の不正メッセージ／パートで検証を打ち切る方式に変更）。さらに、失敗したツール呼び出しのエラーテキストを「モデルが受け取ったまま」クライアントへ送るよう既定を変更し、挙動を上書きする **`redactToolErrors` オプション**を追加。`createDownload` に `fetch` オプションを追加してプロバイダの fetch トランスポートをファイルダウンロードに転送（Azure／Vertex の認証をファイルホストへ渡さない）。実験的な extract API も追加。同等の検証修正と `redactToolErrors` は `6.0.331` にもバックポートされた。
- 何が便利か: 不正入力による CPU／メモリスパイクを抑止できる。`redactToolErrors` でツールエラー文言のクライアント露出を制御でき、情報漏えい対策や UX 調整に使える。ダウンロードのトランスポート制御で認証境界を守れる。
- 使いどころ: ツール／エージェントを使うチャット UI で、ツールエラーの扱いを明示的に制御したいケース。ファイルダウンロードを伴うプロバイダ連携。
- 開発者にとっての価値: メジャー 6／7 系に同時対応のパッチで、どのメジャーを固定していても恩恵を受けられる。
- 注意点: パッチリリースのため大きな API 変更はないが、ツールエラーの既定挙動が「モデルが受け取ったテキストをそのままクライアントへ送る」に変わる点に注意（隠したい場合は `redactToolErrors` を使う）。extract API は実験的。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.171
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 前回（11-12）は `ai@7.0.170`／`6.0.330` を扱った。本項は `ai@7.0.171`／`6.0.331` の新規差分。

#### 使用例

```bash
# メジャー7系を使っている場合
npm install ai@7.0.171
```
