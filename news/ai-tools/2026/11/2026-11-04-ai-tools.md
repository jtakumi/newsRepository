## 今日の注目

### 1. Claude Code / `v2.1.317`

- 種別: CLI / Agent SDK
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-03（JST、UTC 2026-11-03 01:25）
- 概要: 安定性修正中心のパッチ。開発者向けには、Agent SDK のフックコールバックに `onFailure: "block"` が追加され、失敗したフックがアクションをそのまま実行させずにブロックできるようになった。Web/シェルツールの呼び出しがアカウントのメールアドレスをネットワークへ送る前に確認を求めるチェック、`/schedule` でクラウド定期タスクに頼んでいないコネクタが付いた場合の警告、管理API のコスト集計エンドポイント `GET /v1/organizations/analytics/cost`（期間・開発者別・日別・IdPグループ別の利用額）も追加。ほか MCP 切断、auto mode のゲートウェイ 403/422 応答、`claude auth status` のトークン更新保存漏れなど多数のバグ修正。
- 何が便利か: 自動化パイプラインで「検査フックが失敗したら処理を止める」を明示的に設定できる。組織のClaude利用コストをAPIで日次・開発者別に取得して可視化できる。
- 使いどころ: CI や非対話実行（`claude -p`）で、危険操作をフックで検査し、検査が落ちたらアクションを実行させずに止める。社内のエージェント利用コストのダッシュボード化。
- 開発者にとっての価値: フック失敗の扱いが「握りつぶし」ではなく「ブロック」を選べるようになり、ガードレールを信頼できる形で組める。メール送信前の確認はエージェントの情報漏えい対策として有効。
- 注意点: 大半はバグ修正。npm の `latest` タグへの反映にはラグがある場合がある。コスト集計APIは管理者権限が前提。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.317
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 前日（11-03）は `v2.1.316` までを別記事で扱い済み。本件は `v2.1.317` の新規差分。

### 2. Pydantic AI / `v2.65.0`

- 種別: OSS / Python ライブラリ
- 関連: その他（Pydantic）/ OpenAI / Anthropic / OpenRouter
- 公開・更新日: 2026-11-03（JST、UTC 2026-11-02）
- 概要: OpenAI Responses API 用の WebSocket トランスポートを追加。会話永続化に `ConversationStore`（各メッセージを一度だけ保存）と `Conversation.revision`（保存の競合検知）を導入。`ModelFallback` がモデルの拒否（refusal）でも次モデルへフォールバックするようになり、`ContentFilterError` を `fallback_on` で拒否にマッチさせられる。GPT-5.6 以降向けに OpenAI Responses API の 12 時間プロンプトキャッシュ保持、OpenRouter の OpenAI 系ルートと対応 Claude モデルで会話途中のシステムプロンプトをネイティブ対応。
- 何が便利か: マルチモデル構成で「拒否されたら次のモデルへ」という自動フォールバックが堅牢になる。会話履歴を重複なく保存し、同時更新の競合も検知できる。
- 使いどころ: 可用性を上げたい本番エージェント、長い会話を永続化するアプリ、プロンプトキャッシュでコストを抑えたい GPT-5.6 系の利用。
- 開発者にとっての価値: フォールバックが「エラー時」だけでなく「拒否時」も効くため、モデルの安全フィルタに引っかかった場合の挙動を設計しやすい。
- 注意点: 前日まで扱った `v2.64.0` の `ModelFallback` をさらに拡張した版。一部は互換性変更（Z.ai の 429 が `ModelQuotaExceededError` を送出、Google リクエストの最小デッドライン 20 分化など）を含む。
- 公式リンク: https://github.com/pydantic/pydantic-ai/releases/tag/v2.65.0
- 参考リンク: https://ai.pydantic.dev/
- メモ: `daytona>=0.226.1` が新たに必須。

### 3. Ollama / `v0.40.14`

- 種別: CLI / ローカルLLM ランタイム
- 関連: その他（Ollama）/ Claude / OpenAI（Codex）
- 公開・更新日: 2026-11-03（JST、UTC 2026-11-03 06:57）
- 概要: `ollama launch claude` がモデルの出力トークン上限を適用するようになり、クラウドモデルがデフォルトの 128k 上限で頭打ちにならないよう修正。`ollama launch codex` は設定前に ChatGPT ルーティングを検証し、使えない場合は明確なエラーを表示。OpenAI 互換エンドポイントは、クライアントが `temperature` / `top_p` を省略したときにモデル同梱のサンプラー既定値を維持する（従来は 1.0 固定）ようになり `/api/chat` と挙動が揃った。ほか `/api/chat` のクラウドWeb検索レスポンス（圧縮含む）の解凍修正、`/v1/responses` の入力内容保持、MLX の大語彙 top-k サンプリング高速化。
- 何が便利か: Ollama 経由でエージェントCLI（Claude Code / Codex）を起動する構成が実用的に。OpenAI互換APIでモデル本来のサンプラー設定が尊重される。
- 使いどころ: ローカル/クラウド混在でエージェントCLIを起動、OpenAI互換クライアント（既存SDK）からOllamaのモデルを既定サンプラーで呼ぶ。
- 開発者にとっての価値: 出力トークン上限の修正で、長い出力を返すエージェント用途でも途中打ち切りが起きにくくなる。
- 注意点: 本記事時点で `v0.40.15-rc0`（MiMo V2.6 レンダラ追加）も出ているがリリース候補のため採用は安定版の `v0.40.14`。`ollama launch codex` は ChatGPT ルーティングが使える環境が前提。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.14
- 参考リンク: https://ollama.com/
- メモ: サンプラー既定値の変更で、既存の OpenAI 互換クライアントからの出力傾向が変わる可能性がある。

#### 使用例

```bash
# 更新確認
ollama --version   # 0.40.14 以上であること

# Ollama 経由でエージェントCLIを起動（出力トークン上限が適用される）
ollama launch claude
```

### 4. Vercel AI SDK / `ai@7.0.162`

- 種別: OSS / TypeScript SDK
- 関連: その他（Vercel）
- 公開・更新日: 2026-11-03（JST、UTC 2026-11-03 01:26）
- 概要: パッチリリース。ツール承認（tool approval）の継続検証時に、サーバー定義のツールメタデータ・動的ステータス・タイトルを復元し、承認ポリシーが新規モデル呼び出しと同じツール定義フィールドを参照できるよう修正。Durable な `WorkflowAgent` 実行が、プロンプト・出力・ステップ・ツールを 1 つのテレメトリ操作としてまとめて報告できるようになった（OpenTelemetry 利用時はステップ間でトレースコンテキストをつなぐため共有 ID 生成器とサンプラーの指定が必要。テレメトリ連携用の実験的な型付きコンテキストフックも追加）。
- 何が便利か: human-in-the-loop のツール承認で、承認判断が常に完全なツール定義を見るようになり、承認ポリシーの取りこぼしが減る。
- 使いどころ: ツール実行前に人間/ポリシーの承認を挟むエージェント、Durable Workflow の観測性（トレーシング）を一本化したいケース。
- 開発者にとっての価値: 承認継続時のメタデータ欠落という分かりにくいバグが解消し、承認ロジックを安定して書ける。
- 注意点: 前日（11-03）に扱った `ai@7.0.160`（`steering.queue()`）とは別の差分。本件はパッチ扱いで、`@ai-sdk/provider-utils@5.0.74` / `@ai-sdk/gateway@4.0.135` への依存更新を含む。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.162
- 参考リンク: https://ai-sdk.dev/
- メモ: テレメトリのブリッジは OpenTelemetry 側の設定が前提。
