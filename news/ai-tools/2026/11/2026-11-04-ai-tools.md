## 今日の注目

### 1. Claude Code / v2.1.317

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-02（UTC 23:57 / JST 11-03 08:57）
- 概要: 追加点: `/schedule` でクラウドのスケジュールタスクが依頼していないコネクタを持つ場合の警告と外し方、Web／シェルツールがアカウントのメールアドレスを送信する前の確認、Agent SDK フックコールバックが失敗したら実行を止める `onFailure: "block"`、Claude Desktop の Code タブでの管理設定読み込み通知、auto モードの確認がサブエージェントのツール呼び出しに答えられなかったときの通知、OTel への `anthropic.plan`／`seat_type`／`provider`／`custom_base_url`、Claude apps ゲートウェイ管理 API の費用レポート `GET /v1/organizations/analytics/cost`（期間・開発者別・日別・IdP グループ別）、`admin:` を設定したゲートウェイの IdP グループ日次記録、セルフホストランナーでの `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID`。修正は、Claude desktop セッションで project／local の MCP サーバーが最初のターン後に切断される問題、ゲートウェイの安全確認が 403/422 を返すと auto モードが毎ターン失敗する問題、`claude auth status` が遅いトークン更新の保存前に終了してサインアウトを招く問題、自己ペース `/loop` のウェイクアップが予約されないことがある問題など。
- 何が便利か: ゲートウェイ運用者は費用レポート API で支出を期間・開発者・IdP グループ単位に集計できる。メールアドレス送信前の確認など、プライバシー面の配慮が入った。
- 使いどころ: Claude apps ゲートウェイの運用者、SDK フックで失敗時にブロックしたい構成、`/loop` や `/schedule` を使う無人運用。
- 開発者にとっての価値: 無人運用で「失敗したらブロックする」フックや費用の可視化が揃う。
- 注意点: `onFailure: "block"` はフック失敗時に処理が止まる挙動になるため、導入時に既存フックの安定性を確認すること。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.317
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 翌日公開の `v2.1.318` は 11-05 記事で扱う。
