### 1. Gemini CLI / `v0.67.0`

- 種別: CLI（ターミナル向けコーディングエージェント）
- 関連: Google / Gemini
- 公開・更新日: 2026-11-04（GitHub Releases, Latest）
- 概要: 利用可能なモデルを探せる `models` コマンドと `--list-models` フラグを追加。IDE コンパニオンをコンテナサンドボックス内へ exec stdio 経由でブリッジし、サンドボックス実行時も IDE 連携を効かせられるようにした。相対ファイルパスをアクティブな IDE ワークスペースのルート基準で解決、IDE 設定と GEMINI.md を開いているファイルのコンテキストから除外する調整も入った。
- 何が便利か: モデル探索コマンドにより、設定ファイルを覗かずに CLI から直接使えるモデルを確認できる。信頼できないフラグのチェックを外部出力に限定し承認済みフラグを記憶、非対話モードが終了シグナルを扱いキャンセル後はツール実行をブロックするなど、権限と安全まわりが堅くなった。関数呼び出しを含む全ターンに thought signature を付与し、拡張トークン使用メタデータを保持してターンごとの計上を整合させる修正も実務的。
- 使いどころ: Gemini 系モデルで CLI コーディングを回す日常作業。サンドボックス内で IDE 連携を使いたいケース。プロジェクト支出上限エラーを終端的なクォータエラーとして分類するため、CI などで上限到達を検知したい運用。Android（Termux）で ripgrep の解決に信頼済みシステムパスを許可。
- 開発者にとっての価値: 直近は nightly が続いていた中での新しい安定版で、モデル探索・権限・トークン計上の改善がまとまって入る。安定版で試せる導入のしやすさ。
- 注意点: リリースノートに破壊的変更の記載はないが、設定移行時に `${VAR}` プレースホルダを保持する修正や CRLF 正規化など挙動変更があるため、独自設定を使っている場合は移行後の動作を確認するとよい。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.67.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 2026-11-01〜11-03 版では Gemini CLI は `v0.67.0-nightly.*` のナイトリーのみで本文未掲載とし、安定版は 10/27 の `v0.66.0` だった。本項は新規の安定版 `v0.67.0` を扱う。

#### 使用例

```bash

npm install -g @google/gemini-cli@latest
gemini --version

# 使えるモデルを一覧する（新コマンド）

```

### 2. Claude Code / `v2.1.317`・`v2.1.318`

- 種別: CLI（ターミナル向けコーディングエージェント）
- 関連: Anthropic / Claude Code
- 公開・更新日: 2026-11-03（`v2.1.317`）／2026-11-04（`v2.1.318`）（GitHub Releases）
- 概要: `v2.1.317` で、Web / Shell ツール呼び出しがアカウントのメールアドレスを送信しうる場合に事前チェックを挟む安全対策を追加。Agent SDK のフックコールバックが失敗時に `onFailure: "block"` でアクションをブロックできるように。OpenTelemetry のメトリクス・イベント・スパンへ plan / seat type / provider / カスタム base URL 属性を追加。`/schedule` が要求していないコネクタについて警告し削除方法を案内。`v2.1.318` では、`claude auth status` と `claude -p` の JSON に claude.ai サインインの有効期限を表示し、期限 10 日前から stderr に警告。ヘッドレス（`-p`）実行が API エラー後に誤って成功と報告する不具合などフック周りを修正し、`$.model.fork` が `effort` オプションを受け付けるようになった。

- 使いどころ: `-p` でのヘッドレス実行を CI / 自動化に組み込んでいる運用。OpenTelemetry でメトリクスを収集・課金/可視化している組織。共有ネットワークのホームディレクトリで複数ログインを扱う環境（サインイン・設定保存の修正多数）。
- 開発者にとっての価値: 自動化の正確性（ヘッドレスの成功誤報告修正）と安全性（メール送出チェック、フックの block）、可観測性（OTel 属性）という日常運用に直結する改善がまとまって入る。

- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.318

- メモ: 2026-11-01 版で安定版 `v2.1.316`（10/31）を扱った。本項はその後の新規安定版 `v2.1.317` / `v2.1.318` を扱う。

### 4. Qwen Code / `v0.26.7`

- 種別: CLI（ターミナル向けコーディングエージェント）
- 関連: Alibaba / Qwen（Gemini CLI 派生）
- 公開・更新日: 2026-11-04（GitHub Releases, Latest）
- 概要: `experimental.unifiedAgentLoop` を有効にすると、ACP の Goal ターン・cron ジョブ・バックグラウンド通知ターンが共有エージェントループで動き、ラウンド処理・ツールのバッチ・停止点の挙動が揃うようになった。`prompt.submit` フックが Ink ターミナルで、入力されたプロンプトの処理前に実行されるようになり、貼り付け内容が展開済みの状態でフックから見える。`qwen serve` へのリモートアクセスを Settings → Connections から再起動なしで有効化できる。
- 何が便利か: フォルダ信頼（folder trust）を、リポジトリ提供のフック・権限付与・プロジェクト言語サーバの実行前に必須化し、`.qwen/settings.json` のプロジェクトフックが抑止された場合は警告を出すようにして安全性を強化。OpenRouter のモデル ID で `:exacto` サフィックス付き（例 `qwen/qwen3-coder:exacto`）がベースモデル名を保持し、262K コンテキストを正しく得られる修正、`grep -n` / `--line-number` をフラグとして扱いファイル読み取りの権限チェックを維持する修正など、実務的な不具合解消が入る。
- 使いどころ: Qwen 系モデルで CLI コーディングを回す日常作業。cron / バックグラウンド通知を使う自動化（統一エージェントループ）。OpenRouter 経由で長コンテキストの Qwen3-Coder を使うケース。
- 開発者にとっての価値: フォルダ信頼ゲートで信頼していないリポジトリのフック自動実行を防げる安全改善と、OpenRouter コンテキスト幅や権限チェックの実務修正がまとまる。
- 注意点: 本リリースの機能の一部は Web Shell / Managed Agent（ホスティング前提）や実験フラグ（`experimental.unifiedAgentLoop`）向けで、個人の CLI 利用では使わないものもある。モデル固有のツール選択（forced tool selection）非対応回避など、モデル依存の挙動変更がある点は確認すること。
- 公式リンク: https://github.com/QwenLM/qwen-code/releases/tag/v0.26.7
- 参考リンク: https://github.com/QwenLM/qwen-code/releases
- メモ: 2026-11-03 版で安定版 `v0.26.6` を扱った。本項は新規の安定版 `v0.26.7` を扱う。

#### 使用例

```bash

npm install -g @qwen-code/qwen-code@latest
```

### 5. LangChain / `langchain-core==1.7.5`（＋ `langchain==1.4.9`・`langchain-anthropic==1.7.10`・`langchain-openai==1.7.4`）

- 種別: OSS / ライブラリ（LLM アプリ・エージェント構築フレームワーク）
- 関連: LangChain / Anthropic・OpenAI・Gemini（provider 連携）
- 公開・更新日: 2026-11-04（GitHub Releases）
- 概要: `langchain-core==1.7.5` で、モデルの拒否（refusal）をコンテンツブロックとして標準化し、Gemini のセーフティブロックを refusal コンテンツブロックへ変換するようにした。ツールのキャンセル時に実行が正しく終了するよう修正し、LangChain.js でシリアライズされた `RemoveMessage` の読み込み不具合も修正。`langchain==1.4.9` はこの refusal 対応のために `langchain-core>=1.7.5` を要求する依存更新が中心。`langchain-anthropic==1.7.10` / `langchain-openai==1.7.4` も同日に更新。

- 使いどころ: 複数プロバイダ（Claude / OpenAI / Gemini）を切り替えて使う LangChain アプリ・エージェントで、拒否・セーフティブロックを横断的に扱いたいケース。ツールのキャンセル処理を実装している構成。
- 開発者にとっての価値: provider 横断で refusal を標準化する地味だが実用的な改善で、安全ガードやフォールバックのロジックを統一的に書ける。`pip install -U` で取り込める導入のしやすさ。
- 注意点: 拒否の表現が変わるため、これまでプロバイダ固有の形で拒否を判定していたコードは新しい refusal コンテンツブロックに合わせて見直す必要がある。`langchain==1.4.9` は `langchain-core>=1.7.5` を要求するため、同時に更新すること。
- 公式リンク: https://github.com/langchain-ai/langchain/releases/tag/langchain-core%3D%3D1.7.5
- 参考リンク: https://github.com/langchain-ai/langchain/releases
