### 1. Vercel AI SDK / `ai@7.0.179`

- 種別: OSS / SDK（TypeScript）
- 関連: Vercel AI SDK / OpenAI（Live models）/ AI Gateway
- 公開・更新日: 2026-11-20 23:17（UTC、JST 11-21 08:17）
- 概要: AI Gateway 経由の **Live（継続接続）モデルを WebSocket でサポート**。`gateway.experimental_realtime()` が `openai/gpt-live-1` / `openai/gpt-live-1.1` を継続 Live モデルとして返し、Gateway の Live ルートへ正規化プロトコルで接続する。`{ api: 'live' }` で他の Live モデル ID も、`{ api: 'realtime' }` で realtime ルートを強制できる。`gateway.experimental_realtime.getToken()` が Live 用のクライアントシークレットを発行し、モデルが `client-secret-websocket` を宣言していれば `api.token`（短命トークン）でプロバイダへ直接接続できる。
- 何が便利か: これまで継続 WebSocket セッションはアプリ側のリレーが必須だったが、短命トークンで**クライアントから直結**できるようになり、音声・リアルタイム系アプリのバックエンド構成が簡素化される。従来 realtime ルートが `invalid_model` で弾いていた Live モデル ID も扱えるようになった。
- 使いどころ: 音声エージェント、リアルタイム会話 UI、ストリーミング前提のフロントエンドを Next.js / TypeScript で組むケース。
- 開発者にとっての価値: Live モデルの接続経路（アプリ中継 vs 直結）を選べるようになり、レイテンシとサーバー負荷のトレードオフを設計段階で調整できる。
- 注意点: `experimental_realtime` の名前どおり**実験的 API** で、将来変更の可能性。クライアント直結はモデル側が `client-secret-websocket` を宣言している場合のみ。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.179
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 既存記事（11-21）の `ai@7.0.178`（ツール承認まわりのセキュリティ修正）の次版。本記事では未掲載の 7.0.179 を採用。

#### 使用例

```bash
npm install ai@7.0.179
# 以降は gateway.experimental_realtime() で Live モデルを取得して利用
```

### 2. Cline / `v4.1.27`（拡張機能）＋ SDK `v0.2.1`・CLI `v3.0.75`・Desktop `v0.0.50`

- 種別: 拡張機能（VS Code）/ OSS / CLI
- 関連: Cline / AI コーディングエージェント
- 公開・更新日: 2026-11-21（拡張機能は UTC 06:05、JST 15:05 ごろ。SDK・CLI・Desktop も同日公開）
- 概要: 拡張機能 `v4.1.27` は **`read_files` の 8k 文字打ち切りを撤廃**（読み込みが欠けない）、MCP ツールへの read-only バッジ、LM Studio 用 API キー欄、Cline プロバイダが未設定時に最初の無料モデルで起動、**モデルカタログ刷新**、GPT-6 Azure で reasoning effort を「None」に設定したときの保存・送信修正（ツール呼び出し拒否の解消）、undici 7.30.1 でクラッシュ 2 件を修正など。Headless `SDK v0.2.1` は `read_files` の上限を 8k→50k に拡大し、チェックリストをサブエージェントへ委譲する **`ux_verifier` ツール**を追加、リクエスト全文をディスクに書く `CLINE_CAPTURE_*` を削除、プロバイダを 94 追加してカタログ刷新。`CLI v3.0.75` はワンショット実行を yolo モードで開始し `--timeout`・Ctrl+C で初回ターンを停止可能、起動ディレクトリの `.env` / `bunfig.toml` を読まなくなり、`CLINE_CLOUD_SESSIONS=1` で実験的クラウドタスクに対応。
- 何が便利か: 大きめのファイルを読む際の打ち切りが解消され、エージェントが参照できる文脈が増える。`ux_verifier` でレビュー的なチェックをサブエージェントに任せられる。CLI の yolo・`--timeout`・Ctrl+C は自動化スクリプトでの扱いやすさを上げる。
- 使いどころ: VS Code 上でのエージェント型コーディング、ローカル LLM（LM Studio）接続、CLI での非対話バッチ実行。
- 開発者にとっての価値: `read_files` 打ち切り撤廃とモデルカタログ刷新は、既存ワークフローをそのままに精度・対応モデルを底上げできる。CLI が起動ディレクトリの `.env` を読まなくなった点は、意図しない環境変数混入を避ける安全側の変更。
- 注意点: 製品ライン（拡張機能 / SDK / CLI / Desktop）ごとにバージョン体系が別なので、更新時は対象を取り違えないこと。`CLINE_CLOUD_SESSIONS=1` は実験的機能。
- 公式リンク: https://github.com/cline/cline/releases/tag/v4.1.27
- 参考リンク: https://github.com/cline/cline/releases
- メモ: Cline は直近の本リポジトリ記事では未掲載。同日に複数プロダクトが更新されているため、代表として拡張機能 `v4.1.27` を主リンクに採用。

### 3. LiteLLM / `1.108.15`（LTS）＋ `v1.112.0-dev.2`（開発版）

- 種別: OSS / プロキシ・ゲートウェイ
- 関連: LiteLLM / OpenAI / Anthropic / Bedrock / 各種プロバイダ
- 公開・更新日: 2026-11-21（LTS `1.108.15`）、2026-11-21 20:13（UTC、JST 11-22 05:13）で `v1.112.0-dev.2`
- 概要: LTS `1.108.15` は、**JSON 設定のキーレスデプロイが `api_key`（またはプロバイダのキー環境変数）未設定だと 401 を返す**ようになる要対応変更、Cohere v2 のストリーミングツール呼び出しと `tool_choice` の修正などを含む。開発版 `v1.112.0-dev.2` は **FIPS 140-3 対応プロキシ Docker イメージ**、`x-litellm-*` レスポンスヘッダを省く設定、アプリ／顧客スコープの予算アラート、Lens へのトレース送信、Bedrock の BM25 ツール検索、**Azure GPT-Live リアルタイムセッション**、キーレスプロバイダへ `OPENAI_API_KEY` を送らない変更など多数。`previous_response_id` を chat completions / Messages で拒否するなどの破壊的変更も含む。
- 何が便利か: セルフホストの LLM プロキシを運用する人に直結。FIPS 対応イメージはコンプライアンス要件のある環境で有用。キーレス運用の 401 化はセキュリティ既定の厳格化。
- 使いどころ: 社内で複数プロバイダを 1 本の OpenAI 互換エンドポイントに集約するゲートウェイ運用、予算アラートやコスト可視化。
- 開発者にとっての価値: 認証既定が厳しくなるため、キーレス運用をしている場合は**更新前にキー設定を見直す**だけで事故を防げる。Azure GPT-Live 対応はリアルタイム系の選択肢を広げる。
- 注意点: `v1.112.0-dev.2` は**開発版（pre-release）**で破壊的変更あり。本番は LTS 系（`1.108.15`）を基準に。キーレス 401 化と `previous_response_id` 拒否は挙動が変わるため移行確認が必要。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.112.0-dev.2
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 既存記事（11-21）は `v1.110.2`・`1.108.13` までを掲載。本記事は未掲載の `1.108.15`（LTS）と `v1.112.0-dev.2` を採用。
