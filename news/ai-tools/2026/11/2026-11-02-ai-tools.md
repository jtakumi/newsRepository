## 今日の注目

### 1. Pydantic AI / `v2.64.0`

- 種別: OSS / SDK（型安全なエージェントフレームワーク）
- 関連: Pydantic / Anthropic / Google / Amazon Bedrock（各プロバイダ対応）
- 公開・更新日: 2026-10-30（GitHub Releases, Latest）
- 概要: リトライ付きトランスポートから出たエラーを `ModelHTTPError` として表面化し、フォールバックが継続できるようにする `ModelFallback` 機能を追加。ストリーミングで最初のイベントが来るまでの待ち時間を区切る `first_event_timeout`、Memory と Skills をスキャンする `ArtifactScanner`、実行時に能力を読み込む `RunContext.load_capability`、隔離実行用の `BoxdSandbox` ワークスペースを導入した。
- 何が便利か: モデル障害時のフォールバックが「リトライ層のエラーで止まる」問題を避けて素直に次モデルへ移れる。サーバ側で払い出した ID を生成元エンドポイントにのみ送るよう整理され、`json-repair` はオプション化、`Coder` では strict なツールスキーマが既定オフになった。Bedrock・Gemini Live・Temporal の `SubAgents`・Anthropic のトークンカウントまわりの不具合も多数修正。
- 使いどころ: 複数プロバイダをフォールバック構成で束ねる本番エージェント。ストリーミング応答のハング対策にタイムアウトを入れたいサービス。Memory／Skills を使うエージェントの安全性チェック。
- 開発者にとっての価値: フォールバックとタイムアウトという可用性に直結する制御が型安全に書けるようになり、マルチプロバイダ構成の信頼性を上げやすい。`ArtifactScanner` でエージェントが読む成果物のスキャンを組み込める。
- 注意点: リトライ系トランスポートのエラー表面化（`ModelHTTPError` 化）や `Coder` の strict ツールスキャン既定オフなど挙動変更があるため、既存のエラーハンドリング／ツール定義は要確認。`BoxdSandbox` など新規 API は導入前に対象プロバイダの前提を確認すること。
- 公式リンク: https://github.com/pydantic/pydantic-ai/releases/tag/v2.64.0
- 参考リンク: https://github.com/pydantic/pydantic-ai/releases
- メモ: 既存の AI Tools News で扱った pydantic-ai は 2026-09 の `v2.41.0`〜`v2.43.0`（画像生成・Codex/Copilot プロバイダ）まで。本項は新規の `v2.64.0`（`ModelFallback` ほか）を扱う。

#### 使用例

```bash

pip install -U pydantic-ai

# 例: フォールバック構成でモデル障害に備える（概念例）
#   from pydantic_ai.models.fallback import FallbackModel
#   model = FallbackModel(primary_model, fallback_model)
```

### 2. Qwen Code / `v0.26.5`

- 種別: CLI（ターミナル向けコーディングエージェント）
- 関連: Alibaba / Qwen（Gemini CLI 派生）
- 公開・更新日: 2026-11-01（GitHub Releases, Latest）
- 概要: Generated UI を既定で有効化し、チャットが対話カードの値を「取り外し可能なコンテキスト」として取り込めるようにした。CLI は npm のバージョン探索なしで特定バージョンへ更新でき、推論 effort の既定値を DeepSeek-V4 と新しい Qwen モデル接頭辞にも広げた（明示指定は尊重）。管理ストレージ向けに上限付き SQL 履歴クエリ（ページング、操作/コマンドの厳密検索）を追加。
- 何が便利か: `/autofix-pr` がブロックされたラウンドにコメントし、同じチェックへの修正プッシュが3回失敗したら再試行を止めるため、CI 自動修正が無限ループしにくい。MCP クライアント／コアを 2.4.0 に更新。Web Shell にセッション概要／分割表示のキーボードショートカット、ロシア語ロケール、次ターンの設定を切り替える Workflow スイッチを追加。長い行のツールカード差分は横スクロールではなく折り返すよう修正。
- 使いどころ: Qwen 系モデルで CLI コーディングを回す日常作業。CI の PR 自動修正を回したいが暴走を抑えたいケース。MCP サーバ連携を前提にしたエージェント運用。
- 開発者にとっての価値: バージョン固定更新や推論 effort の既定拡張で運用を揃えやすく、`/autofix-pr` の打ち切り制御で自動修正の安全性が上がる。MCP 2.4.0 追従で最新の MCP 機能を扱いやすい。
- 注意点: 本リリースには Managed Agent（Hosted Harness / MySQL / 認証ゲートウェイ）向けの実験的な一括 Helm デプロイやチャネルアダプタなど、個人開発では使わない管理機能も多く含まれる。CLI 利用時は該当機能の前提（ホスティング構成）を確認すること。
- 公式リンク: https://github.com/QwenLM/qwen-code/releases/tag/v0.26.5
- 参考リンク: https://github.com/QwenLM/qwen-code/releases
- メモ: 既存の AI Tools News で Qwen Code は 2026-10-05 版で `v0.24.7-nightly`（内容薄く見送り）に触れたのみ。本項は新規の安定版 `v0.26.5` を扱う。

#### 使用例

```bash
# インストール / 更新
npm install -g @qwen-code/qwen-code@latest
qwen --version
```

### 3. GitHub Copilot CLI / `1.0.106-1`〜`1.0.106-2`（プレリリース）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-10-31（`1.0.106-1`） / 2026-11-01（`1.0.106-2`）（GitHub Releases, Pre-release）
- 概要: `1.0.106-2` で、スクリーンリーダー有効時に失敗/拒否されたツール呼び出し・不明コマンド・警告を「Error:」「Warning:」の接頭辞で判別できるよう改善。`/resume` が実行中のバックグラウンドセッションを（終了時に二重表示せず）前面に戻すよう修正。接続を受け付けるが応答しない HTTP MCP サーバの起動待ちを3接続分から1接続分に短縮。`1.0.106-1` では `apply_patch` の行末（CRLF）保持、`web_fetch` の文字エンコーディング解釈、WSL のクリップボードコピー、複数行貼り付けの改行保持などを修正。
- 何が便利か: MCP 設定（`mcp-config.json`）がシンボリックリンクのとき、保存でリンクを壊さずリンク先を更新するようになった。`/skills` の追加・削除・再読み込みがセッションのスキルと同期し、更新失敗を即時に報告する。
- 使いどころ: バックグラウンドで長めのタスクを走らせつつ `/resume` で戻る運用。MCP やスキルを多用し設定をシンボリックリンクで共有しているセットアップ。WSL 上での日常利用。
- 開発者にとっての価値: バックグラウンドセッションの取り回しと MCP／スキル管理まわりの実務的な不具合が解消され、長時間作業の安定性が上がる。前回フラグした `1.0.106-1` の修正群に、セッション前面化やアクセシビリティ改善が積み増された。
- 注意点: `1.0.106-1` / `1.0.106-2` はいずれも Pre-release。本番運用では安定版 `1.0.105`（10/28, 既出）を推奨し、上記の修正が必要な場合のみプレリリースを明示指定して試すのが無難。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.106-2

- メモ: 2026-11-01 版では `1.0.106-1` をプレリリースとして調査メモで見送り扱いにしていた。本項は積み増された `1.0.106-2` を含むプレリリース系の更新を扱う。

### Pydantic AI / `ModelFallback`（`v2.64.0`）

選定理由:

- モデル障害時のフォールバックが「リトライ層のエラーで止まる」問題を避けられる、可用性に直結する新機能。本番エージェントの信頼性に効く。
- `pip install -U pydantic-ai` だけで試せる導入のしやすさ。型安全なフレームワーク上で設定として書ける。
- `first_event_timeout` と併用すれば、ストリーミングのハング対策とフォールバックを同時に組み込め、日常のサービス運用に乗せやすい。

最初に試すこと:

```bash
# 最新版へ更新
pip install -U pydantic-ai

# フォールバック構成の最小例（概念）
# from pydantic_ai import Agent
# from pydantic_ai.models.fallback import FallbackModel
# agent = Agent(FallbackModel('anthropic:claude-...', 'openai:gpt-...'))
```
