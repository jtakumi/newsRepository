### 1. Gemini CLI / `v0.70.0`・`v0.69.0`

- 種別: CLI
- 関連: Gemini / Google AI
- 公開・更新日: 2026-11-19（`v0.69.0` は JST 10:45 ごろ、`v0.70.0` は JST 翌 06:08 ごろ＝UTC 21:08。いずれも 11-19 付）
- 概要: ターミナル向け Gemini エージェント CLI の安定版が 2 連続で公開。`v0.69.0`（PR 約 33 件）は、日次トークン使用量を見る `/stats heatmap` サブコマンド、スタンドアロンの `theme.json` でカスタムテーマ設定、`/model` のモデル名検証と引数直接指定、既定 60 秒の API ヘッダタイムアウトを `model.requestTimeoutMs` または `GEMINI_API_HEADERS_TIMEOUT_MS` で全認証モードにわたり上書き可能、などを追加。あわせてネットワーク障害時の数分間の無言ハング修正、数時間に及ぶクォータ再試行の抑止、マルチモーダル（PDF インラインデータ・古い画像データの退避）やサンドボックス（Seatbelt 突入前のフォルダ信頼解決）周りの修正。`v0.70.0`（約 20 件）は、認証再起動をまたいで選択中の worktree を保持、モデル一覧の出力トークン上限を正しく表示、安全でないコマンド権限を持つ system MCP サーバをスキップ、`commandPrefix`/`commandRegex` ポリシー規則をトップレベルのコマンド引数に対して照合、ポリシーの `argsPattern` 評価を re2js で線形時間化、などを含む。
- 何が便利か: `/stats heatmap` でトークン消費の傾向を日単位で可視化でき、コスト管理に使える。API ヘッダタイムアウトを上げられるため、応答の遅いゲートウェイやプロキシ裏で「ヘッダ待ちタイムアウト」が起きる構成を救える。安全でない権限の system MCP サーバを自動スキップし、ポリシー規則をトップレベルコマンドに照合する変更で、権限ガバナンスの取りこぼしが減る。
- 使いどころ: Gemini CLI を日常のコーディング・調査に使っていて、トークンコストを把握したいケース。社内で MCP サーバやコマンド権限ポリシーを配布している環境。カスタムテーマを `theme.json` で共有したいチーム。
- 開発者にとっての価値: 前回記事（11-18/11-19）まで「Gemini CLI は `v0.68.0`（11-10）以降に新規安定リリースなし」として見送っていたが、本日 2 つの安定版が出て実用追加が揃った。worktree 保持やクォータ再試行抑止など、長時間・無人運用の安定性が上がる。

### 2. Claude Code / `v2.1.328`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-19（UTC 01:14 / JST 10:14）
- 概要: ターミナル向け AI コーディングエージェントの定期更新。追加点として、Claude Opus 4.6 / Sonnet 4.6 向けの **auto モード**を Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry・Claude apps ゲートウェイで利用可能にし、権限モードを指定しない対話セッションは auto モードで起動するようになった。`mcp_tool` フックに `"onFailure": "block"`（フック呼び出しが失敗したらアクションをブロック。command/HTTP フックと同様）を追加。`CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME` で、`claude -p --resume` / `--continue` がフックの遅延したツール呼び出しを実行しないようにできる。セルフホストランナー向けに `--repository-folder` / `--hook-label` / `claude --environment` の `--metadata key=value` などを追加。修正として、zsh での `echo ====` のような `=` 始まりの語でコマンドが「not found」になる問題、自動 compaction が旧システムプロンプトを再利用していた問題（`/compact` と同様に再構築）、権限プロンプトでの Esc 取りこぼし、Markdown レンダリングの長文・不正入力でのフリーズ、など多数。
- 何が便利か: エンタープライズゲートウェイ（Bedrock / Vertex=Agent Platform / Foundry / Claude apps）でも Opus 4.6・Sonnet 4.6 を auto モードで動かせ、権限モード未指定でも auto で起動するため導入時の摩擦が減る。`mcp_tool` の `onFailure: "block"` で、MCP ツール呼び出しに連動するフックが失敗したときにアクションを止められ、ガードを効かせやすい。
- 使いどころ: エンタープライズの各ゲートウェイ経由で Claude Code を配布している組織。MCP ツールにフックで検証・前処理をかけ、失敗時は止めたい運用。セルフホストランナーで無人セッションをオーケストレーションしている構成（ラベル・メタデータ付与、キュー待ちメトリクス追加）。
- 開発者にとっての価値: 自動 compaction のシステムプロンプト再構築や、サブエージェントの effort 設定が誤って無効化される回帰（2.1.327）の修正など、長時間・無人セッションの安定性に効く修正が揃う。zsh の `=` 始まり語や Esc 取りこぼしなど、日常の操作性バグも多数解消。
- 注意点: auto モードはエンタープライズゲートウェイ／Claude apps ゲートウェイ上の Opus 4.6・Sonnet 4.6 が対象。リリースノートは「Changed」「Improved」項目を別途多数含む（`/code-review` が多くのモデルでバグと CLAUDE.md 違反のみ報告するよう変更、など）。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.328
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 前回記事（11-19）は `v2.1.327`。`v2.1.328` は本記事が初出。

### 3. LiteLLM / `v1.109.2`（＋ `v1.110.1` Latest・`1.108.12` LTS）

- 種別: OSS（LLM プロキシ／SDK, Python）
- 関連: Google Gemini / OpenAI（GPT-6.2）/ Azure / AWS Bedrock / その他
- 公開・更新日: 2026-11-19（`v1.110.1` が Latest、`v1.109.2`・`1.108.12` LTS も同日）
- 概要: 100+ の LLM を統一 API で扱うプロキシ／SDK の更新群。`v1.109.2`（30 PR）は **Gemini のバッチジョブを `/v1/batches` エンドポイントで実行**できるようにし、出力を `/v1/files` から取得、スペンドを追跡（従来 `/gemini` 経由のバッチは model 名「unknown」で $0 計上だったのを修正）。あわせて `1month`/`7days`/`2weeks` のような長い単位名の予算が毎晩リセットされていた問題、既定チームへ自動参加したユーザーのチームメンバースペンドが一度もリセットされない問題（v1.95.0 で発生）、TLS 終端裏で SSO ログインが `http://` に飛ぶ問題（v1.108.0 で発生）を修正。`v1.110.1`（Latest）は GPT-6.2 の `store: false` システムプロンプトのプロンプトキャッシュ修正＋UI イメージ軽量化と新しい Wolfi ベースイメージ。LTS `1.108.12`（8 PR）は Azure モデルルーター・Vertex バッチスキーマ・Messages API のツール名エラーなどを修正。
- 何が便利か: Gemini のバッチ処理をプロキシ経由で回しつつ、コスト（スペンド）をモデル単位で正しく集計できるようになる。予算の単位名バグ・チームスペンドの未リセット・SSO の `http://` 転落といった、運用でハマりやすい実務バグがまとめて直る。
- 使いどころ: LiteLLM プロキシで Gemini を含む複数プロバイダを束ね、バッチ推論と課金・予算管理を運用しているチーム。TLS 終端（リバースプロキシ／LB）裏で Admin UI の SSO を使っている構成。安定運用重視なら LTS `1.108.12`。
- 開発者にとっての価値: マルチプロバイダゲートウェイとして、バッチのコスト可視化とガバナンス（予算・SSO）の正確性が、実務で効く部分で改善される。アップグレードは「no action needed」と明記。
- 注意点: 破壊的変更を含む `v1.110.0`（11-18・前回記事で既出）とは別に、`v1.109.2` は破壊的変更の記載がなく当てやすい。`v1.111.0-rc.1`/`rc.2` はプレリリースのため本番は非推奨。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.109.2

### 4. Pydantic AI / `v2.71.0`

- 種別: OSS（Python エージェントフレームワーク）
- 関連: Google AI（Gemini 4 Neon）/ Anthropic / その他
- 公開・更新日: 2026-11-18 タグ付け（GitHub 表示は 11-19 公開）
- 概要: 型安全なエージェント構築フレームワークの機能リリース。`ToolBridge` が search / describe / call ツールの裏でツール一覧を固定し、**プロンプトキャッシュを効かせやすく**する。`GoogleModel` で Gemini 4 Neon 対応、ゲートウェイプロバイダに Stav・Otari を追加。新機能として `ReportRemainingBudget`、`CurrentTime`、`Goal`、`WrapUpAtLimits`、`DeferredToolRequests.validated_args` を追加。互換性変更として `PeerNetwork` → `PeerConnection` リネーム（`Peers(network)` がエージェント名で `InMemoryPeerNetwork` に参加可能に）、`DEPRECATED_ANTHROPIC_MODELS` を deprecated 化。バグ修正では、プロバイダからの HTTP 408 を `ModelTimeoutError` として送出、`stream_text()`/`stream_response()` がコンシューマ早期終了時に debounce ジェネレータを閉じるよう修正。
- 何が便利か: `ToolBridge` でツール一覧を固定したまま検索・記述・呼び出しを分離でき、ツール数が多いエージェントでもプロンプトキャッシュが効いてコストを抑えやすい。`WrapUpAtLimits` や `ReportRemainingBudget` で、上限到達時の挙動や残予算をエージェントに宣言的に扱わせられる。
- 使いどころ: 多数のツールを持つエージェントでキャッシュ効率を上げたいケース。Gemini 4 Neon を型付きで使いたいプロジェクト。マルチエージェント連携（`PeerConnection`）を Python で組む構成。
- 開発者にとっての価値: HTTP 408 の `ModelTimeoutError` 化やストリーム早期終了時のジェネレータ解放など、エラー・リソースの取り扱いが堅牢になる。予算・時刻・ゴールを扱う組み込み部品が増え、制御を宣言的に書きやすい。
- 注意点: 互換性変更あり。`PeerNetwork` → `PeerConnection` のリネーム、`DEPRECATED_ANTHROPIC_MODELS` の deprecated 化を使っている箇所は確認してから上げること。
- 公式リンク: https://github.com/pydantic/pydantic-ai/releases/tag/v2.71.0
- 参考リンク: https://ai.pydantic.dev/
- メモ: 前回記事（11-19）は `v2.70.0`。`v2.71.0` は本記事が初出。
