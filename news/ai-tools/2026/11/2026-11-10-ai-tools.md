### 1. Claude Code / `v2.1.321`

- 種別: CLI（AIコーディングエージェント）
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-09（タグ公開 UTC 19:22、日本時間 11-10 04:22）
- 概要: 既定 Fable モデルの更新と、`remote-control` の設定指定、そしてセキュリティ・権限まわりの集中的な修正が中心のリリース。前回記事（11-07）時点の `v2.1.319` からの更新で、途中の `v2.1.320` はタグとして配布されていない。
- 何が便利か:
  - 新モデル `Claude Fable 5.2` を既定の Fable モデルとして追加。軽量・高速系の用途で既定が新しい世代に更新される。
  - `claude remote-control` に `--settings` オプションを追加。リモートコントロール起動時に設定を明示できる。
  - MCP OAuth トークンの扱い、サンドボックスと権限チェックの抜け、`cp`/`mv` の deny ルール網羅など、セキュリティ・権限関連の修正を多数投入。
  - ネットワークパス上でのファイル編集の修正、`/config`・`/model`・サインインフローの修正、ゲートウェイ／Windows／パフォーマンス改善も含む。
- 使いどころ: 常用の CLI を最新の権限・サンドボックス修正に追従させたい場面。リモートコントロールを使う運用で設定を明示したいとき。Fable を使うワークフローで既定モデルを新世代に合わせたいとき。
- 開発者にとっての価値: 権限・サンドボックス・MCP OAuth まわりの修正は、エージェントに実行権限を与える運用の安全性に直接効く。deny ルールの網羅性向上は、意図しないファイル操作の抑止という実務面で価値が高い。
- 注意点: Fable 5.2 は「Fable モデル」の既定変更であり、通常の Opus/Sonnet 系の既定を置き換えるものではない。モデル指定を固定している場合は影響を受けない。変更点が多いため、更新後は普段使う権限設定・MCP 接続が従来どおり動くか軽く確認しておくとよい。
- 公式リンク: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: 直前の `v2.1.319` では `permissions.denyInsteadOfPrompting` 設定やバックグラウンド MCP タスクの端末サポートが入っていた（11-07 記事参照）。

#### 使用例

```bash
# 更新
npm install -g @anthropic-ai/claude-code

# バージョン確認
claude --version   # 2.1.321

# リモートコントロールを設定指定付きで起動
claude remote-control --settings ./my-settings.json
```

### 2. GitHub Copilot CLI / `1.0.108`（安定版）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-11-09（Release "Latest" / 安定版、UTC 16:20、日本時間 11-10 01:20）
- 概要: 約70項目の更新を含む安定版。コード検索用インデックス、サンドボックス・MCP・権限まわりの改善、各種スラッシュコマンドの使い勝手修正が中心。11-08 記事で扱ったのはプレリリース `1.0.108-1` で、今回はそれを正式版に昇格させた GA リリース。
- 何が便利か:
  - 新しい `/index` コマンド群を追加。対象となるリポジトリでは「managed shared tgrep インデックス」が既定で有効になり、コード検索が高速化。
  - 実行中の `/compact` を `Ctrl+C` で停止できる。長い圧縮処理を中断しやすい。
  - MCP の deny ルールが、サニタイズ名だけでなくサーバが申告するツール名にもマッチ。意図したツールを確実に拒否できる。
  - Windows で「列挙のみ許可（enumerate-only）」のディレクトリ権限を `settings.json` で指定可能に。サンドボックス有効時は `/cd` 後にローカル MCP サーバを再起動。
  - `/model` が Copilot から 421 応答を受けたときにモデル一覧を表示。`/mcp disable` がセッションをまたいで保存されるように。`/pr`・`/lsp`・`/skills`・`/plugin` などのサブコマンドが大文字小文字を区別しなくなった。
- 使いどころ: 大きめのリポジトリでコード検索を多用する開発に `/index` を入れて検索を高速化したい場面。MCP サーバを権限制御しながら使う運用で、deny ルールの確実性を上げたいとき。
- 開発者にとっての価値: `/index` の既定インデックス化は、コードベースを横断する調査・リファクタで体感速度に効く。MCP deny ルールのサーバ申告名マッチは、ツール権限の取りこぼしを防ぐ実務的な堅牢化。
- 注意点: `/index` の managed shared インデックスは「対象リポジトリ（eligible repos）」で既定有効という位置づけ。全リポジトリで自動的に有効になるわけではない。並行して `1.0.109-0` のプレリリースも出ている（常用は安定版 `1.0.108` を推奨）。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.108
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: Grok 4.7/4.6 での PDF 添付がターンを失敗させず「ファイル参照」にフォールバックする修正は、プレリリース時点（11-08 記事）から継続して入っている。

#### 使用例

```bash
# 更新（npm 経由の場合）
npm install -g @github/copilot

# バージョン確認
copilot --version   # 1.0.108

# 対話内でインデックスを操作
# /index            … インデックス状態の確認・操作
# Ctrl+C            … 実行中の /compact を中断
```

### 3. Qwen Code / `v0.27.1`

- 種別: CLI / OSS（Gemini CLI 系フォーク）
- 関連: Qwen / その他
- 公開・更新日: 2026-11-09（GitHub Releases, Latest、UTC 15:00、日本時間 11-10 00:00）
- 概要: LSP 連携やバックグラウンドエージェント、個人メモリなどの機能追加と、多数の修正を含むリリース。前回記事（11-08）時点の `v0.27.0` からの更新。追加の多くは web shell / チャンネル / managed agent 基盤向けだが、CLI 単体で効く項目も含む。
- 何が便利か:
  - LSP をユーザースコープ設定と環境変数で有効化できるように。プロジェクト単位ではなく利用者単位で言語サーバ連携を切り替えられる。
  - 起動コンテキストにアクティブなシェル名を表示。どのシェルで動いているかが明確に。
  - バックグラウンドエージェントの既定実行を設定可能に。常時バックグラウンドで動かす運用を構成しやすい。
  - Mem0 を使うオプトインの個人メモリを追加。会話をまたいだ記憶を任意で有効化できる。
  - 修正面: OpenAI の `cache_write_tokens` をキャッシュ生成として正しく計上、モデル切り替え時のセッション復旧の整合、出力速度統計に最初のトークンまでの時間を含める、など。
- 使いどころ: 言語サーバ連携を利用者単位で管理したいチーム・個人環境。長時間の作業でバックグラウンドエージェントを既定で回したいとき。会話をまたいだメモリを試したいとき。
- 開発者にとっての価値: LSP のユーザースコープ化は、プロジェクト設定を汚さずに補完・診断連携を使える点で導入しやすい。OpenAI キャッシュトークンの計上修正は、コスト把握の正確性に効く。
- 注意点: 追加項目の多くは web shell / チャンネル / managed agent（CI ランナー連携や PR ウォッチ基盤）向けで、ローカル CLI 単体利用では恩恵が及ばない変更も多い。個人メモリ（Mem0）はオプトインで、外部サービス連携を伴う点に留意。
- 公式リンク: https://github.com/QwenLM/qwen-code/releases/tag/v0.27.1
- 参考リンク: https://github.com/QwenLM/qwen-code/releases
- メモ: 同日前後に SDK TypeScript の `v0.1.31` / `v0.1.29` も公開されている。

#### 使用例

```bash
# インストール / 更新
npm install -g @qwen-code/qwen-code

# バージョン確認
qwen --version   # 0.27.1

# ヘッドレス実行（非対話）
qwen -p "変更ファイルの差分を要約して"
```

### 4. Vercel AI SDK / `ai@7.0.166`

- 種別: OSS ライブラリ（TypeScript）
- 関連: Vercel AI SDK
- 公開・更新日: 2026-11-09（`ai@7.0.166` 公開）
- 概要: 前回記事（11-03）時点の `ai@7.0.160`〜`7.0.161` からの更新。`7.0.162`〜`7.0.166` を含み、直近の最新は依存更新が中心だが、途中にテレメトリ関連のセキュリティ修正と機能追加が入っている。
- 何が便利か:
  - `7.0.165`: テキスト生成結果がテレメトリ連携やトレースに渡る前に、プロバイダのリクエスト URL をサニタイズ。エンドポイントの認証情報が露出しないように修正（セキュリティ修正）。`recordOutputs` が false のときは文字起こしの単語タイミングをテレメトリから除外。
  - `7.0.163`: ストリーミング中の steering メッセージを UI へ反映、Google レスポンスでのテキストと関数呼び出しの順序保持、Groq のネイティブ URL 文字起こし対応、`Output.object`/`Output.array` にスキーマのユニオンを渡した際の型推論など、機能追加が多数。
  - `7.0.166` / `7.0.164`: `@ai-sdk/gateway` 依存の更新（それぞれ 4.0.139 / 4.0.137）。
- 使いどころ: AI SDK でテレメトリ・トレーシングを有効にしている本番アプリ。ログや監視にリクエスト URL が流れる構成では、`7.0.165` 以降への更新で認証情報の露出リスクを下げられる。
- 開発者にとっての価値: 観測性（OpenTelemetry 連携）を使う構成で、認証情報を含む URL がトレースに漏れないようにする修正は、セキュリティ面で地味だが重要。steering メッセージの UI 反映やストリーミング周りの改善も、対話 UI 実装の実用性に効く。
- 注意点: 最新の `7.0.166` 自体は依存更新のみ。意味のある変更は主に `7.0.163`（機能追加）と `7.0.165`（テレメトリ URL サニタイズ）に含まれる。更新時はこれらを含むバージョンに上げること。各パッチの正確な公開日時は CHANGELOG に明記がないため、まとめて最新へ上げる前提で確認するとよい。
- 公式リンク: https://github.com/vercel/ai/blob/main/packages/ai/CHANGELOG.md
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: `@ai-sdk/vue`・`@ai-sdk/svelte` など UI バインディングも同時期に更新されている。
