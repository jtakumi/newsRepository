### 1. Claude Code / `v2.1.326`

- 種別: CLI（＋ VS Code 拡張）
- 関連: Anthropic / Claude Code
- 公開・更新日: 2026-11-16 22:11 UTC（JST 2026-11-17 07:11 早朝）
- 概要: 既出の `v2.1.325`（11-13）に続く安定版。**実験的な Code Mode（Claude が JavaScript を書いて自分のツールを呼ぶ方式）を、エージェントチーム有効時にも使えるように**した（既に Code Mode を有効化済みなら、チーム有効のセッションは Code Mode で開始）。`--allowedTools`/`--disallowedTools`/`--tools` に不完全なルール値があると**起動時に警告**。`managed-mcp.json` がセッション中に追加された際に MCP サーバ読み込みが止まる理由の表示、`/status` に「プロバイダや `DISABLE_TELEMETRY` などの環境変数で機能が無効化された理由」を示す行、**Ctrl+O で隠れた起動時通知を表示**などを追加。テレメトリでは **`OTEL_RESOURCE_INCLUDE_HOST`**（`host.name`/`host.id` を OpenTelemetry リソース属性に含める。既定オフ）を追加。本体は**膨大なバグ修正と権限ハードニング**が中心で、`cp`/`mv` の一部が確認を求めるように、サインイン資格ファイル（`.credentials.json` 等）への書き込み拒否、PowerShell ツールの権限厳格化、`/rewind`・サインイン・設定ファイルのパース・ターミナル描画・MCP 接続まわりの多数の修正を含む。
- 何が便利か: Code Mode とエージェントチームを同時に使えるようになり、複数エージェント構成でもツール呼び出しをコードで表現できる。権限・サンドボックスのハードニングで無人運用・CI 実行時の事故（意図しないファイル破壊や資格ファイルへの書き込み）が起きにくくなる。`OTEL_RESOURCE_INCLUDE_HOST` でホスト単位の可観測性を上げられる。
- 使いどころ: Claude Code を日常のコーディング／自動化で使っている開発者。エージェントチームや Code Mode を試している構成、サンドボックス Bash で無人実行している構成、OpenTelemetry で利用状況を集計している組織。
- 開発者にとっての価値: フラッグシップ CLI の安定版で、`claude update` 1コマンドで反映できる。今回は新機能より「安全側に倒した権限既定」と大量の修正が主眼で、既存ワークフローの堅牢性・信頼性に直接効く。
- 注意点: 権限既定が**安全側に変更**されており、これまで通っていた一部の Bash／PowerShell／`cp`・`mv` コマンドが**確認を求める／拒否される**ようになる。無人運用では allow ルールやモード設定の見直しが必要になる場合がある。Code Mode は依然として実験的オプトイン。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.326
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: 直近の AI Tools News は `v2.1.325`（11-14 掲載）まで。本項は新規の安定版 `v2.1.326`。

#### 使用例

```bash
# 最新版へ更新してバージョン確認
claude update
claude --version   # v2.1.326 を確認

# OpenTelemetry にホスト属性(host.name / host.id)を含める（既定はオフ）

```

### 2. Anthropic SDK（Python） / `v2.9.0`

- 種別: OSS / SDK（Python。C# など他言語 SDK にも関連変更あり）
- 関連: Anthropic / Claude Developer Platform
- 公開・更新日: 2026-11-16
- 概要: 安定版。**旧 `anthropic-beta` ヘッダ値群を非推奨化**し、将来の SDK で削除予定（`prompt-caching-2024-07-31`、`pdfs-2024-09-25`、`token-counting-2024-11-01`、`token-efficient-tools-2025-02-19`、`extended-cache-ttl-2025-04-11`、`cache-diagnosis-2026-04-07`、`ce-user-management-2026-07-13`）。`files-api-2025-04-14` と `skills-2025-10-02` は**レスポンス形状が変わる**ため、削除前に各移行ガイドの確認が必要。`beta.messages.batches` は `message-batches-2024-09-24` を送らなくなり、既定の `anthropic-beta` ヘッダを設定している場合はバッチ要求にもそれが載る。ツール面では **`grep` ツールのセキュリティ強化**（絶対 `PATH` エントリの `rg` のみ使用、`ANTHROPIC_*` 変数を `rg` に渡さない、ビルトイン探索は通常ファイルのみ）、ファイルツール／メモリファイルのパス処理を厳格化。終了したセッションスレッドのツール呼び出しを実行しないよう修正。Windows（Python 3.12 以前）で資格情報ファイルが書けなかった不具合を修正。API では RBAC ロール read に source/error コードを追加し、Claude Tag Bundle の指示を設定する **Update Bundle** を追加。
- 何が便利か: ベータヘッダの整理方針が明確になり、古い値に依存したコードの**移行判断**がしやすい。`grep`・ファイルツールのパス／環境変数まわりの堅牢化で、エージェントのツール実行の安全性が上がる。
- 使いどころ: Anthropic Python SDK で Messages API やエージェントツール（grep／ファイル／メモリ）を使っているアプリ。古いベータ機能（prompt caching、PDFs、token counting など）を明示ヘッダで使っている構成の棚卸し。
- 開発者にとっての価値: 一次 SDK の安定版で、非推奨化の告知により**破壊的変更の前倒し対応**ができる。ツールのセキュリティ修正は本番エージェントにそのまま効く。
- 注意点: **C# の `AnthropicBeta` enum は番号が変更**され、旧バージョンでビルドしたコードは再ビルドしないと別のベータ値を送ってしまう（silent）。`files-api` / `skills` ベータはレスポンス形状変更のため移行ガイド要確認。非推奨ヘッダは将来削除予定（今すぐ壊れるわけではないが対応推奨）。
- 公式リンク: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.9.0
- 参考リンク: https://github.com/anthropics/anthropic-sdk-python/releases
- メモ: 直近の AI Tools News では Anthropic Python SDK は未掲載。本項は新規の安定版 `v2.9.0`。

#### 使用例

