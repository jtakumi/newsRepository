### 1. Claude Code / `v2.1.326`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-16（UTC 22:11 / JST 2026-11-17 07:11）
- 概要: ターミナル向け AI コーディングエージェントの定期更新。エージェントチーム（agent teams）を有効にしたセッションでも Code Mode が利用でき、チーム有効時は Code Mode で起動するようになった。権限・設定・MCP/プラグイン・セッション復元・compaction など広範囲の修正を含む。
- 何が便利か: チームを使いながら Code Mode でそのまま作業に入れる。`cp` の source だけが `Edit` の deny ルールに該当して拒否されていた不具合、`find -delete` / `cat a > b` / `sort -o` のような書き込み系コマンドを「読み取り」と誤要約していた挙動が直り、権限判定の取りこぼしが減る。
- 使いどころ: 無人・半自動でコマンド実行まで任せる運用で、権限の誤判定による停止や取りこぼしを減らしたいとき。Bedrock / Vertex / Foundry で compaction が要約でなくユーザー宛て返信になる不具合や、画像の多い Vertex セッションが 30MB 上限で詰まる問題の修正も効く。
- 開発者にとっての価値: クラッシュや低メモリ時に直近ターンや履歴が失われない復元修正、`max_tokens` がモデル上限を超えたらAPI報告の最大値で再試行するなど、長時間セッションの安定性が上がる。
- 注意点: `--allowedTools` / `--disallowedTools` / `--tools` に不完全なルールらしき値があると起動時に警告。設定のネストが64階層を超える分は警告のうえ破棄される。`/login` は `ANTHROPIC_API_KEY` 経由のままかどうかを明示するようになった。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.326
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 前回記事（11-14）は `v2.1.325`。`v2.1.326` は本記事が初出。

#### 使用例

```bash
# 最新版へ更新してバージョン確認
npm install -g @anthropic-ai/claude-code@latest
claude --version
```

### 2. Pydantic AI / `v2.69.0`

- 種別: OSS（Python エージェントフレームワーク）
- 関連: Pydantic / Google AI / Anthropic / その他
- 公開・更新日: 2026-11-17（UTC 01:03 / JST 10:03）
- 概要: 型安全なエージェント構築フレームワークの機能追加リリース。`GoogleModel` の Gemini 4 Hydrogen 対応、`GroqModel` の `service_tier` 対応、`Coder` への `autonomy` オプション追加のほか、`Peers` によるエージェント間メッセージング、`WindowsWorkspace`、`KubernetesSandbox` などハーネス部品が増えた。E2B / Boxd / Daytona / OpenSandbox のサンドボックスオプションも追加。
- 何が便利か: 自律度を `Coder` 側で切り替えられ、実行環境（ローカル/コンテナ/各種クラウドサンドボックス/Kubernetes）を宣言的に選べる。`DetectLoops` がストリーミング中の thinking・text・tool call 引数のループも検出するようになり、暴走の検知点が増えた。
- 使いどころ: 複数エージェントを連携させる構成（`Peers`）や、コード実行を隔離環境で回すエージェントを Python で組むとき。Gemini 4 を含む最新モデルを型付きで扱いたいプロジェクト。
- 開発者にとっての価値: `ModelQuotaExceededError`（Anthropic のスペンドキャップ）や `ModelHTTPError` といったエラー型の整理で、課金上限・転送失敗のハンドリングが書きやすくなる。
- 注意点: 破壊的変更あり。`DockerSandbox` → `DockerContainer`（旧名はdeprecatedエイリアスとして残存）、`BubblewrapSandbox` → `BubblewrappedWorkspace` にリネーム。`Advisor` の `mode` は deprecated で `native=` / `local=` 指定へ。`RequestInput` は `HandleDeferredToolCalls` に統合。アップグレード時はこれらの参照を確認すること。
- 公式リンク: https://github.com/pydantic/pydantic-ai/releases/tag/v2.69.0
- 参考リンク: https://ai.pydantic.dev/
- メモ: 前回記事での既出は `v2.64.0`（11-02）。本リリースは初出。

#### 使用例

```bash
# インストール／更新
pip install -U pydantic-ai
python -c "import pydantic_ai; print(pydantic_ai.__version__)"
```

### 3. Vercel AI SDK / `ai@7.0.174`〜`7.0.176`（＋ `@ai-sdk/workflow@2.0.108`）

- 種別: OSS（TypeScript/JS SDK）
- 関連: Vercel / OpenAI / Anthropic / Google AI / その他
- 公開・更新日: 2026-11-17（UTC 18:39〜20:56 / JST 2026-11-18 03:39〜05:56）
- 概要: `ai@7.0.174` でバッチ機能に `output` 対応（`startBatch` に `output`、`getBatchResults` で解析）、`streamText` が transform factory に `tools: undefined` を渡す不具合の修正、テレメトリ/インテグレーション併用時の locked-stream エラー修正、provider registry・カスタムプロバイダ・文字列モデルIDでの extraction model 対応などを追加。`7.0.175`/`7.0.176` は依存更新中心。`ai@5.0.291` / `ai@6.0.333` では UI メッセージ検証のメモリ/CPU削減（単一パス化）。
- 何が便利か: バッチ処理で構造化出力（`output`）を扱えるようになり、まとめて投げる推論ジョブの結果整形が楽になる。`streamText` + transform の不具合修正で、ストリーミング加工パイプラインが安定。
- 使いどころ: 大量の分類・抽出・要約をバッチで回すワークフロー、ストリーミング出力を変換して流すUI。メジャー7系を使っているプロジェクトは `7.0.174` 以上へ。
- 開発者にとっての価値: provider registry 経由でも extraction model を指定できるため、抽出用途のモデル切り替えが宣言的に書ける。検証の単一パス化で大きな UI メッセージ配列のコストが下がる。
- 注意点: パッチ更新だが機能追加と修正が混在するため、`7.0.174` の変更点（特に `streamText` transform と batch）を使っている箇所はテストしてから上げること。
- 公式リンク: https://github.com/vercel/ai/releases
- 参考リンク: https://ai-sdk.dev/
- メモ: 前回記事（11-15）は `ai@7.0.173`。本記事は `7.0.174`〜`7.0.176` が初出。

#### 使用例

```bash
# 7系を使っている場合
npm install ai@7.0.176
```

### 5. OpenCode / `v1.19.6`

- 種別: OSS / CLI・デスクトップ
- 関連: その他（sst/opencode）
- 公開・更新日: 2026-11-17
- 概要: OpenCode 1 系の更新。デスクトップ版で OpenCode 1 から OpenCode 2.0 へのアップグレードが提示されるようになり、バックグラウンドでダウンロードし任意のタイミングでインストールできる（セッション・プロジェクト・設定は引き継がれる）。画像の多いセッションが過大なリクエストを送らないよう、画像履歴が 25MiB を超えると古い画像をプレースホルダに置換。リクエストボディ過大による provider エラーで失敗せず compaction + 再試行するようになった。
- 何が便利か: 作業状態を保ったまま 2.0 への移行を選べる。画像を多用する長いセッションでリクエストが肥大化して失敗する問題が緩和される。
- 使いどころ: すでに OpenCode 1 を使っていて 2.0 への移行を検討中のユーザー。スクリーンショットや画像を多く扱うエージェントセッション。
- 開発者にとっての価値: compaction への自動フォールバックで、長時間セッションの中断が減る。
- 注意点: OpenCode 1 向けプラグインは 2.0 では更新が必要。2.0 系（`v2.3.0` など）は別ラインで、本項目は 1 系の `v1.19.6`。
- 公式リンク: https://github.com/sst/opencode/releases/tag/v1.19.6
- 参考リンク: https://opencode.ai/
- メモ: 11-08 記事は 2 系 `v2.2.6` を扱った。1 系 `v1.19.6` は本記事が初出。
