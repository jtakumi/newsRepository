# 2026-11-27 AI Tools News

## 今日の要点

- **Claude Code `v2.1.332`** が公開。**MCP サーバー由来のスキルを beta でサポート**（`/` メニューに `server:skill` として表示）、スキル／コマンドのインラインシェルコマンドを読み込み時に拒否できる **`PreSkillShellCommand` フック**を追加。`claude auth login` が保存失敗時に **成功を偽らずに exit 1 で理由を返す**ように修正し、名前付きパイプ・巨大フック出力・長い権限ルール照合など多数のフリーズを解消。Bedrock Mantle の `sonnet` エイリアスが Haiku 4.5 に解決される不具合も修正。
- **LiteLLM `v1.111.0`**（Latest stable）が公開。**Claude Fable 5.2（`claude-fable-5-2`）を Anthropic API・Bedrock・Azure AI・Vertex AI・GitHub Copilot・Databricks でサポート**し `claude-fable-latest` を張り替え。**OpenSearch パススルー（キー単位の read/write 権限付き）** やカスタマー階層・予算、Messages ルートの Rust 化を追加。**破壊的変更**として文字起こし課金がプロバイダ報告秒数ベースに、RAG ingest が managed file ID を返す、Docker が単一イメージ化など。翌 26 日には LTS 系 `1.108.18` / `1.108.19` も公開。
- **Cline `v4.1.28`** が公開。**モデルカタログを刷新**し、OpenAI プロバイダから upstream が非推奨にしたモデルを除外、新プロバイダ **Concentrate・Prima Labs を追加**。同日に Cline CLI `v3.0.76`・SDK `v0.2.2`・Desktop `v0.0.51` も更新。
- **LangChain（Python）**の `langchain-anthropic 1.7.13` が公開。**カスタム HTTP クライアント／SDK クライアントを受け付ける**ようになり、プロキシや独自 httpx 設定を差し込みやすくなった。`langchain-core 1.8.5` はストリームチャンクでプロバイダのメッセージ ID を再利用する修正を含む。

### 1. Claude Code / `v2.1.332`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code / MCP
- 公開・更新日: 2026-11-25 01:32（UTC、JST 11-25 10:32）
- 概要: 安定版の更新。**新機能**として、**MCP サーバーが提供するスキルを beta でサポート**し、`/` メニューに `server:skill` 形式で表示（他のスキル名は従来どおり）。**`PreSkillShellCommand` フックイベント**を追加し、スキルやコマンドのインラインシェルコマンドを読み込み時に拒否できる（2.1.331 以前は同フックを指定した設定ファイルがあると起動時にダイアログが開く）。他セッションからの保留メッセージ確認に「Always deliver（常に配信）」を追加、`SendUserMessage` や Cowork のメッセージツール経由テキストを記録する OpenTelemetry `assistant_response` イベント、claude.ai サインイン時の startup ヘッダーへの Cyber Verification Program アクセス階層表示など。**バグ修正**が非常に多く、`claude auth login` がログイン保存に失敗しても成功と報告していた問題（exit 1 と原因提示に修正）、何も書き込まれない名前付きパイプで Read・@メンション・コンパクションがハングする問題（20 秒でタイムアウト）、巨大なフック出力・長いコマンドへのワイルドカード権限ルール照合・ローカル MCP サーバーの stdout 氾濫などによる各種フリーズ、SSE MCP サーバーがストリーム切断後に手動再接続までツール呼び出しを拒否する問題などを解消。**変更**として、Bedrock Mantle の `sonnet` エイリアスが Haiku 4.5 に解決されていたのを Sonnet 5 を指すよう修正、各種ゲートウェイ／プロバイダ（Bedrock・Agent Platform・Foundry）でモデルが使えないとき family 内の旧モデルへ段階的に下げるフォールバックを整備。
- 何が便利か: MCP サーバーのスキルが `/` メニューから直接使え、エージェント拡張をチームで配りやすくなる。`PreSkillShellCommand` フックで、スキル／コマンドが読み込み時に実行するインラインシェルコマンドをポリシーでガードできる。フリーズ・ハング系の修正が多く、名前付きパイプや大量ログを扱う実運用での引っかかりが減る。`claude auth login` が失敗を失敗として返すため、CI やスクリプトでの認証エラーを確実に検知できる。
- 使いどころ: MCP サーバーを多数つなぎ、スキルとして機能を配布・共有したいチーム。フック（`PreSkillShellCommand`）でスキル／コマンド実行を審査したいセキュリティ要件のある環境。Bedrock / Vertex / Foundry 経由で Claude を使い、モデルエイリアスやフォールバックの挙動を安定させたいケース。
- 開発者にとっての価値: ターミナルエージェントの拡張性（MCP スキル）と運用安全性（シェルコマンド審査フック、認証失敗の正しい報告）が同時に上がる。長時間・大規模セッションでのフリーズ修正は体感品質に直結する。
- 注意点: MCP スキルは **beta**。OpenTelemetry の `service.name` が Desktop Code タブで `claude-code-desktop` に変わるなど、テレメトリのフィルタ更新が必要な変更を含む。`computer-use` が Mac でcomputer use 有効時に予約スキル名になり、同名の独自スキル／コマンドは読み込み停止する。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.332
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: 既存記事では `v2.1.331`（11-24 記事）まで掲載済み。本記事は未掲載の `v2.1.332` を採用。

#### 使用例

# 更新して確認
claude update   # もしくは各配布チャネルで更新
claude --version

# MCP サーバーのスキルは / メニューに server:skill として表示される
# PreSkillShellCommand フックは settings.json の hooks に定義する

### 2. LiteLLM / `v1.111.0`

- 種別: OSS / プロキシ・ゲートウェイ
- 関連: LiteLLM / Claude（Fable 5.2）/ Bedrock / Azure / Vertex AI / OpenSearch / MCP
- 公開・更新日: 2026-11-25 01:42（UTC、JST 11-25 10:42）
- 概要: stable 系のマイナー更新。**Claude Fable 5.2（`claude-fable-5-2`）を広くサポート**し、Anthropic API とその Claude Platform on AWS ミラー、Bedrock（GovCloud リージョン行・トークンカウント含む）、Azure AI（通常版と fast variant）、Vertex AI、GitHub Copilot、Databricks のエントリを追加、`claude-fable-latest` エイリアスを新モデルへ張り替え。**新機能**として **OpenSearch パススルー（キー単位の read/write 権限付き）**、ベクターストア検索の k-NN フィルタマッピングとハイブリッド検索、カスタマー階層・予算（組織／チーム／メンバー、予算テンプレート、モデル単位の TPM/RPM 制限）、カスタマーポータル（beta）、Microsoft Web IQ 検索プロバイダや Replicate の動画／画像／TTS、Copilot CLI ログインなどを追加。**Messages ルートを Rust 実装に移行**し、コストマップや Redis バッチ処理も Rust 化。デプロイは単一 Docker イメージ・単一 Helm チャートに統一。**破壊的変更**として、文字起こしがプロバイダ報告の秒数で課金、RAG ingest が managed file ID を返しベクターストアのファイルルートがチーム資格情報を使用、Vertex AI でクライアント指定の location/project は管理者がオプトインしない限り拒否、role なしメッセージは 400 を返す、など。
- 何が便利か: Claude Fable 5.2 を主要クラウド横断で OpenAI 互換エンドポイント経由で呼べる。OpenSearch パススルーとベクターストアのハイブリッド検索で、RAG 基盤をゲートウェイ側に寄せやすい。カスタマー階層・予算とレート制限で、マルチテナント運用のコスト・流量管理が細かく行える。
- 使いどころ: 複数プロバイダ・複数クラウドの LLM を 1 本のゲートウェイに集約し、RAG やマルチテナント課金まで含めて運用する構成。Claude Fable 5.2 を Bedrock / Azure / Vertex 経由で検証したいケース。
- 開発者にとっての価値: 新モデル（Fable 5.2）への追従と、RAG・マルチテナント・レート制限といった本番運用機能がまとめて入る。Rust 化で Messages ルートのパフォーマンス改善も見込める。
- 注意点: **破壊的変更が複数ある**。特に文字起こし課金方式の変更、RAG ingest の戻り値（managed file ID）、Vertex AI の location/project 拒否、role なしメッセージの 400 化は、既存クライアント実装に影響し得るため更新前に確認すること。Docker は単一イメージ・単一エントリポイントに統一され、`litellm-helm` チャートは削除された。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.111.0
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 既存記事では stable 系 `v1.110.3`・LTS `v1.108.16`（11-24〜11-25 記事）まで掲載済み。本記事は未掲載の stable `v1.111.0` を採用。翌 11-26 に LTS 系 `1.108.18`（Bedrock Mantle gemma-4 のツールスキーマ拒否で Claude Code ターンが壊れる問題の修正など）・`1.108.19`（OpenAI tool-use・web search 設定の修正、OpenRouter ストリームチャンク欠落による thinking signature 喪失の修正など）も公開されている。

#### 使用例

```bash
pip install -U litellm
# config.yaml のモデル定義で claude-fable-5-2 を指定して起動
litellm --config config.yaml
```
