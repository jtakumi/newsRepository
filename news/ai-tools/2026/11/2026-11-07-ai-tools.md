### 1. Claude Code / `v2.1.319`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-06（GitHub Releases, Latest）
- 概要: 権限・自動化まわりの改善が中心のリリース。非対話実行で「権限プロンプトが必要になる操作」を待たずに拒否して続行させる設定や、MCP タスクのバックグラウンド化が入った。
- 何が便利か:
  - `permissions.denyInsteadOfPrompting` を有効にすると、本来プロンプト待ちになるツール呼び出しを自動拒否してターンを継続（ターミナルセッション・サブエージェント・チームメイト対象）。無人実行で止まらない。
  - MCP タスクが即座にバックグラウンドで走り、完了時に結果を Claude へ返す。長時間ツールでブロックされない。
  - `claude -p`（ヘッドレス）が、安全性チェック不可で auto モードが操作を拒否した場合に終了コード 1 を返すようになり、CI での失敗検知がしやすい。
  - Bash の deny/ask ルールがクオート付きコマンドも捕捉。環境変数プレフィックスや `sed` を使った権限バイパスを修正（セキュリティ強化）。
- 使いどころ: CI / バッチ / スケジュール実行で、権限プロンプトに引っかかって停止するのを避けたい自動化ワークフロー。MCP で重いツールを並行実行する構成。
- 開発者にとっての価値: 無人・非対話運用での「止まらなさ」と安全境界の両立。終了コードでの失敗検知と組み合わせやすい。
- 注意点: `denyInsteadOfPrompting` は「拒否して続行」なので、許可が必要な操作は実行されない点を前提に設計すること。MCP タスクのバックグラウンド化を止めたい場合は `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`、タスク自体を無効化するなら `CLAUDE_CODE_DISABLE_MCP_TASKS=1`。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.319
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: `/claude-api latency-optimize`（Claude API コードの遅延最適化）や `/tasks` の「Earlier in this session」行なども追加。

#### 使用例

```bash
# 更新して最新版を確認
claude update
claude --version   # v2.1.319 を確認

# settings.json 例: 権限プロンプトを待たずに拒否して続行（非対話/CI 向け）
#   {
#     "permissions": { "denyInsteadOfPrompting": true }
#   }

# ヘッドレス実行。安全性チェック不可で拒否されたら exit 1 になる
claude -p "リポジトリのテストを実行して結果を要約" || echo "auto mode が操作を拒否 (exit $?)"
```

### 2. OpenAI Codex CLI / `rust-v0.167.0`

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 2026-11-06（GitHub Releases, Latest / 安定版）
- 概要: ターミナル常駐のエージェント運用を強化した安定版。複数エージェントやバックエンドを跨いだ作業の切り替えがしやすくなった。
- 何が便利か:
  - `codex agents --no-daemon` で「エージェント・コマンドセンター」を起動。セッションピッカーと合わせて未読の結果にマークが付く。
  - セッションピッカーから接続済みバックエンドを、下書きを失わずに切り替え可能。
  - 対応ターミナルではコンポーザがローカル画像添付をプレビュー。トランスクリプト内の画像パスがクリック可能に。
  - `Ctrl+L` で画面クリア（過去メッセージは `Ctrl+T` で参照可）、ネットワーク承認プロンプトはリクエスト終了時に閉じる。
- 使いどころ: 複数の作業スレッド/バックエンドを並行管理するエージェント運用。画像を混ぜたやり取りをターミナルで完結させたい場面。
- 開発者にとっての価値: 「どのエージェントに未読結果があるか」を把握しやすく、長時間の並行作業を見失いにくい。安定版なので日常運用に載せやすい。
- 注意点: `rust-v0.168.0-alpha.*` / `rust-v0.169.0-alpha.*` も並行して出ているが、それらは alpha。常用は安定版の `0.167.0` を推奨。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.167.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 失敗レスポンスやトークン使用量が取れないレスポンスも自動コンテキスト圧縮の計算に含めるよう改善。

#### 使用例

```bash
# インストール / 更新
npm install -g @openai/codex   # もしくは各配布物から

# エージェント・コマンドセンターを起動
codex agents --no-daemon
```

### 3. GitHub Copilot CLI / `v1.0.107`

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-11-06（GitHub Releases, Latest）
- 概要: 300 以上の変更を含む大型リリース。エディタ連携や設定体験、セッション管理が強化された。
- 何が便利か:
  - `/code` で現在のセッションをそのまま VS Code で開ける。CLI とエディタの往復がスムーズに。
  - `/settings` が全ユーザ向け統合ダッシュボードになり、設定とローカルリソースを横断検索できる。

  - 負荷時の空の 404 応答をリトライ、長い会話は推論をトリミングして再試行するなど堅牢性も改善。
- 使いどころ: Copilot CLI を日常のコーディング補助として常用し、VS Code と行き来しながら作業する開発者。
- 開発者にとっての価値: CLI 単体で完結しにくかった「設定・エディタ連携・セッション管理」が底上げされ、実務での取り回しが良くなる。
- 注意点: GPT-6.1 Terra は対象アカウントで利用可能な場合に「New models」から選択可。サンドボックス実行やログインの `http://` 拒否などセキュリティ関連の挙動変更も含むため、CI 設定は再確認を。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.107
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: `copilot login --device-code` が平文 `http://` ホストを拒否、`/session delete` が未知オプションを拒否するなど安全側の修正多数。

#### 使用例

```bash
# インストール / 更新
npm install -g @github/copilot

# 起動後、現在のセッションを VS Code で開く
copilot
#   > /code
# 設定ダッシュボードを開く
#   > /settings
```

### 4. Gemini CLI / `v0.67.0`

- 種別: CLI
- 関連: Gemini / Google AI
- 公開・更新日: 2026-11-04（GitHub Releases, Latest / 安定版）
- 概要: 利用可能モデルの確認手段を追加し、IDE 連携やセキュリティ周りを整えた安定版。
- 何が便利か:
  - 新しい `models` コマンドと `--list-models` フラグで、使えるモデルを一覧確認できる。
  - IDE コンパニオンが exec stdio 経由でコンテナサンドボックス内のツールに接続可能に。
  - 非対話モードが終了シグナルを適切に処理し、キャンセル後はツール実行をスキップ。アトミック書き込みが読み取り専用ファイルやハードリンクを尊重。
- 使いどころ: モデル選択をスクリプトで確認したい場合や、コンテナ化した開発環境で Gemini CLI を使う構成。
- 開発者にとっての価値: 「どのモデルが使えるか」をコマンドで取得できるため、CI やスクリプトでのモデル指定が確実になる。キャンセル時の後始末が改善され、自動実行の後片付けが安全に。
- 注意点: `v0.68.0-preview.0` や nightly も出ているが、常用は安定版 `v0.67.0` を推奨。
- 公式リンク: https://github.com/google-gemini/gemini-cli/releases/tag/v0.67.0
- 参考リンク: https://github.com/google-gemini/gemini-cli/releases
- メモ: 未信頼フラグのチェックは外部出力のみに適用し、承認済みフラグを記憶。ACP の権限要求に MCP サーバ/ツールのメタデータを含めるよう改善。

#### 使用例

```bash
# インストール / 更新
npm install -g @google/gemini-cli

# 利用可能なモデルを一覧表示
gemini models
# もしくは
gemini --list-models
```

- 種別: OSS / ローカルLLMランタイム
- 関連: Ollama / ローカルLLM
- 公開・更新日: 2026-11-06（GitHub Releases, Latest）
- 概要: 新モデル対応と `ollama launch` の対応 CLI 拡充が中心。ローカルで試せるコーディング/判定系モデルが増えた。
- 何が便利か:
  - MiMo V2.6（Xiaomi の 9B、コーディング/エージェント向け）を `ollama run mimo-v2.6` で実行可能。
  - AutoTrust 判定モデル（`autotrust-jev`、9b / 35b / 27b-vl）に対応。テキストへの選択肢・yes/no 確率・評点での回答が可能で、35b と 27b-vl は画像も読める（本リリースでは Apple シリコン向け）。
  - `ollama launch` が Kimi Code CLI に対応（kimi-cli を置き換え、既存設定の移行も可能）。Pi のモデル一覧を自動補完、Claude Desktop のモデルピッカーに Ollama のモデル名を表示。
  - 再帰系/ビジョン GGUF が複数リクエストを同時処理可能に。Qwen3 / Qwen3.5 が YaRN による長コンテキストスケーリングに対応。
- 使いどころ: ローカルでコーディング支援モデルを試したい、あるいは「テキストの判定（yes/no・評点）」をローカル完結でやりたいケース。
- 開発者にとっての価値: クラウドに出さずにローカルで新しめのコーディング/判定モデルを試せる。`ollama launch` 経由で各種 AI CLI の初期設定を肩代わりしてくれる。
- 注意点: AutoTrust の各サイズは本リリースでは Apple シリコン向けとの記載。モデルサイズ（35b 等）に見合う VRAM/メモリが必要。
- 公式リンク: https://github.com/ollama/ollama/releases/tag/v0.40.15
- 参考リンク: https://github.com/ollama/ollama/releases
- メモ: 引数なしで `ollama` を実行するとウェルカムランチャーが開くようになった。

#### 使用例

```bash
# 本体を更新後、MiMo V2.6 をローカルで実行
ollama run mimo-v2.6

# Kimi Code CLI の初期設定を ollama launch で行う
ollama launch kimi
```
