### 1. OpenAI Codex CLI / `rust-v0.169.0`（＋ `rust-v0.168.0`）

- 種別: CLI
- 関連: OpenAI / Codex
- 公開・更新日: 2026-11-13（安定版・「Latest」）
- 概要: 大型の機能リリース。**オプトインのターミナルワークスペースで複数のサイドチャットタブ**を持ててキーボード／マウスで切り替え、保存したローカルサイドチャットを再起動後も復元できる。**カスタムモデルプロバイダをターミナルから追加・編集**（サインイン中やデバイスコードログインにも対応）、**`Ctrl+S` でアップロード無効時でも診断 ZIP をローカル保存**、過去タスクを名前・プロンプト・作業ディレクトリで検索、フルスクリーン転写での「Collapse turn details」折りたたみ、Cloud 連携（macOS/Linux・オプトイン）で画像送信・モデル／推論量選択・アーカイブに対応。バグ修正として **`codex exec` が未信頼ディレクトリではプロジェクト設定と MCP サーバを既定で無効化**（明示信頼は `--trust`）、Windows サンドボックスの引用符付き `cmd.exe` パス修正、MCP 未報告サーバでのハング解消など。直前の `rust-v0.168.0`（同日）もプロバイダブラウズ、サイド会話ペイン（`features.tui_workspace`）、音声録音添付、GIF 生成などを追加している。
- 何が便利か: 複数サイドチャットタブで並行した問い合わせ・検討をターミナル内で分けて進められる。カスタムプロバイダ対応で OpenAI 以外のゲートウェイを設定ファイルを触らずに登録できる。`Ctrl+S` の診断 ZIP は不具合報告の再現情報収集を1操作に短縮する。
- 使いどころ: ターミナル中心の開発で、調査用チャットと実装用チャットを分けたいとき。社内ゲートウェイや独自エンドポイントを Codex に登録したいとき。未信頼のクローン済みリポジトリを安全に開くとき（既定で設定・MCP が無効）。
- 開発者にとっての価値: 安定版で入るためそのまま追従でき、`codex exec` の未信頼ディレクトリ既定無効化は CI・自動実行時の安全性に直結する。カスタムプロバイダのターミナル登録は運用の手数を減らす。
- 注意点: ターミナルワークスペース（複数タブ）はオプトイン機能。Cloud 連携は macOS/Linux のオプトイン。`0.170.0`／`0.171.0` 系の alpha も並行進行中だが本番非推奨。
- 公式リンク: https://github.com/openai/codex/releases/tag/rust-v0.169.0
- 参考リンク: https://github.com/openai/codex/releases
- メモ: 前回（11-13 の記事）は安定版パッチ `rust-v0.167.2` を扱った。本項は新規の安定版 `rust-v0.168.0`／`rust-v0.169.0` の差分。

#### 使用例

```bash
# インストール／更新
npm install -g @openai/codex
codex --version

# 未信頼ディレクトリでプロジェクト設定・MCP を使いたい場合のみ明示信頼
codex --trust
```

### 2. Claude Code / `v2.1.325`

- 種別: CLI / 拡張機能
- 関連: Claude / Anthropic / Claude Code
- 公開・更新日: 2026-11-13（「Latest」）
- 概要: セキュリティ修正として **zstd 圧縮応答のデコードの問題を修正**。権限・サンドボックス関連の修正が多数入り、特に **compound（複合）Bash コマンドが無確認で走ってしまう穴を塞ぎ**、**Bash の allow ルールが名前と異なるプログラムを実行し得る**不具合を修正。挙動変更として **サンドボックス実行の Bash コマンドを既定で通常の権限フローに従わせる**ようになり、無確認で走らせたい場合は `sandbox.autoAllowBashIfSandboxed: true` を設定する。読み取り専用の git コマンドも、プロジェクト外／未信頼のリポジトリでは確認を求めるよう変更（`--add-dir` で明示）。スケジュールタスク／`/loop` は `allowed-tools` やフックを宣言するスキルの実行前に確認を求めるようになった（無人実行には `permissions.allow` に `Skill(name)` を追加）。ほか、自分のモデルを持つサブエージェントが `opusplan`／`haiku` 時に plan-mode モデルへ移される不具合、サードパーティゲートウェイで毎ターン context length エラーになり compaction されない不具合、VS Code で Jupyter ノートブック編集後にセル再実行を促すヒント表示などを修正・追加。
- 何が便利か: 自動化・CI で Claude Code を使う際の権限の抜け穴が塞がれ、サンドボックス Bash が既定で権限フローに従うため、無確認実行の範囲を明示的に制御できる。サードパーティゲートウェイのセッションが compaction されるようになり長時間セッションが安定する。
- 使いどころ: 権限・サンドボックスを厳格化した上での CI・無人実行。サードパーティ LLM ゲートウェイ経由での長時間セッション。plan/execute を使うサブエージェント運用。
- 開発者にとっての価値: セキュリティ修正（zstd デコード・Bash 権限の穴）は早期更新の価値がある。サンドボックス Bash の既定挙動変更は自動化スクリプトの前提に影響するため、更新時に確認フローの有無を見直すべき。
- 注意点: **サンドボックス Bash の既定が「通常の権限フローに従う＝確認を求める」に変わる**ため、無人運用で無確認実行を前提にしていた場合は `sandbox.autoAllowBashIfSandboxed: true` の設定が必要。スケジュールタスク／`/loop` でのスキル実行も確認が入るため `Skill(name)` の allow 追加を検討。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.325
- 参考リンク: https://github.com/anthropics/claude-code/releases
- メモ: 前回（11-13 の記事）は `v2.1.323`（Code Mode 追加）を扱った。本項は新規の `v2.1.325` 差分（間の `v2.1.324` はリリース一覧に現れず、`v2.1.325` が次の公開版）。

#### 使用例

```bash
# 最新版へ更新
claude update && claude --version

# サンドボックス Bash を無確認で走らせたい無人運用向け設定（settings.json）
# "sandbox": { "autoAllowBashIfSandboxed": true }
```

### 3. GitHub Copilot CLI / `1.0.111`（＋ `1.0.110`）

- 種別: CLI
- 関連: GitHub Copilot
- 公開・更新日: 2026-11-13（`1.0.111`・「Latest」）／2026-11-12（`1.0.110`・安定版）
- 概要: 前回まではプレリリースのみだったが、安定版 `1.0.110`（11-12）と `1.0.111`（11-13）が公開された。`1.0.111` では **企業管理の Shell／Bash／PowerShell 権限ルールに正規表現対応**を追加。**`--host-allow-session-creation`** により、リモートクライアントが CLI ホスト上に一時的にセッションを作成できる（保存設定は変えず1回の起動のみ）。`/usage` はプレミアムリクエスト使用率を更新して表示を最新化し、アクティビティグラフが狭いターミナルに収まり、入力したプロンプトのみを数えるようになった。MCP 周りは重複 OAuth 再接続の防止、キャンセル後の needs-auth 維持、ワークスペースサーバの相対作業ディレクトリ解決、`/mcp delete` が他サーバを再起動しない修正。ワークフローは、ワークフロー自身のエージェントがワークフロー実行を開始・再開できないよう制限し、作業中に入力した follow-up を入力順に実行するよう修正。狭い／短いターミネルや CJK 折り返し、`--screen-reader` モードの表示修正も多数。
- 何が便利か: 正規表現の権限ルールで、企業環境のコマンド許可／拒否をより柔軟に表現できる。`/usage` の改善でプレミアムリクエストの消費を正確に把握できる。MCP の再接続・認証まわりの安定化で、MCP サーバ接続が切れにくくなる。
- 使いどころ: 組織でコマンド実行ポリシーを細かく管理したいチーム。MCP サーバを複数つないだ運用。CI やリモート経由で Copilot CLI セッションを立てたいケース。
- 開発者にとっての価値: プレリリース追従をやめ安定版で最新機能を取り込める。権限ルールの正規表現対応はガバナンス面で実用的。
- 注意点: 正規表現対応は「企業管理（enterprise-managed）」の権限ルールが対象。`--host-allow-session-creation` はセキュリティ境界に関わるため、どのリモートクライアントに許すか運用方針を決めてから使うこと。
- 公式リンク: https://github.com/github/copilot-cli/releases/tag/v1.0.111
- 参考リンク: https://github.com/github/copilot-cli/releases
- メモ: 前回（11-13 の記事）は Copilot CLI を「安定版の新規なし（プレリリース `v1.0.110-2`／`-3` のみ、安定版 `v1.0.109` は既出）」として見送っていた。本項は新規の安定版 `1.0.110`／`1.0.111` の採用。

### 4. Vercel AI SDK / `ai@7.0.172`（＋ `@ai-sdk/workflow@2.0.104`）

- 種別: OSS / SDK
- 関連: Vercel AI SDK
- 公開・更新日: 2026-11-13
- 概要: `ai@7.0.172` は、**`experimental_extract`／`experimental_decide` でリモートファイル URL を扱う際に、明示的な `experimental_download` フックを必須化**する変更（インラインのファイルデータは従来どおり動作）。暗黙のリモート取得に依存していた呼び出しは動かなくなる可能性がある。あわせて provider-utils と gateway の依存を更新。同日公開の `@ai-sdk/workflow@2.0.104` は `WorkflowAgent` の修正4件：コンストラクタで `onError`／`onAbort` を受け取れる、ツールにシステムプロンプトや現在のツール呼び出しメッセージを渡さない、`prepareStep` のオーバーライドが1ステップにのみ適用、`totalUsage` 集計を `ToolLoopAgent` と一致させる。
- 何が便利か: ファイル取得が明示フック経由になることで、リモート URL のダウンロード経路を制御でき、意図しない外部取得や認証情報の漏れを防ぎやすい。`WorkflowAgent` の修正でエージェントのエラー／中断ハンドリングと使用量集計が整う。
- 使いどころ: `experimental_extract`／`experimental_decide` を使う抽出・判定処理。`WorkflowAgent` でマルチステップのエージェントを組むケース。
- 開発者にとっての価値: パッチだが、抽出 API のセキュリティ境界が明確になる重要な変更。ワークフローエージェントの挙動修正は実運用の正確性に効く。
- 注意点: **リモートファイル URL を暗黙取得していたコードは `experimental_download` フックの追加が必要**になる（破壊的変更に近い挙動変更）。`extract`／`decide` は実験的 API のため今後も変わり得る。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.172
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 前回（11-13 の記事）は `ai@7.0.171`／`6.0.331` を扱った。本項は新規の `ai@7.0.172` と `@ai-sdk/workflow@2.0.104`。
