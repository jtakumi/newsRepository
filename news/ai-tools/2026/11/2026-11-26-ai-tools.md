# 2026-11-26 AI Tools News

## 今日の要点

- **Claude Code `v2.1.332`** が公開。**MCP サーバー由来のスキル（beta）** が `/` メニューに `server:skill` として並ぶようになり、ロード時にスキル／コマンドのインラインシェルコマンドを拒否できる新フック **`PreSkillShellCommand`** が追加。`claude auth login` が保存失敗時に「Login successful.」と誤報せず **exit 1 で原因を表示**するよう修正され、各種フリーズ・ハング・MCP 不具合もまとめて直った。
- **LangChain（Python）** が 11-25 に更新。**`langchain-anthropic 1.7.13` が独自の HTTP クライアント・SDK クライアントの差し込みに対応**（プロキシや独自トランスポートを使う構成で有用）。**`langchain-core 1.8.5`** は **プロバイダのメッセージ ID をストリーミングの後続チャンクでも再利用する修正**を収録。
- **Vercel AI SDK `ai@7.0.182`** が、**WebSocket リアルタイム音声のバージイン（割り込み）時に、実際に再生中の音声アイテムを正しい位置で打ち切る修正**を収録。短いプリアンブルを先にキューした場合などにプロバイダがリクエストを拒否する問題が解消。
- **LiteLLM `v1.109.5`（stable）** が公開。**スタンドアロン UI イメージの nginx / zlib 更新**（nginx 1.31.10・zlib 1.4）とエンドユーザー制限リフレッシュの高速化を収録（「アップグレードに特別な対応は不要」）。同日に LTS `v1.108.18` と RC `v1.112.0-rc.1` も公開。

### 1. Claude Code / `v2.1.332`

- 種別: CLI
- 関連: Claude / Anthropic / Claude Code / MCP
- 公開・更新日: 2026-11-25 01:32（UTC、JST 11-25 10:32）
- 概要: 新機能・変更・多数の不具合修正を含む更新。**新機能**として、**MCP サーバーが提供するスキル（beta）** を `/` メニューに `server:skill` 形式で表示（他のスキルは従来名のまま）、スキルやコマンドのインラインシェルコマンドをロード時に拒否できる新フックイベント **`PreSkillShellCommand`**、他セッションからの保留メッセージに対する「Always deliver」オプション、応答ログ有効時に `SendUserMessage` / Cowork のメッセージツール経由テキストを記録する OpenTelemetry `assistant_response` イベント、claude.ai アカウントでサインイン時にモデル名の横へ表示される **Cyber Verification Program アクセスティア**などを追加。**修正**では、**`claude auth login` が保存に失敗しても「Login successful.」と誤表示していた問題**を直し、exit 1 で原因（ロックファイル残存やディスク満杯など）を表示するように変更。ほかに、MCP の **SSE サーバーがイベントストリーム切断・再接続後に全ツール呼び出しを拒否／ハングする問題**、**タスクハンドルが 128 文字超で「malformed task handle」になる問題（最大 1,024 文字まで対応）**、名前付きパイプへの Read / @メンション / 圧縮が書き込みのないパイプでハングする問題（20 秒でタイムアウト）、巨大なログを吐くフックでのセッション凍結、長い会話の再開・`/compact` 失敗時の復旧など、フリーズ・ハング・圧縮・認証／モデル選択・MCP・VS Code 周りを広く修正。**変更**として、`computer-use` が Mac（computer use 有効時）の予約スキル名になり、同名のユーザースキル／コマンドはロードを停止して改名を促すように。
- 何が便利か: MCP サーバー側でスキルを配布し、`/` メニューからそのまま呼べるようになる（beta）。`PreSkillShellCommand` フックでスキル／コマンドが実行するインラインシェルコマンドをロード段階で検査・拒否でき、ガバナンスを強化できる。`claude auth login` の誤成功表示が直り、ログイン失敗を確実に検知できる。
- 使いどころ: MCP サーバーを常用し、スキルを MCP 経由で配布・利用したいチーム。フックでスキルの実行内容を監査・制御したい環境。CI やスクリプトで `claude auth login` の成否を終了コードで判定したいケース。SSE MCP サーバーや長時間会話でハング・フリーズに悩んでいた環境。
- 開発者にとっての価値: MCP スキルの `/` メニュー統合と `PreSkillShellCommand` により、スキルの配布と安全な実行制御がしやすくなる。多数のハング・凍結・認証周りの修正はエージェント運用の信頼性に直結する。
- 注意点: MCP スキルは **beta**。`computer-use` が予約スキル名になったため、同名のユーザースキル／コマンドは改名が必要。Bedrock / Agent Platform / Foundry など各プロバイダのモデルエイリアス（`sonnet` / `opus`）とデフォルトモデルの解決・ステップダウン挙動が大きく変わっているため、該当環境は更新前に確認すること。
- 公式リンク: https://github.com/anthropics/claude-code/releases/tag/v2.1.332
- 参考リンク: https://code.claude.com/docs/en/changelog
- メモ: 既存記事では `v2.1.331`（11-24 記事）まで掲載済み。本記事は未掲載の `v2.1.332` を採用。

#### 使用例

```bash
npm install -g @anthropic-ai/claude-code@latest
claude --version

# MCP サーバー由来のスキルは / メニューに server:skill として表示される
# ログインの成否は終了コードで判定できる（失敗時は exit 1）
claude auth login; echo "exit=$?"
```

### 2. LangChain（Python） / `langchain-anthropic 1.7.13` ・ `langchain-core 1.8.5`

- 種別: OSS（Python ライブラリ）
- 関連: LangChain / Anthropic / Claude
- 公開・更新日: 2026-11-25（UTC、JST 11-26 06:42〜06:52）
- 概要: パートナー統合とコアの更新。**`langchain-anthropic 1.7.13`** は **独自の HTTP クライアントおよび SDK クライアントの差し込みに対応**（#42101）。あわせてモデルプロファイルデータを更新（#42085・#42062）。**`langchain-core 1.8.5`** は、**プロバイダのメッセージ ID をストリーミングの後続チャンクでも再利用する修正**（#42050）を収録。ほかに v3 ランタイムの警告挙動とサポートされるストリーミングイベント API の説明をドキュメント側で明確化、依存の mistune を 3.3.4 に更新。
- 何が便利か: `langchain-anthropic` で独自の HTTP クライアント／SDK クライアントを渡せるようになり、社内プロキシ・カスタムトランスポート・タイムアウトやリトライの独自設定を LangChain 経由でも適用しやすくなる。`langchain-core` のメッセージ ID 再利用修正は、ストリーミング中のチャンクを 1 つのメッセージとして正しく紐付けできるようにする。
- 使いどころ: LangChain（Python）で Claude（Anthropic）を使い、独自 HTTP 設定やプロキシ経由で API を呼ぶ構成。ストリーミング応答のチャンクをメッセージ ID で集約・追跡している処理。
- 開発者にとっての価値: 認証プロキシや独自トランスポートが必須の企業環境で、`langchain-anthropic` をそのまま組み込みやすくなる。ストリーミングの ID 整合が取れることでログ・UI 側の後処理が安定する。
- 注意点: リリースノートはコミットタイトル中心で、独自クライアントの具体的な設定方法は PR／ドキュメントを要確認。`langchain-core` 1.8 系・`langchain-anthropic` 1.7 系の前提（Python バージョン・依存）に合わせること。
- 公式リンク: https://github.com/langchain-ai/langchain/releases/tag/langchain-anthropic==1.7.13
- 参考リンク: https://github.com/langchain-ai/langchain/releases/tag/langchain-core==1.8.5
- メモ: 既存記事では 11-23 公開のパートナー統合一括更新（`langchain-ollama 1.2.0` ほか、11-24 記事）まで掲載済み。本記事は未掲載の `langchain-anthropic 1.7.13`（独自クライアント対応）と `langchain-core 1.8.5`（メッセージ ID 再利用修正）を採用。

### 3. Vercel AI SDK / `ai@7.0.182`

- 種別: OSS / SDK（TypeScript）
- 関連: Vercel AI SDK / Realtime（リアルタイム音声）
- 公開・更新日: 2026-11-25（UTC、JST 11-26 早朝）
- 概要: パッチ更新。**リアルタイム音声のバージイン（ユーザー割り込み）時に、実際に再生中の音声アイテムを正しいオフセットで打ち切る修正**（`ac22e59`）。従来は WebSocket リアルタイムセッションで割り込み時に誤った音声アイテムやオフセットを打ち切り、短いプリアンブルを回答前にキューした場合などにプロバイダがリクエストを拒否することがあった。修正後は各音声チャンクのアイテムと位置（アンダーラン越しも含む）を追跡し、ユーザーが実際に聞いた地点でアイテムを打ち切る。依存の `@ai-sdk/gateway` を 4.0.155、`@ai-sdk/provider-utils` を 5.0.84 に更新。
- 何が便利か: 音声エージェントでユーザーが話して割り込む（バージイン）ユースケースで、打ち切り位置がずれてプロバイダにリクエストを拒否される不具合が解消し、割り込み時の挙動が安定する。
- 使いどころ: Vercel AI SDK の Realtime（WebSocket 経由のリアルタイム音声）でボイスアシスタントや会話エージェントを実装し、ユーザーの割り込みを扱う構成。
- 開発者にとっての価値: リアルタイム音声の割り込み処理という、実装・デバッグが難しい箇所の信頼性が上がる。既存コードへの影響が小さいパッチ。
- 注意点: 影響範囲は主にリアルタイム音声の割り込み処理で、テキスト中心の利用には直接関係しない。コアの新 API 追加はなく、新機能はなし。
- 公式リンク: https://github.com/vercel/ai/releases/tag/ai%407.0.182
- 参考リンク: https://github.com/vercel/ai/releases
- メモ: 既存記事では `ai@7.0.181`（`stoppedBy` / `onWarning` 追加、11-24 記事）まで掲載済み。本記事は未掲載の `ai@7.0.182`（リアルタイム音声バージイン修正）を採用。

#### 使用例

```bash
npm install ai@7.0.182
# リアルタイム音声セッションでのバージイン時の打ち切り挙動が改善される
```
