### 1. Charmbracelet Crush / `v0.100.0`

- 種別: CLI / OSS（AIコーディングエージェント）
- 関連: Charmbracelet Crush / その他
- 公開・更新日: 2026-11-05（GitHub Releases, Latest / UTC 19:22、日本時間 11-06 早朝）
- 概要: ターミナル UI の AI コーディングエージェント Crush の大型安定版。並行作業（サブエージェント）と、実行権限まわりの制御・安全性強化が中心。
- 何が便利か:
  - **サブエージェント**: バックグラウンドでサブエージェントを起動し、進捗確認・途中での追加指示・停止・別モデルへの切替ができる。各サブエージェントには名前が付き、トランスクリプト／サイドバー／ヘッダに表示される。
  - **sysadmin モード**: システム上の任意コマンドを実行できるモード（リリースノートも「Be careful」と明記）。コマンドパレット（ctrl+p）または shift+tab のモード循環から切替。
  - **安全なコマンド制御**: `permissions safe` / `permissions block` / `permissions unblock` で、yolo モードが許可・ブロック・解除するコマンドを指定できる。危険コマンド検出もコマンド連鎖のパース＋大文字小文字非依存で強化。
  - **プロジェクト単位のコマンド設定**: プロジェクトごとに「よく実行するコマンド」を設定可能。
  - **SSH / GPG プロンプト対応**: SSH パスワードや GPG pinentry のプロンプトを Crush 側で扱える。
- 使いどころ: 1 つの作業セッション内で、調査・修正・テストなど複数タスクをサブエージェントに分けて並行実行したい場面。CI や自動化で yolo 実行を使いつつ、`permissions block` で危険コマンドだけ明示的に遮断したい運用。
- 開発者にとっての価値: 「待ち時間に別の作業を進めたい」をサブエージェントで吸収でき、権限制御が細かくなったことで無人・yolo 運用の安全余地が広がる。SSH/GPG 対応で、署名付きコミットや鍵認証を挟む実運用でも止まりにくい。
- 注意点: sysadmin モードは任意コマンド実行を許すため、信頼できる作業ディレクトリ・環境に限定して使うこと。yolo モードの挙動は `permissions safe/block` で明示的に絞るのが安全。
- 公式リンク: https://github.com/charmbracelet/crush/releases/tag/v0.100.0
- 参考リンク: https://github.com/charmbracelet/crush/releases
- メモ: 既存の AI Tools News では `v0.99.0`（11-01 記事）まで掲載。本項は新しい安定版 `v0.100.0` を扱う。公開日は 11-05（UTC）のため厳密には 48 時間をやや超えるが、新機能が明確な新安定版として採用。

#### 使用例

```bash
# インストール / 更新（Homebrew の例）
brew upgrade charmbracelet/tap/crush
# もしくは
go install github.com/charmbracelet/crush@latest

# 起動後、モード切替・権限制御は TUI 内で操作
crush
#   ctrl+p           … コマンドパレット（sysadmin モード等を選択）
#   shift+tab        … モード循環
#   permissions block <command>    … yolo モードで特定コマンドをブロック
#   permissions safe  <command>    … 許可リストに追加
```

### 2. LiteLLM / `v1.110.0-dev.2`

- 種別: OSS / APIプロキシ・SDK
- 関連: OpenAI / Anthropic / Gemini / その他（LLM ゲートウェイ）
- 公開・更新日: 2026-11-08（GitHub Releases / dev プレリリース、UTC 02:25）
- 概要: 多数の LLM プロバイダを統一 API/プロキシでまとめる LiteLLM の開発版。セキュリティ系ガードレールとコスト/ログ制御の追加が中心。
- 何が便利か:
  - **プリビルトの資格情報検出ガードレール**: OpenAI / Anthropic / Gemini の API キー形式を検出するパターンを標準提供（#50268）。プロキシ経由のリクエスト/レスポンスでキー流出を検知しやすくなる。
  - **プロンプト保存の無効化をキー/チーム単位で設定**（#50135）。ログに生のプロンプトを残したくない運用に対応。
  - **ストリームで `usage.cost` を返すリクエスト単位ヘッダ**（#50574）。グローバルフラグを立てずに、必要なリクエストだけコストを取得できる。
  - その他、ルータのリトライ/フォールバック記録の改善、キャンセル時のトークン予約解放、Anthropic のストリーミング・ツール引数の逐語保持（#50470）、`reasoning_effort: "none"` で思考を無効化（#50541）など多数の修正。
- 使いどころ: 複数プロバイダを LiteLLM プロキシ経由で束ねている構成で、(1) うっかりログに API キーが混入するのを検知したい、(2) チーム/キー単位でプロンプトのログ保持ポリシーを変えたい、(3) 特定リクエストだけコストを取りたい、といった運用。
- 開発者にとっての価値: ゲートウェイ層で「鍵の漏えい検知」「ログ最小化」「コスト可視化」をコード変更なしに足せる。マルチプロバイダ運用のガバナンス・コスト管理を一段締められる。
- 注意点: これは **dev ビルド**（`-dev.2` サフィックス、本記事時点で main にさらに 11 コミット）。常用は安定版を推奨（LTS は `1.108.2`）。`Responses` の SSE イベント整形に破壊的変更（#47980）を含むため、Responses API 利用時は挙動を要確認。
- 公式リンク: https://github.com/BerriAI/litellm/releases/tag/v1.110.0-dev.2
- 参考リンク: https://github.com/BerriAI/litellm/releases
- メモ: 前回記事（11-08）では `v1.110.0-dev.1` を「dev ビルドのため除外」としていたが、`dev.2` で資格情報検出ガードレール等の具体的な新機能が入ったため、dev 版である旨を明示した上で採用。

#### 使用例

```bash
# 安定版の導入（推奨）
pip install "litellm[proxy]"

# dev 版の機能を試す場合のみ明示指定
pip install "litellm[proxy]==1.110.0.dev2"

# プロキシを起動（config.yaml でガードレールやキー単位のログ設定を定義）
litellm --config config.yaml
```

### 3. Qwen Code TypeScript SDK / `@qwen-code/sdk` `v0.1.30`

- 種別: OSS / SDK（TypeScript）
- 関連: Qwen / その他
- 公開・更新日: 2026-11-08（GitHub Releases, Latest / UTC 00:55）
- 概要: AI コーディングエージェント Qwen Code を、CLI の対話 UI ではなくコードから（ヘッドレスで）呼び出すための公式 TypeScript SDK。CLI `v0.27.0` と同系統で、SDK パッケージに CLI 本体をバンドルする。
- 何が便利か:
  - `npm install @qwen-code/sdk` だけで、Qwen Code エージェントを自分の Node.js スクリプト/アプリから駆動できる（0.1.1 以降は CLI 同梱のため CLI の別途インストール不要）。
  - インプロセス MCP サーバ（`@modelcontextprotocol/sdk` ベース）に対応し、自前ツールをエージェントに渡しやすい。
  - この `v0.1.30` は CLI `v0.27.0` をバンドル。CLI 側の `FileChanged` フックや PR ウォッチなどの機能更新と同系統。
- 使いどころ: CI/バッチで「差分を要約」「テスト失敗を調査」などをスクリプト化したい、社内ツールにコーディングエージェントを組み込みたい、独自の MCP ツールと組み合わせて自動化したい、といった場面。
- 開発者にとっての価値: 対話 CLI を人が操作する前提から外し、エージェントを「ライブラリとして組み込む」運用に寄せられる。Node.js 環境があれば既存の自動化に載せやすい。
- 注意点: SDK は公式ドキュメントでも「experimental / minimal」と位置づけられており、API は変わり得る。Node.js のバージョン要件（公式ドキュメントは 22 以降）を確認すること。本リリースはバージョン固有の詳細変更がリリースノートに列挙されておらず（「commit history を参照」）、主要点は CLI `v0.27.0` と共通。
- 公式リンク: https://github.com/QwenLM/qwen-code/releases/tag/sdk-typescript-v0.1.30
- 参考リンク: https://qwenlm.github.io/qwen-code-docs/en/developers/sdk-typescript/
- メモ: 同日に Qwen Code Desktop `v0.27.0`（tag `desktop-v0.27.0`）も公開。CLI 本体 `v0.27.0` は前回記事（11-08）で既出。
